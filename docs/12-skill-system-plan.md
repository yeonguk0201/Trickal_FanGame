>

## 1. 결정된 사항 요약

### 1.1 저학년 스킬 (SP 스킬)

| 항목 | 결정 |
|------|------|
| 리소스 | SP (기본 최대 3, 아티팩트로 Run 중 증가 가능) |
| 획득 방식 | 적 처치 시 확률 드롭 (20~30%, 플테 후 조정) |
| 소비량 | 1회 사용 시 SP 1 소비 |
| 드롭 형태 | 바닥에 SP 픽업 오브젝트 생성 |
| 최대 SP일 때 | 픽업은 사라지지만 SP 변화 없음 |
| 입력 키 | Space |
| 스킬 형태 | 바라보는 방향 중심 36° 부채꼴의 `1→3→2→4` 슬롯 순서로 0.08초 간격 유도탄 4발 → 이후 타깃 유도 → 피격 시 범위 폭발 |
| 다수 타깃 | 거리순 라운드로빈으로 4발을 배분하며 같은 타깃 중복 배정 허용 |
| 연속 입력 | 4발 연사가 끝나기 전에는 재사용과 추가 SP 소비 차단 |
| 타깃이 없을 때 | 플레이어가 바라보는 방향 중심의 전방 퍼짐으로 발사 후 수명 종료 시 소멸 |
| 폭발 중첩 | 같은 적이 여러 폭발 범위에 있으면 피해 중첩 가능 |
| 폭발 피해 | **현재 공격력 × 100%** |
| 단일 적 최대 피해 | 현재 공격력 × 400% (4발 전부 적중 시) |

### 1.2 고학년 스킬 (필살기)

| 항목 | 결정 |
|------|------|
| 리소스 | 쿨타임 (20~40초, 플테 후 조정) |
| 입력 키 | Q |
| 스킬 형태 | 무적 돌진 |
| 지속 | 최대 10초 (적 접촉 시 즉시 종료) |
| 방향 조작 | 이동 키 WASD로 조정, 입력이 없으면 마지막 이동 방향 유지 |
| 중도 취소 | 불가 |
| 벽 충돌 | 종료하지 않음. 방향 입력으로 벽을 벗어날 수 있음 |
| 충돌 시 | 광역 피해 + 0.2초 넉백 후 경직 |
| 적 경직 | 일반 적 0.4초, 보스 0.15초 |
| 보스 넉백 | 일반 적의 25% 넉백 계수 적용 |
| 광역 피해 | **현재 공격력 × 200%** |
| 제약 | 돌진과 회복 중 이동·기본 공격·저학년 스킬·재사용·방/층 전환 차단 |
| 쿨타임 시작 | 돌진 종료 시점 |
| 수동 취소 | 돌진 중 Q 재입력, 피해 없이 감속 회복 후 전체 쿨타임의 80% 적용 |
| 방/층 이동 | 돌진 및 충돌 경직·감속 중 차단, 회복 종료 후 허용 |
| 적 충돌 종료 | 플레이어를 즉시 정지시키고 0.4초 무적 경직 적용 |
| 시간 만료 종료 | 무적 없이 0.25초 동안 돌진 속도를 0까지 감속 |

### 1.3 스킬 피해 계산 공식

```
현재 공격력 = 캐릭터 기본 공격력 + Run 중 공격력 보너스
최종 스킬 피해 = 현재 공격력 × 스킬 배율 × (1 + 스킬 피해 보너스%)
```

> 기존의 "기본 공격력" 표현은 아티팩트 보너스를 포함하는 의미였으므로 "현재 공격력"으로 통일한다.
> 피해와 HP는 내부적으로 `float`를 사용하고 계산 중간에는 반올림하지 않는다.
> UI 숫자는 최대 소수점 1자리로 표시하며 HP가 0 이하가 되면 사망한다.

**예시:**
| 상황 | 현재 공격력 | 스킬 배율 | 스킬 피해 보너스 | 계산 피해 |
|------|------------|----------|-----------------|----------|
| 초반 저학년 | 1 | 100% | 0% | 1 |
| 아티팩트 획득 후 | 5 | 100% | 0% | 5 |
| 스킬 피해 아티팩트 추가 | 5 | 100% | +50% | 7.5 |
| 고학년 스킬 | 5 | 200% | +50% | 15 |

### 1.4 메타 진행 (Run 외부 성장)

| 항목 | 결정 |
|------|------|
| 리소스 | 경험치 |
| 획득 시점 | Run 종료 시 (클리어/사망) |
| 성장 단위 | 캐릭터별 레벨과 경험치 |
| 레벨업 조건 | 현재 레벨의 필요 경험치를 모두 채움 |
| 레벨업 보상 | 스킬 포인트 1 획득 |

## 2. 아티팩트 시스템 (`Item` 안정 계약)

### 2.1 아티팩트 등급

| 등급 | 영문 계약 | 색상 | 드롭 가중치(초안) | 경험치 가중치 |
|------|-----------|------|-------------------|--------------|
| 일반 | `COMMON` | 흰색 | 60 | ×1 |
| 고급 | `UNCOMMON` | 녹색 | 25 | ×2 |
| 희귀 | `RARE` | 파랑 | 12 | ×3 |
| 전설 | `EPIC` | 보라 | 3 | ×5 |

> 등급별 값은 고정 확률이 아니라 가중치다. 현재 획득 가능한 후보만 모은 뒤 가중치 추첨한다.
> `EPIC`은 기존 Backend seed 계약을 유지하며 게임 내 한글 표시는 "전설"을 사용한다.

### 2.2 Phase G 활성 아티팩트 10종

| ID | 이름 | 등급 | 스택당 또는 1회 효과 | 최대 스택 | 구현 구분 |
|----|------|------|----------------------|----------:|-----------|
| `item-01` | 급조한 목검 | 일반 | 공격력 +5% | 5 | 기존 공격력 효과를 퍼센트로 전환 |
| `item-12` | 녹슨 송곳 | 일반 | 치명타 확률 +3%p | 5 | 신규 |
| `item-04` | 낡은 화살 | 고급 | 공격속도 +10% | 3 | 신규 |
| `item-14` | 광기의 가면 | 고급 | 1초마다 주변 적에게 플레이어 최대 HP의 1% 피해 (HP-3에서 공격력 20%로 변경) | 3 | 신규 |
| `item-02` | 풍선 갑옷 | 희귀 | 최대 HP +2 (반 칸 단위 전환 후 +1칸), 획득 시 방어막 부여 | 2 | 기존 최대 HP 효과 확장 |
| `item-03` | 도깨비 감투 | 희귀 | HP 30% 이하에서 이동속도 +25% | 2 | 기존 이동속도 효과를 조건부로 전환 |
| `item-08` | 코미의 베개 | 희귀 | 적 처치 시 최대 HP의 5% 회복 (HP-3에서 2처치마다 반 칸으로 변경) | 2 | 기존 처치 회복 효과를 퍼센트로 전환 |
| `item-15` | 장난감 망원경 | 전설 | 공격력 +15%, 거리에 따라 추가 피해 최대 +40% | 1 | 신규 안정 ID |
| `item-11` | 다야의 다이아몬드 커터 | 전설 | 관통 +1, 첫 적 관통 후 소형 투사체 3개로 분열 | 1 | 기존 관통 효과 확장 |
| `item-13` | 에르핀의 지팡이 | 전설 | 최대 SP +1, 저학년 스킬 시전 직전 SP 1 이상이면 투사체 +2 | 1 | 신규 |

등급별 기본 최대 스택은 일반 5, 고급 3, 희귀 2, 전설 1이다. 개별 아티팩트에 별도 값이 필요해지면 표의 값을 우선한다.

`item-06`은 기존 코드에서 다중 투사체와 `item-11` 관통 시너지의 안정 ID로 이미 사용되므로 장난감 망원경에 재사용하지 않는다. Phase G 활성 보상 풀에서는 제외하되 기존 에셋·ID의 의미는 보존한다. 장난감 망원경은 새 ID `item-15`를 사용한다. 따라서 구현 시 새 에셋은 5개가 추가되지만 `item-06`이 활성 풀에서 빠져 활성 아티팩트 수는 6종에서 10종으로 순증 4종이다.

현재 Unity 에셋의 `item-02`(+3 HP), `item-03`(+0.75 이동속도), `item-08`(고정 HP 회복)과 Backend seed의 이름·등급은 위 표에 맞춘다. 변경 전 ID를 다른 효과에 재사용하지 않으며, 활성 풀 제외는 삭제나 의미 변경으로 취급하지 않는다.

### 2.3 최대 스택 보상 정책

1. 최대 스택에 도달한 아티팩트는 보상 후보에서 제외하고 남은 후보로 재추첨한다.
2. 모든 후보가 최대 스택이면 회복 보상을 대신 지급한다.
3. 최대 스택이 아닌 아티팩트의 중복 획득은 기존처럼 허용한다.
4. 아티팩트 선택 UI를 추가할 경우에도 같은 획득 가능 판정을 공유한다.
5. 비활성·레거시 아티팩트는 가중치 추첨 후보에 넣지 않는다.
6. 모든 활성 후보가 최대 스택일 때의 회복 대체 보상은 플레이어가 사망 상태가 아닐 때만 적용한다.

### 2.4 아티팩트 효과 타입 (`ItemEffectType`)

```csharp
public enum ItemEffectType
{
    AttackDamagePercent,
    CriticalChance,
    AttackSpeedPercent,
    MaxHealthDamageAura,
    MaxHealthFlat,
    ShieldOnAcquireMaxHealthPercent,
    MoveSpeedPercentBelowHealth,
    HealOnKillMaxHealthPercent,
    DistanceDamage,
    Pierce,
    SplitAfterPierce,
    MaxSP,
    SkillProjectileBonusAtSP,

    // 안정 ID 보존용. Phase G 활성 풀에서는 사용하지 않는다.
    MultiShot,
}
```

현재 `ItemDefinition`의 단일 `effectType`·`effectValue` 구조로는 복합 효과와 조건부 효과를 표현할 수 없다. Phase G에서는 한 아이템이 여러 `ItemEffectEntry`를 가질 수 있도록 확장하고, 각 항목은 효과 종류와 주 수치 외에 필요한 경우 임계값·보조 수치·개수·거리 값을 명시한다. 이름이 불분명한 범용 숫자 필드를 무분별하게 늘리지 않고, 검증기가 효과 종류별 필수 값을 검사한다.

### 2.5 공통 전투 계산 규칙

- 기본 치명타 확률은 5%, 기본 치명타 피해는 150%다.
- 급조한 목검과 장난감 망원경의 공격력 증가는 합산한 뒤 기본 공격력에 곱한다.
- 장난감 망원경의 거리 추가 피해와 치명타 피해는 공격력 계산 뒤 별도 배율로 적용한다.
- 기본 공격, 저학년 스킬, 고학년 스킬과 다이아몬드 커터 분열탄은 직접 피해로서 치명타가 발생할 수 있다.
- 광기의 가면 지속 피해에는 치명타, 거리 추가 피해, 관통과 분열이 적용되지 않는다.
- 방어막은 HP보다 먼저 피해를 흡수하며, 남은 피해만 HP에 적용한다.
- 피해와 HP·방어막은 `float`로 계산하고 중간 반올림을 하지 않는다.
- 치명타 여부와 최종 피해는 공통 `DamageContext`·피해 계산 경로에서 결정하고, 테스트에서는 치명타 판정을 제어할 수 있어야 한다.

### 2.6 개별 아티팩트 세부 규칙

#### 풍선 갑옷

- 획득 순서는 최대 HP +2 적용 후 새 최대 HP를 기준으로 방어막을 계산한다. (HP-1 이후 수치 2는 반 칸 단위로 해석되어 +1칸이다.)
- 획득 시 현재 방어막을 `max(현재 방어막, 최대 HP × 50%)`로 맞춘다. 기존 방어막에 계속 더하지 않는다.
- 방어막은 시간·방 이동·층 이동으로 자동 소멸하거나 회복되지 않고, 피해로 소진될 때까지 유지한다.

#### 도깨비 감투

- 현재 HP가 최대 HP의 30% 이하일 때 스택당 이동속도 +25%를 적용하고, 30%를 초과하면 즉시 해제한다.
- 2스택이면 조건 충족 중 총 +50%가 적용된다. 무적과 타깃 해제는 Phase G 범위에 포함하지 않는다.

#### 장난감 망원경

- 공격력 +15%는 거리와 관계없이 항상 적용한다.
- 투사체 발사 위치에서 충돌 위치까지 이동한 거리를 기준으로 2m 이하는 추가 피해 0%, 2~6m는 0~40% 선형 증가, 6m 이상은 +40%로 제한한다.
- 저학년 유도탄처럼 경로가 휘는 투사체도 실제 누적 경로가 아니라 발사 위치와 충돌 위치의 직선거리를 사용한다.

#### 다야의 다이아몬드 커터

- 기본 투사체가 첫 적에게 정상 피해를 주고 관통한 직후 기본 투사체를 제거하고 소형 투사체 3개로 분열한다.
- 분열탄은 진행 방향 기준 `-15° / 0° / +15°`로 발사한다.
- 분열탄 크기는 기본 투사체의 60%, 각 피해는 분열 전 기본 투사체 피해의 30%, 최대 이동거리는 3m다.
- 분열탄은 추가 관통·재분열하지 않으며 벽과 문을 통과하지 않는다.
- 분열탄의 공격 출처는 플레이어로 유지해 치명타와 적 처치 이벤트가 정상 동작한다.

#### 에르핀의 지팡이

- 획득 시 최대 SP를 1 증가시키고 현재 SP는 그대로 유지한다.
- 저학년 스킬의 SP를 소비하기 직전 SP가 1 이상이면 해당 시전의 투사체를 4개에서 6개로 늘린다.
- 현재 저학년 스킬은 SP 1이 있어야 시전할 수 있으므로 Phase G 테스트 기간에는 조건이 항상 충족된다.
- SP 수급 아티팩트나 추가 SP 규칙이 생기면 플레이테스트 결과를 바탕으로 임계값을 3 이상 등으로 조정한다.

#### 광기의 가면

- 플레이어 중심 반경 2.5m 안의 살아 있는 적에게 1초마다 스택당 공격력 20% 피해를 준다. Scene의 Gizmos가 켜져 있으면 선택 여부와 관계없이 분홍색 범위가 표시되며 `PlayerDamageAura.Show Debug Radius`로 끌 수 있다.
- 같은 틱에서 같은 적에게 한 번만 피해를 주며, 방이 비활성화되거나 Run이 종료되면 틱을 중단한다.
- 지속 피해로 적을 처치해도 공격 출처는 플레이어이므로 코미의 베개 등 처치 이벤트가 정상 발동한다.

### 4.1 Phase F-5 완료 게이트

Phase G로 이동하기 전에 [둘째 달 실행 계획의 Phase F-5](./10-second-month-plan.md#phase-f-5-구현-순서)를 완료한다.

- [x] F-1: `RoomDefinition`과 안정적인 `floor-XX-room-YY` ID를 사용하는 결정적 그래프 기반
- [x] F-2: 생성 결과와 검증된 방 인스턴스·출입구·`RoomGraphController` 바인딩
- [x] F-3: 현재 방 단독 활성화와 재방문 클리어·아티팩트 수령 상태 유지
- [x] F-4: 새 Run별 seed 생성, 같은 Run 내부 유지와 재방문 무재추첨
- [x] F-5: 층당 6~8방의 상하좌우 Random Growth, 시작방·일반방·보물방·보스방 배정, 4방향 Room Prefab 조립과 3층 Run 진행 (`Verify Phase F-5 Seeded Grid Floors` 및 사용자 Play Mode 확인, 2026-08-30)

F-5 완료 판단은 다음 불변조건을 모두 검증한 뒤에만 한다.

- 같은 seed의 ID·좌표·연결·RoomType·몬스터 구성은 같고 다른 seed에서는 실제 구성이 달라진다.
- 모든 방은 시작방에서 도달 가능하며 좌표 중복, 중복·자기 연결과 문 방향 불일치가 없다.
- 시작방과 보스방은 각각 1개, 보물방은 최소 1개이며 보스방은 시작방에서 먼 끝방에 배치된다.
- 좌상·우하·좌우·상하 등 방향 조합과 반대편 진입점이 올바르게 바인딩된다.
- 층 이동과 재방문 중 seed, 클리어, 아티팩트 수령과 Encounter 상태가 유지된다.
- Setup 재실행 시 중복이 없고, Backend/Web 검색 결과 로컬 seed로 충분하면 외부 계약을 변경하지 않는다.

여러 spawn point에 같은 적 Prefab을 반복 배치하는 현재 Encounter 정책은 F-5 최소 범위에서 허용하되 Verification에서 의도된 동작으로 확인한다. 상점·엘리프 경제, 열쇠와 잠긴 보물방, 이벤트방·비밀방, 미니맵과 층당 8~12방 실사용은 Phase G/H에 끼워 넣지 않고 별도 후속 범위로 남긴다.

### 4.2 기반 정리를 먼저 하는 이유

- `PlayerStats`를 스탯의 단일 소유자로 두어 아티팩트, 기본 공격, 두 스킬이 같은 값을 사용한다.
- 기본 공격, 유도탄, 폭발, 분열탄과 피해 오라는 공통 피해 계산 경로를 사용한다.
- 처치 회복과 SP 드롭은 공통 적 처치 이벤트를 구독한다.
- Phase G의 최소 치명타는 위 기반에 추가하고 치명타 저항·전용 연출과 고급 밸런스는 Phase I로 남긴다.
- 메타 경험치는 Run 저장과 연결되므로 게임 전체 흐름이 안정된 뒤 Backend에서 구현한다.
- 고학년 돌진보다 방 경계와 전환 규칙을 먼저 구현해 돌진 중 이동 가능 범위를 명확히 한다.
- 격자 생성 전에 고정된 방 그래프로 화면 전환, 방 상태 보존과 Run seed 수명주기를 먼저 검증한다.
- 격자형 층과 보물방 획득 흐름을 안정시킨 뒤 아티팩트 후보·등급·최대 스택 정책을 확장한다.

### 4.3 방과 층의 최종 구조

현재 씬에서 층마다 가로로 이어진 3개 방은 HP, 인벤토리, 아티팩트 효과, Run 진행 상태가 층 이동 후에도
유지되는지 확인하기 위한 검증 구조다. 최종 게임에서는 다음 구조를 사용한다.

```text
FloorGenerator
  → Run seed에서 층별 6~8방 격자 그래프 생성
  → 시작방·일반방·보물방·보스방 배정
  → RoomGraphAssembler가 검증된 Room Prefab과 4방향 문 슬롯 조립
  → RoomGraphController가 현재 방 하나만 활성화
  → 출입구 진입 시 연결된 다음 RoomNode로 이동
  → 보스 클리어 시 다음 층 시작방
```

- 현재 방 하나만 활성·노출하고 다른 방의 전투 오브젝트는 보이지 않게 한다. `한 화면에 현재 방
  하나`는 현재 방 전체를 항상 한 화면에 맞춘다는 뜻이 아니다.
- 기준 화면보다 작거나 같은 축은 방 중앙에 카메라를 고정한다. 더 큰 축만 플레이어 위치를
  Room Profile의 카메라 경계 안으로 제한해 추적한다. 따라서 가로로 긴 방은 가로만, 세로로 긴
  방은 세로만 움직이고 기본 방과 더 작은 방은 카메라가 움직이지 않는다.
- 다음 방으로 이동하면 카메라는 다음 방의 축별 경계와 유효 위치로 전환하며, 이전 방이나 벽
  바깥을 비추지 않는 범위 안에서 보간한다.
- 연결문의 물리 차단 콜라이더는 열린 뒤에도 포탈형 장벽으로 유지한다. 별도의 전환 트리거는 통로 중앙에 두며 일반 상태의 플레이어를 장벽 충돌 전에 반대편 안전 진입점으로 이동시킨다.
- 돌진·기본 공격 투사체·적 투사체는 잠금 여부와 관계없이 연결문 장벽을 통과하지 못한다. 저학년 유도탄은 발사 시 타깃이 배정된 탄만 벽과 문을 관통하고, 타깃 없이 발사된 탄은 벽과 문에서 폭발 없이 소멸한다.
- 실제 방 전환 시에는 타깃 배정 여부와 관계없이 남아 있는 모든 발사 완료 투사체를 정리한다.
- 비활성 방도 클리어 여부, 아티팩트 수령 여부 등 방문 상태를 유지한다.
- `floor-XX-room-YY` ID는 seed와 좌표에 관계없이 안정된 형식을 유지하고 격자 좌표는 별도 생성 데이터로 둔다.
- 랜덤 생성은 방 내부를 무작위로 흩뿌리는 것이 아니라 검증된 `RoomDefinition`, Room Template,
  Room Prefab과 Encounter의 연결·선택을 바꾼다. 같은 seed와 콘텐츠 버전은 출입구·크기 조건이
  호환되는 같은 안정 `templateId`를 선택한다.
- Scene 오브젝트와 분리된 생성 그래프는 `RunProgress`가 소유하고, 현재 층에 필요한 Prefab 인스턴스만 구성한다.

### 4.5 Phase H 구현 순서와 완료 조건

Phase H는 Database·Backend·Unity·Web을 한 번에 변경하지 않는다. 먼저 성장과 멱등성 계약을 고정하고,
각 계층을 아래 순서로 연결한다. 각 단계는 해당 자동 검증을 통과한 뒤 다음 단계로 이동하며,
H-7의 실제 Run 검증 전에는 Phase H 전체를 완료 처리하지 않는다.

#### H-1. 메타 성장·멱등성 계약과 저장 기반

- [x] Lv.1~Lv.19의 시스템 검증용 초기 경험치 곡선, 최대 레벨 도달 후 처리, 아티팩트 중복 획득의 등급 보너스와 최종 조정 기준을 확정한다. (H-1 계약 테스트 통과, 2026-09-02)

- [x] `clientRunId` 비교 대상, 같은 ID에 다른 요청이 들어왔을 때의 충돌 기준, 재전송 응답에서 보존할 Run 결과와 진행 스냅샷 범위를 확정한다. (정규화 시각·아이템 순서 결정성 및 내용 변경 충돌 지문 테스트 통과, 2026-09-02)

## 7. 경험치와 스킬 성장 시스템

### 7.1 경험치 획득

```
경험치 = (도달 층 × 100) + (처치 수 × 5) + (아티팩트 등급 보너스)
```

| 아티팩트 등급 | 보너스 |
|------------|--------|
| 일반 | +10 |
| 고급 | +20 |
| 희귀 | +30 |
| 전설 | +50 |

- 아티팩트 보너스는 `RunItem`에 기록된 실제 획득 건마다 계산한다. 같은 아티팩트를 최대 스택 안에서
  여러 번 획득했다면 각 획득이 보너스를 받는다.
- 존재하지 않거나 비활성인 아티팩트는 Run 저장 검증에서 거절하므로 경험치 계산 대상이 아니다.

**계산 예시:** 2층 도달, 처치 30, 일반 2개 + 희귀 1개
- 경험치 = (2 × 100) + (30 × 5) + (10 × 2) + 30 = 200 + 150 + 20 + 30 = **400**

위 400 XP는 산식 설명을 위한 예시이며 첫 레벨업 기준이 아니다. 첫 레벨업의 최종 밸런스 목표는
신규 Lv.1 캐릭터가 3층 최종 보스까지 완료한 평균적인 전체 Run 1회 후 Lv.2가 되는 것이다.
정확한 요구량은 방·적·아티팩트 획득량이 안정된 뒤 서로 다른 seed의 실제 완주 경험치를 측정해 조정한다.

### 7.2 캐릭터 레벨과 스킬 포인트

- 캐릭터는 Lv.1에서 시작한다.
- 현재 레벨의 필요 경험치를 채우면 캐릭터 레벨이 1 증가하고 스킬 포인트를 1 얻는다.
- 레벨업 시 현재 구간의 필요 경험치만 차감하고 초과 경험치는 다음 레벨 구간으로 이월한다.
- 한 번의 Run 경험치로 여러 레벨 조건을 충족하면 최대 레벨 또는 경험치 부족 시점까지 연속 레벨업한다.
- 스킬 포인트 1로 저학년 또는 고학년 스킬 중 하나를 1레벨 강화한다.
- 두 스킬은 각각 Lv.1에서 시작해 최대 Lv.10까지 성장한다.
- 사용하지 않은 스킬 포인트는 캐릭터 진행 데이터에 남는다.

현재 규칙에서 두 스킬을 모두 최대 레벨로 만들려면 총 18포인트가 필요하므로
MVP 캐릭터 최대 레벨은 Lv.19로 확정한다. 최대 레벨에서는 추가 경험치를 저장하지 않고
`experience = 0`, `experienceToNextLevel = 0`을 반환한다. 최대 레벨과 경험치 곡선은 Backend의
단일 진행 계약 데이터에서 파생해 향후 확장 시 Database 구조를 바꾸지 않는다.

### 7.3 레벨별 필요 경험치 (시스템 검증용 초기값)

| 현재 레벨 | 다음 레벨 필요 경험치 | 현재 레벨 | 다음 레벨 필요 경험치 |
|---:|---:|---:|---:|
| 1 | 400 | 10 | 1,300 |
| 2 | 500 | 11 | 1,400 |
| 3 | 600 | 12 | 1,500 |
| 4 | 700 | 13 | 1,600 |
| 5 | 800 | 14 | 1,700 |
| 6 | 900 | 15 | 1,800 |
| 7 | 1,000 | 16 | 1,900 |
| 8 | 1,100 | 17 | 2,000 |
| 9 | 1,200 | 18 | 2,100 |
| 19 | 0 | 최대 레벨 | 추가 경험치 미저장 |

현재 400~2,100 곡선은 초과 경험치 이월, 연속 레벨업과 최대 레벨 처리를 구현·검증하기 위한
초기값이다. 현재 값만으로 “3층 전체 Run 완주 1회 후 첫 레벨업”을 보장한다고 보지 않는다.
게임 콘텐츠가 안정되면 평균 완주 경험치에 맞춰 Lv.1→2 요구량과 이후 증가 폭을 함께 조정한다.
현재 초기값 기준 Lv.1부터 Lv.19까지 필요한 누적 경험치는 22,500이다.

경험치 곡선과 등급 보너스는 Backend의 단일 진행 계약 데이터로 관리한다. 수치를 조정할 때는
계약 데이터와 기대값 테스트만 함께 변경하며 Database schema와 API DTO는 변경하지 않는다.

### 7.4 스킬 레벨별 효과

- 두 스킬 모두 레벨이 1 오를 때마다 Lv.1 피해 계수의 10%만큼 피해가 증가한다.
- 저학년 스킬은 Lv.5부터 기본 투사체가 4발에서 5발로 증가한다. 에르핀의 지팡이 등 Run 중
  투사체 보너스는 이 기본 개수에 별도로 더한다.
- 고학년 스킬은 Lv.5부터 설정된 기본 쿨타임이 15% 감소한다. 현재 30초 기준으로 25.5초다.
- Lv.5의 특수 효과도 해당 레벨의 피해 증가와 함께 적용하며, Lv.6~10은 다시 피해만 강화한다.

| 스킬 레벨 | Lv.1 대비 피해 배율 | 저학년 기본 투사체 | 고학년 쿨타임 배율 |
|---:|---:|---:|---:|
| 1 | 100% | 4 | 100% |
| 2 | 110% | 4 | 100% |
| 3 | 120% | 4 | 100% |
| 4 | 130% | 4 | 100% |
| 5 | 140% | 5 | 85% |
| 6 | 150% | 5 | 85% |
| 7 | 160% | 5 | 85% |
| 8 | 170% | 5 | 85% |
| 9 | 180% | 5 | 85% |
| 10 | 190% | 5 | 85% |

강화 결과는 진행 데이터에 즉시 저장하지만 진행 중인 Run의 전투 수치는 바꾸지 않는다. Unity는
Run 시작 전에 진행 데이터를 읽어 두 스킬 레벨을 스냅샷으로 적용한다. 조회에 실패하면 마지막으로
성공한 로컬 진행을 사용하고, 캐시도 없으면 Lv.1로 시작하되 오프라인 기본값 사용 상태를 표시한다.

### 7.5 Backend 처리와 중복 방지

1. Backend가 Run 저장과 경험치 계산을 하나의 트랜잭션으로 처리한다.
2. Unity는 `experienceGained`, 현재 레벨, 현재 경험치, 필요 경험치, 미사용 스킬 포인트를 응답으로 받는다.
3. 각 Run에 클라이언트가 생성한 안정적인 식별자 또는 멱등성 키를 둔다.
4. 같은 Run이 재전송되면 기존 결과를 반환하고 경험치와 스킬 포인트를 다시 지급하지 않는다.
5. 스킬 강화도 포인트 차감과 스킬 레벨 증가를 하나의 트랜잭션으로 처리한다.
6. 한 Run에서 여러 레벨이 오르면 각 레벨의 필요 경험치를 순서대로 차감하고 포인트를 레벨 수만큼 지급한다.
7. `clientRunId`의 동일 요청 판정에는 `clientRunId` 자체를 제외한 Run 필드와 `order`로 정렬한
   `itemId`, `floor`, `order`, `acquiredAt`을 사용하고 SHA-256 요청 지문을 저장한다.
8. 같은 ID와 같은 지문은 최초 `runId`, `experienceGained`와 당시의 전체 진행 스냅샷을 반환한다.
   같은 ID와 다른 지문은 현재 진행 상태와 관계없이 `RUN_IDEMPOTENCY_CONFLICT`로 거절한다.
