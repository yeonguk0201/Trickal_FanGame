## 1. 결정된 사항 요약

### 1.1 저학년 스킬 (SP 스킬)

| 항목 | 결정 |
|------|------|
| 리소스 | SP (최대 3) |
| 획득 방식 | 적 처치 시 확률 드롭 (20~30%, 플테 후 조정) |
| 소비량 | 1회 사용 시 SP 1 소비 |
| 드롭 형태 | 바닥에 SP 픽업 오브젝트 생성 |
| 최대 SP일 때 | 픽업은 사라지지만 SP 변화 없음 |
| 입력 키 | Space |
| 스킬 형태 | 바라보는 방향 중심 36° 부채꼴의 `1→3→2→4` 슬롯 순서로 0.08초 간격 유도탄 4발 → 이후 타깃 유도 → 피격 시 범위 폭발 |
| 다수 타깃 | 거리순 라운드로빈으로 4발을 배분하며 같은 타깃 중복 배정 허용 |
| 연속 입력 | 4발 연사가 끝나기 전에는 재사용과 추가 SP 소비 차단 |
| 타깃이 없을 때 | 플레이어가 바라보는 방향 중심의 전방 퍼짐으로 발사 후 수명 종료 시 소멸 |
| 폭발 중첩 | 같은 적이 여러 폭발 범위에 있으면 피해 중첩 가능 |
| 폭발 피해 | **현재 공격력 × 100%** |
| 단일 적 최대 피해 | 현재 공격력 × 400% (4발 전부 적중 시) |

### 1.2 고학년 스킬 (필살기)

| 항목 | 결정 |
|------|------|
| 리소스 | 쿨타임 (20~40초, 플테 후 조정) |
| 입력 키 | Q |
| 스킬 형태 | 무적 돌진 |
| 지속 | 최대 10초 (적 접촉 시 즉시 종료) |
| 방향 조작 | 이동 키 WASD로 조정, 입력이 없으면 마지막 이동 방향 유지 |
| 중도 취소 | 불가 |
| 벽 충돌 | 종료하지 않음. 방향 입력으로 벽을 벗어날 수 있음 |
| 충돌 시 | 광역 피해 + 0.2초 넉백 후 경직 |
| 적 경직 | 일반 적 0.4초, 보스 0.15초 |
| 보스 넉백 | 일반 적의 25% 넉백 계수 적용 |
| 광역 피해 | **현재 공격력 × 200%** |
| 제약 | 돌진과 회복 중 이동·기본 공격·저학년 스킬·재사용·방/층 전환 차단 |
| 쿨타임 시작 | 돌진 종료 시점 |
| 방/층 이동 | 돌진 및 충돌 경직·감속 중 차단, 회복 종료 후 허용 |
| 적 충돌 종료 | 플레이어를 즉시 정지시키고 0.4초 무적 경직 적용 |
| 시간 만료 종료 | 무적 없이 0.25초 동안 돌진 속도를 0까지 감속 |

### 1.3 스킬 피해 계산 공식

```
현재 공격력 = 캐릭터 기본 공격력 + Run 중 공격력 보너스
최종 스킬 피해 = 현재 공격력 × 스킬 배율 × (1 + 스킬 피해 보너스%)
```

> 기존의 "기본 공격력" 표현은 아티팩트 보너스를 포함하는 의미였으므로 "현재 공격력"으로 통일한다.
> 피해와 HP는 내부적으로 `float`를 사용하고 계산 중간에는 반올림하지 않는다.
> UI 숫자는 최대 소수점 1자리로 표시하며 HP가 0 이하가 되면 사망한다.

**예시:**
| 상황 | 현재 공격력 | 스킬 배율 | 스킬 피해 보너스 | 계산 피해 |
|------|------------|----------|-----------------|----------|
| 초반 저학년 | 1 | 100% | 0% | 1 |
| 아티팩트 획득 후 | 5 | 100% | 0% | 5 |
| 스킬 피해 아티팩트 추가 | 5 | 100% | +50% | 7.5 |
| 고학년 스킬 | 5 | 200% | +50% | 15 |

### 1.4 메타 진행 (Run 외부 성장)

| 항목 | 결정 |
|------|------|
| 리소스 | 경험치 |
| 획득 시점 | Run 종료 시 (클리어/사망) |
| 성장 단위 | 캐릭터별 레벨과 경험치 |
| 레벨업 조건 | 현재 레벨의 필요 경험치를 모두 채움 |
| 레벨업 보상 | 스킬 포인트 1 획득 |
| 강화 방식 | 포인트를 사용해 저학년 또는 고학년 스킬 중 하나를 선택 강화 |
| 스킬 레벨 범위 | 각 Lv.1 → Lv.10 |
| 경험치 처리 | 소비 재화가 아닌 누적 레벨 경험치 |
| 계산 주체 | Backend가 Run 저장과 함께 계산하고 Unity는 결과만 표시 |
| 캐릭터 최대 레벨 | MVP Lv.19, 데이터 설정으로 추후 확장 가능 |
| 연속 레벨업 | 한 Run의 경험치로 여러 레벨 조건을 충족하면 모두 처리 |
| 초과 경험치 | 다음 레벨 구간으로 이월 |

| 기본 공격 | 방향키 투사체 |

## 2. 아티팩트 시스템 (`Item` 안정 계약)

### 2.1 아티팩트 등급

| 등급 | 영문 계약 | 색상 | 드롭 가중치(초안) | 경험치 가중치 |
|------|-----------|------|-------------------|--------------|
| 일반 | `COMMON` | 흰색 | 60 | ×1 |
| 고급 | `UNCOMMON` | 녹색 | 25 | ×2 |
| 희귀 | `RARE` | 파랑 | 12 | ×3 |
| 전설 | `EPIC` | 보라 | 3 | ×5 |

> 등급별 값은 고정 확률이 아니라 가중치다. 현재 획득 가능한 후보만 모은 뒤 가중치 추첨한다.
> `EPIC`은 기존 Backend seed 계약을 유지하며 게임 내 한글 표시는 "전설"을 사용한다.

### 2.2 아티팩트 목록 (MVP 10종 후보)

| ID | 이름 | 효과 | 등급 | 상태 |
|----|------|------|------|------|
| item-01 | 공격력 강화 | 공격력 +1 | 일반 | 기존 |
| item-02 | 체력 강화 | 최대 HP +2 | 일반 | 기존 |
| item-03 | 신속 | 이동속도 +0.5 | 일반 | 기존 |
| item-04 | 속사 | 공격속도 증가 | 고급 | **신규** |
| item-06 | 다중 투사체 | 투사체 +1 | 희귀 | 기존 |
| item-08 | 흡혈 | 처치 시 HP +1 | 고급 | 기존 |
| item-11 | 관통 | 관통 +1 | 희귀 | 기존 |
| item-12 | 연쇄 폭발 | 처치 시 폭발 | 희귀 | **신규** |
| item-13 | SP 확장 | SP 최대치 +1 | 전설 | **신규** |
| item-14 | 스킬 마스터리 | 스킬 피해 +50% | 전설 | **신규** |

> 역할과 등급 방향은 확정했지만 이름, 효과 값, 최대 스택은 후속 구체화 작업에서 조정할 수 있다.
> 현재 Unity 에셋의 `item-02`(+3 HP), `item-03`(+0.75 이동속도)와 Backend seed의 일부 등급 값도
> 그 작업에서 최종 표에 맞춰 변경한다. 출시 후에는 기존 Item ID의 의미를 바꾸거나 재사용하지 않는다.

### 2.3 최대 스택 보상 정책

1. 최대 스택에 도달한 아티팩트는 보상 후보에서 제외하고 남은 후보로 재추첨한다.
2. 모든 후보가 최대 스택이면 회복 보상을 대신 지급한다.
3. 최대 스택이 아닌 아티팩트의 중복 획득은 기존처럼 허용한다.
4. 아티팩트 선택 UI를 추가할 경우에도 같은 획득 가능 판정을 공유한다.

### 2.4 아티팩트 효과 타입 (`ItemEffectType`)

```csharp
public enum ItemEffectType
{
    // 기존
    AttackDamage,
    MaxHealth,
    MoveSpeed,
    MultiShot,
    Pierce,
    HealOnKill,

    // 신규
    AttackSpeed,      // 공격속도
    ExplodeOnKill,    // 처치 시 폭발
    SPMaxUp,          // SP 최대치 증가
    SkillDamage,      // 스킬 피해량 증가
}
```

## 4. 구현 우선순위

> 마감일보다 시스템 간 결합을 줄이는 순서를 우선한다. 아래 단계는 기존 주차에 억지로 맞추지 않고,
> 앞 단계가 안정된 뒤 다음 단계로 이동한다.

```text
[완료]
코어 루프 + 아티팩트 6종 + 시너지
        ↓
[완료 — Phase A 전투 기반 정리]
PlayerStats 도입
+ 기존 아티팩트 효과 이전
+ 공통 DamageContext / 피해 계산
+ 적 처치 이벤트 경로 통합
        ↓
[완료 — Phase B 방 전환 기반 정리]
한 화면에 현재 방 하나만 표시
+ 포탈 장벽 출입구 이동 + 돌진·투사체 경계 차단 + 카메라 화면 전환
+ 방 상태 보존 + 고정 방 그래프 검증
        ↓
[완료 — Phase C 저학년 스킬]
SP 리소스 + SP 바닥 드롭
+ 입력 방향 중심 36° 부채꼴·`1→3→2→4` 순서·0.08초 간격 유도탄 4발 + 다수 타깃 배분 + 중첩 범위 폭발
        ↓
[완료 — Phase D 고학년 스킬]
플레이어 행동 상태 관리
+ 무적 돌진 + 충돌 피해 + 넉백 후 경직 + 종료 원인별 회복 + 쿨타임
        ↓
[완료 — Phase E 기존 MVP 콘텐츠]
몬스터 3종 + 3개 층 구성
+ 전체 Run 진행 검증 (`Verify Phase E-8 Floor Difficulty Scaling`, 2026-08-27)
        ↓
[진행 중 — Phase F seed 기반 격자형 층 생성]
검증된 방 정의 데이터로 결정적 층별 방 그래프 생성 완료 (`Verify Phase F-1 Random Room Graph`, 2026-08-28)
+ 생성 결과를 검증된 방 인스턴스·출입구 및 `RoomGraphController`에 연결 완료 (`Verify Phase F-2 Generated Room Graph Binding`, 2026-08-28)
+ 현재 방만 활성화 + 재방문 클리어·아티팩트 수령 상태 유지 전체 Run 확인 (`Verify Phase F-2 Generated Room Graph Binding` 실행 후 사용자 확인, 2026-08-28)
+ 새 Run별 seed 생성·Run 내부 유지 + 같은 seed 결정성·다른 seed 구성 변화·재방문 무재추첨 검증 완료 (`Verify Phase F-4 Run Seed Lifecycle`, 2026-08-28)
+ 층당 6~8방 Random Growth + 필수 방 배정 + 4방향 Room Prefab 조립·자동 검증 완료, 전체 3층 Play Mode 확인 대기 (Phase F-5)
        ↓
[Phase G — 아티팩트 확장]
아티팩트 4종 추가 + 10종 완성
+ 등급별 가중치 드롭
+ 최대 스택 재추첨 / 대체 보상
        ↓
[Phase H — 메타 진행]
Backend 경험치 계산
+ 캐릭터 레벨 + 스킬 포인트 + 스킬 Lv.10
+ Run 재전송 멱등성
        ↓
[Phase I — 후순위 확장]
치명타 + 추가 밸런스 + UI 폴리싱
```

### 4.1 Phase F-5 완료 게이트

Phase G로 이동하기 전에 [둘째 달 실행 계획의 Phase F-5](./10-second-month-plan.md#phase-f-5-구현-순서)를 완료한다.

- [x] F-1: `RoomDefinition`과 안정적인 `floor-XX-room-YY` ID를 사용하는 결정적 그래프 기반
- [x] F-2: 생성 결과와 검증된 방 인스턴스·출입구·`RoomGraphController` 바인딩
- [x] F-3: 현재 방 단독 활성화와 재방문 클리어·아티팩트 수령 상태 유지
- [x] F-4: 새 Run별 seed 생성, 같은 Run 내부 유지와 재방문 무재추첨
- [ ] F-5: 층당 6~8방의 상하좌우 Random Growth, 시작방·일반방·보물방·보스방 배정, 4방향 Room Prefab 조립

F-5 완료 판단은 다음 불변조건을 모두 검증한 뒤에만 한다.

- 같은 seed의 ID·좌표·연결·RoomType·몬스터 구성은 같고 다른 seed에서는 실제 구성이 달라진다.
- 모든 방은 시작방에서 도달 가능하며 좌표 중복, 중복·자기 연결과 문 방향 불일치가 없다.
- 시작방과 보스방은 각각 1개, 보물방은 최소 1개이며 보스방은 시작방에서 먼 끝방에 배치된다.
- 좌상·우하·좌우·상하 등 방향 조합과 반대편 진입점이 올바르게 바인딩된다.
- 층 이동과 재방문 중 seed, 클리어, 아티팩트 수령과 Encounter 상태가 유지된다.
- Setup 재실행 시 중복이 없고, Backend/Web 검색 결과 로컬 seed로 충분하면 외부 계약을 변경하지 않는다.

여러 spawn point에 같은 적 Prefab을 반복 배치하는 현재 Encounter 정책은 F-5 최소 범위에서 허용하되 Verification에서 의도된 동작으로 확인한다. 상점·엘리프 경제, 열쇠와 잠긴 보물방, 이벤트방·비밀방, 미니맵과 층당 8~12방 실사용은 Phase G/H에 끼워 넣지 않고 별도 후속 범위로 남긴다.

### 4.2 기반 정리를 먼저 하는 이유

- `PlayerStats`를 스탯의 단일 소유자로 두어 아티팩트, 기본 공격, 두 스킬이 같은 값을 사용한다.
- 기본 공격, 유도탄, 폭발, 연쇄 폭발은 공통 피해 계산 경로를 사용한다.
- 처치 회복, SP 드롭, 연쇄 폭발은 공통 적 처치 이벤트를 구독한다.
- 치명타는 위 기반이 안정된 뒤 같은 피해 계산 경로에 추가한다.
- 메타 경험치는 Run 저장과 연결되므로 게임 전체 흐름이 안정된 뒤 Backend에서 구현한다.
- 고학년 돌진보다 방 경계와 전환 규칙을 먼저 구현해 돌진 중 이동 가능 범위를 명확히 한다.
- 격자 생성 전에 고정된 방 그래프로 화면 전환, 방 상태 보존과 Run seed 수명주기를 먼저 검증한다.
- 격자형 층과 보물방 획득 흐름을 안정시킨 뒤 아티팩트 후보·등급·최대 스택 정책을 확장한다.

### 4.3 방과 층의 최종 구조

현재 씬에서 층마다 가로로 이어진 3개 방은 HP, 인벤토리, 아티팩트 효과, Run 진행 상태가 층 이동 후에도
유지되는지 확인하기 위한 검증 구조다. 최종 게임에서는 다음 구조를 사용한다.

```text
FloorGenerator
  → Run seed에서 층별 6~8방 격자 그래프 생성
  → 시작방·일반방·보물방·보스방 배정
  → RoomGraphAssembler가 검증된 Room Prefab과 4방향 문 슬롯 조립
  → RoomGraphController가 현재 방 하나만 활성화
  → 출입구 진입 시 연결된 다음 RoomNode로 이동
  → 보스 클리어 시 다음 층 시작방
```

- 화면에는 현재 방 하나만 보인다.
- 다음 방으로 이동하면 카메라가 다음 방 단위로 전환된다.
- 출입구의 초록 문은 열린 뒤에도 물리 장벽으로 남고 일반 상태의 플레이어만 안쪽 트리거에서 포탈 전환한다.
- 돌진·기본 공격 투사체·적 투사체는 문을 통과하지 못한다. 저학년 유도탄은 발사 시 타깃이 배정된 탄만 벽과 문을 관통하고, 타깃 없이 발사된 탄은 벽과 문에서 폭발 없이 소멸한다.
- 실제 방 전환 시에는 타깃 배정 여부와 관계없이 남아 있는 모든 발사 완료 투사체를 정리한다.
- 비활성 방도 클리어 여부, 아티팩트 수령 여부 등 방문 상태를 유지한다.
- `floor-XX-room-YY` ID는 seed와 좌표에 관계없이 안정된 형식을 유지하고 격자 좌표는 별도 생성 데이터로 둔다.
- 랜덤 생성은 방 내부를 무작위로 흩뿌리는 것이 아니라 검증된 `RoomDefinition`, Room Prefab과 Encounter의 연결·선택을 바꾼다.
- Scene 오브젝트와 분리된 생성 그래프는 `RunProgress`가 소유하고, 현재 층에 필요한 Prefab 인스턴스만 구성한다.

## 7. 경험치 시스템 (초안)

### 7.1 경험치 획득

```
경험치 = (도달 층 × 100) + (처치 수 × 5) + (아티팩트 등급 보너스)
```

| 아티팩트 등급 | 보너스 |
|------------|--------|
| 일반 | +10 |
| 고급 | +20 |
| 희귀 | +30 |
| 전설 | +50 |

**예시:** 2층 도달, 처치 30, 일반 2개 + 희귀 1개
- 경험치 = (2 × 100) + (30 × 5) + (10 × 2) + 30 = 200 + 150 + 20 + 30 = **400**

### 7.2 캐릭터 레벨과 스킬 포인트

- 캐릭터는 Lv.1에서 시작한다.
- 현재 레벨의 필요 경험치를 채우면 캐릭터 레벨이 1 증가하고 스킬 포인트를 1 얻는다.
- 레벨업 시 현재 구간의 필요 경험치만 차감하고 초과 경험치는 다음 레벨 구간으로 이월한다.
- 한 번의 Run 경험치로 여러 레벨 조건을 충족하면 최대 레벨 또는 경험치 부족 시점까지 연속 레벨업한다.
- 스킬 포인트 1로 저학년 또는 고학년 스킬 중 하나를 1레벨 강화한다.
- 두 스킬은 각각 Lv.1에서 시작해 최대 Lv.10까지 성장한다.
- 사용하지 않은 스킬 포인트는 캐릭터 진행 데이터에 남는다.

현재 규칙에서 두 스킬을 모두 최대 레벨로 만들려면 총 18포인트가 필요하므로
MVP 캐릭터 최대 레벨은 Lv.19로 확정한다. 향후 패시브나 스탯 강화가 추가될 수 있으므로
구현에서는 최대 레벨을 상수로 고정하지 않고 캐릭터 진행 데이터로 관리한다.

### 7.3 레벨별 필요 경험치 (초안)

| 구간 | 필요 경험치 | 비고 |
|------|------------:|------|
| Lv.1 → Lv.2 | 500 | 첫 강화 획득 |
| 이후 레벨 | 이전 구간보다 증가 | 증가 공식은 실제 Run 경험치 플테 후 확정 |

### 7.4 Backend 처리와 중복 방지

1. Backend가 Run 저장과 경험치 계산을 하나의 트랜잭션으로 처리한다.
2. Unity는 `experienceGained`, 현재 레벨, 현재 경험치, 필요 경험치, 미사용 스킬 포인트를 응답으로 받는다.
3. 각 Run에 클라이언트가 생성한 안정적인 식별자 또는 멱등성 키를 둔다.
4. 같은 Run이 재전송되면 기존 결과를 반환하고 경험치와 스킬 포인트를 다시 지급하지 않는다.
5. 스킬 강화도 포인트 차감과 스킬 레벨 증가를 하나의 트랜잭션으로 처리한다.
6. 한 Run에서 여러 레벨이 오르면 각 레벨의 필요 경험치를 순서대로 차감하고 포인트를 레벨 수만큼 지급한다.
