## 1. 계획의 역할과 완료 상태

사용자가 20주차까지 완료했다고 보고한 상태를 출발점으로 한다. 다섯째 달에서 남긴 후속 후보와
2026-10-01 대화·손글씨 메모의 신규 구상, 같은 날 계획 검토에서 확정한 결정을 함께 관리한다.
이전 계획과 Play-1 기록에 남은 진행 중·미확인 표시는 구체적인 증거를 확인하며 정리하고, 이 문서
작성만으로 이전 체크리스트를 일괄 완료 처리하지 않는다.

일정은 기존 계획의 다음 4주를 잇는 표기다. 실제 진행은 날짜보다 선행 시스템과 검증 순서를 우선한다.
이 문서는 계획이며 아래 신규 작업의 상태는 모두 **예정**이다. 게임 코드나 API에 적용된 규칙으로
오해하지 않도록 확정 방향, 제안 초기값, 구현 전 결정 사항을 구분한다.

아이작의 분류·희귀도·액티브 충전 방식을 적은 사진 4는 **참고 메모**다. 그 메모의 종류별 순위나
충전 조건을 이 게임의 확정 규칙으로 가져오지 않는다. 같은 이름의 아이작 아이템과도 별도 설계한다.

### 용어

트릭컬 세계관에 맞춰 손글씨 메모의 분류명을 다음과 같이 바꾼다. 아이템 이름은 바꾸지 않는다.

| 메모 표기          | 이 문서와 게임 표기 | 의미                                                         |
| ------------------ | ------------------- | ------------------------------------------------------------ |
| 카드               | **스펠**            | 공용 슬롯에 보관하는 일회용 아이템                           |
| 룬                 | **짱셈스펠**        | 스펠과 같은 슬롯을 공유하는 일회용 아이템의 다른 분류        |
| (현재 화폐) 엘리프 | **골드**            | Run 한정 화폐. 기존 엘리프의 역할을 대체한다                 |
| —                  | **엘리프**          | Run 이후에도 남는 희귀 영구 화폐. 이번 달은 계약 설계만 한다 |

`멤버십카드`·`멜룬카드`처럼 이름에 "카드"가 들어간 아이템도 분류는 위 표를 따른다. 멜룬카드는
이름과 관계없이 **짱셈스펠**이다. 현재 코드의 `ItemKind.Spell`과 `spell-*` 아이템은 상시 효과를 주는
기존 스펠이며, 새 일회용 스펠과 같은 분류값을 공유하지 않는다(§3.4, Contract-0).

## 2. 범위와 우선순위

### 이번 달 필수 흐름

```text
Run 시작
  → 스펠 또는 짱셈스펠을 공용 슬롯 1칸에 보관
  → 전투방 클리어 시 33% 확률로 상자 생성
  → 일반 / 황금 / 다이아몬드 상자 개봉
  → 골드·소모품 획득 또는 스펠·짱셈스펠 교체
  → 황금상자의 특별 보상 / 시스트의 가짜 날개 획득 → 구덩이·장애물 위 비행
  → 현재 방 스펠 효과·시작방 탈출·상자/픽업 복제 사용
  → 상점에서 골드로 구매하거나 멤버십카드 사용
  → 3층 클리어 / 사망 → 저장 → 웹 전적 확인
```

필수는 새 보상·소비 흐름의 완결성이다. Run 화폐의 골드 전환, 비행 대상인 구덩이 지형 1종,
황금상자 전용 패시브인 시스트의 가짜 날개는 필수다. 신규 공격 변화 패시브는 최소 2종을 먼저
연결하고, 나머지는 독립 검증을 마친 순서로 추가한다. 장신구는 효과·슬롯 규칙이 확정되어 실제로
구현된 후보만 보상 풀에 넣는다.

## 3. 확정 방향과 규칙

### 3.1 상자 3종

일반 전투방의 기존 클리어 확률 드롭을 상자로 대체한다. **상자 등장 확률은 33%를 유지**한다.
장애물 드롭, 상점 구매 픽업, 보물방·비밀방·보스방의 기존 선택 보상을 일괄 상자로 바꾸지는 않는다.
기존 개별 클리어 픽업과 새 상자가 동시에 지급되지 않게 한다.

| 종류            | 상자 등장 후 종류 선택           | 개봉                 | 보상                                                               |
| --------------- | -------------------------------- | -------------------- | ------------------------------------------------------------------ |
| 일반상자        | 허용 범위 70~80%, 초기값 **75%** | 닿으면 개봉          | 골드·하트·SP·폭탄·열쇠 등 기본 소모품 **1~3개**, 낮은 확률로 스펠  |
| 황금상자        | 허용 범위 15~20%, 초기값 **20%** | 닿으면 열쇠 1개 소비 | 소모품 다수 + **20~30% 확률로 장신구 또는 황금상자 전용 아티팩트** |
| 다이아몬드 상자 | 허용 범위 3~5%, 초기값 **5%**    | 폭탄 폭발로 개봉     | 스펠·짱셈스펠과 많은 양의 소모품                                   |

사용자가 이전 제안을 수락한 초기 구성은 75/20/5이며 합계 100%다. 범위 수치를 각각 독립 확률로
추첨하지 않는다. 클리어마다 전체 기준 일반상자 24.75%, 황금상자 6.6%, 다이아몬드 상자 1.65%,
상자 없음 67%다. 이 수치는 상자 선택 확률이며 개별 내용물 확률이 아니다.

- 황금상자의 특별 보상 20~30%는 **합산 확률**이다. 당첨 시 장신구 또는 전용 아티팩트 중 하나를 선택한다.
  제안 초기값은 25%이며, 장신구 후보가 없으면 구현된 전용 아티팩트 풀만 사용한다.
- 일반상자 스펠 확률, 황금·다이아몬드 소모품 개수는 Chest-1에서, 특별 보상 확률과 다이아몬드 스펠·짱셈스펠의 보장 여부와
  개수는 Chest-2에서 확정했다(아래).
- 개봉 시 내용물을 바닥에 생성해 직접 줍는다. 열쇠 부족·일반 공격으로 다이아몬드 상자 개봉을 시도해도
  자원과 상태가 바뀌지 않는다. 개봉 입력과 여러 폭발이 겹쳐도 한 번만 열린다.
- **개봉 방식(사용자 결정, 2026-10-02)**: 별도 입력 키 없이 플레이어가 **닿으면** 연다(E는 D1대로 액티브용 예약 유지).
  일반상자는 닿는 즉시 열린다. 황금상자는 닿을 때 열쇠가 있으면 **자동으로 1개 소비**하고 열리며, 없으면 아무 일도
  일어나지 않는다. 다이아몬드 상자는 닿아도 열리지 않고 폭탄 폭발로만 열린다.
- 상자는 벽·문·필수 진입점·구덩이와 겹치지 않는 안전 위치에 배치한다. 열지 않아도 보스 경로가 막히지 않는다.
- **상자 충돌(사용자 결정, 2026-10-03)**: 상자는 장애물처럼 플레이어·적·투사체를 모두 막는다. 플레이어는 상자를 밀 수
  있지만 하트보다 훨씬 약하게 조금씩(초당 1.2) 밀리며, 벽·장애물·적·픽업 앞에서 멈춘다. 클리어 순간 플레이어 위에 생기지
  않으며, 내용물은 상자 바깥의 빈 지점에 떨어진다. 같은 층 재구성 시에는 밀린 위치가 아니라 처음 놓인 위치로 복원한다.
- 상자 ID, 종류, 개봉 상태, 보상 추첨과 수령 상태는 Run 런타임 방 상태(`RoomRunState` 계열)에 기록한다.
  서버 저장 대상이 아니다. 같은 seed와 콘텐츠 버전에서 재현하고, 재방문·층 재구성으로 상자나 내용물이
  다시 지급되지 않게 한다.
- **미개봉 상자 수명(사용자 결정, 2026-10-02)**: 안 연 상자는 **층을 떠나면 사라진다**. 기존 바닥 픽업이 층 이탈 시
  사라지는 규칙과 같으며, 사라진 상자와 보상은 재지급하지 않는다. 같은 층 안의 방 재방문에서는 미개봉·개봉 상태를 유지한다.
- **Chest-0 개봉 확인(사용자 결정, 2026-10-02)**: Chest-0은 내용물을 생성하지 않고 **개봉 상태만 기록**해 검증한다.
  실제 내용물 생성은 Chest-1·D2에서 한다.
- **Chest-1 내용물(D2 일부 확정, 사용자 결정, 2026-10-03)**: 일반상자 소모품 1~3개(1개 60%·2개 30%·3개 10%, 평균 1.5)와
  5% 확률로 일회용 스펠 1개 추가, 황금상자 2~4개 균등, 다이아몬드 상자 4~6개 균등. 소모품 종류 가중치는 구 클리어 드롭과
  같은 하트 30·SP 30·골드 20·열쇠 12·폭탄 8. 황금 특별 보상과 다이아몬드 스펠/짱셈스펠은 Chest-2에서 정한다.
  내용물은 개봉 시 상자 주변에 바닥 픽업으로 떨어지고, 스펠은 플레이어가 한 번 벗어난 뒤 주울 수 있다.
- **Chest-2 특별 보상·다이아몬드 스펠(D2 확정, 사용자 결정, 2026-10-05)**: 황금상자 특별 보상은 **25%**이며 당첨 시 소모품
  2~4개에 더해 황금 전용 아티팩트 1개가 일반 아티팩트 픽업으로 떨어진다(장신구는 구현 전이라 전용 아티팩트 풀만 사용).
  당첨 여부는 상자 seed로 고정하고, 아티팩트는 **개봉 시점에 더 얻을 수 있는 것만** 후보로 삼는다. 이미 최대 스택으로 보유한
  아티팩트는 후보에서 빼고, 후보가 없으면 특별 보상 없이 소모품만 나온다(주울 수 없는 픽업을 남기지 않음). 다이아몬드
  상자는 소모품 4~6개에 더해 **일회용 아이템 1개를 항상** 준다. 구현된 짱셈스펠이 있으면 그 자리가 **25%로 짱셈스펠**,
  나머지는 스펠이며, 짱셈스펠이 없는 동안(Jjangsem-0 전)은 전부 스펠이다. 일반상자는 짱셈스펠과 특별 보상을 주지 않는다.
  Chest-1의 소모품 개수·종류와 스펠 당첨 추첨은 같은 seed에서 그대로다.

#### 확률과 층 수 점검

전투방 수는 방 수에서 시작방·보스방·특수방을 뺀 근사치다. 특별 보상은 25%, 황금 전용 풀이 가짜 날개
1종뿐이라고 가정한다.

| 구성                    | Run당 전투방 | 상자   | 황금   | 다이아몬드 | 특별 보상 | 가짜 날개 1회 이상 |
| ----------------------- | ------------ | ------ | ------ | ---------- | --------- | ------------------ |
| 현재 3층(10/10/13방 예) | 약 23        | 약 7.6 | 약 1.5 | 약 0.4     | 약 0.4    | 약 32%             |
| 9층 확장 구상           | 약 100       | 약 33  | 약 6.6 | 약 1.7     | 약 1.7    | 약 81%             |

9층 구상은 1~2층 8~12방(보스 최소 거리 4~5), 3~6층 12~18방(5~7), 7~9층 15~22방(6~8)이다.
현재 3층은 이 구성의 1~3층에 해당한다. 위 표에서 다음 결정을 이끌어낸다.

- 3층 기준으로는 정상 Run 몇 번으로 황금·다이아몬드·가짜 날개를 자연스럽게 확인하기 어렵다.
  기능 확인은 개발 패널의 상자 강제 생성 보조 Run으로 하고, 정상 Run은 경제 기록에 쓴다.
- 9층으로 늘리면 황금상자가 Run당 6개를 넘으므로 열쇠 수요가 잠긴 방·상점 입장과 크게 경쟁한다.
  전용 풀이 1종이면 대부분의 Run에서 가짜 날개를 얻게 된다. 층 확장 전에 황금 전용 아티팩트·장신구
  후보를 늘리고, 상자 확률을 층 구간별 표로 나눌지 검토한다. 이번 달은 75/20/5 단일 표를 유지한다.

### 3.2 구덩이 지형과 시스트의 가짜 날개

#### 구덩이 지형 1종

- 일반 구덩이는 **이동만 차단**한다. 플레이어와 지상 적은 지나갈 수 없고, 투사체는 통과한다.
- 장애물을 부술 때 나오는 비밀방 입구 `SecretPit`과는 별도 지형이다. 기존 비밀방 진입 규칙을 바꾸지 않는다.
- 사람이 설계한 Layout에만 배치한다. 기존 Layout ID의 의미를 바꾸지 않고 구덩이가 있는 변형은 새 ID로 추가한다.
- 필수 통로·문 진입점·SpawnPoint·상자 안전 위치를 막지 않으며, 같은 seed에서 배치를 재현한다.
- 적 경로 탐색과 근접 추적이 구덩이를 우회하고, 구덩이 너머에 끼어 방 클리어가 멈추지 않게 한다.
- 비행 적은 현재 없다. 도입하면 구덩이 통과 여부를 그 적의 규칙으로 정한다.
- **Terrain-0 배치·충돌(D3 일부 확정, 사용자 결정, 2026-10-03)**: 구덩이 Layout은 `basic-central-pit`(Basic, 중앙 4×2)과
  `large-pit-lanes`(Large, 좌우 3×2 구덩이 4개 + 가운데 파괴 장애물 4개) 2종이며 1~3층 일반 전투방 후보에 균등 추가한다.
  Layout 난이도 보정은 장애물 Layout과 같은 +1이다. 이동 충돌 분류는 새 Physics 레이어 `Pit`로 나눈다. `Pit`은
  Player·Enemy·Pickup과만 충돌하고 투사체(PlayerProjectile·Default 트리거)·벽과는 충돌하지 않는다. 적 이동 탐색은
  `Environment`+`Pit`, 사선 판정은 `Environment`만 본다. 밀리는 상자도 구덩이 앞에서 멈춘다. 떨어짐·낙하 피해는 없다.
  Flight-0은 플레이어의 `Pit` 충돌만 끄는 방식으로 이어간다.
- **구덩이 Layout 작성 참고(Terrain-0)**: 구덩이 하나는 축 정렬 직사각형이며 가로·세로 각각 1 이상, 네 변이 0.5 격자 위에
  있어야 한다(1×1, 1.5×1, 3×2 가능 / 0.5 폭·격자 밖 위치는 검증 실패). L·T자 등은 여러 직사각형을 맞닿게 붙여 만든다.
  변이 닿는 것은 허용, 구덩이끼리·장애물과 겹치는 것은 실패다. 구덩이마다 테두리가 따로 그려지므로 1×1을 여러 개 붙이면
  사이에 테두리 줄이 보인다. 한 덩어리로 보여야 하면 가능한 한 큰 직사각형으로 나누고, 이어 붙인 경계의 테두리 처리는
  정식 아트 교체 때 정한다.

#### 시스트의 가짜 날개와 비행

- **시스트의 가짜 날개**는 황금상자 전용 아티팩트다. 일반 선택 보상·상점 풀에 자동 포함하지 않는다.
- 획득한 **Run이 끝날 때까지** 비행한다. 시간제한은 없고 다음 Run에는 유지되지 않는다.
- 일반 구덩이와 **낮은 장애물** 위를 이동할 수 있다. 현재 구현된 장애물은 모두 낮은 장애물로 취급한다.
  벽·닫힌 문은 통과하지 않는다. 높은 장애물(나무 등)은 후속 후보이며, 도입하면 비행으로도 통과하지 못한다.
- 장애물을 부수는 공격·타수 규칙은 비행 중에도 유지한다. 장애물 위에 있어도 공격으로 장애물을 부술 수 있다.
- 적 공격·투사체·폭탄 자해는 기존 피해 규칙을 유지한다. 비행 자체는 무적이 아니다.
- 비밀방 `SecretPit` 위를 지나가는 행동과 통로에 진입하는 행동의 구분은 D3에서 정한다(→ 구분 없이 자동 진입으로 확정, 아래).
- 떠 있는 캐릭터·그림자 등으로 비행 상태를 표시한다. 플레이어 이동 통과와 투사체 사선 통과는 별도 규칙이다.
- 현재 장애물·벽이 공유하는 충돌 분류를 확인한다. Environment 충돌을 통째로 끄는 방식으로 구현하지 않고,
  벽·높은 장애물 / 낮은 장애물 / 구덩이를 나눈 이동 충돌 분류를 쓴다.
- 비행 상태에서도 적 경로 탐색·근접 추적·방 클리어가 멈추지 않아야 한다. 구덩이나 장애물 위에서
  폭탄을 설치할 때의 위치 처리는 D3에서 정한다.
- **Flight-0 비행 규칙(D3 확정, 사용자 결정, 2026-10-03)**:
  - `SecretPit`은 비행 중에도 걸을 때와 같이 중심이 닿으면 **자동 진입**한다. 지나가기와 진입을 별도 입력으로 나누지 않는다.
  - 폭탄은 비행 중 **구덩이 위에서는 설치할 수 없고 소비하지 않는다**. **장애물 위에서는 가장 가까운 걸을 수 있는 지점**
    (벽·장애물·구덩이와 0.25 이상 떨어진 곳, 0.25 간격 동심원 탐색, 최대 2.5)에 설치한다.
  - 지상 적이 플레이어에게 걸어서 닿을 수 없으면(구덩이·장애물 위 비행, 막힌 목표) **도달 가능한 가장 가까운 지점까지
    가서 멈춘다**. 원거리 적은 구덩이 너머로 계속 사격하고 보스 패턴은 바꾸지 않는다. 이전의 직선 밀어붙이기 대체 동작을
    이 규칙으로 바꿨다.
  - 이동 충돌 분류: 벽·문·상자(와 후속 높은 장애물)는 비행으로도 막힌다. 현재 장애물(`DestructibleObstacle`·
    `RoomStaticObstacle`)은 낮은 장애물로 Environment 레이어를 유지하고(적·투사체·사선은 그대로 막힘), 비행 중인 플레이어
    충돌체와만 쌍별로 충돌을 끈다. 구덩이는 플레이어 몸체에서 `Pit` 레이어를 제외한다. Environment 레이어 전체를 끄지 않는다.
  - 표시: 발밑 그림자와 장애물보다 위 정렬(+2). 가짜 날개는 Epic 아티팩트(`artifact-sist-fake-wings`, 효과 35 `Flight`,
    최대 1스택)이고 `chest-content-table`의 황금 전용 풀에만 들어간다. 황금상자 특별 보상 추첨은 Chest-2(2026-10-05)에서
    연결했다. 확인용으로는 `F1` 패널 `Drop 시스트의 가짜 날개`(보조 Run)로 바로 획득할 수 있다.

### 3.3 스펠·짱셈스펠 공용 슬롯

- 스펠과 짱셈스펠은 **일회용이며 슬롯 1칸을 공유**한다. 어느 분류를 사용하든 성공 시 한 번 소비한다.
- 슬롯 HUD와 획득 전 설명으로 이름·분류·효과·사용 가능 여부를 읽을 수 있게 한다.
- 공용 사용 키는 **Left Shift**다(D1, 기존 입력과 충돌 없음 확인). 슬롯이 찼을 때 바닥의 스펠·짱셈스펠에
  닿으면 자동 교체하고 기존 아이템을 그 자리에 배출한다. 배출된 아이템은 플레이어가 한 번 벗어난 뒤에 다시 주울 수 있다.
- 방 한정 효과는 사용한 방에만 적용한다. 방을 떠나면 해제하며 재방문에 되살아나지 않는다.
- 사용 불가·Run 종료·중복 입력·사망 전환 중 사용 처리를 명시하고 소비와 효과를 원자적으로 처리한다.

### 3.4 기존 스펠의 일회용 전환

현재 상시 효과를 주는 기존 스펠 3종을 **모두** 새 일회용 스펠로 전환한다.

| 이름         | 현재 구현                                                          | 새 일회용 스펠 방향                                                                                                   |
| ------------ | ------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------- |
| 저놈 잡아라  | `spell-catch-that-one`: 다음 미클리어 전투방의 기본 공격 피해 +10% | 효과 수치를 유지한다. 사용 후 **현재 방** 기본 공격 피해 +10%, 스킬에는 미적용                                        |
| 막판 스퍼트  | `spell-final-sprint`: 보스방에서 공속 +30%·이속 +5%                | 효과 수치를 유지한다. **보스방에서 사용**하면 그 방에서 공속 +30%·이속 +5%. 보스방 밖에서는 사용 불가·미소비(D0 확정) |
| 그건 내 잔상 | `spell-afterimage`: 스택당 이속 +10%·공속 +5%, 최대 3스택          | 기존 상시 강화 대신 **전투 중 현재 층 시작방으로 순간이동**하는 일회용 위기 탈출 스펠                                 |

- 기존 `spell-*` ID와 `ItemKind.Spell`의 의미·과거 전적 설명을 바꾸지 않는다. 이들은 과거 전적 표시용
  레거시로 남기고 신규 획득 풀에서 제외한다.
- 새 일회용 스펠과 짱셈스펠은 별도 안정 ID와 새 분류값(기존 enum 뒤에 추가)을 사용한다.
  이전 데이터 표시·로드 호환과 콘텐츠 버전 정책을 Contract-0에서 함께 설계한다.

#### 그건 내 잔상 — 탈출한 방의 재진입

아이작처럼 탈출한 방은 **다음 진입 때 처음부터 다시 시작**한다. 현재 전투 중에는 문이 잠겨 방을 떠날
수 없으므로(`RoomController`) 아래 규칙을 새로 만든다.

- 탈출하는 순간 그 방의 남은 적·적 투사체·진행 중인 웨이브를 제거하고, 방을 미클리어 상태로 되돌린다.
- 다시 들어가면 같은 seed의 같은 Encounter를 첫 웨이브부터 다시 시작하고 문을 다시 잠근다.
  보스방도 같은 보스를 최대 HP로 다시 시작한다.
- 파괴한 장애물, 바닥에 떨어진 픽업, 연 상자, 발견한 비밀 벽 같은 지형·보상 상태는 유지한다.
- 클리어 보상은 아직 지급되지 않았으므로 실제로 클리어할 때 한 번만 지급한다. 상자 등장·종류는
  방 seed로 고정되어 재진입으로 다시 추첨되지 않는다.
- 탈출은 체력 회복·방 클리어 처리를 하지 않는다. 시작방에서는 사용·소비하지 않는다.
  일반 전투방과 보스방 모두 탈출 가능을 기본 방향으로 한다.
- 스펠 사용 도중 방 이동·층 이동·보스 사망이 겹쳤을 때 중복 전환하지 않는지 검증한다.

### 3.5 멤버십카드와 상점

- 멤버십카드는 **현재 상점에 진열된 미구매 상품 가격을 전부 0**으로 바꾸는 일회용 스펠이다.
- 상품은 직접 선택해 수령하고 판매 완료 상태를 기록한다. 재방문에도 무료·판매 상태가 유지된다.
- 상점 입장용 열쇠와는 별개이며, 다른 상점·다음 층에는 이어지지 않는다.
- 상점 밖에서는 사용·소비하지 않는다. 모든 상품이 판매 완료인 상점에서의 사용 처리는 D5에서 정한다.
- 현재 4상품 상점(`ShopCatalog.OfferCount = 4`)으로 먼저 구현·검증한다. 3×3 상점 UI에 의존하지 않는다.
- 현재 상점에는 리롤이 없다. 리롤 후 새 상품에도 무료를 적용할지는 리롤을 도입할 때 정한다.
- 일반 상점은 시스트를 왼쪽에 두고 오른쪽에 3×3 상품을 보여주는 UI 구상이다.
  실제 방은 캐릭터를 중앙에, 주변 장애물은 **젤다의 항아리 느낌**으로 배치한다.
- UI 9칸과 실제 9상품은 구분한다. 현재 4상품에서의 확장 수량·판매 풀·가격·입장 방식은 설계 조각에서 결정한다.
- **Shop-0 결정(2026-10-06)**: 월드 진열대 4개를 없애고 3×3 화면으로 교체한다. 방 중앙의 시스트에게 `E`로 말을 걸면
  화면이 열리고, 구매는 화면에서만 한다. 실제 상품은 **6개**(아티팩트 3 + 하트·열쇠·폭탄 각 1)이며 윗줄이 아티팩트,
  가운뎃줄이 소모품, 아랫줄 3칸은 빈 칸이다(`ShopCatalog.ItemOfferCount = 3`, `ConsumableOfferCount = 3`,
  `GridSlotCount = 9`). 판매 풀(선택 보상 풀)·등급별 가격·열쇠 입장은 Special-4 그대로다. 소모품은 사면 시스트 앞
  바닥에 칸 열마다 다른 자리에 떨어진다(지갑 상한·멜룬카드 복제 대상 규칙 유지).
- 조작: 방향키/WASD로 칸 이동(가장자리에서 멈춤), Enter·Space·`E`로 구매, Esc 또는 `닫기`로 닫는다. 마우스는 칸을
  눌러 고르고 `구매`를 누른다. 화면이 열린 동안 이동·공격·스킬·폭탄·방 이동과 일시정지가 막히고, 스펠 슬롯(Left
  Shift)은 쓸 수 있어 멤버십카드를 쓰면 열린 화면의 가격이 바로 `무료`로 바뀐다.
- 시스트 캐릭터 에셋은 아직 없어 방 안의 시스트와 화면 왼쪽 초상화는 색 사각형 플레이스홀더다. 항아리 느낌의 방
  장식은 에셋이 생긴 뒤 한다.
- 골디 상점은 같은 UI를 더 화려하게 표현하고 캐릭터를 골디로 교체하며 더 좋은 상품을 제공한다.
  등장률, 일반 상점 대체/별도 생성 여부, 좋은 상품의 기준은 미정이다.

### 3.6 멜룬카드

짱셈스펠 분류의 오리지널 아이템이며 현재 방의 **미개봉 상자와 바닥 기본 소모품**을 각각 하나씩 복제한다.

- 일반·황금·다이아몬드 상자 모두 대상이다. 복제한 황금상자에는 열쇠, 다이아몬드 상자에는 폭탄이 필요하다.
- 열린 상자, 보유 지갑 수량, 상점 상품, 아티팩트·패시브·장신구·스펠·짱셈스펠 자체는 복제하지 않는다.
- 복제 상자와 픽업은 원본과 다른 안정 인스턴스 ID를 갖고 각자 한 번만 수령한다.
- 원본 목록을 고정한 뒤 복제하여 같은 사용 중 새 복제물이 연쇄 복제되지 않게 한다.
- **D4 확정(사용자 결정, 2026-10-05)**: 복제 상자는 원본과 **다른 상자로 취급**해 내용물을 각자의 확률로 따로 추첨한다
  (동일 내용물 복사가 아님). 대상은 **열기 전의 상자만**이다. **중첩 사용이 가능**하며, 이전 사용으로 생긴 복제 상자·픽업도
  다음 사용의 원본이 된다(한 번의 사용 안에서는 원본 목록을 고정). 배치 부족은 상자 밀기를 바꿔 해소한다: 현재 상자는
  4방향으로만 밀리는데, **바닥 하트처럼 자유로운 방향으로 밀리게** 바꾼다(Jjangsem-1에서 함께 구현, §3.1 상자 충돌 규칙 갱신).
  Jjangsem-1(2026-10-05)에서 구현했다. 구현 기본값은 §4.2 "Jjangsem-1 멜룬카드"에 정리한다.
- 영구 화폐인 엘리프는 도입 전까지 대상이 아니며, 도입 시 복제 허용 여부를 별도 결정한다.

### 3.7 골드 전환

- 현재 Run 한정 화폐인 엘리프를 **골드**로 바꾼다. 획득·보유 상한 99·상점 가격·층 이탈 규칙 같은
  Run 화폐의 동작은 그대로 유지하고, 이름과 표시만 바꾼다.
- 현재 엘리프는 Unity 런타임에만 있다. Backend·Web·Prisma에는 엘리프 계약이 없으므로 이번 전환은 Unity 범위다.
- `RunResourceType.Elif = 0`은 픽업 Prefab에 값으로 직렬화되어 있다. 값 0의 의미인 "Run 한정 화폐"는
  유지하고 식별자와 표시를 Gold로 바꾸는 방향을 제안한다. 영구 엘리프 픽업이 필요해지면 새 값을 뒤에
  추가한다. Contract-0에서 이 방식으로 확정했다([23번 §6](./23-item-classification-contract.md#6-골드-enum-방식사용자-결정-이름만-변경)).
- HUD·상점 가격·드롭 표·개발 패널·검증기 로그의 화폐 이름을 함께 바꾼다. 기존 Prefab·ScriptableObject
  참조와 GUID를 보존한다.

### 3.8 투사체 사거리(Range-0)

2026-10-02 대화에서 추가한 범위다. 원래 계획에는 없었다. 이전 수명은 방(16×9)보다 길어서 투사체가 항상
어딘가에 부딪힐 때까지 날아갔다. 사용자 결정은 다음과 같다.

- **시간 기준**: 날아가는 거리 = 체공 시간 × 탄속. 탄속이 늘면 사거리도 늘어난다(체공 시간을 보정하지 않음).
- 플레이어 기본 공격 2/3초(사거리 약 5.3). 처음 1초(약 8)로 정한 뒤 사용자 결정으로 1.5배 줄였다(2026-10-02). 적은 종류별 수명으로 사거리를 다르게 한다. 원거리형 1.8초(9),
  빠른 원거리형 1.4초(약 9), 저격형 1.3초(약 14), 크레용 궁수 1.7초(약 12), 마법사 1.4초(약 10).
  보스 탄막(4초)과 저학년 스킬 유도탄(2.5초)은 그대로 둔다.
- 플레이어 탄은 이동 속도의 25%를 물려받아 이동 방향에 따라 사거리가 조금 달라진다. 의도한 동작이다.
- 사거리 끝에서는 페이드 없이 바로 사라진다. 사거리 만료 경로를 충돌 소멸과 분리해 두고, 연출은 에셋 작업 때 붙인다.
- 사거리(`ProjectileLifetimePercent = 34`)·탄속(`ProjectileSpeedPercent = 33`) 효과 계약을 연다. 탄속은 아직
  아이템이 없다. 사거리는 기존 `item-15` 장난감 망원경에 +30%(약 5.3 → 약 6.9)로 추가했다(사용자 결정, 2026-10-02).
- 기본 공격 넉백은 현재 물리 충돌(Dynamic 투사체 질량 1 ↔ Dynamic 적)로만 생긴다. 탄속 × 아이템 넉백 비율 /
  적 질량 같은 명시적 공식, 느린 탄과 관통의 시너지는 Passive-0에서 정한다.

#### Chest-1 기대 지급량 비교(전투방 클리어 1회당, 2026-10-03)

구 드롭은 33% × 1개, 상자는 33% × (75% × 1.5 + 20% × 3 + 5% × 5) = 클리어당 약 0.652개다. `Week22Chest1Verification`이
두 표 에셋에서 계산해 아래 값과 대조한다.

| 자원 | 구 드롭 | 상자   | 비고                                                            |
| ---- | ------- | ------ | --------------------------------------------------------------- |
| 하트 | 0.0990  | 0.1955 |                                                                 |
| SP   | 0.0990  | 0.1955 |                                                                 |
| 골드 | 0.0660  | 0.1304 |                                                                 |
| 열쇠 | 0.0396  | 0.0782 | 황금상자 개봉 비용 0.0660을 빼면 순수 약 0.0122                 |
| 폭탄 | 0.0264  | 0.0521 | 다이아몬드 상자 개봉 비용 0.0165를 빼면 순수 약 0.0356          |
| 스펠 | 0       | 0.0289 | 일반상자 5%(0.0124) + 다이아몬드 상자 1개 보장(0.0165, Chest-2) |

열쇠 순수 획득이 구 드롭의 약 1/3로 줄어든다. 잠긴 방·상점 입장과의 경쟁은 Balance-0에서 실측한 뒤 조정한다(사용자 결정, 가중치 유지).

Chest-1은 짱셈스펠 후보 확정을 기다리지 않는다. 다이아몬드 상자의 짱셈스펠 연결은 Chest-2에서
구현된 유효 ID만 사용하며, 후보가 없으면 스펠과 소모품으로 채운다. 멜룬카드는 Jjangsem-0의 첫 후보가 될 수 있다.

Chest-2(2026-10-05) 기준 클리어 1회당 황금 특별 보상은 6.6% × 25% = 약 0.0165개, 다이아몬드 상자 스펠도 약 0.0165개다.
짱셈스펠을 구현하면 Chest-1 Setup(또는 Chest-2 Setup)을 다시 실행해 `chest-content-table`의 짱셈스펠 목록에 넣는다.
활성·유효한 `ItemKind.JjangsemSpell` 에셋을 모두 모으므로, 효과가 연결되지 않은 짱셈스펠 에셋은 활성으로 두지 않는다.

#### Jjangsem-0 빅우드의 열매(D10, 사용자 결정, 2026-10-05)

첫 짱셈스펠은 **빅우드의 열매**(`jjangsem-bigwood-fruit`, Rare, 효과 36 `ReduceAndRecoverDamageTaken`)다.

- 사용하면 **10초 동안** 받는 모든 피해가 **하트 반 칸**씩 줄어든다. 감소는 방어막보다 먼저 적용한다. 플레이어가 받는
  최소 피해가 하트 1칸이므로 감소 후에도 최소 반 칸은 받는다.
- 그 10초 동안 **HP 피해를 받을 때마다 2초 뒤** 그 HP 피해에 **하트 1칸을 더해** 회복한다(최대 HP까지). 피해마다 따로
  예약되며, 10초가 끝난 뒤의 피해는 줄지도 회복되지도 않는다. 10초 안에 예약된 회복은 10초가 지나도 도착한다.
- 방어막이 전부 막은 피해는 회복하지 않고, 방어막을 뚫고 들어온 HP 피해만 회복한다. 방어막은 복구하지 않는다.
- 사망을 막지 않는다. HP가 0이 되면 그대로 사망하고 효과와 예약된 회복이 모두 사라진다. Run 종료도 같다.

  감소는 중첩하지 않는다. 사용 장소 제한은 없으며(구현 기본값) 일시정지·사망·Run 종료 중에는 사용·소비되지 않는다.

  자해 1칸은 그대로다. 비행 중 장애물 위 폭탄의 설치 지점 탐색 거리(최대 2.5)는 별개 값이라 바꾸지 않았다.
- **셰이디의 랜덤박스**: 방 seed·장애물 ID에서 결과 하나가 정해진다. 폭발(25%)하면 다른 결과가 없고, 폭발하지 않은 것 중
  20%(전체의 15%)는 **쥬비 5마리**가 나오며, 나머지는 드롭 판정 83%로 픽업 3개(골드 30·하트 20·SP 20·열쇠 15·폭탄 15)
  또는 꽝이다. 쥬비가 나와도 문은 잠기지 않고 클리어 보상·상자를 다시 주지 않는다(사용자 결정). 전투 중에 나오면 쥬비까지
  처치해야 방이 클리어된다. 재방문·층 재구성에서는 다시 나오지 않는다.
- **마요의 수집품 상자**: 가장 드문 종류다. 아티팩트는 선택 보상 풀에서 최대 스택이 아닌 것 중 등급 가중치로 뽑는다.
  엘리프는 영구 화폐가 구현되면 후보에 추가한다(§6.2).
- **높은 장애물 — 나무**: 부서지지 않고 드롭이 없는 고정 장애물(`RoomStaticObstacle`의 비행 차단 표시)이며, 걷는 몸체·
  투사체·사선뿐 아니라 **비행 중인 플레이어도 막는다**. 폭탄으로도 부서지지 않는다. 기존 중앙 기둥은 낮은 장애물로 남는다.
  Layout `basic-tree-grove`(Basic, 나무 1×1 4그루: (±2.5, ±1.5))를 새 템플릿 ID로 1~3층 일반 전투방 후보에 추가했고
  Layout 난이도 보정은 다른 장애물 Layout과 같은 +1이다. 나무 그림은 초록색 플레이스홀더다.

#### Enemy-6 쥬비(사용자 결정, 2026-10-06)

작은 비행형 적 **쥬비**(`Assets/Prefabs/JyubiEnemy.prefab`)를 추가했다. 사용자가 정한 것은 이름·반 칸 피해·한 대에 죽는

- **체력 1**: 층 체력 배율(3층 ×2)을 받아도 플레이어 기본 공격(10) 한 대에 죽는다. 폭탄·스킬·오라에도 죽는다.
- **피해 반 칸(1단위), 모든 층 고정**: 몸에 닿으면 피해를 주고 같은 쥬비는 1초 뒤 다시 피해를 줄 수 있다. 플레이어가 받는
  피해의 최소 1칸 규칙([하트 체력 계획](./idea-implementation/01-player-heart-health.md) D-1·H-3)의 **유일한 예외**이며,
  반 칸을 명시한 피해만 1단위가 된다. 다른 적 피해와 층별 등급 표는 그대로다.
- **이동 속도 5.5**(플레이어 기본 5). 감지 거리 20, 멈춤 거리 0이라 플레이어에게 곧장 부딪친다.
- **비행**: 구덩이와 낮은 장애물(짱돌·특수 장애물·중앙 기둥) 위를 지나가고 벽·문·상자·나무에는 막힌다. 길찾기 없이
  플레이어를 향해 직선으로 난다. 플레이어의 공격·스킬·폭탄은 그대로 맞는다. 낮은 장애물 위에 있을 때는 투사체가 장애물에
  먼저 막힐 수 있다.
- **등장**: 지금은 셰이디의 랜덤박스에서만 5마리가 나온다. 일반 Encounter·위협 점수 표에는 넣지 않았다(넣으려면 역할과
  위협 점수, 한 방에 나올 수를 정해야 한다).
- **그림**: 추적형 적 스프라이트를 절반 크기·연보라색으로 쓴 플레이스홀더다. 그림자·날갯짓 연출은 없다.
- **겹친 적과 투사체(2026-10-06 수정)**: 관통이 없는 플레이어 투사체는 겹쳐 있는 적 중 **하나만** 맞히고, 관통 1회마다 한
  마리씩 더 맞힌다. 이전에는 투사체 제거가 프레임 끝에 일어나 같은 물리 스텝에 닿은 적이 모두 피해를 받았다. 근접 공격·
  스킬 폭발·폭탄 같은 범위 공격은 그대로 범위 안의 적을 모두 맞힌다. 적끼리 겹치지 않게 밀어내는 처리는 넣지 않았다.
- 개발 패널 `— Obstacle —`의 `Next broken random box releases enemies`를 켜고 `Make shady-random-box`로 바꾼 장애물을
  부수면 seed 결과와 관계없이 쥬비 5마리가 나온다(보조 Run).

- 같은 스탯은 덧셈, 다른 스탯은 곱셈으로 누적된다. 상시 효과인 아티팩트는 한 개의 수치를 작게(Common 스탯 하나 +3~5%)
  두고 누적으로 체감시키며, 방 한정 일회용 스펠은 누적되지 않으므로 한 장을 크게(+20~30% 수준) 둔다.
- 기본 스탯(공격력 10·공속 1·치명타 5%/150%)에서 치명타 확률 1%p는 DPS 약 +0.49%, 치명타 피해 1%p는 약 +0.049%다.
- 저놈 잡아라(+10%)·막판 스퍼트 이속(+5%)을 포함한 **나머지 수치 조정은 Balance-0 이후로 미룬다**(사용자 결정).
  공속 상한·방 한정 보너스 합산 상한 같은 안전장치도 Run당 실제 획득 수를 본 뒤 정한다.

## 6. 장애물·상점과 영구 재화 후보

### 6.1 자원별 장애물

나무(높은 장애물)를 뺀 장애물은 모두 비행으로 넘을 수 있는 낮은 장애물이다. 아래 후보도 별도 표시가 없으면 낮은 장애물로 만든다.

| 골드        | 황금돌·시스트의 금고                                | **구현(Obstacle-5, §4.3)**. 희귀 엘리프는 영구 화폐 도입 시에만 추가      |

드롭 표·최대 특수 장애물 1개 규칙은 변경 여부를 명시한 뒤 확장한다. Obstacle-5는 최대 1개 규칙과 안전 슬롯을 그대로
두고 종류별 드롭 표만 추가했다.

### 6.2 골드와 영구 엘리프

**확정 방향**: Run 화폐는 골드이고(§3.7, 이번 달 Gold-0), 엘리프는 Run 이후에도 남는 희귀 영구 화폐다.
엘리프는 아이작처럼 상점을 영구 업그레이드하는 데 쓰고, 상점이 일부 상품을 골드 대신 엘리프 가격으로
팔 수도 있다. 엘리프는 희귀하므로 엘리프 가격은 골드 가격보다 적은 개수다.

이번 달에는 아래 계약 설계 메모까지만 작성하고, 획득·저장·사용 구현은 다음 달에 한다.

- 획득처: 골드 장애물의 낮은 확률 드롭, 마요의 수집품 상자 등. 확률과 Run당 기대 획득량.
- 저장: Run 종료 시 획득량을 결과 저장과 함께 서버에 반영하는 방식, `clientRunId` 재전송 중복 방지.
  Run 도중 사망·포기·중단 시 획득분 처리.
- 사용: 상점 영구 업그레이드 목록과 비용, 엘리프 가격 상품의 등장 규칙과 골드 대비 환율.
  Run 도중 엘리프로 구매할 때 서버 잔액과의 동기화·실패 처리.
- 영향: Unity DTO·Backend DTO/서비스·Prisma/seed·Web 표시·가격 표시·과거 전적.
- 영구 화폐가 생기더라도 열쇠·폭탄 없이 필수 보스 경로를 완료하는 원칙은 유지한다.

## 9. 계층별 영향과 검증

### Unity

Run 지갑(골드)·카탈로그·Inventory/효과·공용 슬롯·RoomRunState·클리어 보상·폭탄·이동 충돌·구덩이
Layout·Shop·HUD가 영향 범위다. Setup은 콘텐츠/참조 구성만 하고 런타임 규칙을 소유하지 않는다.
재실행 시 이전 콘텐츠와 GUID를 보존한다. 기존 33% 자원 드롭을 검사하는 검증기는 새 상자 계약으로
갱신하되 이전 행동의 검증 기록을 소급해서 바꾸지 않는다.

가까운 검증부터 실행한다: 골드 전환 회귀 → 슬롯 1회 소비·상한·방 효과 해제 → 탈출 방 초기화·재진입 →
개봉/복제/지급 멱등성 → 분포/seed → 구덩이·비행과 이동·적 전투 → 상점·카메라·방 재방문 → 전체 Run 회귀.
명시적 잘못된 설정은 실패해야 한다. 배치 검증은 처음부터 권한이 허용된 실행을 요청한다.
프로젝트 인스턴스 잠금과 코드 실패는 구분한다.

### Backend·Web

영구 엘리프는 이번 달 구현하지 않는다. 그래도 새 Item 분류·안정 ID·설명·획득 내역을 저장/표시하는
소비자를 확인한다. 레거시 `spell-*`가 과거 전적에 그대로 표시되는지 확인한다. 변경이 필요한
DTO·seed·서비스·Unity DTO·Web 타입/표시·API 문서를 함께 수정한다. 아이템 사용 로그를 저장할지는
Contract-0에서 결정하고 필요 없는 DB 계약을 미리 확장하지 않는다.

Backend는 관련 Jest와 필요 시 build, Web은 계약/화면 변경 시 lint와 필요 시 build 및 가까운 UI 테스트를
실행한다. 기존 `clientRunId` 재전송·결과 저장·경험치 중복 방지를 보존한다.

### 실제 플레이와 경제 측정

- 서로 다른 seed 정상 Run 최소 3회로 층별 경제와 시간을 기록한다.
- 황금·다이아몬드 상자 개봉, 가짜 날개 비행, 멜룬카드 복제는 3층 기준 자연 등장 빈도가 낮다(§3.1).
  개발 패널의 상자 강제 생성 보조 Run으로 확인하고 정상 Run 비교에서 분리한다.
- 최소 1회는 열쇠·폭탄을 사용하지 않고 보스 경로를 끝까지 확인한다.
- 스펠·짱셈스펠 교체/사용, 비행·비행하지 않는 이동과 구덩이 우회, 탈출 후 재진입 재시작, 복제 후
  개별 개봉을 확인한다.
- 층별 자원 획득/소비·상자 등장/개봉·스펠 사용·상점 구매·아티팩트/패시브 획득·실제 시간을 기록한다.
- 개발 도구 사용 기록은 정상 경제/난이도 비교에서 분리한다. seed·콘텐츠 버전·오류 재현 조작을 남긴다.
- 검증기의 분포·가상 시간 테스트를 실제 Run 완료 증거로 취급하지 않는다.

전체 Run 자동 플레이나 모든 이벤트를 수집하는 텔레메트리는 별도 도구 후보다. 필요한 로컬 측정부터
확장하며 로깅 실패가 게임을 중단하지 않게 한다. 상자 강제 생성 같은 새 개발 도구의 계획·상태는 13번,
실제 메뉴·명령은 구현 후 개발 환경 문서에 기록한다.

## 10. 완료 체크리스트와 축소 순서

- [ ] 기존 스펠 ID·과거 전적을 보존하면서 기존 스펠 3종을 새 일회용 스펠로 전환했다.
- [ ] Run 화폐를 골드로 전환하고 직렬화 값·Prefab 참조와 상점·드롭 회귀를 보존했다.
- [ ] 스펠·짱셈스펠이 슬롯 1칸을 공유하며 획득·교체·사용·효과 해제가 중복 없이 동작한다.
- [ ] 그건 내 잔상으로 탈출한 방이 재진입 시 처음부터 시작하고 지형·보상 상태는 유지된다.
- [ ] 전투방 상자 등장 33%, 종류 75/20/5와 일반 1~3개 보상이 검증됐다.
- [ ] 열쇠 황금상자·폭탄 다이아몬드 상자가 1회 개봉되고 재방문에도 상태를 보존한다.
- [ ] 구덩이 지형 1종이 이동을 막고, 황금 특별 보상 합산 확률과 가짜 날개의 전용 획득·Run 한정 비행을 검증했다.
- [ ] 멜룬카드의 미개봉 상자·픽업 복제와 각 복제물의 단일 수령을 검증했다.
- [ ] 현재 상점 무료 구매·판매 상태 보존과 신규 상점 UI를 검증했다.
- [ ] 자원 특화 장애물과 신규 공격 변화 패시브 최소 2종을 실제 플레이했다.
- [ ] 인게임 설정·사망 확인·근접 설명·미니맵/자원/슬롯 HUD를 두 해상도에서 확인했다.
- [ ] 실제 여러 seed Run에서 진행 차단·재추첨·중복 지급 없이 층별 경제/시간을 기록했다.
- [ ] 새/기존 아이템의 서버 저장·재전송·웹 전적과 실제 빌드를 검증했다.
- [ ] 영구 엘리프 계약 설계 메모를 작성하고 남은 후보와 미정 게이트를 다음 계획으로 이관했다.

일정이 밀리면 (1) 새 적·함정·높은 장애물·비정형 방/아트·전체 Run 자동화, (2) 액티브·장신구,
(3) 골디 상점·아로마 테라피/명상의 시간(Spell-0)과 후보 스펠/짱셈스펠의 추가 수, (4) 최소 2종을 넘는
패시브·장애물 수, (5) 3×3 상점 UI(Shop-0)와 후속 UX 연출 순으로 줄인다. 제외 항목의 상태와 다음 착수
조건을 남긴다.

공용 슬롯의 일회용 소비, 골드 전환, 상자 3종과 지정 확률, 개봉·복제·자원·보상 중복 방지, 구덩이와
가짜 날개 비행, 탈출 방 초기화, 기존 ID 호환, 무자원 필수 경로, 실제 Run/저장 회귀는 축소하지 않는다.
장신구를 이연해도 황금상자의 특별 보상은 유효한 전용 아티팩트 풀로 구현하고 빈 추첨 결과를 만들지 않는다.
멤버십카드는 3×3 UI를 축소해도 현재 4상품 상점으로 완료한다.
