## 1. 이 문서의 역할

둘째 달에 3층 Run, 스킬, 아티팩트, 캐릭터 메타 성장과 Unity → Backend → DB → Web 연동을 완료했다. 이 문서는 실제로 축적되는 Run 데이터를 사용자가 검색하고 비교할 수 있는 Web 서비스로 확장하는 실행 계획이다.

- 날짜보다 `전적 조회 계약 확정 → 통계 정의 → 집계 API → 랭킹 → 시각화 → 통합 검증` 의존성 순서를 우선한다.
- 이미 구현된 유저 전적·Run 상세·캐릭터 성장 화면은 다시 만들지 않고 검증된 기반으로 사용한다.
- Unity와 Web은 Database에 직접 접근하지 않고 Backend API만 사용한다.
- 통계의 분모, 중복 아티팩트 처리, 동률 정렬처럼 결과 해석에 영향을 주는 규칙을 UI보다 먼저 확정한다.
- 8주차에 남긴 최종 밸런스와 콘텐츠 폴리싱은 데이터가 충분히 쌓인 뒤 수행하며, 셋째 달 필수 완료 조건에 포함하지 않는다.
- 매주 마지막 날에 실제 소요 시간, 막힌 원인과 다음 주 조정 사항을 기록한다.

## 2. 시작 시점의 확정 기반

### 완료된 게임·데이터 흐름

- 캐릭터 선택부터 3층 최종 보스까지의 전체 Run
- 일반 몬스터 3종, 보스 1종의 층별 강화형
- 저학년·고학년 스킬과 SP
- 활성 아티팩트 10종, 등급별 가중치, 최대 스택과 대체 보상
- Run 종료 경험치, 캐릭터 레벨과 스킬 강화
- `clientRunId` 기반 Run·경험치 중복 지급 방지
- Unity → Backend → PostgreSQL → Web 관통 검증

### 이미 존재하는 Web·API 기반

- 닉네임 입력 후 유저 페이지로 이동하는 메인 화면
- 유저 요약 통계와 캐릭터 성장 상태 조회
- 최근 Run 목록 조회
- 개별 Run 상세와 아티팩트 획득 순서 조회
- 존재하지 않는 데이터, API 실패와 재시도 상태의 기본 처리
- Web에서 스킬 포인트를 사용한 강화

### 셋째 달에서 확정할 부분

- 검색 결과와 전적 페이지의 완성 기준
- 페이지네이션과 빈 데이터·오류 상태
- 통계 지표의 정확한 정의와 Backend 집계 계약
- 캐릭터·아티팩트·층 통계
- 최고 도달 층·클리어 타임·클리어 횟수 랭킹
- 실제 API 데이터를 사용하는 차트와 반응형 화면

## 3. 이번 달에서 제외하는 범위

다음 항목은 중요하지만 데이터 활용 기능이 완성된 뒤 Phase 7에서 처리한다.

- 방 크기 변형과 추가 Room Profile 확정
- 적 조합과 보스 패턴의 최종 확정
- 아티팩트 효과 값과 등급별 가중치의 최종 조정
- 최대 스택 대체 보상의 최종 조정
- SP 드롭률과 스킬 피해·쿨타임의 최종 조정
- 몬스터·보스 HP와 공격력의 최종 조정
- 10~15분 목표 플레이 시간의 최종 판정
- 캐릭터·몬스터·아티팩트 정식 아트와 사운드
- 로그인·회원가입과 테스트용 고정 `userId` 제거
- Production 배포와 운영 환경 설정

단, 통계 구현에 필요한 데이터가 현재 Run 계약에 없다는 사실이 확인되면 계약 추가 여부를 기록한다. 셋째 달 목표를 위해 불필요한 게임 이벤트나 개인정보를 미리 수집하지 않는다.

# 7. 10주차 — 유저 전적과 Run 상세 제품화

## 목표

## 권장 진행 순서

```text
전적 DTO 확정
  → 정렬·페이지네이션
  → 유저 요약
  → Run 목록
  → Run 상세
  → 오류·빈 데이터·반응형
  → Phase 5 관통 검증
```

## 필수 작업

### 유저 요약

- [x] 총 플레이, 클리어 횟수, 클리어율, 최고·평균 도달 층과 평균 플레이 시간 표시 (`test-player` 실제 화면 확인, 2026-09-03)
- [x] Run이 없는 유저의 모든 집계 값을 일관되게 `0`으로 처리 (UsersService 경계 테스트 통과, 2026-09-03)

- [x] 유저가 없을 때 `USER_NOT_FOUND`를 일반 API 실패와 구분 (`missing-user` 화면 확인, 2026-09-03)

### Run 목록

- [x] 종료 시각 내림차순과 동일 시각의 안정적인 보조 정렬 규칙 적용 (`endedAt DESC, id DESC` 저장소 테스트, 2026-09-03)

- [x] 중복되거나 누락되는 Run 없이 다음 페이지로 이동하는지 검증 (10·10·3개, 각 경계 ID 비교, 2026-09-03)

### Run 상세

- [x] 유저, 캐릭터, 게임 버전, 시작·종료 시각과 플레이 시간 표시 (실제 상세 화면 확인, 2026-09-03)
- [x] 도달 층, 클리어 여부, 처치 수와 사망 원인 표시 (클리어·`ENEMY` 사망 화면 확인, 2026-09-03)

# 8. 11주차 — 통계 정의, 집계 API와 랭킹

## 기간

2026-10-27(화) ~ 2026-11-02(월)

## 목표

같은 Run 데이터에서 누구나 같은 결과를 얻도록 통계의 의미를 먼저 확정하고, Backend에서 통계와 랭킹을 계산한다.

## 권장 진행 순서

```text
지표 정의와 예제 데이터
  → 조회 계약
  → 유저 통계
  → 캐릭터·아티팩트·층 통계
  → 랭킹
  → 정확성·성능 검증
```

## 통계 공통 계약

- 비율은 `0~100` 범위의 퍼센트로 반환한다.
- 분모가 `0`이면 비율과 평균은 `0`으로 반환한다.
- 클리어 타임 랭킹은 `isCleared = true`인 Run만 포함한다.
- 아티팩트 통계의 기본 단위는 획득 횟수가 아니라 **해당 아티팩트를 한 번 이상 획득한 고유 Run 수**로 한다. 같은 Run의 중복 획득은 선택률과 획득 후 클리어율의 분모에서 한 번만 센다.
- 층 도달은 `reachedFloor >= 대상 층`으로 계산한다.
- 모든 랭킹은 주 정렬 값이 같을 때 사용할 안정적인 보조 정렬을 가진다.
- 테스트·개발 Run 제외가 필요하다면 임의 조건으로 숨기지 않고 식별 계약을 먼저 추가한다.

## 10. 개발 도구 병행 범위

개발 도구는 기능 구현을 막는 별도 프로젝트로 진행하지 않는다. 상태와 상세 완료 조건은 [개발 생산성·검증 인프라 계획](./13-development-tooling-plan.md)에서 관리한다.

### T3 — 계층 간 계약 검사

- 11주차 통계·랭킹 API 구현 시 Backend 응답과 Web 소비 타입의 필드 이름·필수 여부를 확인한다.
- 기존 Unity Run 저장 계약은 변경하지 않는 것을 우선한다.
- 계약 검사를 구현했다면 정상 계약과 의도적인 불일치 실패를 모두 재현하고 실행 방법을 `docs/05-development-setup.md`에 기록한다.

### T4 — 플레이테스트 텔레메트리

- 최종 밸런싱 전에 필요한 지표와 현재 Run 저장 데이터로 계산 가능한 지표를 구분한다.
- 셋째 달에는 이벤트 이름·공통 필드·Run 격리·개인정보 제외 원칙과 최소 기록 경로까지만 준비할 수 있다.
- 텔레메트리 때문에 통계·랭킹 필수 범위가 밀리면 T4를 다음 달로 연기한다.

### T5 — Unity MCP

- 수동 Unity 검증이 실제로 반복 병목이라는 기록이 없으면 착수하지 않는다.
