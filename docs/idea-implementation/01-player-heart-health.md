# 플레이어 체력 칸 단위 전환

- 상태: **HP-1~HP-5 구현 완료(자동 검증)**, 수동 플레이 확인 대기 (2026-09-28)
- 관련 문서: [4개월 차 계획](../15-fourth-month-plan.md), [게임 디자인](../03-game-design.md), [아티팩트·스펠 후보](../12-artifact-spell-candidates.md)
- 범위: 플레이어 HP·피해·회복·방어막의 표현 단위. 적 HP와 플레이어 공격력 스케일은 별도 단계로 둔다.

## 1. 배경

현재 플레이어 HP는 `5`이지만 내부 타입이 float이고 적 피해가 `0.75`, `1.25`, `1.5`처럼 소수이며,
층 배율(2층 ×1.3, 3층 ×1.6)이 곱해져 `3.2` 같은 값이 생긴다. HUD 숫자는 `Ceil`로 표시되어
`4.25 / 5`가 `5 / 5`로 보이는 등 작은 회복이 드러나지 않는다.

최대 HP 비례 효과도 작은 기준값 위에서 계산되어 체감이 약하다.

| 효과                  | 설정               | HP 5 기준 실제 양 |
| --------------------- | ------------------ | ----------------- |
| 코미의 베개 처치 회복 | 최대 HP 5%         | 0.25              |
| 광기의 가면 오라      | 1초마다 최대 HP 1% | 0.05/초           |
| 보상 회복 카드        | 최대 HP 25%        | 1.25              |
| 생명의 보석 (미구현)  | 3초간 최대 HP 45%  | 2.25              |

HP를 100으로 늘려도 비율은 같으므로 체감 문제는 해결되지 않는다. 문제는 수치 크기가 아니라
표현 단위다.

## 2. 원칙

1. 플레이어 HP·피해·회복·방어막은 **반 칸 = 1단위의 정수**로만 다룬다.
2. 적 HP, 플레이어 공격력, 화상 같은 지속 피해는 연속 수치를 유지한다. 화상은 적에게만 적용한다.
3. **기본 체력 기준 난이도는 현재보다 가벼워지지 않는다.** 로그라이크 성장은 아이템 획득으로
   얻으며, 아이템 없는 기본 상태는 어려워야 한다.
4. 기존 Item ID는 유지하고, 이미 사용 중인 `ItemEffectType` 번호의 계산식 의미를 바꾸지 않는다.

## 5. 적 피해 등급

기준: 모든 층에서 현재 값 이상이 되도록 반 칸 단위로 올림한다. 괄호 안은 현재 층 배율 적용 값이다.

| 등급 | 해당 공격 (현재 1층 값)                                              | 1층                  | 2층                 | 3층                 |
| ---- | -------------------------------------------------------------------- | -------------------- | ------------------- | ------------------- |
| 약   | 산사모·크레용 졸개 접촉 0.75, 부스러기 졸개 1                        | **1칸** (0.75~1)     | **1칸** (0.98~1.3)  | **1.5칸** (1.2~1.6) |
| 중   | 산사모·졸개 근접 1.25, 보스 투사체 1.5                               | **1.5칸** (1.25~1.5) | **2칸** (1.63~1.95) | **2.5칸** (2~2.4)   |
| 강   | 원거리·저격·궁수·마법사 투사체 2, 불효자손 접촉 2, 보스 접촉 2, 돌진 | **2칸** (2)          | **3칸** (2.6)       | **3.5칸** (3.2)     |
| 치명 | 불효자손 근접 3, 크레용사용 황금 3방향 강타                          | **3칸** (3)          | **3.5칸**           | **4칸**             |

- 현재 근접 공격(`MeleeEnemyAttack`)은 층 배율이 적용되지 않는다. 등급표를 쓰면 근접 공격도 층에 따라
  무거워지므로 현재보다 어려워진다.
- 보스 대형 패턴은 D-6에 따라 새마음금고 착지는 중, 크레용사용 내려찍기는 강, 황금 3방향 강타는 치명이다.
  다른 보스 공격은 현재 값 기준으로 위 표에 맞춘다.
- 3층 약공격은 D-5에 따라 1.5칸으로 올려 현재(1.2~1.6)보다 가벼워지지 않게 한다. 적 수·조합으로 난이도를
  보충하는 조정은 이후 Encounter 확장에서 함께 검토한다.

## 7. `ItemEffectType` 번호 기준

새 번호가 필요한지는 효과 이름이 아니라 **기존 데이터의 계산식이 조용히 바뀌는지**로 판단한다.

| 경우                                                              | 처리                                                | 예                                                                    |
| ----------------------------------------------------------------- | --------------------------------------------------- | --------------------------------------------------------------------- |
| 계산식이 같고 결과만 단위로 내림                                  | 기존 번호 유지                                      | 보상 회복 25%, 풍선 갑옷 방어막 50%, 도깨비 감투 30%, 생명의 보석 45% |
| 계산식 자체가 바뀜 (비율 → 고정·횟수, 최대 HP 기준 → 공격력 기준) | 새 번호를 끝에 추가하고 기존 번호는 호환용으로 남김 | 코미의 베개, 광기의 가면                                              |
| 수치 해석 단위만 바뀜 (HP → 반 칸)                                | 기존 번호 유지, 에셋·Backend 수치를 함께 갱신       | `MaxHealthFlat (11)`                                                  |

**생명의 보석(24):** 최대 HP 45% 비율 회복을 그대로 유지하면 H-5 내림만 적용되므로 번호를 새로 만들지 않는다.
또한 24번은 런타임 구현과 Backend 계약이 아직 없고 `Week16Content0Setup`·검증기와 에셋 1개만 참조한다.
나중에 고정 칸 회복으로 계산식을 바꾸려면 새 번호를 추가한다.

신규 번호 (HP-3에서 확정, 2026-09-28):

| 번호 | 이름               | 설명                                  |
| ---- | ------------------ | ------------------------------------- |
| 26   | `HealOnKillEveryN` | N마리 처치마다 고정 단위 회복. `integerAmount` = 필요 처치 수, `magnitude` = 회복 단위 |
| 27   | `AttackDamageAura` | 주기마다 주변 적에게 공격력 비례 피해. `magnitude` = 공격력 비율, `radius`·`intervalSeconds` 필수 |

## 11. HP-1 구현 기록 (2026-09-28)

- `Health`에 반 칸 단위 모드를 추가했다. `PlayerStats`가 플레이어에만 이 모드를 켜며, 피해는 올림 후 최소 2단위,
  회복·방어막은 내림, 최대 HP 비례 결과는 `GetMaxHealthRatioAmount`로 내림 후 최소 1단위를 적용한다. 적 `Health`는 연속값을 유지한다.
- 모든 적 공격 컴포넌트의 float 피해 필드를 `EnemyDamageTier`로 교체했다. `FloorDifficultyScaler`는 피해 배율 대신
  `EnemyFloorLevel`에 층을 기록하고, 적중 시 `HealthUnits.GetEnemyDamageUnits(등급, 층)`으로 단위를 정한다.
- 공격별 등급: 접촉(부스러기·산사모·크레용 도끼/방패) 약, 불효자손·보스 접촉 강, 부스러기 근접 약, 산사모·크레용 근접 중,
  불효자손 근접 치명, 원거리·저격·궁수·마법사 투사체 강, 돌진 강, 보스 투사체 중, 부스러기 장애물 충돌 약,
  새마음금고 착지 중, 크레용사용 검격(내려찍기)·대시 강, 맵 베기(황금 3방향 포함) 치명.
- Prefab·Scene은 해당 직렬화 줄만 등급 값으로 바꿨고 GUID는 유지했다. 플레이어 `baseMaxHealth`는 4개 Scene에서 10으로 바꿨다.
- HUD-2 전까지 HP 숫자와 회복 카드는 칸 단위(`4.5 / 5`)로 표시한다.
- 과도기 동작(HP-3에서 정리): 코미의 베개 5%는 최소 1단위 규칙으로 처치당 반 칸, 광기의 가면은 기존 체감 유지를 위해
  칸 기준 최대 HP(5)에 비례한다. 아이템 설명의 `최대 HP +2` 문구는 아직 단위를 반영하지 않는다.
- 유지한 기존 동작: 황금 3방향 강타는 겹친 선 수만큼 중첩된다(1층 최대 9칸). 보스 소환물은 기존처럼 층 정보를 받지 않아 1층 등급으로 계산된다.
- 검증: `Hp1HealthUnitsVerification.VerifyRegressionBatch` 25개 항목 통과. Scene 구성 선행이 필요한 `Week14Room7`,
  `Week7ChaserMonster`, `Week8FloorDifficulty` 전체 Run 단계와 기존 실패(`Week6Item`, `Week15Enemy0`, `Week15Enemy2` 레거시 보스 격리)는
  배치에서 제외했다.
- 수동 확인 필요: 3층 약공격 1.5칸, 보스 패턴 등급 체감(9절).

## 12. HP-4 구현 기록 (2026-09-28)

- `PlayerLowHealthRecovery`를 추가하고 `PlayerInventory`가 효과 `24` 획득 시 붙인다. 효과 번호·에셋·수치(30%, 45%, 3초)는 바꾸지 않았다.
- 발동: 현재 HP가 `최대 HP × 30%` 이하로 바뀌는 순간 1회. 임계치 아래에서 획득하면 즉시 시작한다. HP가 0이 되는 피격으로는 발동·소비하지 않는다.
- 회복량은 발동 시점 최대 HP 기준 `GetMaxHealthRatioAmount(45%)`(내림, 최소 1단위)이며, 1단위(반 칸)씩 3초 동안 균등 간격으로 지급한다.
  5칸 기준 4단위를 0.75초마다, 풍선 갑옷 6칸 기준 5단위를 0.6초마다 지급한다. 마지막 회복은 3초 시점이다.
- 시간은 `Time.time`을 써서 일시정지·보상 선택 중에는 진행하지 않는다. 회복 중 사망하면 남은 회복을 취소한다.
- 층당 1회: `RunProgress.RoomChanged`에서 층이 바뀔 때 소비 상태를 갱신한다. 같은 층의 방 재방문과 디버그 `Heal / Reset HP`는 소비 상태를 되돌리지 않는다.
- Backend `item-catalog.ts`에는 아직 Week16 아티팩트·스펠 6종이 없다. 생명의 보석의 Backend 계약 추가는 해당 콘텐츠 계약 동기화 작업에서 함께 다룬다.
- 수동 확인 필요: 1.5칸 이하에서 회복이 반 칸씩 보이는지, 발동 체감(HUD-2 하트 HUD 이후 재확인).

## 14. HP-3 구현 기록 (2026-09-28)

- `ItemEffectType`에 `HealOnKillEveryN = 26`, `AttackDamageAura = 27`을 끝에 추가했다. 기존 `10`·`14`는 계산식을 바꾸지 않고 호환용으로 남긴다.
- 코미의 베개(`item-08`): `effectType 26, magnitude 1, integerAmount 2`. 첫 스택이 필요 처치 수(2)와 회복량(1단위)을 정하고,
  이후 스택마다 필요 처치 수를 1 줄인다(최소 1). 처치 카운터는 `PlayerStats`가 관리하며 N번째 처치에서 0으로 되돌린다.
  HP가 가득 차 있어도 카운터는 진행하고 회복은 버려진다. 처치 경로는 기존 `PlayerCombatEvents` 공유 경로라 중복 보고는 세지 않는다.
- 광기의 가면(`item-14`): `effectType 27, magnitude 0.2, radius 2.5, intervalSeconds 1`. `PlayerDamageAura`가 최대 HP 비율과
  공격력 비율을 따로 누적하고, 틱 피해는 `최대 HP(칸) × 비율₁₀ + 현재 공격력 × 비율₂₇`이다. 3스택은 공격력 60%/초다.
  치명타·거리 보정은 적용하지 않는다(기존 지속 피해 규칙 유지). HP-5 이전 공격력 1 기준 3스택은 초당 0.6 피해다.
- 풍선 갑옷(`item-02`): 에셋·Backend 수치 `MaxHealthFlat 2`는 그대로이며 단위로 해석되어 +1칸이다. 설명만 바꿨다.
- 설명 문구: `ArtifactEffectDescription`이 플레이어 HP 값(`MaxHealth`, `MaxHealthFlat`, `HealOnKill`, 26번)을 칸으로 표시한다
  (`1` → 반 칸, `2` → 1칸, `3` → 1.5칸). `칸` 글리프는 `Hp3ItemEffectsVerification.Setup`이 HUD-3B 설명 글리프 루틴으로 Frontend 폰트에 추가한다.
- Backend: `item-catalog.ts`의 `item-08`·`item-14` 효과와 `item-02`·`item-08`·`item-14` 설명을 갱신했다. 효과 타입은 문자열 이름이라 번호 동기화는 없다.
  DB에는 `seed`가 `effectData`를 upsert하므로 기존 환경은 `pnpm prisma:seed` 재실행으로 반영된다. Prisma 스키마와 API DTO는 바뀌지 않았다.
- 검증: `Hp3ItemEffectsVerification.SetupAndVerifyBatch`(Setup 2회, HP-3 검사, Phase G-1 계약, HP-4, HP-1 회귀 25개) 통과. Backend `item-catalog.spec.ts` 포함 Jest 56개와 `pnpm build` 통과.
- 수동 확인 필요(HP-5 이후 일괄): 코미의 베개 반 칸 회복 체감, 광기의 가면 딜 체감(HP-5 공격력 10배 이후 재확인).
