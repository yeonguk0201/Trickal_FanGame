## 1. 계획의 역할과 출발 상태

여섯째 달 계획(21번)의 21~23주차 조각은 자동 검증과 실제 화면 확인까지 끝났다(2026-10-09). 21번이 끝난 조각의 구현
기록으로 길어져, 남은 작업을 이 문서로 옮겼다(사용자 결정, 2026-10-11). 옮긴 것은 다음과 같다.

- 24주차 조각 6개(UX-0·UX-1·Balance-0·Verify-0·Play-2·Build-0). 모두 미착수다.
- 결정은 끝났지만 구현하지 않은 콘텐츠: 스펠 5종, 짱셈스펠 4종, 교주의 권능 6종, 신규 적, 함정 7종.
- 영구 엘리프 계약 설계 메모와 미정 게이트 D7·D8·D9.

끝난 조각의 규칙·구현 기본값·검증 기록은 21번에 그대로 있다. 이 문서의 사양은 21번에서 **옮긴 것**이며 21번에는 링크만
남겼다. 같은 수치를 두 문서에 두지 않는다.

일정은 기존 계획의 다음 4주를 잇는 표기다. 실제 진행은 날짜보다 선행 시스템과 검증 순서를 우선한다. 아래 신규 조각의
상태는 모두 **예정**이며, "확정"이라고 적은 것은 결정이 끝났다는 뜻이지 구현됐다는 뜻이 아니다.

## 2. 범위와 순서

### 진행 순서(사용자 결정, 2026-10-11)

콘텐츠를 먼저 넣고 UX를 병렬로 진행한다. Balance-0과 Play-2는 맵 Layout을 더 추가한 뒤에 하기로 되어 있으므로
(2026-10-09), seed 결과를 바꾸는 작업을 그 전에 모두 끝낸다.

```text
함정 7종 + 함정 Layout 3종
  → 신규 적 출현(이름 변경·쥬비 Encounter·쫄따구 폭발·신규 적 2종)
  → 짱셈스펠 4종 → 스펠 5종
  → 교주의 권능(계약 → 슬롯·게이지·6종 → 1층 시작 보물방)
  → Layout 추가 → 경제 측정 → 여러 seed 실제 Run → 빌드 검증
병렬: 인게임 설정·사망 연출(UX-0), 움직임 연출(Motion-0)
권능과 함께: 우측 HUD·미니맵·획득 전 설명(UX-1)
```

- **함정을 먼저 하는 이유**: 원화가 있고, Balance-0을 막고 있는 Layout 추가와 겹친다. Room 계약을 건드리므로 작업 중에도
  회귀 묶음을 돌린다.
- **권능을 짱셈스펠보다 먼저 하는 이유(사용자 결정, 2026-10-15)**: 권능이 있어야 Run을 테스트에 가깝게 돌릴 수 있다.
  공용 적 스턴 규칙은 Power-1이 만들고 Jjangsem-2의 깜짝상자가 재사용한다. 피해 감소는 이미 있는 빅우드의 열매 규칙을
  애착 담요가 재사용한다.
- **UX-1을 권능과 묶는 이유**: 권능 게이지 HUD가 우측 HUD와 같은 영역을 쓴다. 먼저 하면 배치를 두 번 잡게 된다.
  UX-0은 콘텐츠와 겹치는 파일이 거의 없어 처음부터 병렬로 한다.
- **콘텐츠 버전**: 함정 Layout과 1층 시작 보물방은 Room 콘텐츠 버전을, 신규 적과 쥬비 Encounter는
  `encounterContentVersion`을 올린다. 같은 seed의 결과가 바뀌므로 Balance-0·Play-2의 기록은 이 변경이 모두 끝난
  버전에서만 남긴다.

### 필수와 조건부

- 필수: 이관된 24주차 조각 6개. 여섯째 달의 완료 조건에서 남은 것이다.
- 이번 달 콘텐츠: 함정, 신규 적, 짱셈스펠 4종, 스펠 5종, 교주의 권능. 결정이 끝난 순서대로 독립 조각으로 넣는다.
- 병행: 움직임 연출(원화는 있고 움직임만 없는 것).
- 조건부: 영구 엘리프 구현(계약 설계 메모가 확정된 뒤), 2~3층 일반 보물방의 권능 등장.
- 보류: 장신구(§4.5).

가져오기 도구(T7)로 작성하며, 함정 Layout 3종(Trap-1)은 이 추가분에 포함된다. 그 밖의 추가 범위는 28주차 시작 때 정한다(§6).

#### 함정 7종

이름은 아래 표의 직관적인 표기를 그대로 쓴다(사용자 결정, 2026-10-11). 외형 원화는 사용자가 만들어 두었다.

- **판정(사용자 결정, 2026-10-12 변경)**: 바닥형 함정은 **발 중심부터 발바닥(발 중심 아래 0.3)까지의 세로선이 그림에 걸칠 때** 밟은 것으로 본다. 캐릭터 그림의
  발이 발 중심보다 0.3 아래에 그려지므로, 아래쪽은 발 중심이 그림 안일 때, 위쪽은 그려진 발이 그림에 닿을 때부터 맞는다
  (위로 0.3 더 넓다. 좌우는 그림 폭 그대로). 그림은 칸
  가로에 맞춘 원화의 보이는 영역이고 판정은 그 영역에 내접한 타원이다(장판 1×0.37, 바닥 가시 1×0.59, 주기 가시 1×0.66,

  기준(발밑 원 반지름 0.3이 1×1 칸에 닿으면 판정)은 그림 밖에서 맞아 폐기했다. 배치 단위와 Trap-1 배치 검증은 1×1 칸
  그대로다. 함정 피해도 기존 피격 무적 창을 함께 써서 적에게
  맞은 직후 가시를 밟아 연속으로 깎이지 않는다.
- **독가스**: 가스 안의 적은 1초마다 중독 1스택을 받는다. 수치는 비비의 콧물과 같다(4초, 1초 틱, 공격력 15% × 스택, 최대
  3스택, [24번 §4.8](./24-attack-modifier-contract.md)). 플레이어는 가스 하나당 반 칸 피해를 1회만 받는다. 적은 독버섯을
  부술 수 없다.
- **불**: 적 투사체도 막고 적의 공격으로는 꺼지지 않는다.
- **적 경로**: 불·가시 돌·독버섯은 `Environment` 장애물이라 기존 A\*가 그대로 우회한다.
- **Layout 첫 묶음**: 기존 Layout ID를 바꾸지 않고 새 ID 3종을 추가한다. `basic-spike-field`(바닥 가시·주기 가시),
  `wide-fire-lane`(불·가시 돌), `large-web-garden`(거미줄·독버섯·장판). Layout 난이도 보정은 장애물 Layout과 같은 +1이다.
- **배치 검증**: 불·가시 돌·독버섯은 장애물로 취급해 기존 겹침·필수 통로·도달성 검증을 통과해야 한다. 바닥형은 0.5 격자 위
  1×1 단위이며 문 안전 진입점 반경 1.5 안, SpawnPoint, 상자 안전 위치, 구덩이와 겹치면 실패한다. 모든 문 사이에 바닥 함정을
  밟지 않는 경로(발밑 원 기준)가 있어야 한다. 주기 가시는 한 방에서 A·B 두 위상만 쓰고 반 주기 어긋나게 한다.
- **구현 기본값**(환경 피해를 적에게 넓히며 구현이 고른 것. 바꾸려면 알려 달라):
  - 적이 가시·장판에서 받는 피해는 1회 5(기본 공격력 10의 절반)이고, 같은 함정은 1초 뒤 다시 피해를 준다. 층 체력 배율과
    무관한 고정값이다.
  - 적은 중심이 함정 그림(같은 타원) 안에 있을 때 밟은 것으로 본다(적은 발밑 판정이 따로 없다).
  - 지상 적의 경로 탐색은 바닥 함정을 피하지 않는다. 플레이어가 적을 함정 위로 유인할 수 있다.
  - 쥬비 같은 비행 적은 바닥형을 무시하고 독가스는 맞는다.
  - 가시·장판으로 죽은 적은 방 클리어에는 세지만 플레이어 처치로 귀속하지 않는다(처치 시 효과 미발동). 독가스 중독은
    플레이어가 버섯을 부숴 생기므로 플레이어 처치로 귀속한다.
  - 불·가시 돌의 접촉 피해는 플레이어만 받는다. 적은 이들을 장애물로 우회하므로 환경 피해 대상에 넣지 않았다.
  - Trap-0 구현이 추가로 고른 값(2026-10-12): 주기 가시 A 위상은 내려간 상태로, B 위상은 올라온 상태로 시작한다.
    불·가시 돌·독버섯은 다른 장애물처럼 폭탄 한 번에 부서진다(불은 꺼지고 독버섯은 가스를 남긴다). 가시 돌은 짱돌의
    기본 드롭 표를 그대로 쓴다. 피격 무적 중에 밟은 함정은 간격을 시작하지 않아 무적이 끝나는 즉시 피해를 준다.
    거미줄 감속은 겹쳐도 한 번만 적용되고 벗어난 뒤 0.15초에 끝난다. 독가스는 생긴 순간과 1초·2초에 중독을 건다.
    함정으로 죽으면 사망 원인은 `HAZARD`로 기록한다. 함정으로 죽은 적도 Run 처치 수에는 센다.
  - Trap-1 구현이 고른 값(2026-10-12): 세 방의 등장 가중치는 기본 100이다. 방 파일의 함정 글자는 `^` 바닥 가시,
    `a`·`b` 주기 가시 A·B, `~` 장판, `w` 거미줄, `*` 불, `Z` 가시 돌, `P` 독버섯이다. 문 안전 진입점 반경 1.5는 함정
    칸(1×1)까지의 거리로 잰다. SpawnPoint는 같은 칸만 금지하고 옆 칸의 바닥 함정은 허용한다(적은 중심이 그림 안일
    때만 밟는다). "상자 안전 위치"는 런타임 규칙으로 넣었다. 클리어 상자·복제 상자의 위치 탐색이 상자 몸체가 바닥
    함정 칸에 걸치는 자리를 건너뛴다. 방 구성은 [개발 환경](./05-development-setup.md)의 Trap-1 항목에 있다.
- 이 결정으로 다섯째 달 [8장](./19-fifth-month-plan.md#8-구현-전에-정할-규칙)의 함정 미정 두 항목(작동 조건·피해 대상, 전투 종료 뒤·재방문
  처리)이 정해졌다. 남은 것: 외형 원화의 Unity 연결, 장판·가스의 화면 표현. (Layout 3종은 Trap-1에서 만들었고 사용자가
  실제 Play로 확인했다, 2026-10-12.)

  유지된다.
- **깜짝상자**: 대상은 균등 무작위이고 seed 재현은 하지 않는다. 체력 감소는 피해 숫자·체력바·피격 깜빡임·적 전투 돌입을

  먼저 걸고 체력을 줄인다.
- **보스 패턴 취소(공용 스턴 규칙 변경)**: 스턴이 걸리면 예고·실행 중인 보스 패턴을 취소하고, 스턴이 끝나면 **같은 패턴을
  예고부터** 다시 시작한다. 회복 중에는 취소할 것이 없다. 명치 꽂기도 같은 규칙을 쓴다(이전에는 멈췄다가 이어서 진행).

능력치가, 위 줄에 `Homing`이 보인다. 시각 이펙트는 없다. 계획에 없던 부분은 아래 구현 기본값으로 정했다. 바꾸려면 알려 달라.

- **등급**: 네티의 지도·에슈르의 마도서 Uncommon, 티그의 도전장·골디의 초대장·엘리스의 타로카드 Rare. Balance-0에서 다시 본다.
- **네티의 지도**: 층마다 한 번 공개되면 그 층이 끝날 때까지 유지된다. 공개된 층의 미니맵은 모든 방과 일반 통로를 그리고,
  비밀방은 표시(`H`, 골디 상점이면 `G`)만 하고 숨은 통로 선은 그리지 않는다. 이미 공개된 층에서도 사용할 수 있다(골드만 얻음).
- **에슈르의 마도서**: 유도는 발사 시점에 정해져 그 방에서 쏜 기본 공격 탄에만 붙는다. 분열탄과 샤샤의 항아리 물줄기는 유도하지
  않는다(24번 §9 "미정"). 그 탄이 이미 맞힌 적은 다시 맞힐 수 없으므로 대상에서 뺀다(24번 §4.2의 "방금 맞힌 적"을 넓힌 것).
  튕김(칸타의 팽이)이 대상을 정한 동안은 튕김이 우선한다.
- **티그의 도전장**: 도착하면 방 트리거를 기다리지 않고 바로 보스전을 시작한다. 시작방·보물방 등 전투가 없는 방에서도 쓸 수 있다.
  떠난 방이 전투 중이면 그건 내 잔상과 같이 남은 적이 사라지고(처치 미집계) 다음 진입 때 첫 웨이브부터 시작한다.
- **골디의 초대장**: 비밀방의 바뀐 상태는 생성 그래프의 방에 남아 같은 Run 동안 유지된다. 재고는 원래 골디 상점과 같은 규칙으로
  그 방의 콘텐츠 seed에서 추첨하고, 비밀방의 보물방형 보상(권능 3택1 포함)은 사라진다. 도착 위치는 비밀방 숨은 통로 하나의 안쪽
  진입점이고, 닫힌 비밀방에 들어가면 구덩이 진입과 같이 숨은 통로가 모두 열린다. 비밀방 안에서는 사용 불가·미소비다.
  **사용자 결정(2026-10-16, Play 확인 뒤)**: 계획의 "전투 중 사용 시 떠난 방 처리는 티그의 도전장과 같다"를 바꿔, 전투 중인 방에서는
  사용 불가·미소비다. 같은 확인에서 바뀐 비밀방의 상점지기가 시스트 그림으로 보이던 문제를 고쳤다(숨겨진 방에서 만든 상점지기가
  나중에 깨어날 때 기본 그림으로 덮던 문제).
- **엘리스의 타로카드**: 탄속 증감은 Range-0 규칙대로 사거리도 함께 바꾼다(사거리 = 체공 시간 × 탄속). 여러 장의 하락이 쌓여도
  탄속·사거리 배율은 0.1 아래로 내려가지 않는다. 추첨 번호는 Run 안의 타로카드 사용 순서(0부터)다.

### 4.4 교주의 권능(액티브)

트릭컬의 **교주의 권능**을 바탕으로 한 액티브 분류다.

- **방향 결정(2026-10-09)**: 방을 일정 수 클리어할 때마다 게이지가 1칸 차고, 차면 사용하는 아이작의 액티브 방식이다.
- **획득(같은 날 변경)**: 별도 선택 화면 대신 아이작처럼 **1층 시작방에 인접한, 열쇠 없이 들어가는 보물방**을 두고 그
  보물방에서 권능이 나올 수 있게 한다.
- 권능 후보는 원작의 찐짜천벌·날먹보호막·급발진·애착 담요·명치 꽂기·팝핀 스타 6종이다. 6종의 효과·필요 게이지·충전·
  교체·시작 보물방 3택1 중 1칸 보장은 아래 "교주의 권능 6종"에 확정했다.

  마지막 칸이 권능(`RARE` 가격)이고 들고 있는 권능과 같으면 구매 불가다. 고르거나 산 권능은 바로 슬롯에 들어가 빈 게이지로

- 산사모-순수(2026-10-19): 활발을 참고한 걷기 네 프레임과 독립 꽃 반동, 꽃 발사점 연결을 구현했다. 단독 검증 통과, Scene 미리보기·F1 소환 제공. 실제 Play 미술 검수 대기. [작업 기록](./art-prompts/sansamo-pure-motion.md).
- 쥬비. 지금은 추적형 적 스프라이트를 절반 크기로 쓴 플레이스홀더이고 그림자·날갯짓이 없다.
- 물줄기(샤샤의 항아리). 메시·셰이더·월드 입자 대표 효과를 구현했고 사용자 실제 Play 비교에서 개선을 확인했다(2026-10-13). 이 제작 방향은 채택했다. v4에서 발사구 분출·물안개·테두리 물방울로 물다운 형태를 보강했고, 전용 검사·회귀 배치 통과(종료 코드 0)와 사용자 수동 확인(Play, 캐릭터 가림)을 거쳐 수용했다(2026-10-18). [작업 기록](./art-prompts/shasha-realtime-v1/README.md).
- 폭발. 폭발 머핀이 스킬 폭발 스프라이트를 임시로 쓰고 있다. 쫄따구 사망 폭발과 폭발 상자까지 같은 연출을 쓸지는
  조각을 시작할 때 정한다.

함정 7종의 외형 원화도 만들어져 있다. Unity 연결은 Trap-0에서 하고, 장판·독가스의 화면 표현은 그때 정한다.

**이펙트 제작 방향 결정(2026-10-13)**: 새 효과·어색한 기존 효과는 메시·시간 변화 셰이더·독립 파티클 합성을 우선 검토한다.
현재 무난한 에르핀 저학년 등은 유지하고, 폭탄은 외형을 살린 발생·팽창·소멸 보강을 검토한다. 프레임 애니메이션은 필요한 효과에서 계속 사용한다.
샤샤에 대한 사용자 비교만으로 Motion-0 전체나 모든 경계·시너지의 검증을 완료 처리하지 않는다. 구체 기준은 [25번](./25-combat-effects-guide.md)을 따른다.

**21번에서 넘어온 잔여 항목**: 조각으로 잡지 않았고, 관련 조각을 할 때 함께 처리한다.

- 느린 탄과 관통의 재적중([24번 §4.3](./24-attack-modifier-contract.md)): 방식만 확정했다. 탄속을 낮추는 아이템을 만들 때 구현한다.
- 방어막 픽업(12번 확정 상세 효과의 방탄불괴용): 아직 없다. 만들 때 체력·방어막 합 15칸 상한을 따른다.
- 거대화 물약의 최대 스택: 2스택은 시험값이다. 아이템 스택 대신 스탯 상한을 두는 방식을 검토 중이다.
- 레비의 단도의 무적 표시 연출이 없다.
- 적별 넉백 무게, 골디 상점의 등급 기준·등장률, 멜룬카드 등급, 자원 특화 장애물 수치 같은 구현 기본값의 조정은
  Balance-0에서 한다.

## 5. 골드와 영구 엘리프

Run 화폐는 골드이고([21번 §3.7](./21-sixth-month-plan.md), Gold-0 완료), 엘리프는 Run 이후에도 남는 희귀 영구 화폐다.
엘리프는 아이작처럼 상점을 영구 업그레이드하는 데 쓰고, 상점이 일부 상품을 골드 대신 엘리프 가격으로 팔 수도 있다.
엘리프는 희귀하므로 엘리프 가격은 골드 가격보다 적은 개수다.

Elif-0에서 아래 항목을 계약 설계 메모로 확정한다. 획득·저장·사용 구현은 메모가 확정된 뒤의 조건부 범위이며, 메모 전에는
Backend·Prisma 계약을 만들지 않는다.

- 획득처(사용자 결정, 2026-10-09): **골드가 나오는 곳에서 5~10% 확률로 골드 대신 엘리프가 나온다**
  (시험 범위, 플레이로 조정). **아이시아의 지갑은 획득할 때 한 번만 추첨해 엘리프 0~4개 안팎을
  함께 준다**(골드 100을 1개씩 따로 추첨하지 않음). 지갑의 분포는 0개 40%·1개 30%·2개 15%·3개 10%·
  4개 5%(평균 약 1.0개)다. 남은 것: 정확한 확률과 Run당 기대 획득량, 랜덤코인·네티의 지도에도 적용할지.
- 저장: Run 종료 시 획득량을 결과 저장과 함께 서버에 반영하는 방식, `clientRunId` 재전송 중복 방지.
  Run 도중 사망·포기·중단 시 획득분 처리.
- 사용: 상점 영구 업그레이드 목록과 비용, 엘리프 가격 상품의 등장 규칙과 골드 대비 환율.
  Run 도중 엘리프로 구매할 때 서버 잔액과의 동기화·실패 처리.
- 영향: Unity DTO·Backend DTO/서비스·Prisma/seed·Web 표시·가격 표시·과거 전적.
- 영구 화폐가 생기더라도 열쇠·폭탄 없이 필수 보스 경로를 완료하는 원칙은 유지한다.

마요의 수집품 상자와 황금돌·시스트의 금고의 엘리프 드롭은 영구 화폐가 구현된 뒤에 후보로 추가한다
([21번 §6.1](./21-sixth-month-plan.md)). 멜룬카드의 엘리프 복제 허용 여부도 그때 정한다.

## 7. 검증

계층별 영향과 검증 원칙은 [21번 §9](./21-sixth-month-plan.md)의 Unity, Backend·Web 절을 그대로 따른다. 이번 달에 더해지는
것은 다음과 같다.

- 함정 Layout과 1층 층 생성은 여러 조각이 함께 쓰는 기반이므로 작업 중에도 회귀 묶음을 실행한다.
- 새 스펠·짱셈스펠·권능은 Backend `ITEM_CATALOG`와 Unity 카탈로그의 차이가 없어야 한다. 분류값을 추가하는 Power-0은
  Unity DTO·Web 표시·seed·API 문서까지 함께 확인한다.
- 새 스펠·짱셈스펠·권능·함정은 같은 조각에서 Game Scene 개발 패널(`F1`)로 바로 얻거나 배치할 수 있게 하고, 수동 확인
  항목에 패널 경로를 적는다.

### 실제 플레이와 경제 측정

- 서로 다른 seed 정상 Run 최소 3회로 층별 경제와 시간을 기록한다.
- 황금·다이아몬드 상자 개봉, 가짜 날개 비행, 멜룬카드 복제는 3층 기준 자연 등장 빈도가 낮다([21번 §3.1](./21-sixth-month-plan.md)).
  개발 패널의 상자 강제 생성 보조 Run으로 확인하고 정상 Run 비교에서 분리한다.
- 최소 1회는 열쇠·폭탄을 사용하지 않고 보스 경로를 끝까지 확인한다.
- 스펠·짱셈스펠 교체/사용, 비행·비행하지 않는 이동과 구덩이 우회, 탈출 후 재진입 재시작, 복제 후
  개별 개봉을 확인한다.
- 층별 자원 획득/소비·상자 등장/개봉·스펠 사용·상점 구매·아티팩트/패시브 획득·실제 시간을 기록한다.
- 개발 도구 사용 기록은 정상 경제/난이도 비교에서 분리한다. seed·콘텐츠 버전·오류 재현 조작을 남긴다.
- 검증기의 분포·가상 시간 테스트를 실제 Run 완료 증거로 취급하지 않는다.

전체 Run 자동 플레이나 모든 이벤트를 수집하는 텔레메트리는 별도 도구 후보다. 필요한 로컬 측정부터
확장하며 로깅 실패가 게임을 중단하지 않게 한다. 상자 강제 생성 같은 새 개발 도구의 계획·상태는 13번,
실제 메뉴·명령은 구현 후 개발 환경 문서에 기록한다.
