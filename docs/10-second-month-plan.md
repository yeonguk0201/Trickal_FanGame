## 1. 이 문서의 역할

첫 달에 Unity → Backend → DB → Web 데이터 파이프라인과 최소 Run 수직 슬라이스를 완성했다. 이 문서는 그 기반 위에 게임 콘텐츠를 MVP 범위까지 확장하는 실행 계획이다.

- 날짜는 작업의 우선순위를 정하기 위한 기준이며 절대적인 마감일이 아니다.
- 첫 달의 실제 속도를 기준으로 범위를 산정했다.
- 에셋(그래픽/사운드)은 임시 에셋을 유지하고 기능 완성을 우선한다.
- 필수 범위는 유지하고 목표·확장 범위의 아이템과 몬스터 수는 구현 속도에 따라 조정한다.
- 매주 마지막 날에 실제 소요 시간과 막힌 원인을 기록하고 다음 주 범위를 조정한다.

## 2. 첫 달 결과 요약

### 완료된 항목

- Phase 0~3 완료
- Unity → Backend → DB → Web 관통 검증 완료
- 플레이어 이동, 피격, 사망
- 기본 공격(투사체)
- 테스트 적 1종 (추적, 접촉 피해)
- 방 상태 흐름 (Waiting → Combat → Cleared)
- 2개 방 연결과 카메라 추적
- 보스 1종 (단순 패턴 1개)
- Run 시작/종료, 결과 전송
- Web 전적 조회

### 첫 달 속도 기준

- 1~3주차: 주당 1개 시스템 완성
- 4주차: 3일로 보스와 Run 연결 완료
- 가장 오래 걸린 문제: Unity 6 API 차이, 충돌 처리, 에셋 직접 제작

### 다음 달 전제

- 에셋은 임시 에셋 유지
- 기능 완성 우선, 폴리싱은 Phase 7로 연기
- 아이템/몬스터 수는 최소 필수 범위부터 구현

- 아이템 시너지 1개

- 아이템 10종
- 일반 몬스터 3종의 패턴과 조합 완성

### 확장 범위

- 일반 몬스터 5종

# 5. 5주차 — 아이템 시스템과 층 구조 뼈대

## 기간

2026-09-15(화) ~ 2026-09-21(월)

## 목표

아이템을 획득하면 플레이어의 능력이 실제로 변하는 시스템을 구현한다. 임시 콘텐츠로 3개 층의 이동 구조를 먼저 연결하고 캐릭터 선택 화면을 추가한다.

## 권장 진행 순서

```text
아이템 데이터 구조
  → 아이템 획득
  → 플레이어 스탯 적용
  → 아이템 드롭/보상
  → 3개 층 이동 뼈대
  → 캐릭터 선택 UI
  → Run에 캐릭터 기록
```

## 필수 작업

### Item 시스템

- [x] 아이템 데이터 구조 정의 (ID, 이름, 효과 타입, 값)
- [x] ScriptableObject 또는 데이터 테이블로 아이템 정의
- [x] 플레이어가 아이템을 보유하는 인벤토리 구조 구현
- [x] 아이템 획득 시 플레이어 스탯에 효과 적용
- [x] 테스트 아이템 2~3종 구현 (공격력 증가, HP 증가, 이동 속도 증가)
- [x] 동일한 아이템을 중복 획득할 수 있도록 구현
- [x] 아이템별 중첩 규칙 정의 (기본값은 가산, 예외와 상한은 아이템 데이터에 명시)

### Item ID와 Run 데이터 계약

- [x] DB `Item.id`와 Unity ScriptableObject의 `itemId`에 동일한 영문 식별자 사용
- [ ] ID는 출시 후 의미를 바꾸거나 재사용하지 않는 안정적인 키로 관리
- [x] 획득 순서 `order`는 첫 아이템을 1로 기록하고 중복 아이템도 별도 순서로 기록
- [x] `acquiredAt`은 Run 시작 후 경과시간을 기준으로 계산한 UTC ISO 8601 시각으로 기록
- [x] `startedAt <= acquiredAt <= endedAt` 검증
- [x] 존재하지 않거나 비활성화된 `itemId`는 API에서 `ITEM_NOT_FOUND`로 Run 전체를 거절
- [ ] 전송 실패가 게임 진행을 멈추지 않고 로그 또는 재전송 대상으로 남는지 확인

### Item 획득

- [x] 아이템 보상방과 보스 처치 후 아이템 드롭 구현
- [x] 각 층에 아이템 보상방 1개 배치
- [x] 1~2층 보스 처치 시 아이템 1개 확정 지급
- [x] 3층 최종 보스 처치 시에는 아이템 대신 Run 클리어 처리
- [x] 일반 전투방은 성장 아이템을 확정 지급하지 않고 회복 등 소규모 보상만 허용
- [x] 아이템 획득 시 UI 또는 Console로 확인
- [x] Run 상태에 획득 아이템 기록
- [x] 아이템 획득 순서 기록

### 층 구조 뼈대

- [x] 임시 방과 기존 적만 사용하여 1층 → 2층 → 3층 이동 가능
- [x] 층 이동 후 HP, 인벤토리, 아이템 효과, RunProgress 유지
- [x] 각 층의 일반 방, 보상방, 보스방 슬롯 정의

### 캐릭터 선택

- [x] 캐릭터 선택 씬 또는 UI 구현
- [x] 캐릭터 1종 선택 가능
- [x] 선택한 캐릭터로 Run 시작
- [x] Run 데이터에 characterId 기록
- [x] 향후 캐릭터 추가가 가능한 구조 확인

### MVP 보상 규칙

```text
일반 전투방 → 성장 아이템 없음, 소규모 보상은 선택
층별 보상방 → 아이템 1개 확정 (총 3회)
1~2층 보스 → 아이템 1개 확정 (총 2회)
3층 최종 보스 → Run 클리어
```

- 정상적인 클리어 Run에서는 총 5번의 아이템 획득 기회를 제공한다.
- 이미 보유한 아이템도 다시 등장할 수 있다.
- MVP에서는 아이템 선택 UI 없이 등장한 아이템을 직접 획득한다.
- 아이템 선택 시스템과 보상 풀 세분화는 필수 범위 완료 후 검토한다.

## 완료 조건

> 캐릭터를 선택하여 Run을 시작하고, 방을 클리어하면 아이템을 획득할 수 있다. 아이템을 획득하면 플레이어의 능력치가 실제로 변하고, Run 종료 시 획득한 아이템 목록이 기록된다.

## 선택 작업

- [ ] 아이템 획득 연출
- [ ] 아이템 설명 UI
- [ ] 캐릭터 선택 화면 스타일링

## 주간 회고

- 실제 작업 시간: 하루
- 가장 오래 걸린 문제: 크게 없음
- 다음 주에 반영할 점: 크게 없음

# 6. 6주차 — 아이템 확장과 시너지

## 기간

2026-09-22(화) ~ 2026-09-28(월)

## 목표

아이템 종류를 5종 이상으로 확장하고, 일부 아이템 조합에서 시너지가 발생하도록 구현한다.

## 권장 진행 순서

```text
아이템 효과 타입 확장
  → 아이템 5종 구현
  → 시너지 규칙 정의
  → 시너지 효과 구현
  → 시너지 발동 확인
```

## 필수 작업

### 아이템 확장

- [ ] 능력치 증가 아이템 2종 이상 (공격력, HP, 이동 속도, 공격 속도)
- [ ] 공격 변화 아이템 1종 이상 (투사체 크기, 투사체 개수, 관통)
- [ ] 특수 효과 아이템 1종 이상 (적 처치 시 효과, 피격 시 효과)
- [ ] 총 5종 이상 구현 완료

### 시너지

- [ ] 시너지 규칙 정의 (`MULTI_SHOT` + `PIERCE` 조합 사용)
- [ ] 아이템 조합 감지 로직 구현
- [ ] 시너지 효과 적용
- [ ] 시너지 발동을 Console 또는 UI로 확인

시너지 인수 조건:

- 두 아이템의 획득 순서와 관계없이 활성화된다.
- 중복 획득으로 같은 시너지가 여러 번 활성화되지 않는다.
- 활성화 후 생성된 모든 투사체에 관통 효과가 적용된다.
- 층 이동 후에도 활성 상태가 유지된다.
- Run 종료 기록에는 두 원본 아이템의 ID와 획득 순서가 각각 남는다.

### 아이템 밸런스

- [ ] 각 아이템의 효과 값 조정
- [ ] 아이템 간 효과가 중복 적용되는지 확인
- [ ] 극단적인 조합에서 게임이 깨지지 않는지 확인

## 완료 조건

> 5종 이상의 아이템을 획득할 수 있고, 특정 아이템 조합에서 시너지 효과가 발생한다. 아이템을 여러 개 획득하면 빌드가 점점 강해지는 것을 체감할 수 있다.

## 선택 작업

- [ ] 아이템 6~10종 추가
- [ ] 시너지 조합 2개 이상 추가
- [ ] 아이템 등급 또는 희귀도 구분
- [ ] 아이템 선택 시스템 (3개 중 1개 선택)

# 7. 7주차 — 몬스터 확장과 층 구성

```text
몬스터 2~3종 추가
```

- [ ] 원거리 공격 몬스터 1종
- [ ] 돌진 또는 특수 패턴 몬스터 1종

- [ ] 3개 층 구조 정의

- [ ] 층 클리어 후 다음 층 이동

- [ ] 층이 올라갈수록 몬스터 HP/공격력 증가
- [ ] 층이 올라갈수록 방당 몬스터 수 증가 또는 조합 변화

- [ ] RunProgress에 현재 층 기록

# 8. 8주차 — MVP 통합과 밸런스

## 기간

2026-10-06(화) ~ 2026-10-12(월)

## 목표

지금까지 구현한 모든 시스템을 연결하여 MVP 범위의 게임을 완성하고, 전체 플레이 흐름을 검증한다.

## 권장 진행 순서

```text
전체 흐름 연결
  → 반복 플레이 테스트
  → 버그 수정
  → 밸런스 조정
  → Run 데이터 검증
  → Web 전적 확인
```

## 필수 작업

### 통합 테스트

- [ ] 캐릭터 선택 → 1층 → 2층 → 3층 → 최종 보스 → 클리어 전체 흐름 확인
- [ ] 사망 Run과 클리어 Run 모두 정상 기록
- [ ] 아이템 획득과 빌드 변화가 Run 전체에서 유지
- [ ] Run 데이터에 캐릭터, 아이템, 도달 층, 처치 수, 플레이 시간 정확히 기록
- [ ] 1층 또는 2층에서 사망한 Run의 도달 층과 사망 원인 확인
- [ ] 동일한 아이템을 중복 획득한 Run의 개수와 획득 순서 확인

## 9. 일정이 밀릴 때의 축소 순서

일정이 예상보다 느릴 때는 다음 순서로 범위를 줄인다.

1. 방 배치 랜덤화를 제외한다.
2. 보스를 1종의 층별 강화형으로 통일한다.
3. 몬스터 수를 3종으로 유지하고 추가 몬스터를 제외한다.
4. 아이템 수를 5종으로 유지하고 추가 아이템을 제외한다.
5. 캐릭터 선택 화면의 스타일링을 제외한다.

다음 항목은 축소하지 않는다.

- 3개 층 진행
- 일반 몬스터 3종
- 아이템 5종과 시너지 1개
- 아이템 획득 시 능력 변화
- Run 데이터에 아이템 기록
- 층 진행과 보스 처치 흐름
- Run 결과 전송과 Web 조회
