## 1. 이 문서의 역할

첫 달에 Unity → Backend → DB → Web 데이터 파이프라인과 최소 Run 수직 슬라이스를 완성했다. 이 문서는 그 기반 위에 게임 콘텐츠를 MVP 범위까지 확장하는 실행 계획이다.

- 날짜는 작업의 우선순위를 정하기 위한 기준이며 절대적인 마감일이 아니다.
- 첫 달의 실제 속도를 기준으로 범위를 산정했다.
- 에셋(그래픽/사운드)은 임시 에셋을 유지하고 기능 완성을 우선한다.
- 필수 범위는 유지하고 목표·확장 범위의 아티팩트와 몬스터 수는 구현 속도에 따라 조정한다.
- 매주 마지막 날에 실제 소요 시간과 막힌 원인을 기록하고 다음 주 범위를 조정한다.

## 3. 둘째 달의 최종 완료 조건

2026-10-12까지 다음 흐름을 반복해서 플레이할 수 있는 상태로 만든다.

```text
캐릭터 선택
  → 3개 층 진행
  → seed로 생성된 층별 격자 탐색
  → 일반방 전투와 보물방 아티팩트 획득
  → 층 보스 처치
  → 최종 보스 클리어 또는 사망
  → Run 결과 전송
  → Web에서 전적 확인
```

### 필수 범위

- 캐릭터 선택 UI (1종 선택 가능)
- 3개 층
- 층당 6~8개의 상하좌우 격자형 방
- 시작방·일반방·보물방·보스방과 층당 보물방 최소 1개
- 일반 몬스터 3종
- 보스 1종 (층별 강화 또는 최종 보스 변형 허용)
- 아티팩트 5종
- 아티팩트 시너지 1개

### 목표 범위

- 아티팩트 10종
- 일반 몬스터 3종의 패턴과 조합 완성
- 설정 변경만으로 층당 8~12방까지 확장 가능한 생성 계약

### 확장 범위

- 일반 몬스터 5종
- 보스 2종
- 추가 Room Prefab과 Encounter 변형
- 상점과 엘리프 경제
- 열쇠와 잠긴 보물방, 이벤트방·비밀방, 미니맵

# 5. 5주차 — 아티팩트 시스템과 층 구조 뼈대

## 기간

2026-09-15(화) ~ 2026-09-21(월)

## 목표

아티팩트를 획득하면 플레이어의 능력이 실제로 변하는 시스템을 구현한다. 임시 콘텐츠로 3개 층의 이동 구조를 먼저 연결하고 캐릭터 선택 화면을 추가한다. 기존 코드와 API의 `Item`, `itemId`는 안정 계약으로 유지한다.

## 권장 진행 순서

```text
Item 데이터 구조
  → 아티팩트 획득
  → 플레이어 스탯 적용
  → 아티팩트 드롭/보상
  → 3개 층 이동 뼈대
  → 캐릭터 선택 UI
  → Run에 캐릭터 기록
```

## 필수 작업

### 아티팩트 시스템 (`Item` 코드 계약)

- [x] 아티팩트 데이터 구조 정의 (ID, 이름, 효과 타입, 값)
- [x] ScriptableObject 또는 데이터 테이블로 아티팩트 정의
- [x] 플레이어가 아티팩트를 보유하는 인벤토리 구조 구현
- [x] 아티팩트 획득 시 플레이어 스탯에 효과 적용
- [x] 테스트 아티팩트 2~3종 구현 (공격력 증가, HP 증가, 이동 속도 증가)
- [x] 동일한 아티팩트를 중복 획득할 수 있도록 구현
- [x] 아티팩트별 중첩 규칙 정의 (기본값은 가산, 예외와 상한은 아티팩트 데이터에 명시)

### Item ID와 Run 데이터 계약

- [x] DB `Item.id`와 Unity ScriptableObject의 `itemId`에 동일한 영문 식별자 사용
- [x] ID는 출시 후 의미를 바꾸거나 재사용하지 않는 안정적인 키로 관리 (06-database.md 섹션 42 참조, 2026-09-02)
- [x] 획득 순서 `order`는 첫 아티팩트를 1로 기록하고 중복 아티팩트도 별도 순서로 기록
- [x] `acquiredAt`은 Run 시작 후 경과시간을 기준으로 계산한 UTC ISO 8601 시각으로 기록
- [x] `startedAt <= acquiredAt <= endedAt` 검증
- [x] 존재하지 않거나 비활성화된 `itemId`는 API에서 `ITEM_NOT_FOUND`로 Run 전체를 거절
- [x] 전송 실패가 게임 진행을 멈추지 않고 로그 또는 재전송 대상으로 남는지 확인 (Play Mode 검증: 게임 미중단, save failed 로그, Retry 버튼 표시, 2026-09-02)

### 아티팩트 획득

- [x] 보물방과 보스 처치 후 아티팩트 드롭 구현
- [x] 각 층에 보물방 1개 배치
- [x] 1~2층 보스 처치 시 아티팩트 1개 확정 지급
- [x] 3층 최종 보스 처치 시에는 아티팩트 대신 Run 클리어 처리
- [x] 일반 전투방은 성장 아티팩트를 확정 지급하지 않고 회복 등 소규모 보상만 허용
- [x] 아티팩트 획득 시 UI 또는 Console로 확인
- [x] Run 상태에 획득 아티팩트 기록
- [x] 아티팩트 획득 순서 기록

### 층 구조 뼈대

- [x] 임시 방과 기존 적만 사용하여 1층 → 2층 → 3층 이동 가능
- [x] 층 이동 후 HP, 인벤토리, 아티팩트 효과, RunProgress 유지
- [x] 각 층의 일반방, 보물방, 보스방 슬롯 정의

### 캐릭터 선택

- [x] 캐릭터 선택 씬 또는 UI 구현
- [x] 캐릭터 1종 선택 가능
- [x] 선택한 캐릭터로 Run 시작
- [x] Run 데이터에 characterId 기록
- [x] 향후 캐릭터 추가가 가능한 구조 확인

### MVP 보상 규칙

```text
일반 전투방 → 성장 아티팩트 없음, 소규모 보상은 선택
층별 보물방 → 아티팩트 1개 확정 (총 3회)
1~2층 보스 → 아티팩트 1개 확정 (총 2회)
3층 최종 보스 → Run 클리어
```

- 정상적인 클리어 Run에서는 총 5번의 아티팩트 획득 기회를 제공한다.
- 이미 보유한 아티팩트도 다시 등장할 수 있다.
- MVP에서는 아티팩트 선택 UI 없이 등장한 아티팩트를 직접 획득한다.
- 아티팩트 선택 시스템과 보상 풀 세분화는 필수 범위 완료 후 검토한다.

## 완료 조건

> 캐릭터를 선택하여 Run을 시작하고, 방을 클리어하면 아티팩트를 획득할 수 있다. 아티팩트를 획득하면 플레이어의 능력치가 실제로 변하고, Run 종료 시 획득한 아티팩트 목록이 기록된다.

## 선택 작업

- [ ] 아티팩트 획득 연출
- [ ] 아티팩트 설명 UI
- [ ] 캐릭터 선택 화면 스타일링

## 주간 회고

- 실제 작업 시간: 하루
- 가장 오래 걸린 문제: 크게 없음

# 6. 6주차 — 아티팩트 확장과 시너지

## 기간

2026-09-22(화) ~ 2026-09-28(월)

## 목표

아티팩트 종류를 5종 이상으로 확장하고, 일부 아티팩트 조합에서 시너지가 발생하도록 구현한다.

**상태: Phase G 확장 범위까지 완료.** 활성 아티팩트 10종, 복합·조건부 효과, 등급별 가중치 드롭,
최대 스택 후보 제외와 회복 대체 보상, `MULTI_SHOT + PIERCE` 호환 경로가 동작한다. (`Verify Phase G-7 Rewards and Full Run` Edit Mode·Play Mode 통과, 2026-09-01)

## 권장 진행 순서

```text
아티팩트 효과 타입 확장
  → 아티팩트 5종 구현
  → 시너지 규칙 정의
  → 시너지 효과 구현
  → 시너지 발동 확인
```

## 필수 작업

### 아티팩트 확장

- [x] 능력치 증가 아티팩트 2종 이상 (공격력, HP, 이동 속도, 공격 속도)
- [x] 공격 변화 아티팩트 1종 이상 (투사체 크기, 투사체 개수, 관통)
- [x] 특수 효과 아티팩트 1종 이상 (적 처치 시 효과, 피격 시 효과)
- [x] 총 5종 이상 구현 완료

### 시너지

- [x] 시너지 규칙 정의 (`MULTI_SHOT` + `PIERCE` 조합 사용)
- [x] 아티팩트 조합 감지 로직 구현
- [x] 시너지 효과 적용
- [x] 시너지 발동을 Console 또는 UI로 확인

시너지 인수 조건:

- 두 아티팩트의 획득 순서와 관계없이 활성화된다.
- 중복 획득으로 같은 시너지가 여러 번 활성화되지 않는다.
- 활성화 후 생성된 모든 투사체에 관통 효과가 적용된다.
- 층 이동 후에도 활성 상태가 유지된다.
- Run 종료 기록에는 두 원본 아티팩트의 ID와 획득 순서가 각각 남는다.

### 아티팩트 밸런스

- [x] 각 아티팩트의 효과 값 조정
- [x] 아티팩트 간 효과가 중복 적용되는지 확인
- [x] 극단적인 조합에서 게임이 깨지지 않는지 확인

## 완료 조건

> 5종 이상의 아티팩트를 획득할 수 있고, 특정 아티팩트 조합에서 시너지 효과가 발생한다. 아티팩트를 여러 개 획득하면 빌드가 점점 강해지는 것을 체감할 수 있다.

## 선택 작업

### Phase F — seed 기반 격자형 층 생성

Phase F-1~F-4에서는 층마다 3개 방인 고정 선형 그래프로 데이터 분리, 바인딩, 재방문 상태와 Run seed 수명주기를 검증했다. Phase F-5는 이 기반을 층당 6~8개의 상하좌우 격자 그래프로 교체하는 작업이며, 완료 후에는 선택 작업이 아니라 둘째 달 MVP의 필수 층 구조가 된다.

생성기는 방 내부 장애물이나 spawn point를 임의 좌표에 만들지 않는다. seed에 따라 방의 격자 좌표·연결·종류와 검증된 RoomDefinition/Prefab/Encounter 선택을 바꾸며, 현재처럼 여러 spawn point에 같은 적 Prefab을 반복 배치하는 Encounter 정책은 이번 최소 범위에서 유지한다.

Phase F-5 구현을 위해 기존 Room 파일 전체를 먼저 이동하지 않는다. 새 책임은 [프로젝트 구조](./08-project-structure.md)에 맞춰 배치하되, 기존 Unity 파일을 옮겨야 한다면 파일과 `.meta`를 함께 이동하여 GUID와 직렬화 참조를 보존한다.

```text
전체 흐름 연결

  → Web 전적 확인
```

## 9. 일정이 밀릴 때의 축소 순서

일정이 예상보다 느릴 때는 다음 순서로 범위를 줄인다.

1. Room Prefab과 Encounter 변형 수를 최소화하고 검증된 기본형을 재사용한다.
2. 방 수 범위를 층당 6개로 고정하되 생성 설정은 8~12개까지 확장 가능하게 유지한다.
3. 보스를 1종의 층별 강화형으로 통일한다.
4. 몬스터 수를 3종으로 유지하고 추가 몬스터를 제외한다.
5. 아티팩트 수를 5종으로 유지하고 추가 아티팩트를 제외한다.
6. 캐릭터 선택 화면의 스타일링을 제외한다.

다음 항목은 축소하지 않는다.

- 3개 층 진행
- seed 기반 상하좌우 격자 생성과 시작방·보물방·보스방 보장
- 일반 몬스터 3종
- 아티팩트 5종과 시너지 1개
- 아티팩트 획득 시 능력 변화
- Run 데이터에 아티팩트 기록
- 층 진행과 보스 처치 흐름
- Run 결과 전송과 Web 조회
