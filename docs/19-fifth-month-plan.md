## 1. 이 문서의 역할

넷째 달에는 화면 흐름, 전투 HUD, Room Profile·Template, Encounter, 일반 적 3종과 층별 보스,
아티팩트·스펠 선택 보상을 완성했다. 다섯째 달에는 반복 플레이에서 드러나는 다음 문제를 해결한다.

1. 방 내부가 비어 있거나 고정 기둥 하나뿐이라 같은 크기의 방이 비슷하게 느껴진다.
2. Encounter가 조합 단위로만 선택되고 웨이브당 1~3마리여서 같은 방의 적 구성이 자주 반복된다.
3. 방 난이도라는 개념이 없어 층 안에서 쉬운 방과 어려운 방의 흐름을 설계할 수 없다.
4. 열쇠·폭탄·엘리프 같은 탐색 자원이 없어 보스 직행과 탐색 사이의 선택이 약하다.
5. 층당 6~8방에 특수방이 보물방뿐이라 층 구조의 변화가 적다.

이번 달은 **탐색 자원 → 파괴 가능한 장애물과 Layout → SpawnPoint 후보와 방 난이도 →
특수방과 층 규모 확장** 순서로 진행한다. 방 내부는 계속 사람이 설계한 Layout을 기준으로 하고,
정해진 후보 안에서만 제한적으로 랜덤화한다.

## 2. 시작 시점의 확정 기반

### 완료된 게임 흐름

- 타이틀 → 로컬 프로필 → 홈 → 캐릭터 선택 → Run → 결과의 Frontend 흐름
- 3층 Run, 층당 6~8개의 seed 기반 격자형 방, 보스 최소 거리 3의 막다른 방 배치
- 시작방·일반 전투방·보물방·보스방
- Small·Basic·Wide·Tall·Large Room Template, 고정 기둥 Template, 층별 보스방 Template
- Template과 분리된 Encounter 계약, 2웨이브, 역할 기반 SpawnPoint 해석과 안전거리
- 추적형·원거리형·돌진형과 고속형·저격형 변형, 층별 보스 3종
- 반 칸 단위 플레이어 HP와 피해 등급, 적 HP 10배 스케일
- 아티팩트·스펠 통합 후보 3개 중 1개 선택 보상
- 재방문 시 웨이브·보상 상태 보존과 중복 지급 방지

### 이번 달의 제품 방향

- 방 내부 지형과 SpawnPoint는 임의 좌표에 흩뿌리지 않고 Layout에 미리 설계한다.
- 적 구성은 Layout·SpawnPoint 배치 역할·Encounter 후보의 적합성을 확인한 뒤 선택한다.
- 같은 Run seed와 콘텐츠 버전에서 Layout·장애물 드롭·Encounter·스폰 후보 선택을 재현한다.
- 소모 자원이 없어도 필수 진행 경로는 항상 완료할 수 있다.
- 탐색 자원과 방 상태는 Run 한정이며, Backend와 Web 계약은 필요한 경우에만 확장한다.
- 기존 Room·Encounter·장애물 안정 ID의 의미를 바꾸거나 재사용하지 않는다.

## 3. 다섯째 달 최종 완료 조건

2027-01-04까지 다음 흐름을 한 게임 안에서 반복할 수 있어야 한다.

```text
Run 시작
  → 장애물 배치가 다른 방에서 전투
  → 장애물을 부수며 체력·SP·엘리프·열쇠·폭탄 획득
  → 시작방에서 멀수록 어려운 방이 나올 확률이 높은 층 진행
  → 열쇠로 잠긴 방을 열거나 폭탄·구덩이로 비밀방 발견
  → 보스 처치 후 다음 층
  → 클리어 또는 사망
```

### 플레이 경험 완료 조건

- 같은 크기의 방이라도 장애물 Layout에 따라 이동 경로와 공격 판단이 달라진다.
- 같은 방 Layout이라도 스폰 위치별 후보 때문에 적 구성이 Run마다 달라진다.
- 층 안에 쉬운 방과 어려운 방이 섞이고, 먼 방일수록 어려운 방이 나올 확률이 높다.
- 장애물 파괴와 전투 드롭으로 얻은 자원을 선택 경로에 쓸 수 있다.
- 적이 장애물에 끼어 전투가 멈추거나 방을 클리어할 수 없는 상황이 없다.
- 전체 Run을 여러 seed로 완료하며 자원·보상·방 상태의 중복 지급이나 재추첨이 없다.

# 7. 확정 규칙

## 7.1 장애물 (2026-09-28)

- 장애물은 플레이어·적·투사체·돌진을 모두 막는다.
- 기본적으로 플레이어 공격과 폭탄으로만 파괴된다. 적 투사체·돌진 등 다른 주체의 파괴는
  보스 패턴처럼 명시한 예외에서만 허용한다. 기존 부스러기 크림·반죽 장애물의 HP 기반 파괴와
  보스 접촉 파괴는 이 예외로 유지한다.
- 파괴는 피해량이 아닌 타격 횟수로 판정한다. 기본 장애물은 플레이어 공격 5타에 파괴되고,
  공격력 증가는 필요 타격 수를 줄이지 않는다. 폭탄은 타격 수와 관계없이 즉시 파괴한다.
  후속 장애물은 종류별로 필요 타격 수를 따로 정할 수 있다.
- 장애물은 파괴 시 아이템을 드롭할 수 있다. 드롭 확률은 장애물 종류별로 1~5% 범위에서 정하고
  기본 장애물은 3%다. 드롭이 발생하면 아래 가중치로 후보 하나를 고른다.

  | 후보                | 가중치 |
  | ------------------- | -----: |
  | 체력 회복           |    25% |
  | SP                  |    25% |
  | 열쇠                |    10% |
  | 폭탄                |     8% |
  | 엘리프              |    30% |
  | 비밀방 통로(구덩이) |     2% |

- 후속 장애물 종류를 추가하면 장애물마다 드롭 후보를 나눠 맡기고 확률을 다시 조정한다.
  드롭 표는 장애물 종류별 데이터로 두어 이 조정을 코드 수정 없이 할 수 있게 한다.
- 드롭 판정은 방 seed와 콘텐츠 버전으로 재현하고, 드롭은 장애물당 한 번만 생성한다.
- 비밀방 통로는 파괴된 장애물 자리에 구덩이로 나타나며 해당 층 비밀방으로 이어진다.
  폭탄 벽 파괴와 함께 비밀방 진입 방식 두 가지 중 하나다.
- `1 × 1` 유닛 장애물을 기본 단위로 만들고, 여러 칸 형태는 1칸 장애물의 조합으로 구성한다.
- 기존 `central-pillar`(`3 × 3`, 파괴 불가)는 안정 ID와 의미를 바꾸지 않고 고정 지형 예외로 유지한다.
- 파괴 상태는 `RoomRunState`에 보존해 재방문 시 되살아나거나 다시 추첨되지 않는다.

## 7.2 SpawnPoint와 스폰 위치별 후보 (2026-09-28)

- SpawnPoint는 장애물 배치와 함께 Layout마다 따로 소유한다. 장애물 Collider 안과 필수 통로에는
  둘 수 없고, 원거리 역할 지점은 전투 영역으로의 사선을 확보해야 한다.
- SpawnPoint에 후방 사격·근접 압박·돌진 경로 같은 배치 역할을 지정한다.
- Encounter 슬롯은 한 역할 대신 가중치가 있는 후보 적 목록을 가질 수 있다. Template은 위치와
  배치 역할만, Encounter는 적 후보만 소유하는 경계를 유지한다.
- 적 종류와 SpawnPoint를 독립적으로 추첨하지 않고, Layout·Encounter·배치 역할의 적합성을 확인해 선택한다.
- 후보 선택은 방 seed와 콘텐츠 버전으로 결정하고 선택 결과를 생성 노드에 남겨 재방문 시 재추첨하지 않는다.

## 7.3 위협 점수와 방 난이도 (2026-09-28)

- 적 역할마다 위협 점수를 둔다. 점수는 런타임에 적을 채우는 예산이 아니라 Encounter 난이도
  검증에 사용한다. 스폰 위치별 후보가 만드는 최소·최대 합계가 선언한 난이도 범위를 벗어나면 검증이 실패한다.
- 방 난이도는 Encounter 난이도에 장애물·함정에 따른 Layout 보정을 더해 정한다.
- 층마다 허용 난이도 범위를 둔다.
- 시작방에서 멀수록 높은 난이도가 선택될 **확률만** 높인다. 가까운 방도 어려울 수 있고 먼 방도
  평이할 수 있으며, 거리로 난이도를 고정하지 않는다.
- 엘리트 적은 후속 추가 후보다. 위협 점수 체계는 엘리트를 나중에 넣을 수 있게 역할별 값으로 설계한다.

## 7.4 적 수와 층 규모 (2026-09-28)

- 일반 전투방 적 수는 현재 방 전체 최대 4마리 정도에서 2~7마리 범위로 늘리는 것을 목표로 한다.
  정확한 범위는 장애물 Layout 플레이테스트 후 확정한다.
- 층당 방 수는 현재 6~8개에서 특수방(상점·잠긴 보물방·비밀방) 추가와 함께 늘린다.

| 일부 SpawnPoint  | 선택한 Encounter에 적합한 지점 또는 spawn group을 랜덤 활성화 |

- [ ] Room Profile의 방 크기·카메라 계약과 연결되는 수작업 Room Layout을 구성한다. (Obstacle-2)
- [ ] 좁은방·넓은방·가로/세로 일자방·ㄱ자방·ㄴ자방·초대형 방을 Room Template 후보로 만들고,

- [ ] 직사각형이 아닌 방은 하나의 연결된 이동 영역과 카메라 경계, Encounter 영역, 미니맵
      실루엣을 함께 제공한다.
- [ ] 세로로 긴 방 한쪽에 작은 방 두 개가 연결되는 구성을 실험한다. 방향당 연결 하나 대신
      `left-upper`, `left-lower` 같은 안정 port ID를 사용하고 문 슬롯·안전 진입점·미니맵 선도 같은
      포트를 참조하게 한 뒤 기존 단일 문 방과의 호환 방식을 정한다.
- [ ] 한 화면에 다 들어오지 않는 긴 방·초대형 방에서는 카메라가 플레이어를 따라가되 방 경계
      밖을 비추지 않도록 제한하고, 방 전환 시 다음 방의 카메라 규칙으로 부드럽게 넘긴다.
- [x] 직사각형 Small·Basic·Wide·Tall·Large는 14주차의 축별 카메라 계약으로 먼저 구현한다. (Room-6 Unity 배치 카메라·Prefab 검증, 2026-09-16)

- [ ] 같은 방 크기와 적 조합으로 빈 방, 기둥이 있는 방, 고정 함정이 있는 방을 비교한다.

- [ ] SpawnPoint에 후방 사격·근접 압박·돌진 경로 확보 등의 배치 역할을 지정한다. (Spawn-1)

## 11. 일정이 밀릴 때의 축소 순서

다음 순서로 범위를 줄인다.

1. Room Layout 확장 후보와 병행 UX를 제외한다.
2. 상점(Special-4)을 제외한다.
3. 구덩이 통로를 제외하고 비밀방은 폭탄 벽 파괴 진입만 유지한다.
4. Floor-1 층 규모 확장을 제외하고 기존 6~8방에 특수방을 넣는다.
5. 장애물 Layout 수를 방 크기별 1종으로 줄인다.

다음 항목은 축소하지 않는다.

- 드롭 후보 자원의 획득·보유·Run 종료 초기화
- 파괴 가능한 장애물과 재방문 상태 보존
- 적이 장애물에 끼어 방 클리어가 막히지 않는 대응
- 스폰 위치별 후보와 seed 재현
- 방 난이도와 거리 가중 선택
- 소모 자원 없이 필수 진행 경로 완료 보장
- 자원·보상·방 상태의 중복 지급 방지와 전체 Run 회귀 검증
