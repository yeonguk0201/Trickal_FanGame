# 크레용사용 대쉬 검흔 — 실시간 시안 v3

후속 외부 제작 비교(2026-11-23): 같은 8프레임 참고 이미지로 만든
[Blender 시안 v1](./crayon-blender-v1/README.md)은 별도 원본·렌더로 관리한다.
아래 Unity v3의 구현·검증 이력과 구분하며, Blender 시안은 아직 게임에 연결하거나 미술 승인하지 않았다.

## 목적과 사용처

- 28번 계획 §10.4의 검흔을 Unity 적용 전에 검수하기 위한 독립 시안(2026-11-23).
- v3는 사용자에게 제시한 8프레임 이미지 시안의 은백색 검광을 재료로 사용하고 사각 메시·셰이더·명시적 시계로 절단 진행·섬광·파편·소멸을 제어한다.
- 게임 이벤트·보스 Prefab·대쉬·피해 판정에는 연결하지 않았다. 실제 판정 크기도 아직 정하지 않았다.

## 제작 구성

| 레이어 | 제작 방식 | 방향·크기 | 시간·표시 |
| --- | --- | --- | --- |
| 빨간 예고 | 작은 반투명 빨간 띠, 내부 알파 0.12·테두리 최대 합산 0.26 | 검흔 중심 고정, 공격 그림 길이의 56%, 폭 영역의 20% | 0~0.62초 |
| 검은 절단흔 | 가늘고 고정된 폭의 검은 흔적, 작은 각진 가장자리 | 길이 영역 6.2, 폭 영역 2.4 월드 단위. 실제 검은 폭은 중앙 약 0.2 | 한쪽 끝에서 반대 끝까지 0.048초 만에 긋는다. 옆으로 벌어지지 않음 |
| 은백색 검광 원화 | 8프레임 시안 중 완결된 다섯 번째 형태를 붓 질감 재료로 사용 | 원화의 대각선을 UV에서 보정한 뒤 효과 방향으로 회전 | 같은 절단 전선을 따라 드러난 뒤 유지·침식·감쇠 |
| 날카로운 섬광 | 긴 바늘형 검광, 이동하는 절단 끝의 빛, 타격 순간 교차 섬광 | 원화와 별도 레이어, 흰색·차가운 은백색 | 베는 순간 강하고, 발생 후 0.16초까지 소멸 |
| 은빛 파편 | 결정적 선분 거리장, 각 위치의 절단 시각 뒤 방출되는 12개 직선 파편 | 소용돌이·회전·가지 번개 없음 | 같은 시계에서 위치 계산, 되감기 때 동일 상태 |

- 방향 버튼: 좌상→우하(-40도), 우상→좌하(-140도). 각도 슬라이더로 다른 방향도 비교한다.
- 프리뷰의 예고 0.35초·도약 0.17초·도착 후 0.1초는 타이밍 참고이며, 보스·플레이어는 정지 원화다.
- 실제 바닥 스프라이트와 기존 캐릭터 원화로 합성한다. 캐릭터는 임시 비교 크기이므로 최종 런타임 스케일 승인 자료는 아니다.
- 짧은 경로·벽 맞춤·타격 판정·추적·연속 대쉬·황금 페이즈는 미구현이다.

## 미리보기

- Edit Mode: `Trickal Fan Game > Effects > Preview Crayon Hero Rift` → `Open / reset Scene preview`.
- 반복 재생, 속도, 시간 이동, Warning/Cut/Peak/Fade 정지, 공격 그림 길이·폭·각도와 예고 크기 비율, 5개 레이어·참고 원화 표시를 제공한다.
- 원본 Scene과 별개의 Preview Scene을 사용한다. 창 종료·Play 전환·스크립트 리로드에서 자원과 콜백을 정리한다.
- `CrayonRiftVisual.Configure`·`RenderAt`과 같은 셰이더를 Scene 뷰와 배치 렌더에서 공유한다. 입자나 외부 시간에 의존하지 않는다.
- 배치 진입점: `TrickalFanGame.Editor.CrayonRiftPreview.VerifyAndExportBatch`.
- 출력: `output/crayon-slash-v3/frame-000.png`~`frame-084.png`(50fps, 960×640). `-riftOutput <절대 경로>`로 다른 폴더를 지정할 수 있다. 정지 PNG는 보조 자료이고 실시간 미리보기는 별도 창이다.

## 원화 반입과 v3 변경 근거

- 사용자 피드백: 중앙이 벌어지는 연출과 소용돌이를 제거하고, 칼로 한쪽 끝부터 쫙 가르는 움직임·날카로운 빛을 원했다. 이어서 생성한 8프레임 이미지를 “나쁘지 않은걸”이라고 평가하고 이를 토대로 Unity 미리보기 제작을 요청했다. 게임 적용은 명시적으로 제외했다.
- 생성 이력: built-in imagegen으로 작은 반투명 빨간 예고 → 끝에서 끝으로 긋는 은백색 검광·가느다란 검은 절단흔 → 잔광 소멸의 4×2 시안을 생성했다. 새로 이미지를 생성하지 않고 이 원화를 반입했다.
- 원본: `C:/Users/yeonguk/.codex/generated_images/01a20422-5898-73b3-9b47-a9c25ee678e5/exec-ba279528-4f62-4343-b0d0-8b9b2bdeb053.png`.
- 저장본: `game/Assets/Editor/CrayonSlashConcept-v1.png` 및 `.meta`. Editor 폴더의 검수용 재료로 보존해 플레이어 빌드의 원화로 등록하지 않는다. 이후 생성 도구 기본 경로에 의존하지 않는다.
- 1774×887 RGBA 원본은 셀 너비가 정수로 나뉘지 않고 프레임별 배치도 달라 그대로 8프레임 애니메이션으로 재생하지 않는다. 완결된 다섯 번째 셀(UV x 0~0.25, y 0~0.5)을 안전 여백 안에서만 샘플링한다. 새 형태를 확대해 열지 않고, 절단 전선과 소멸 마스크가 원화를 드러내고 지운다.
- 미리보기는 `AssetDatabase`로 원화를 주입한다. 게임 코드에서 PNG를 자동 로드하거나 공격 이벤트를 등록하지 않는다.

## 검수와 적용 상태

- v1: 자동 검증과 42프레임 렌더는 통과했지만 사용자가 외형을 거절했다. 파형처럼 보이는 검흔, 같은 크기의 예고·공격 그림을 폐기한다.
- v2 근거: 사용자 첨부 `우주를 가르는 보랏빛 균열.png`의 검은 열린 공간·보랏빛 휘감김·날카로운 긴 찢김을 참고했다. 첨부 자체를 텍스처로 사용하지 않는다. 배경 굴절을 구현한 것은 아니며 외곽 흐름은 자체 셰이더 표현이다.
- v2의 예고는 공격 그림보다 작게 독립 조절한다. 실제 판정은 아직 연결하지 않았으며 향후 예고 범위와 일치하도록 별도 구현해야 한다.
- v2 검증: 중간본은 원본 프로젝트에서 `CrayonRiftPreview.VerifyAndExportBatch` 통과(`output/crayon-rift-v2-main.log`, 종료 0). 외곽 흐름 최종 조정 때 원본 프로젝트가 다른 배치로 잠겨, 59개 참고 에셋과 같은 시안 코드만 복사한 `output/crayon-rift-review-project`에서 최종 렌더를 수행했다(`output/crayon-rift-v2-isolated-final.log`, 종료 0). 작은 예고·레이어 독립 토글·시간 전환·되감기 검사와 85프레임 출력을 통과했다. 저장소·임시 프로젝트 셰이더의 SHA-256 일치를 확인했다.
- 대표 프레임에서 작은 예고와 큰 검은 틈·은보라 외곽 흐름을 확인했다. 미리보기 GIF는 Unity 출력 프레임을 그대로 묶은 보조 자료다. 사용자 미술 승인으로 간주하지 않는다.
- v2는 이후 사용자 요청으로 폐기한 형태다. 위 검증 기록은 v2 이력이며 v3의 검증 결과가 아니다.
- v3 최종 검증: `CrayonRiftPreview.VerifyAndExportBatch`를 같은 코드·원화·임포트 메타의 독립 Unity 프로젝트에서 실행해 통과했다(`output/crayon-slash-v3-reviewed.log`, Unity 6000.3.22f1 종료 0). C#·셰이더 컴파일, 예고 크기 분리·레이어 독립 토글·시간 전환·되감기 및 85프레임 렌더를 확인했다. 소스 3개·원화·원화 meta의 SHA-256이 저장소와 동일함을 확인했다.
- v3 중간 발견과 수정: 셰이더의 예약어 충돌을 수정했고, 원화 meta를 현재 TextureImporter serializedVersion 13·RGBA 알파·sRGB·비압축 설정으로 맞춰 검광이 검게 임포트되는 문제를 해결했다. 기존 원화 GUID를 유지했다.
- v3 미술 확인: `frame-032.png`(절단 진행), `frame-034.png`(최대 검광), `frame-051.png`(소멸), `silver-artwork-only.png`(검광 단독)에서 시안 질감·방향·가는 절단흔·소멸을 확인했다. GIF는 이 Unity 출력 프레임을 그대로 재생한다. 사용자 미술 검수는 대기다.
- 사용자 미술 검수 대기. 실제 Scene 뷰 조작·창 생명주기 및 실제 Play 검수는 미확인이다.
- 최종 게임 연결 전 위치·방향·실제 판정·벽·여러 크기에서 다시 확인한다. Boss-Pattern-1 완료로 처리하지 않는다.
