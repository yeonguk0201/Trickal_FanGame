# 용사용 대기 기준 공격 시안 v2

2026-10-21. 사용자 미술 검수 대기. 게임 미적용.

범위: 기본 용사용 일반 공격·대쉬·내려찍기, 황금 용사용 내려찍기. 각 4자세, 총 16개 분리 PNG.
대기 원본 2장도 비교를 위해 보존했다. 이전 onehand-v1 및 진행 중이던 다른 변경은 수정하지 않았다.

## 보기

- `connected-preview.gif`: 네 종류의 대기 → 동작 → 대기를 동시에 반복한다. 각 칸 왼쪽은 기존 대기, 오른쪽은 새 동작이다.
- `comparison.png`: 타격 자세의 나란히 비교.
- `preview-standalone.html`: 이미지가 내장된 독립 HTML. 로컬 브라우저에서 파일을 열면 서버 없이 재생·정지·다음 자세·속도·시점·좌우 반전·대기 겹치기·배경·배율을 조작할 수 있다.
- `preview.html`: 이미지와 등록 정보를 별도로 읽는 작은 버전. 같은 폴더를 유지한다.

내장 브라우저는 127.0.0.1 로컬 서버 연결에 실패했다. 브라우저 조작 검증 완료로 기록하지 않는다.
GIF와 대표 합성 PNG를 직접 검사했고, HTML JavaScript 구문 검사와 내장 이미지 존재 검사를 수행했다.

## 제작 및 기준

내장 image_gen 도구로 제작했다. 기준은 `Boss_크레용사용.png`와 `CrayonHero_Awakened.png`이며, 기존 한손 시트는 동작 참고로만 사용했다.
전체 프롬프트는 `prompts.json`에 보존했다. 일반 내려찍기는 불꽃 위쪽 잘림을 발견해 도구로 여백을 보완한 출력을 최종 시안으로 선택했다.
일반형의 청색 투구·붉은 스카프와 망토·큰 방패·짧은 다리, 황금형의 상아색 투구·금색 복장·빛 날개를 각각 기준으로 삼았다.
검은 한 손으로 잡고 반대 손은 방패를 든다. 일반형의 흰색/푸른색 검광, 일반 내려찍기의 노랑/주황 충전, 황금 내려찍기의 금빛 검광을 포함한다.
지면 충격·돌·먼지는 캐릭터 PNG에 합치지 않았다.

`swing.png`, `dash.png`, `slam.png`, `golden-slam.png`는 생성 원본이다. `frames/`는 알파 연결 영역으로 분리한 미리보기 PNG다.
시트 셀을 단순 사각형으로 잘라 망토나 검을 잃지 않도록 연결 영역을 배정했고, 원본의 모든 비투명 픽셀이 분리 출력에 한 번씩 포함되는 것을 검사했다.
그림을 다시 칠하거나 비균일하게 늘이지 않았다. `registration.json`의 투구 크기와 발 기준점으로 미리보기에서 균일 배율을 적용한다.
기본형 투구의 파란 면은 색/연결 영역으로 측정하고, 황금형은 `golden-registration.json`에 시각적으로 지정했다. 이것은 미술 비교용 등록 값이며 Unity PPU·pivot 설정이 아니다.

## 검증과 한계

- 16개 동작 PNG + 2개 대기 PNG 읽기/알파 및 등록 정보 검사.
- 분리 시 원본 비투명 픽셀 수 보존 검사.
- 6단계 반복 GIF 출력 및 대표 타격 비교 PNG 시각 확인.
- 독립 HTML의 에셋 내장 및 `node --check` 구문 검사.
- Unity 변경이 없으므로 Unity 배치 생략. 프리팹, GUID, 실제 공격 타이밍·범위·피해 변경 없음.

현재는 4자세의 미술 시안이다. 내려찍기 준비 2자세만으로 현재 런타임의 3단계 충전 계약 전체가 완성됐다고 보지 않는다.
검광은 이번 시안에 포함돼 있으며 실제 기존 SlamLightEffect·지면 효과와 중복되지 않도록 정식 연결 시 별도 조정이 필요하다.
타이밍과 표시 크기는 검수용이다. 실제 Unity Play의 이동·카메라·정렬·이벤트·셰이더 연결을 재현한 화면이 아니다.
미확인: 사용자 일관성/미술 승인, 최종 충전 단계 정리, Unity 임포트 PPU/pivot와 실제 Play 연속성.

## 재현

Pillow가 있는 Python에서 폴더 내 `prepare_preview.py` 후 `render_preview.py`를 실행한다.
분리 PNG를 다시 만들려면 먼저 해당 `frames/` 출력을 다른 폴더에 보관한다. 기존 분리 PNG는 재실행 때 덮어쓰지 않는다.
텍스트 입출력은 UTF-8을 명시한다.
