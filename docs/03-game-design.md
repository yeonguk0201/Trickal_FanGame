# 게임 디자인

## 1. 게임 개요

### 장르

**2D 탑다운 로그라이크 액션 슈팅**

아이작 스타일의 게임 진행 구조를 참고하여, 플레이어가 매번 하나의 Run을 진행하면서 방을 탐색하고 적을 처치하며 아이템을 획득하고 최종 보스를 목표로 진행한다.

### 핵심 특징

- 짧은 플레이 세션
- 방 단위 전투
- 층 단위 진행
- 랜덤 / 절차적 요소
- 아이템 획득과 빌드 구성
- 아이템 간 시너지
- 저학년·고학년 스킬을 활용한 캐릭터 전투
- 보스 전투
- 클리어 또는 사망으로 Run 종료
- Run 종료 경험치와 캐릭터별 스킬 성장
- Run 결과를 서버에 기록
- 기록된 데이터를 웹에서 전적 및 통계로 조회

---

# 2. 게임의 핵심 목표

본 프로젝트의 게임 부분에서 가장 중요한 목표는 **대규모 콘텐츠를 만드는 것이 아니라 하나의 완성된 로그라이크 플레이 루프를 만드는 것**이다.

플레이어가 다음 흐름을 자연스럽게 경험할 수 있어야 한다.

```text
게임 실행
    ↓
캐릭터 선택
    ↓
Run 시작
    ↓
층 진입
    ↓
방 탐색
    ↓
일반 몬스터 전투
    ↓
방 클리어
    ↓
아이템 / 보상 획득
    ↓
다음 방
    ↓
반복
    ↓
층 보스
    ↓
다음 층
    ↓
반복
    ↓
최종 보스
    ↓
클리어 / 사망
    ↓
Run 종료
    ↓
플레이 데이터 서버 전송
```

# 3. 플레이어 경험

## 3.1 기본 게임 흐름

플레이어는 타이틀에서 로컬 플레이어 프로필을 확인하고 홈으로 이동한 뒤 캐릭터를 선택해 하나의
Run을 시작한다. 게임을 처음 실행한 사용자는 `GAME START`를 누른 뒤 닉네임을 등록한다.

```text
EXE 실행
  → 타이틀
  → 최초 사용자라면 닉네임 등록
  → 홈
      ├─ 게임 시작 → 캐릭터 선택 → Run
      ├─ 스킬 강화
      ├─ 설정
      └─ 나가기
```

하나의 Run은 여러 개의 층으로 구성되며, 각 층에는 여러 개의 방이 존재한다.

각 방에서는 일반적으로 적을 처치해야 다음 방으로 이동할 수 있다.

플레이어는 방을 진행하면서 아이템을 획득하고 자신의 능력을 강화한다.

각 층의 마지막에는 보스가 존재하며, 보스를 처치하면 다음 층으로 이동한다.

최종 층의 보스를 처치하면 Run을 클리어한다.

플레이어의 HP가 0이 되면 Run은 사망으로 종료된다.

## 3.2 로컬 플레이어 프로필

MVP는 계정·비밀번호·로그인 대신 한 PC에 저장되는 로컬 플레이어 프로필을 사용한다.

- 닉네임은 한글·영문·숫자 2~12자로 제한하고 앞뒤 공백을 제거한다.
- 영문 대소문자를 구분하므로 `Erpin`과 `erpin`은 서로 다른 닉네임이다.
- 서버에서 닉네임 중복을 확인한 뒤 User와 에르핀 초기 진행 데이터를 함께 만든다.
- Unity는 최초 등록 요청 전에 `clientProfileId`를 한 번 생성하고 응답 유실 후 재시도에도 유지한다.
- 같은 `clientProfileId`와 닉네임 재전송은 기존 생성 결과를 반환하고 User를 중복 생성하지 않는다.
- 등록 성공 시 Unity는 서버가 반환한 `userId`, 닉네임과 `clientProfileId`를 로컬에 보관한다.
- 다음 실행부터 저장된 프로필로 홈에 진입하며 닉네임 변경과 사용자 전환은 MVP에서 제외한다.
- 로컬 프로필은 인증 수단이 아니며 다른 사용자의 접근을 막는 계정 보안을 제공하지 않는다.

# 4. Run 구조

## 4.1 Run이란?

**Run**은 플레이어가 게임을 시작하여 클리어하거나 사망할 때까지의 하나의 플레이 기록을 의미한다.

```text
Run
├── 시작
├── 1층
│   ├── 방
│   ├── 전투
│   ├── 아이템
│   └── 보스
├── 2층
│   ├── 방
│   ├── 전투
│   ├── 아이템
│   └── 보스
├── 3층
│   ├── 방
│   ├── 전투
│   ├── 아이템
│   └── 최종 보스
└── 클리어 / 사망
```

Run이 종료되면 결과 데이터를 생성하여 Backend API로 전송한다.

# 5. 게임 진행 구조

## 5.1 전체 구조

MVP에서는 총 **3개 층**을 기본 구성으로 한다.

```text
Run
 │
 ├── Floor 1
 │    ├── Start Room
 │    ├── 탐색 경로와 분기
 │    ├── 보물방 / 아티팩트
 │    └── Boss
 │
 ├── Floor 2
 │    ├── Start Room
 │    ├── 탐색 경로와 분기
 │    ├── 보물방 / 아티팩트
 │    └── Boss
 │
 └── Floor 3
      ├── Start Room
      ├── 탐색 경로와 분기
      ├── 보물방 / 아티팩트
      └── Final Boss
```

각 층은 상하좌우 격자에 생성되는 여러 개의 방으로 구성된다. 현재 Floor-1 설정은 특수방을 포함한
총 방 수가 1층 8~12·2층 8~12·3층 12~18이며, 보스 최소 거리는 각각 4·5·5회 이동이다.
초기 6~8방 설정은 이전 생성 방식의 회귀 검증용으로 유지한다.
플레이어가 단순히 한 방씩 직선적으로 진행하는 대신 주 경로와 선택 가지를 탐색하도록 한다.

# 6. 캐릭터 선택

## 6.1 기본 방향

MVP에서는 **플레이 가능한 캐릭터를 에르핀 1종으로 제한한다.**

다만 게임 시작 시 캐릭터를 선택하는 화면은 구현한다.

```text
캐릭터 선택

┌──────────────┐
│              │
│    에르핀    │
│              │
│   [선택]     │
└──────────────┘

※ 향후 캐릭터 추가 가능
```

현재는 선택 가능한 캐릭터가 하나뿐이지만, 향후 캐릭터가 추가되더라도 게임 시스템을 크게 변경하지 않는 것을 목표로 한다.

---

## 6.2 캐릭터 확장 방향

MVP:

```text
에르핀 (erpin)
└── 플레이 가능
```

향후:

```text
에르핀
├── 플레이 가능

Character B
├── 플레이 가능

Character C
└── 플레이 가능
```

따라서 캐릭터 관련 데이터는 특정 캐릭터 하나에 강하게 결합하지 않고 확장 가능한 형태로 설계한다.

### 캐릭터가 가질 수 있는 기본 정보

- Character ID
- 이름
- 기본 HP
- 이동 속도
- 공격력
- 공격 속도
- 공격 방식
- 저학년 스킬
- 고학년 스킬
- 기본 능력치

## 6.3 에르핀

| 항목 | MVP 구성 |
|---|---|
| Character ID | `erpin` |
| 이름 | 에르핀 |
| 기본 공격 | 방향키 방향으로 투사체 발사 |
| 저학년 스킬 | SP 1을 소비해 입력 방향으로 유도탄 4발을 짧은 간격으로 발사, 피격 시 중첩 가능한 범위 폭발 |
| 고학년 스킬 | 방향 조작이 가능한 무적 돌진, 적 접촉 시 광역 피해와 넉백 후 종료, Q 재입력으로 취소 |

스킬과 메타 성장의 상세 계약은 [스킬 & 메타 시스템 계획](./12-skill-system-plan.md)을 따른다.

# 7. 플레이어 조작

## 7.1 이동

플레이어는 키보드를 사용하여 캐릭터를 이동시킨다.

기본 방향:

```text
W
↑

A ← Player → D

S
↓
```

정확한 입력 방식은 Unity Input System 구현 단계에서 결정한다.

---

## 7.2 공격

플레이어는 이동하면서 적을 공격할 수 있어야 한다.

기본 공격 방식은 **탑다운 슈팅 방식**을 사용한다.

예상 구조:

```text
이동 방향
     ↓
Player → 공격
     ↓
Projectile
     ↓
Enemy
     ↓
Damage
```

공격 방식의 세부 구현은 프로토타입 단계에서 결정한다.

### 투사체 사거리(Range-0, 2026-10-02)

투사체가 날아가는 거리는 **체공 시간 × 탄속**으로 정한다. 이전에는 수명이 방 크기(16×9)보다 길어
투사체가 어딘가에 부딪힐 때까지 날아갔다. 체공 시간이 끝나면 투사체는 바로 사라진다(현재 페이드 없음,
사거리 끝 연출은 에셋 작업 때 붙인다). 투사체가 날아가는 도중에는 기존처럼 벽·문·장애물·적에 막힌다.

| 대상 | 탄속 | 체공 시간 | 사거리 |
|---|---:|---:|---:|
| 플레이어 기본 공격 | 8 | 2/3초 | 약 5.3 |
| 원거리형 | 5 | 1.8초 | 9 |
| 원거리형 변형(빠른 이동 사격) | 6.5 | 1.4초 | 약 9 |
| 롱레인지 저격형 | 11 | 1.3초 | 약 14 |
| 크레용 궁수 / 마법사(보스 부하) | 7 | 1.7초 / 1.4초 | 약 12 / 약 10 |
| 보스 탄막 | 4~5.5 | 4초 유지 | 벽까지 |
| 저학년 스킬 유도탄 | — | 2.5초 유지 | 시간 기준 그대로 |

- 플레이어 기본 공격은 이동 속도의 25%를 물려받는다. 앞으로 이동하며 쏘면 조금 더 멀리, 물러나며
  쏘면 조금 덜 날아간다.
- 탄속이 늘면 사거리도 같이 늘어난다. 사거리 아이템은 체공 시간을, 탄속 아이템은 탄속을 올린다.
  장난감 망원경(`item-15`)이 체공 시간 +30%를 준다(사거리 약 6.9). 탄속 효과는 계약만 열려 있고 아직 아이템이 없다.
- 기본 공격 넉백은 현재 물리 충돌로만 생긴다. Dynamic 투사체(질량 1)가 Dynamic 적과 부딪혀 운동량이
  전달되는 방식이다. 명시적인 넉백 공식(예: 탄속 × 아이템 넉백 비율 / 적 질량)은 공격 변화 조합 계약에서
  정한다.

## 7.3 저학년 스킬

- 입력 키: `Space`
- SP 최대치: 기본 3
- 사용 비용: SP 1
- SP는 적 처치 시 확률적으로 바닥에 드롭되며 직접 획득한다.
- 최대 SP에서 픽업해도 SP는 증가하지 않고 픽업은 사라진다.
- SP에는 반 칸 진행도가 있다. 반 칸 두 번이 1칸이 되고, 저학년 스킬은 채워진 칸만 소비한다. 최대치에 도달하면 반 칸은 버린다.
- 초과 충전: 아로마 테라피만 SP를 최대치 +1까지 채운다. 초과 칸은 SP를 사용해 최대치 이하가 되면 사라지고, 픽업·명상의 시간 등 일반 회복은 최대치를 넘기지 않는다. HUD는 초과 칸을 금색 슬롯으로, 반 칸을 흐린 슬롯과 `SP 1.5 / 3` 표기로 보여준다.
- 일회용 스펠(Spell-0): **아로마 테라피**(`single-spell-aroma-therapy`)는 SP를 최대치 +1까지 즉시 회복하고, 이미 초과 상태면 사용 실패·미소비다. **명상의 시간**(`single-spell-meditation-time`)은 사용 1초 후부터 1초마다 SP 반 칸씩 총 12틱 회복한다. 가득 찬 상태에서도 사용할 수 있고, 방·층 이동에도 유지되며, 일시정지 중에는 멈추고 사망·Run 종료 시 중단된다. 다시 사용하면 지속 시간이 12초로 갱신된다(중첩 없음). 둘 다 Uncommon(초기값)이며 아직 정상 획득 경로(상자·상점)는 없다.
- 일회용 스펠(Spell-1): **저놈 잡아라**(`single-spell-catch-that-one`, Uncommon)는 적이 남은 전투방·보스방에서 사용하면 그 방에 있는 동안 기본 공격(근접·투사체) 피해 +10%, 스킬에는 미적용이다. 시작방·보상방·이미 클리어한 방에서는 사용 실패·미소비다. 같은 방에서 다시 사용하면 +10%씩 더해지고, 방을 클리어해도 그 방 안에서는 유지되며, 방·층을 떠나거나 사망·Run 종료 시 해제되고 재방문으로 되살아나지 않는다. 레거시 상시 스펠 `spell-catch-that-one`은 과거 전적 표시용으로 남고 선택 보상·상점 풀에서 빠졌다. 정상 획득 경로(상자)는 아직 없다.
- 일회용 스펠(Spell-2): **그건 내 잔상**(`single-spell-afterimage`, Uncommon)은 전투가 진행 중인 전투방·보스방에서 사용하면 현재 층 시작방으로 즉시 이동한다. 탈출한 방의 남은 적은 처치로 세지 않고 사라지며, 방은 미클리어로 돌아가 문이 열린다. 다시 들어가면 같은 Encounter를 첫 웨이브부터(보스는 최대 HP로) 다시 시작한다. 부순 장애물·바닥 픽업·열린 비밀 통로는 유지되고, 클리어 보상은 실제로 클리어할 때 한 번만 지급된다. 시작방·보상방·전투 시작 전이나 클리어한 방, 방 이동이 막힌 순간(전환 대기·돌진 등)에는 사용 실패·미소비다. 체력 회복은 없고 이동 직후 문 통과와 같은 짧은 무적만 적용된다. 레거시 상시 스펠 `spell-afterimage`는 과거 전적 표시용으로 남고 선택 보상·상점 풀에서 빠졌다.
- 일회용 스펠(Spell-3): **막판 스퍼트**(`single-spell-final-sprint`, Rare)는 아직 클리어하지 않은 보스방에서만 사용할 수 있고, 그 방에 있는 동안 공격속도 +30%·이동속도 +5%를 준다(공격 피해는 그대로). 보스방 밖이나 보스를 쓰러뜨린 보스방에서는 사용 실패·미소비다(D0). 같은 방에서 다시 사용하면 수치가 더해지고, 보스를 쓰러뜨려도 그 방 안에서는 유지되며, 방·층을 떠나거나 사망·Run 종료 시 해제되고 재방문으로 되살아나지 않는다. 저놈 잡아라와 같은 방에서 함께 쓰면 두 효과가 모두 적용된다. 레거시 상시 스펠 `spell-final-sprint`는 과거 전적 표시용으로 남고 선택 보상·상점 풀에서 빠졌으며, 이로써 선택 보상·상점 아이템 풀에는 아티팩트만 남는다.
- 유도탄 4발은 바라보는 방향 중심 36° 부채꼴의 슬롯을 왼쪽부터 1~4로 보아 `1→3→2→4` 순서로 첫 탄을 즉시, 나머지는 0.08초 간격으로 연사하고 발사 후 각자 적을 추적한다.
- 적이 여러 명이면 거리순 라운드로빈으로 네 탄을 배분하며, 연사가 끝나기 전에는 추가 사용과 SP 소비를 차단한다.
- 타깃이 없으면 바라보는 방향 중심으로 퍼져 진행한 뒤 폭발 없이 소멸한다.
- 명중 시 현재 공격력의 100% 범위 피해를 주며 같은 적에게 여러 폭발이 중첩될 수 있다.

## 7.4 고학년 스킬

- 입력 키: `Q`
- 최대 10초 동안 WASD로 조작 가능한 이동 속도 2배의 무적 돌진 상태가 된다.
- 방향 입력이 없으면 마지막 이동 방향으로 계속 진행하며 중도 취소할 수 없다.
- 적과 접촉하면 현재 공격력의 200% 광역 피해와 0.2초 넉백을 적용하고 즉시 종료한다.
- 넉백이 끝난 뒤 일반 적은 0.4초, 보스는 0.15초 동안 이동과 공격이 정지된다.
- 벽 충돌로 종료되지 않으며 방향을 바꾸어 빠져나올 수 있다.
- 돌진과 종료 회복 중 이동, 기본 공격, Space 저학년 스킬과 방 출입구·층 출구 전환을 차단한다.
- 돌진 중 Q를 다시 누르면 피해 없이 즉시 감속 회복으로 전환하며, 취소 시 쿨타임은 현재 전체 쿨타임의 80%다.
- 쿨타임은 돌진 종료 시점부터 시작한다.
- 적 충돌로 종료하면 플레이어를 충돌 지점에 즉시 멈추고 0.4초 동안 무적 경직을 적용한다.
- 적과 충돌하지 않고 제한 시간이 끝나면 무적 없이 0.25초 동안 현재 돌진 방향으로 감속한 뒤 멈춘다.
- 충돌 경직 또는 감속이 끝난 뒤 이동·공격·스킬·방/층 전환을 함께 허용한다.

## 7.5 피해와 HP 표현

- 현재 공격력은 캐릭터 기본 공격력과 Run 중 공격력 보너스의 합이다. 플레이어 기본 공격력은 10이다.
- 스킬 피해 공식은 `현재 공격력 × 스킬 배율 × (1 + 스킬 피해 보너스)`다.
- 플레이어 HP·피해·회복·방어막은 **반 칸 = 1단위의 정수**로 다룬다. 시작 최대 HP는 10단위(5칸)이며
  HP가 0 이하가 되면 사망한다.
- 적이 플레이어에게 주는 피해는 공격마다 지정한 피해 등급(약·중·강·치명)과 층 등급표로 정하며,
  모든 피격은 최소 1칸이다. 층이 올라가도 피해에 배율을 곱하지 않고 등급별 칸 수가 커진다.
- 최대 HP 비례 회복·방어막 결과는 단위로 내림하고 최소 1단위를 보장한다.
- 적 HP와 플레이어가 주는 피해는 `float`를 사용하고 계산 중간에 반올림하지 않는다. 적 HP와 플레이어
  공격력은 10배 스케일을 쓴다. 화상 같은 지속 피해는 적에게만 적용한다.
- 피해 등급표와 아이템 수치의 세부 규칙은 [플레이어 체력 칸 단위 전환](./idea-implementation/01-player-heart-health.md)을 따른다.
- 체력 회복 픽업(하트)은 1칸을 회복한다. 1칸 전부가 최대 HP 아래에 들어갈 때만 획득하고,
  최대 HP이거나 반 칸만 비었으면 바닥에 남는다. 남은 하트는 플레이어가 밀 수 있으며 적과 투사체는 통과한다.

## 7.6 화면과 HUD

UI는 `1920 × 1080`, 16:9를 기준으로 설계한다. Frontend는 타이틀·닉네임 등록·홈·캐릭터
선택·스킬 강화·설정을 제공하고, Game 화면은 전투와 HUD만 담당한다. 홈 배경으로 실제 전투
Scene을 노출하지 않는다. 해상도, 안전 영역, 상호작용 상태와 UI 에셋 제작 기준은
[UI 규격](./16-ui-spec.md)을 따른다.

전투 HUD는 화려한 장식보다 다음 판단 정보를 우선한다.

- 반 칸 하트 줄로 표시하는 현재·최대 HP, 파란 하트로 이어 붙이는 방어막과 피격·회복 변화
- 현재·최대 SP와 저학년 스킬 사용 가능 상태
- 고학년 스킬 쿨타임과 사용 가능 상태
- 현재 아티팩트 아이콘과 스택 수; 10종을 넘으면 일시정지 화면에서 전체 목록 확인
- 현재 방, 방문·클리어한 방과 발견한 특수방을 구분하는 미니맵
- 하단 중앙에 표시되는 보스 이름, HP와 페이즈

층·방 진행 점은 상시 표시하지 않는다. 층 이름은 미니맵 머리글에서 확인하고 새 층이나 이름 있는
방에 들어갈 때 약 1.5초 알림으로 표시한다. 아티팩트 획득 때도 이름과 한 줄 설명을 약 1.5초
표시하되 전투를 멈추지 않는다. 상세 스탯 HUD는 설정에서 켜고 끌 수 있으며 기본값은 끔이다.

플레이어 HP 하트, 보스 HP 게이지, 현재·최대 SP를 나타내는 반복 슬롯 아이콘은 Screen Space Canvas에 고정한다. 적이 받은 피해
숫자는 대상 위에 월드 오브젝트로 표시하고, 플레이어는 고정 하트 HUD만 사용하므로 월드 숫자를 표시하지 않는다. Game Scene에서 `Esc`는 일시정지 진입과
복귀에 사용하며, 일시정지 화면에서 전체 아티팩트와 상세 스탯을 확인한다.

스킬 강화의 기본 진입점은 홈의 독립 메뉴다. Run 결과 화면은 획득 경험치, 레벨 변화, 남은
스킬 포인트와 저장 결과를 보여주며, 전투 중 영구 스킬 레벨을 변경하지 않는다.

# 8. Room

## 8.1 방의 역할

방은 게임 플레이의 기본적인 전투 단위다.

플레이어가 새로운 방에 진입하면 적이 등장하고, 적을 모두 처치하면 방이 클리어된다.

기본 흐름:

```text
방 입장
   ↓
적 스폰
   ↓
전투
   ↓
모든 적 처치
   ↓
방 클리어
   ↓
보상 / 다음 방
```

---

## 8.2 기본 방 상태

방은 최소한 다음 상태를 가질 수 있다.

```text
RoomState

WAITING
  ↓ 전투방 첫 입장
COMBAT
  ↓ 클리어 조건 달성
CLEARED
```

예:

```text
플레이어 방 진입
      ↓
적 생성
      ↓
문 잠금
      ↓
전투
      ↓
적 전멸
      ↓
문 해제
      ↓
다음 방 이동
```

## 8.3 방 화면과 전환

최종 게임에서는 화면에 현재 방 하나만 표시한다. Phase E-5~F-4에서는 3개 층에 각각 3개 방을 둔
고정 선형 그래프로 한 화면 전환, 층 이동, 재방문 상태 보존과 Run seed 수명주기를 먼저 검증했다.
Phase F-5부터는 이 검증 기반을 상하좌우 격자형 가변 그래프로 확장한다. 방 ID는 seed나 방 종류와
관계없이 `floor-XX-room-YY` 형식의 안정 키를 사용하고, 격자 좌표는 별도 생성 데이터로 관리한다.

```text
현재 방 클리어
  → 출입구 개방
  → 다음 RoomNode 선택
  → 플레이어를 다음 방 입구에 배치
  → 카메라를 다음 방 화면으로 전환
  → 다음 방 활성화
```

방을 떠나도 방문·클리어 여부와 아티팩트 획득 여부를 같은 Run 동안 유지한다. 같은 층의 연결은
양방향으로 이동할 수 있고, 위쪽 문은 목적지 아래쪽 진입점, 오른쪽 문은 목적지 왼쪽 진입점처럼
서로 반대 방향의 진입점을 사용한다. 생성 그래프에 연결되지 않은 방향은 문과 전환 트리거를
비활성화하고 벽으로 봉인한다. 보스 처치 후 다음 층으로 향하는 출구만 단방향으로 유지한다.

- 연결문의 초록 문은 클리어 후에도 포탈형 물리 장벽으로 유지한다. 별도의 전환 트리거는 통로 중앙에 두고, 플레이어가 장벽에 닿기 전에 트리거에 진입하면 다음 방의 안전 진입점으로 이동한다.
- 일반 연결문은 초록 계열, 보스방과 맞닿은 양쪽 연결문은 보라 계열로 표시한다. 잠금 상태는 같은 색상의 어두운 톤, 열린 상태는 밝은 톤으로 구분한다. 다음 층 출구는 잠금 여부와 관계없이 청록 계열을 유지한다.
- 기본 방 레이아웃은 `16 × 9`, 격자 배치 간격은 `20 × 13`, Orthographic 카메라 크기는 `5.25`를 사용한다. 벽, 문, 전환 트리거, 안전 진입점, Encounter 범위, 스폰 위치와 층 출구 위치는 공통 `RoomLayout` 규격에서 파생한다. 문 시각물과 blocker는 벽 중심선에 두고 폭 `0.3`인 전환 트리거 중심은 벽에서 `0.2` 안쪽에 둔다. 안전 진입점은 트리거에서 추가로 `1.7`, 즉 벽에서 기존과 같은 `1.9`만큼 안쪽에 유지한다.
- 문 통과 판정 (Door-1, 2026-09-30): 전환 트리거의 문 방향 길이는 문 입구 `2.4`의 2/3인 `1.6`이다. 트리거에 닿아도 플레이어 **중심**이 이 `1.6` 폭 안에 있어야 통과하므로, 문 옆 벽을 몸 가장자리로 비비는 것만으로는 넘어가지 않는다. 통과 직후 `0.75초` 무적(피격 무적 창 연장, 궁극기 무적과 독립)을 주고, 방금 들어온 문(직전 방으로 돌아가는 문)은 `0.4초` 동안 재통과를 막는다. 다른 문은 기존 전역 전환 쿨다운 `0.2초`만 적용한다.
- 돌진·기본 공격 투사체·적 투사체는 잠금 여부와 관계없이 연결문 장벽을 통과하지 못한다.
- 저학년 유도탄은 발사 시 타깃이 배정된 경우 벽과 연결문 장벽을 관통하고, 타깃 없이 발사된 경우 벽과 문에서 폭발 없이 소멸한다.
- 방 전환 직전에 남아 있는 발사 완료 투사체를 정리하여 다음 방 화면에 노출하지 않는다.
- 층 출구도 같은 방 그래프 전환 경로를 사용해 플레이어 HP·인벤토리·아이템 효과를 보존하고,
  카메라와 `RunProgress`를 다음 층 1번 방으로 함께 갱신한다.

## 8.4 Room Profile과 가변 크기

16:9 비율과 현재 방 하나가 화면에 모두 보이는 원칙은 유지하되 방의 절대 크기는 Room Profile에
따라 달라질 수 있다. 기존 `16 × 9`, Orthographic Size `5.25` 레이아웃을 보존하고 1.5배 크기의
일반 전투방을 먼저 비교한다. 2배 크기는 보스방과 특수 전투 후보로 검증한 뒤 채택한다.

Room Profile은 최소한 다음 값을 함께 정의한다.

- 내부 가로·세로 크기와 카메라 Orthographic Size
- 벽, 방향별 출입구와 안전 진입점
- Encounter 가능 영역과 검증된 spawn point
- 장애물과 보상 위치
- 적용 가능한 RoomDefinition과 Encounter 후보

Room Profile과 수작업 Layout Template은 서로 다른 안정 ID를 사용한다. `RoomProfile`은 내부 크기,
실제 이동·Encounter·카메라 경계, 카메라 Orthographic Size와 미니맵 실루엣을 소유한다.
`RoomTemplateDefinition`은 `templateId`, 적용할 Profile과 Room Prefab, 허용 RoomType·층 범위,
방향별 문 슬롯·안전 진입점과 검증된 SpawnPoint를 묶는다. ID는 소문자 영문·숫자·하이픈만 사용하고
빈 ID, 중복 ID, 누락된 Profile/Prefab과 Prefab 좌표가 다른 계약은 콘텐츠 카탈로그에서 거부한다.

기존 방은 `profileId = basic`, `templateId = basic-standard`로 표현하며 기존 `room-grid-base.prefab`을
그대로 참조한다. Profile과 Template은 정적 제작 데이터만 저장하고 방문·클리어·보상 상태는 계속
`RoomRunState`가 소유한다.

첫 비교 규격은 Small `12 × 6.75`, Basic `16 × 9`, Wide `24 × 9`로 고정한다. Small과 Wide의 첫
Template은 일반 전투방 전용이며 각각 `small-standard`, `wide-standard` 안정 ID를 사용한다. 세
Template 모두 네 방향 문을 제공하고 SpawnPoint 3개를 수작업 위치로 유지한다.

두 번째 확장 규격은 Tall `16 × 13.5`, Large `24 × 13.5`다. 일반 전투방은 `tall-standard`,
`large-standard`를 사용하고 기존 Encounter를 같은 안전거리 계약으로 해석한다. 보스방 초안은
1층 Wide, 2층 Tall, 3층 Large 크기의 전용 Profile·Template·Prefab 후보를 사용한다. 각 보스 후보는
자기 층에서만 선택되며 인접 방과 크기가 충돌하면 기존 Basic 보스방으로 결정적으로 폴백한다.

카메라 뷰포트는 `가로 = Orthographic Size × 2 × 종횡비`, `세로 = Orthographic Size × 2`로
계산한다. 각 축의 방 크기가 뷰포트 크기 이하이면 방 중앙에 고정하고, 더 크면 카메라 중심이 벽을
넘지 않는 구간에서만 플레이어를 추적한다. 방 전환 시에는 새 Profile의 유효 중심으로 먼저 제한한
뒤 보간해 이전 방이나 벽 바깥을 노출하지 않는다.

Encounter trigger는 플레이어의 방 진입을 감지하므로 문 통로까지 포함할 수 있다. 대신 문 슬롯과
안전 진입점 사이의 필수 통로에는 적 SpawnPoint나 장애물을 두지 않는다. Template 계약은 이 통로와
SpawnPoint의 겹침을 거부하며, 후속 Encounter 안전거리도 같은 통로를 기준으로 확장한다.

### 8.4.1 Room 내부 구성과 랜덤화 원칙

층의 방 좌표·연결·RoomType은 절차적으로 생성하지만, 개별 방의 내부 지형을 임의 좌표로 새로
만들지는 않는다. 사람이 전투 의도와 이동 가능성을 검증한 Room Layout을 여러 개 제작하고,
생성기가 문 방향·RoomType·층·난이도 조건에 맞는 Layout을 seed로 결정적으로 선택한다.

```text
Floor Graph 생성
  → 호환 Room Layout 선택
  → Layout에 맞는 Encounter 선택
  → 미리 정의된 SpawnPoint/후보 슬롯 활성화
```

- 벽, 출입구, 필수 통로, 안전 진입 영역과 전투를 규정하는 핵심 기둥·장애물은 Layout에 고정한다.
- 적과 장애물을 방 내부의 임의 좌표에 서로 독립적으로 흩뿌리지 않는다.
- 반복성을 더할 때도 일부 장식·파괴물·SpawnPoint만 제작자가 지정한 안전한 후보 슬롯에서
  선택하며, 출입구·필수 통로·회피 공간을 막는 조합은 허용하지 않는다.
- Layout, 선택 후보, Encounter와 활성 SpawnPoint는 같은 Run seed와 콘텐츠 버전에서 재현한다.
- 파괴물·보상·함정의 상태는 `RoomRunState`에 남겨 재방문 시 재추첨하거나 중복 지급하지 않는다.

Template 선택은 검증된 후보를 안정 `templateId` 순으로 정렬한 뒤 방별 `contentSeed`와 콘텐츠 버전으로
시작 후보를 정한다. RoomType과 현재 방의 모든 연결 방향을 지원하지 않는 후보는 제외한다. 배정된
방의 실제 내부 크기는 grid 좌표와 `20 × 13` 간격에서 서로 겹치지 않아야 하며, 충돌하는 후보는
다음 호환 후보로 결정적으로 폴백한다. Wide–Wide 가로, Tall–Tall 세로, Large–Large 및
Wide–Large 가로처럼 겹치는 조합은 제외한다. 같은 seed·버전은 카탈로그 저장 순서가 달라도 같은
`templateId`를 고른다.

14주차의 첫 장애물 Layout은 이 최종 구조의 최소 검증판으로 만든다. 파괴되지 않고 드롭이 없는
고정 기둥만 사용하며, 열쇠·폭탄·파괴 가능한 벽·비밀방과 확률 드롭은 후속 탐색 자원 조각으로
분리한다. 이후 제한적 랜덤화를 추가해도 이 고정 Layout과 후보 슬롯 원칙을 유지한다.

첫 검증판 `large-central-pillar`는 `24 × 13.5` Large 방 중앙에 `3 × 3` 기둥 하나를 고정하고
네 출입구 사이의 우회 공간을 남긴다. `pillar-crossfire` Encounter는 추적형·원거리형·돌진형을
기둥 밖의 고정 SpawnPoint 세 곳에 배치한다. 기둥은 플레이어와 적의 직선 이동, 양쪽 투사체와
돌진을 막지만 자동 길찾기를 제공하지 않는다. 적 우회·재탐색은 15주차 이동 규칙에서 결정한다.

방을 크게 만들었다는 이유만으로 플레이어·적 크기, 이동 속도와 투사체 속도를 즉시 변경하지
않는다. 먼저 이동 시간, 적 밀도, 피격량과 스킬 사거리를 비교한 뒤 필요한 값만 조정한다.

# 9. Room 종류

MVP에서는 지나치게 많은 방 종류를 만들지 않는다.

MVP의 격자형 층 생성에서는 시작방·일반 전투방·보물방·보스방 네 종류를 필수로 사용한다.

### 9.1 시작방

층 진입과 플레이어 배치의 기준이 되는 안전한 방이다. 첫 입장 전투를 요구하지 않으며, 생성
그래프의 모든 거리 계산은 시작방을 기준으로 한다.

### 9.2 일반 전투방

가장 기본적인 방.

```text
입장
 ↓
일반 몬스터 등장
 ↓
전투
 ↓
전멸
 ↓
방 클리어
```

### 9.3 보물방

Run의 빌드를 변화시키는 아티팩트를 획득할 수 있는 공간이다. MVP에서는 층마다 최소 1개의
보물방을 보장하며, 엘리프나 열쇠를 요구하지 않고 현재 검증된 보상 획득 흐름을 재사용한다.

### 9.4 보스방

시작방에서 일정 거리 이상 떨어진 끝방에 배치한다.

```text
보스 등장
 ↓
보스 전투
 ↓
보스 처치
 ↓
층 클리어
```

상점은 Run 화폐(Gold-0 이후 골드)를 소비하는 후속 방으로 고려한다. 엘리프, 열쇠, 잠긴 보물방, 이벤트방, 비밀방은
기본 격자 탐색과 아티팩트 보상 흐름이 안정된 뒤 확장하며 이번 MVP 필수 범위에는 포함하지 않는다.

탐색 자원인 골드(Gold-0 이전 이름 엘리프)·열쇠·폭탄은 Run 한정이며 각각 최대 99개까지 보유한다. 픽업 하나는 1개를 주고,
일부만 들어가면 99개까지 채운 뒤 나머지는 버린다. 이미 99개면 줍지 않고 체력 회복 픽업처럼 밀 수 있게
바닥에 남는다. Run이 끝난 뒤에는 더 획득하지 않으며 새 Run은 모두 0개에서 시작한다.

상자(Chest-0, 2026-10-03)는 일반·황금·다이아몬드 3종이며 별도 입력 키 없이 연다. 일반상자는 플레이어가 닿으면
열리고, 황금상자는 닿을 때 열쇠가 있으면 1개를 자동으로 소비하며 열린다(없으면 아무 일도 일어나지 않는다).
다이아몬드 상자는 닿거나 공격해도 열리지 않고 플레이어 폭탄 폭발 범위에 들어야 열리며, 폭탄은 일반·황금상자를
열지 않는다. 각 상자는 Run 동안 한 번만 열리고 겹친 폭발·연속 접촉에도 열쇠를 한 번만 쓴다. 상자는 장애물과 같은
Environment 레이어의 고체 충돌체로 플레이어·적·투사체·바닥 픽업을 모두 막고, 적은 경로 탐색에서 상자를 피해 간다
(2026-10-03 결정). 플레이어가 상자 쪽으로 걸어 들어가면 그 축 방향으로 초당 1.2(플레이어 이동 속도 5의 약 1/4)씩
천천히 밀리고, 하트처럼 플레이어 속도에 가깝게 밀려나지 않는다. 비스듬히 스치거나 멀어지는 입력으로는 밀리지 않으며,
앞에 벽·장애물·다른 상자·적·픽업이 있으면 그 앞에서 멈춘다. 배치는 방 중앙(선호 위치)에서 가장 가까운
Layout 격자점 중 장애물·필수 문 통로·진입점·다른 상자·플레이어 위치와 겹치지 않고 문에서 걸어갈 수 있는 곳을
고르며, 처음 놓인 위치를 기록해 같은 층 재구성에서도 같은 자리에 둔다. 내용물은 상자 바깥 두 겹의 링 후보점 중
벽·장애물·다른 상자와 겹치지 않는 곳에 떨어진다. 개봉
상태는 방의 Run 상태에 남아 같은 층 재방문에서도 유지되고, 층을 떠나면 열지 않은 상자는 사라져 다시 지급되지
않는다.

전투방 클리어 보상(Chest-1, 2026-10-03)은 기존 단일 픽업 드롭 대신 상자다. 클리어마다 방 seed로 33% 확률로 상자가
나오고, 종류는 일반 75%·황금 20%·다이아몬드 5%다(구 드롭과 동시에 지급하지 않는다). 열면 내용물이 상자 주변에
바닥 픽업으로 떨어진다. 일반상자는 소모품 1~3개(60/30/10)와 5% 확률의 일회용 스펠 1개, 황금상자는 2~4개,
다이아몬드 상자는 4~6개이며 소모품 종류는 하트 30·SP 30·골드 20·열쇠 12·폭탄 8 가중치다. 상자 등장·종류·내용물은
같은 seed에서 재현되고, 재방문·층 재구성에서 상자를 다시 추첨하거나 내용물을 다시 떨어뜨리지 않는다.

특별 보상(Chest-2, 2026-10-05): 황금상자는 25% 확률로 소모품에 더해 황금상자 전용 아티팩트 1개를 떨어뜨린다. 이미 최대
스택으로 가진 아티팩트는 나오지 않으며, 더 얻을 수 있는 전용 아티팩트가 없으면 소모품만 나온다. 다이아몬드 상자는
소모품 4~6개와 함께 일회용 아이템 1개를 항상 준다. 그 1개는 25% 확률로 짱셈스펠, 나머지는 스펠이다. 일반상자에서는
짱셈스펠과 전용 아티팩트가 나오지 않는다.

짱셈스펠(Jjangsem-0, 2026-10-05): **빅우드의 열매**(`jjangsem-bigwood-fruit`, Rare)는 스펠과 같은 슬롯·같은 키(Left
Shift)로 쓰는 첫 짱셈스펠이다. 사용하면 10초 동안 받는 피해가 하트 반 칸씩 줄고, HP 피해를 받을 때마다 2초 뒤 그 피해에
하트 1칸을 더해 회복한다. 방어막이 막은 피해는 회복하지 않고 사망은 막지 않는다. 10초가 끝난 뒤의 피해는 회복하지
않으며, 효과 중 다시 쓰면 10초가 갱신된다. 다이아몬드 상자에서만 나온다.

일회용 스펠 4종(Spell-5, 2026-10-05): **갑옷축제 초대장**(`single-spell-armor-festival-invitation`, Rare)은 방어막 2칸을
기존 방어막에 더한다. **아멜리아의 러브레터**(`single-spell-amelia-love-letter`, Uncommon)는 캐릭터 주변 빈 자리에 1칸
회복 하트 2개를 떨어뜨리며, HP가 가득하면 하트는 바닥에 남는다. **랜덤코인**(`single-spell-random-coin`, Common)은 골드를
2~10 사이에서 무작위로 주고, 골드가 이미 가득하면 사용되지 않는다. **회심의 일격**(`single-spell-decisive-strike`,
Uncommon)은 전투 중인 방에서 사용하면 그 방에 있는 동안 치명타 확률이 15%p(5% → 20%), 치명타 피해가 50%p(150% → 200%)
늘어난다. 네 스펠 모두 상자의
스펠 풀(현재 9종)에 들어간다.

시스트의 가짜 날개(Flight-0, 2026-10-03)는 황금상자 전용 Epic 아티팩트다. 얻으면 Run이 끝날 때까지 날아다니며
구덩이와 장애물(바위·기둥 등 현재 모든 장애물) 위를 지나갈 수 있지만 벽·닫힌 문·상자는 통과하지 못한다. 비행은
무적이 아니어서 적 공격과 폭탄 자해 피해를 그대로 받고, 장애물 위에서도 공격으로 장애물을 부술 수 있다. 비밀방 구덩이
위로 날아가면 걸을 때처럼 바로 떨어진다. 구덩이 위에서는 폭탄을 놓을 수 없고(소비하지 않음), 장애물 위에서 놓으면
가장 가까운 바닥에 놓인다. 지상 적은 날고 있는 플레이어에게 닿을 수 없으면 가장 가까운 지점까지 와서 기다린다.
선택 보상·상점에는 나오지 않으며, 황금상자 특별 보상(25%, Chest-2)으로만 얻는다.

# 10. Floor

## 10.1 층의 역할

여러 개의 방을 하나의 진행 단위로 묶는다.

각 층은 시작방에서 여러 일반방과 선택 가지를 탐색하고, 보물방에서 아티팩트를 획득한 뒤
멀리 떨어진 보스방에 도전할 수 있는 구조를 기본으로 한다. 모든 방을 방문해야 보스방에 입장할
수 있는 것은 아니지만, 보물방과 선택 가지가 추가 탐색의 이득을 제공해야 한다.

```text
          Normal
        ↗        ↘
Start ─ Normal ─ Boss
        ↘
          보물방
          아티팩트
```

---

## 10.2 MVP 층 구성

총 3개 층을 사용한다.

Floor-1은 특수방 포함 총 방 수 8~12/8~12/12~18, 보스 최소 거리 4/5/5를 층별로 사용한다.
비밀방을 제외한 모든 방은 숨김 통로 없이 시작방에서 도달 가능해야 하며,
동일한 격자 좌표를 공유할 수 없다. 보스방은 시작방 바로 옆에 배치하지 않고 시작방에서 일정
거리 이상 떨어진 끝방 후보 중 선택한다. 거리는 숨김 통로를 제외한 최단 이동 횟수다.
보물방은 보스방이 아닌 선택 가지나 끝방에 우선 배치한다. 잠긴 보물방·상점에 들어가지 않아도 보스에
도달할 수 있다. 향후 9층 확장 방향은 [다섯째 달 계획](./19-fifth-month-plan.md)의 Floor-1 계약을 따르되,
현재 Run은 3층으로 유지한다.

```text
Floor 1
└── Boss

Floor 2
└── Boss

Floor 3
└── Final Boss
```

각 층의 테마와 난이도는 점진적으로 상승한다.

# 11. 절차적 / 랜덤 요소

로그라이크의 반복 플레이 재미를 위해 일부 요소는 랜덤하게 구성한다.

### 랜덤화 대상

- 층별 목표 범위 안의 방 수
- 상하좌우 격자 좌표와 방 연결
- 시작방·일반방·보물방·보스방 배정
- 검증된 Room Layout 또는 RoomDefinition 선택
- 검증된 일반 몬스터 구성과 Encounter 선택
- 아이템 등장
- 아이템 획득 순서
- 일부 이벤트

출입구 안전 영역, 장애물과 개별 spawn point의 위치는 임의 좌표로 흩뿌리지 않는다. 사람이 미리
구성하고 검증한 Layout과 spawn point 조합을 seed에 따라 선택한다. 같은 Run seed와 콘텐츠
버전에서는 같은 층 그래프와 방·몬스터 구성을 재현할 수 있어야 한다.

생성 완료 후에는 전체 연결성, 좌표 중복, 문 방향 대응, 필수 Room 종류, 보스 최소 거리와 생성
재시도 상한을 검증한다. 상세 참고 설계는
[아이작식 층·방 생성 구조와 Unity MVP 설계안](./drafts/Isaac_Style_Roguelike_Floor_Room_Design.md)에 둔다.

# 12. Monster

## 12.1 기본 구조

MVP에서는 추적형·원거리형·돌진형 **3종의 일반 몬스터**를 완성한다. 새 종류를 늘리는 것보다
세 역할의 이동, 공격 예고, 공격 후 빈틈과 혼합 Encounter를 우선한다.

각 몬스터는 서로 다른 공격 또는 이동 패턴을 갖도록 구성한다.

예:

```text
Monster A
└── 플레이어 추적

Monster B
└── 원거리 공격

Monster C
└── 돌진 공격

Monster D
└── 특정 방향 공격

Monster E
└── 특수 패턴
```

새 종류를 추가하기 전에 현재 추적형·원거리형·돌진형의 역할, 공격 예고와 공격 후 빈틈을
완성한다. 일반 적은 방 전투가 시작되거나 플레이어에게 공격받으면 경계 상태가 되며, 같은 전투
중 단순히 감지 범위를 벗어났다는 이유로 플레이어를 잊지 않는다. 방 클리어, 플레이어 사망 또는
방 비활성화 시에만 진행 중인 추적과 공격을 종료한다.

Phase E에서 확정한 원거리형은 플레이어를 8 유닛 안에서 감지한다. 6 유닛보다 멀면 접근하고
3 유닛보다 가까우면 후퇴하며, 3~6 유닛 구간에서는 정지해 1.5초마다 플레이어 방향으로
적 투사체를 발사한다. 투사체는 벽과 포탈형 연결문 장벽을 통과하지 않으며 방 전환 시 제거된다.

Phase E에서 확정한 돌진형은 플레이어를 7 유닛 안에서 감지하면 0.65초 동안 정지해 예고하고,
예고 시작 시점의 방향을 고정해 최대 0.8초 동안 빠르게 돌진한다. 돌진 중 플레이어나 벽,
포탈형 연결문 장벽과 충돌하면 즉시 멈추고 회복 상태에 들어간다. 평상시 접촉은 약 등급 피해를
1초 간격으로 주고, 돌진 충돌은 강 등급 피해를 한 번만 적용한다. 넉백·경직·사망·방 비활성화는
진행 중인 패턴을 취소한다.

방 안 장애물이 길을 막으면 일반 적은 직선 대신 격자 경로로 우회한다. 원거리형과 저격형은 사선이
막히면 쏘지 않고 사선이 열리는 쪽으로 이동하며, 돌진형은 플레이어까지 직선이 비어 있을 때만
돌진을 예고한다. 세부 규칙은 [다섯째 달 계획 7.6](./19-fifth-month-plan.md#76-적의-장애물-대응-2026-09-29)을 따른다.

파괴 가능한 `1 × 1` 장애물은 벽처럼 플레이어·적·투사체·돌진을 모두 막는다. 플레이어의 기본 공격과
스킬 적중 5번에 부서지며 공격력은 필요 타수를 줄이지 않는다. 부서질 때 3% 확률로 하트·SP·열쇠·폭탄·
골드 중 하나를 떨어뜨리고, 한 번 부순 장애물은 그 Run에서 다시 생기지 않는다.

Phase E-4의 1층 기본 전투 프로필은 다음과 같다. 돌진형의 이동 속도는 상시 추적 속도가 아닌
돌진 중 속도를 뜻한다. 이 값은 역할 구분을 위한 MVP 기준이며 최종 체감 밸런스는 8주차에 조정한다.

| 유형 | HP | 공격 피해 | 이동 속도 | 역할 |
|---|---:|---:|---:|---|
| 추적형 | 5 | 접촉 1 | 2.5 | 균형형 |
| 원거리형 | 3 | 투사체 2 | 1.5 | 저체력 화력형 |
| 돌진형 | 7 | 접촉 1 / 돌진 3 | 8 | 고체력 단발 위협형 |

Phase E-6의 고정 층별 전투 구성은 다음과 같다. 일반 전투방은 스폰 지점별 프리팹 목록을
사용해 서로 다른 몬스터를 한 방에 함께 배치한다. 각 층 3번 방은 기존 보스 프리팹을 재사용하며,
1~2층 보스는 성장 아이템을 드롭하고 3층 보스만 최종 보스로서 Run 클리어를 발생시킨다.

| 층 | 1번 방 | 2번 방 | 3번 방 |
|---|---|---|---|
| 1층 | 추적형 | 돌진형 + 원거리형 | 보스 |
| 2층 | 원거리형 | 추적형 + 돌진형 | 보스 |
| 3층 | 돌진형 | 추적형 + 원거리형 | 최종 보스 |

Phase E-7의 층 연결은 `1층 3번 방 → 2층 1번 방`, `2층 3번 방 → 3층 1번 방` 두 개다.
층을 되돌아가는 연결은 만들지 않으며, 보스방 클리어 전과 고학년 돌진·회복 중에는 진입할 수 없다.

### 추적형 (Chaser)

| 속성 | 값 | 설명 |
|---|---:|---|

| 피해 등급 | 강 / 치명 | 접촉 / 근접 |

플레이어를 감지하면 직선으로 추적한다. 최종 패턴은 근접 공격 전 짧은 예고와 공격 후 빈틈을

접촉 피해와 근접 공격 피해는 해당 적의 공격력을 기준으로 적용하고, 예고·회복 중에도 접촉
피해를 유지한다. 두 피해는 구현 예정인 플레이어의 공통 피격 무적 시간을 공유해 중복 적용을 막는다.

### 원거리형 (Ranged)

| 속성 | 값 | 설명 |
|---|---:|---|
| HP | 20 | 1층 기본 공격력 10 기준 2타 (Tune-1, 2026-09-30) |
| 피해 등급 | 약 | 투사체 피해, 1층 하트 1칸 (Tune-1, 2026-09-30) |

| 감지 범위 | 12 | |

| 묶음 휴식 | 1.5초 | 마지막 탄 직후 정지, 다음 묶음과 함께 이동 재개 |

계속 선회하며 이동 사격한다. 플레이어의 현재 속도로 탄착점을 예측해 조준하되 과도한 선행을 막기
위해 예측 시간을 제한하고, 예측 사선이 장애물에 막히면 현재 위치 조준으로 되돌린다. 정해진 위치로
복귀하지 않으며 벽·장애물·다른 적에 막혔을 때만 선회 방향을 바꾼다. 묶음의 마지막 탄을 쏘면
즉시 정지해 1.5초 동안 공격 기회를 제공하고, 다음 묶음 사격과 동시에 선회를 다시 시작한다.
전용 아트가 준비되기 전까지 `QuickRangedFairy` Prefab은 저격형 Sprite에 임시 색상만 달리하며,
최종 캐릭터와 외형은 Prefab의 표현 자산만 교체한다.

#### 원거리형 변형 — 롱레인지 저격형

일반 원거리형보다 멀리서 멈춰 쏘고 파고들면 약한 변형이다. HP 30, 피해 등급 강, 투사체 속도 11
(Tune-1에서 7 → 11, 체감으로 조정 중, 2026-09-30).

- 재배치 → 정지 조준 → 발사 → 회복 사이클을 반복한다.
- 재배치할 때 앞뒤 거리 조절과 필요에 따른 좌우 이동으로 사격 위치를 선택한다. 항상 좌우로 움직일 필요는 없다.
- 조준 방향과 발사 시점을 읽을 수 있게 예고하며, 이동 중에는 발사하지 않는다.
- 가까운 거리라는 이유만으로 사격 시작을 금지하지 않는다.
- 후퇴 속도를 플레이어 이동 속도보다 느리게 두고, 조준·발사·회복 중 접근과 공격 기회를 제공한다.
- 접촉만으로 피해를 주지 않는다.
- 벽이나 다른 적에게 막히면 이동 방향을 재선택한다.
- 대형 방에서 우선 검증하며, 기존 방에는 배치하지 않거나 사거리를 줄인 변형을 사용한다.

재배치와 정지 시간은 현재 4방향 사격으로 거리를 좁히고 명중시킬 수 있는지 확인하며 조율한다.

## 12.3 Encounter

Encounter는 방에 적 Prefab 목록만 저장하는 대신 한 전투의 적 조합과 시간 흐름을 정의한다.

- 적 종류와 수
- spawn point 또는 spawn group
- 동시 출현 또는 웨이브 순서
- 다음 웨이브 시작 조건과 전체 클리어 조건
- 적용 가능한 Room Profile과 층 범위
- 플레이어·출입구 주변 spawn 안전거리

같은 Run seed와 콘텐츠 버전에서는 Room과 Encounter 선택을 재현할 수 있어야 한다. 층이
올라갈수록 HP와 개체 수만 높이지 않고 추적형의 압박, 원거리형의 사선과 돌진형의 경로처럼
역할 조합과 웨이브 복잡도를 높인다. 회피 불가능한 동시 공격은 Encounter 검증에서 제외한다.

일반 전투방은 모든 웨이브의 필수 적을 처치한 뒤 문을 열고 클리어 드롭을 한 번 추첨한다. 33% 확률로
하트 30·SP 30·골드 20·열쇠 12·폭탄 8 가중치 중 하나를 방 중앙에 떨어뜨리며, 결과는 방 seed로 재현한다.
적 처치 시 SP 드롭은 없다. 완료 웨이브 수와 드롭 추첨 여부는 `RoomRunState`에 저장하며, 재방문하거나 방 인스턴스를 다시
구성해도 완료한 웨이브·적·보상을 다시 생성하지 않는다.

# 13. Boss

## 13.1 기본 방향

각 층의 마지막에는 보스가 존재한다.

최종 목표는 각 층에 서로 다른 보스 1종씩, 총 **3종의 보스**를 구현하는 것이다.

```text
Floor 1
└── Boss

Floor 2
└── Boss

Floor 3
└── Final Boss
```

현재 층별 진행 기반은 같은 테스트 보스의 강화형을 사용할 수 있지만, 넷째 달에는 사용자가
선정한 트릭컬 보스 3종으로 교체한다. 보스 이름과 상세 패턴은 선정 전까지 미정으로 유지한다.

---

## 13.2 보스 전투

일반 몬스터보다 복잡한 공격 패턴을 가진다.

예:

```text
Boss
├── 기본 공격
├── 범위 공격
├── 투사체 공격
├── 이동 패턴
└── 특수 패턴
```

최종 보스는 일반 보스보다 높은 난이도와 복합적인 패턴을 갖는다.

- 각 보스는 최소 3개의 행동 또는 공격을 갖는다.
- 모든 강한 공격은 예고, 대응 방법과 공격 후 빈틈을 제공한다.
- 1층은 기본 패턴 학습, 2층은 공간과 패턴 조합, 3층은 복합 대응을 중심으로 한다.
- 최종 보스는 최소 한 번의 페이즈 또는 패턴 조합 변화를 갖는다.
- 보스별 패턴은 원작 캐릭터의 특징과 현재 플레이어 조작을 함께 고려해 확정한다.

# 14. Item

## 14.1 기본 방향

아이템은 플레이어의 능력을 변화시키고 Run마다 다른 빌드를 구성하게 하는 핵심 요소다.

MVP에서는 **약 10종의 아이템**을 구현한다.

원작 효과와 시너지 후보를 비교할 때는 [트릭컬 리바이브 아티팩트 원본 참고표](11-artifact-reference.md)를 참고한다.

---

## 14.2 아이템 효과 유형

아이템은 다음과 같은 효과를 가질 수 있다.

### 능력치 증가

```text
공격력 +
HP +
이동 속도 +
공격 속도 +
```

### 공격 변화

```text
투사체 크기 증가
투사체 개수 증가
공격 방식 변경
공격 범위 증가
```

### 특수 효과

```text
적 처치 시 추가 효과
피격 시 효과
특정 조건에서 추가 공격
```

## 14.3 아이템 등급

| 표시 등급 | 데이터 계약 | 기본 드롭 가중치 |
|---|---|---:|
| 일반 | `COMMON` | 60 |
| 고급 | `UNCOMMON` | 25 |
| 희귀 | `RARE` | 12 |
| 전설 | `EPIC` | 3 |

가중치는 고정 확률이 아니다. 최대 스택이 아닌 활성 아이템만 후보로 만든 뒤 후보들의 가중치 합을
기준으로 추첨한다. 높은 등급일수록 낮은 가중치를 사용한다. 구체적인 아이템 이름, 효과 값,
최대 스택은 별도의 아이템 구체화 작업에서 확정한다.

## 14.4 최대 스택 보상

- 최대 스택 아이템은 보상 후보에서 제외한다.
- 남은 획득 가능 후보로 다시 가중치 추첨한다.
- 모든 후보가 최대 스택이면 아이템 대신 회복 보상을 지급한다.
- 아이템 선택 UI가 추가되더라도 같은 획득 가능 판정을 사용한다.

# 15. Item Synergy

아이템 시스템의 핵심 재미 요소 중 하나로 **아이템 간 시너지**를 구현한다.

예:

```text
Item A
공격력 증가

+

Item B
투사체 증가

        ↓

공격력이 증가된 투사체를 여러 발 발사
```

또는:

```text
Item C
공격 속도 증가

+

Item D
투사체 크기 증가

        ↓

빠르고 큰 투사체
```

MVP에서는 모든 아이템에 복잡한 시너지를 부여하기보다 **일부 아이템 조합에서 명확한 시너지 효과가 발생하도록 설계**한다.

# 17. 보상

방 또는 층을 클리어하면 플레이어에게 보상이 제공될 수 있다.

MVP에서는 보상 시스템을 복잡하게 만들지 않고 다음 범위에서 구현한다.

- 아이템
- 회복
- 일반 전투방 클리어 시 33% 확률로 생성되는 하트·SP·골드·열쇠·폭탄 드롭
- 다음 방으로 이동

향후 필요에 따라 추가 보상을 도입할 수 있다.

## 17.1 아티팩트 선택 보상

보물방과 1·2층 보스 보상은 획득 가능한 아티팩트 후보 3개를 보여주고 플레이어가 하나를
선택하는 것을 기본으로 한다.

- 후보에 이름, 등급, 효과, 현재 스택과 최대 스택을 표시한다.
- 비활성 또는 최대 스택인 아티팩트는 후보에서 제외한다.
- 하나를 선택하면 나머지는 제거하고 선택한 아티팩트만 즉시 적용·기록한다.
- 후보가 부족하면 후보 수를 줄이거나 회복으로 대체하는 규칙을 사용한다.
- 선택 중에는 전투 입력, 방 이동과 다음 층 이동을 차단한다.
- 같은 보상에 재진입하거나 입력을 반복해도 두 번 지급하지 않는다.
- Run 결과의 획득 순서에는 실제로 선택한 아티팩트만 포함한다.

# 20. 난이도 설계

난이도는 층이 올라갈수록 점진적으로 상승한다.

### 주요 난이도 요소

- 몬스터 HP

```text
Floor 1
난이도 ★

Floor 2
난이도 ★★

Floor 3
난이도 ★★★
```

단순히 적의 체력만 증가시키기보다는 **새로운 패턴과 조합을 통해 난이도를 높이는 것**을 우선한다.

### 방 난이도 (2026-09-30)

- 층 안에서는 방마다 난이도가 다르다. 적 역할별 위협 점수(추적형 2, 고속형·일반 원거리형 3, 저격형·돌진형 4)의

  가까운 방도 어려울 수 있고 먼 방도 평이할 수 있다.
- 층마다 방 점수 상한(1층 18, 2층 20, 3층 22)을 둔다. 상세 규칙은
  [19-fifth-month-plan.md 7.3](./19-fifth-month-plan.md#73-위협-점수와-방-난이도-2026-09-28-difficulty-1-확정-2026-09-30)을 따른다.

## 23.1 캐릭터 메타 성장

- 경험치는 Run 종료 시 Backend가 도달 층, 처치 수, 획득 아이템 등급을 기준으로 계산한다.
- 캐릭터는 Lv.1에서 시작하며 MVP 최대 레벨은 Lv.19다.
- 레벨업마다 스킬 포인트 1을 얻고 저학년 또는 고학년 스킬을 선택해 강화한다.
- 두 스킬은 각각 Lv.1에서 시작해 최대 Lv.10까지 성장한다.
- 초과 경험치는 다음 레벨 구간으로 이월하며 한 Run에서 여러 레벨 연속 상승을 허용한다.
- 첫 레벨업의 최종 밸런스 목표는 신규 Lv.1 캐릭터가 3층 최종 보스까지 완료한 평균적인 전체
  Run 1회 후 Lv.2가 되는 것이다. 정확한 곡선은 콘텐츠 완성 후 실제 완주 경험치로 조정한다.
- 최대 레벨에서는 추가 경험치를 저장하지 않는다.
- 두 스킬은 레벨마다 Lv.1 기준 피해가 10%씩 증가한다. Lv.5부터 저학년은 기본 투사체 +1,
  고학년은 기본 쿨타임 15% 감소를 추가로 적용한다.
- 강화 효과는 다음 Run 시작 시 불러온 진행 스냅샷부터 적용한다.
- Run 재전송으로 경험치가 중복 지급되지 않도록 Backend가 멱등성을 보장한다.

# 25. MVP에서 제외하는 기능

개발 기간을 고려하여 다음 기능은 기본 MVP 범위에서 제외한다.

- 다수의 플레이 캐릭터
- 다수 캐릭터의 고유 스킬 구현 (에르핀 1명의 저학년·고학년 스킬은 MVP 포함)
- 방대한 아이템 수
- 대규모 맵
- 온라인 멀티플레이
- PvP
- 복잡한 인벤토리
- 상점 시스템과 엘리프 경제
- 열쇠와 잠긴 보물방
- 이벤트방·비밀방과 폭탄 벽
- 미발견 특수방 단서·층 전체 미리보기·확대/축소를 포함한 완성형 미니맵
- 방 내부 장애물·spawn point의 완전 절차적 배치
- 런타임 방 언로드·재로딩 최적화
- 장비 강화 시스템
- 계정 / 로그인 시스템 (한 PC의 로컬 플레이어 프로필은 사용)
- 장비·패시브를 포함한 복잡한 메타 성장 (캐릭터 레벨과 스킬 포인트는 MVP 포함)
- 게임 내 결제
- 장시간 플레이 콘텐츠

필요한 경우 MVP 완성 후 추가한다.

# 26. 개발 우선순위

게임 시스템은 다음 순서로 구현한다.

```text
완료된 수직 슬라이스
  → PlayerStats·공통 피해·처치 이벤트 기반 정리
  → 한 화면 한 방·카메라 전환·방 상태 보존
  → SP와 저학년 스킬
  → 행동 상태와 고학년 스킬
  → 몬스터 3종·3개 층·전체 Run 통합
  → 방 그래프 랜덤 생성
  → 아이템 10종·등급 가중치·최대 스택 대체 보상
  → Backend 캐릭터 경험치·스킬 포인트·멱등성
  → 타이틀·홈·로컬 프로필·캐릭터 선택·설정
  → 전투 HUD와 결과 화면
  → 가변 크기 Room Profile·Encounter·웨이브
  → 일반 적 3종 행동 완성·층별 보스 3종
  → 아티팩트 3개 중 1개 선택 보상
  → 치명타·밸런스·UI 폴리싱
```

초기에는 그래픽과 연출보다 **게임 로직과 데이터 흐름을 우선 구현한다.**

# 28. 게임 디자인 핵심 원칙

## 28.1 콘텐츠보다 플레이 루프

게임의 콘텐츠 양을 늘리는 것보다 다음 루프가 완성되는 것을 우선한다.

```text
방 진입
 ↓
전투
 ↓
보상
 ↓
빌드 강화
 ↓
다음 방
 ↓
보스
 ↓
다음 층
```

---

## 28.2 캐릭터는 1종으로 제한

MVP에서는 캐릭터를 1종으로 제한하여 개발 범위를 통제한다.

다만 캐릭터 선택창과 캐릭터 데이터 구조는 향후 추가 캐릭터를 고려하여 설계한다.

---

## 28.3 데이터가 남는 게임

모든 게임 시스템을 구현할 때 **웹 서비스에서 어떤 데이터를 사용할 수 있는가**를 고려한다.

게임 플레이 데이터가 단순히 게임 내부에서 사라지지 않고 Run 기록으로 남도록 한다.

---

## 28.4 짧고 완성도 있는 경험

목표 플레이 시간은 약 10~15분으로 설정한다.

게임의 규모를 크게 만드는 것보다 짧은 시간 안에 다음 경험을 제공하는 것을 우선한다.

> **캐릭터 선택 → 전투 → 아이템 → 빌드 변화 → 층 진행 → 보스 → 클리어/사망 → 전적 기록**

---

## 29. 최종 게임 구조

```text
┌───────────────────────────┐
│       Character Select    │
│                           │
│          에르핀           │
└─────────────┬─────────────┘
              ↓
         ┌─────────┐
         │  Run    │
         └────┬────┘
              ↓
┌───────────────────────────┐
│          Floor 1          │
│                           │
│ Start → 탐색·분기         │
│      ↘ 보물방·아티팩트    │
│             ↘ Boss        │
└─────────────┬─────────────┘
              ↓
┌───────────────────────────┐
│          Floor 2          │
│                           │
│ Start → 탐색·분기         │
│      ↘ 보물방·아티팩트    │
│             ↘ Boss        │
└─────────────┬─────────────┘
              ↓
┌───────────────────────────┐
│          Floor 3          │
│                           │
│ Start → 탐색·분기         │
│      ↘ 보물방·아티팩트    │
│       ↘ Final Boss        │
└─────────────┬─────────────┘
              ↓
        ┌───────────┐
        │ Clear /   │
        │ Death     │
        └─────┬─────┘
              ↓
         Run Result
              ↓
        Backend API
```

> **본 프로젝트의 게임은 방 단위 전투와 아이템 빌드를 중심으로 진행되는 짧은 로그라이크 Run을 제공하고, 각 Run에서 발생하는 데이터를 서버에 기록하여 전적 검색 및 통계 서비스로 확장하는 것을 목표로 한다.**
