# 게임 디자인

## 1. 게임 개요

### 장르

**2D 탑다운 로그라이크 액션 슈팅**

아이작 스타일의 게임 진행 구조를 참고하여, 플레이어가 매번 하나의 Run을 진행하면서 방을 탐색하고 적을 처치하며 아이템을 획득하고 최종 보스를 목표로 진행한다.

### 핵심 특징

- 짧은 플레이 세션
- 방 단위 전투
- 층 단위 진행
- 랜덤 / 절차적 요소
- 아이템 획득과 빌드 구성
- 아이템 간 시너지
- 저학년·고학년 스킬을 활용한 캐릭터 전투
- 보스 전투
- 클리어 또는 사망으로 Run 종료
- Run 종료 경험치와 캐릭터별 스킬 성장
- Run 결과를 서버에 기록
- 기록된 데이터를 웹에서 전적 및 통계로 조회

---

# 2. 게임의 핵심 목표

본 프로젝트의 게임 부분에서 가장 중요한 목표는 **대규모 콘텐츠를 만드는 것이 아니라 하나의 완성된 로그라이크 플레이 루프를 만드는 것**이다.

플레이어가 다음 흐름을 자연스럽게 경험할 수 있어야 한다.

```text
게임 실행
    ↓
캐릭터 선택
    ↓
Run 시작
    ↓
층 진입
    ↓
방 탐색
    ↓
일반 몬스터 전투
    ↓
방 클리어
    ↓
아이템 / 보상 획득
    ↓
다음 방
    ↓
반복
    ↓
층 보스
    ↓
다음 층
    ↓
반복
    ↓
최종 보스
    ↓
클리어 / 사망
    ↓
Run 종료
    ↓
플레이 데이터 서버 전송
```

---

# 3. 플레이어 경험

## 3.1 기본 게임 흐름

플레이어는 게임을 시작한 후 캐릭터를 선택하고 하나의 Run을 시작한다.

하나의 Run은 여러 개의 층으로 구성되며, 각 층에는 여러 개의 방이 존재한다.

각 방에서는 일반적으로 적을 처치해야 다음 방으로 이동할 수 있다.

플레이어는 방을 진행하면서 아이템을 획득하고 자신의 능력을 강화한다.

각 층의 마지막에는 보스가 존재하며, 보스를 처치하면 다음 층으로 이동한다.

최종 층의 보스를 처치하면 Run을 클리어한다.

플레이어의 HP가 0이 되면 Run은 사망으로 종료된다.

---

# 4. Run 구조

## 4.1 Run이란?

**Run**은 플레이어가 게임을 시작하여 클리어하거나 사망할 때까지의 하나의 플레이 기록을 의미한다.

```text
Run
├── 시작
├── 캐릭터 선택
├── 1층
│   ├── 방
│   ├── 전투
│   ├── 아이템
│   └── 보스
├── 2층
│   ├── 방
│   ├── 전투
│   ├── 아이템
│   └── 보스
├── 3층
│   ├── 방
│   ├── 전투
│   ├── 아이템
│   └── 최종 보스
└── 클리어 / 사망
```

Run이 종료되면 결과 데이터를 생성하여 Backend API로 전송한다.

---

# 5. 게임 진행 구조

## 5.1 전체 구조

MVP에서는 총 **3개 층**을 기본 구성으로 한다.

```text
Run
 │
 ├── Floor 1
 │    ├── Start Room
 │    ├── 탐색 경로와 분기
 │    ├── 보물방 / 아티팩트
 │    └── Boss
 │
 ├── Floor 2
 │    ├── Start Room
 │    ├── 탐색 경로와 분기
 │    ├── 보물방 / 아티팩트
 │    └── Boss
 │
 └── Floor 3
      ├── Start Room
      ├── 탐색 경로와 분기
      ├── 보물방 / 아티팩트
      └── Final Boss
```

각 층은 상하좌우 격자에 생성되는 여러 개의 방으로 구성된다. MVP의 첫 검증 설정은 층당
6~8개 방을 사용하고, 생성기는 콘텐츠가 늘어난 뒤 설정만으로 8~12개 방까지 확장할 수 있게 한다.
플레이어가 단순히 한 방씩 직선적으로 진행하는 대신 주 경로와 선택 가지를 탐색하도록 한다.

# 6. 캐릭터 선택

## 6.1 기본 방향

MVP에서는 **플레이 가능한 캐릭터를 에르핀 1종으로 제한한다.**

다만 게임 시작 시 캐릭터를 선택하는 화면은 구현한다.

```text
캐릭터 선택

┌──────────────┐
│              │
│    에르핀    │
│              │
│   [선택]     │
└──────────────┘

※ 향후 캐릭터 추가 가능
```

현재는 선택 가능한 캐릭터가 하나뿐이지만, 향후 캐릭터가 추가되더라도 게임 시스템을 크게 변경하지 않는 것을 목표로 한다.

---

## 6.2 캐릭터 확장 방향

MVP:

```text
에르핀 (erpin)
└── 플레이 가능
```

향후:

```text
에르핀
├── 플레이 가능

Character B
├── 플레이 가능

Character C
└── 플레이 가능
```

따라서 캐릭터 관련 데이터는 특정 캐릭터 하나에 강하게 결합하지 않고 확장 가능한 형태로 설계한다.

### 캐릭터가 가질 수 있는 기본 정보

- Character ID
- 이름
- 기본 HP
- 이동 속도
- 공격력
- 공격 속도
- 공격 방식
- 저학년 스킬
- 고학년 스킬
- 기본 능력치

## 6.3 에르핀

| 항목 | MVP 구성 |
|---|---|
| Character ID | `erpin` |
| 이름 | 에르핀 |
| 기본 공격 | 방향키 방향으로 투사체 발사 |
| 저학년 스킬 | SP 1을 소비해 입력 방향으로 유도탄 4발을 짧은 간격으로 발사, 피격 시 중첩 가능한 범위 폭발 |
| 고학년 스킬 | 방향 조작이 가능한 무적 돌진, 적 접촉 시 광역 피해와 넉백 후 종료 |

스킬과 메타 성장의 상세 계약은 [스킬 & 메타 시스템 계획](./12-skill-system-plan.md)을 따른다.

# 7. 플레이어 조작

## 7.1 이동

플레이어는 키보드를 사용하여 캐릭터를 이동시킨다.

기본 방향:

```text
W
↑

A ← Player → D

S
↓
```

정확한 입력 방식은 Unity Input System 구현 단계에서 결정한다.

---

## 7.2 공격

플레이어는 이동하면서 적을 공격할 수 있어야 한다.

기본 공격 방식은 **탑다운 슈팅 방식**을 사용한다.

예상 구조:

```text
이동 방향
     ↓
Player → 공격
     ↓
Projectile
     ↓
Enemy
     ↓
Damage
```

공격 방식의 세부 구현은 프로토타입 단계에서 결정한다.

## 7.3 저학년 스킬

- 입력 키: `Space`
- SP 최대치: 기본 3
- 사용 비용: SP 1
- SP는 적 처치 시 확률적으로 바닥에 드롭되며 직접 획득한다.
- 최대 SP에서 픽업해도 SP는 증가하지 않고 픽업은 사라진다.
- 유도탄 4발은 바라보는 방향 중심 36° 부채꼴의 슬롯을 왼쪽부터 1~4로 보아 `1→3→2→4` 순서로 첫 탄을 즉시, 나머지는 0.08초 간격으로 연사하고 발사 후 각자 적을 추적한다.
- 적이 여러 명이면 거리순 라운드로빈으로 네 탄을 배분하며, 연사가 끝나기 전에는 추가 사용과 SP 소비를 차단한다.
- 타깃이 없으면 바라보는 방향 중심으로 퍼져 진행한 뒤 폭발 없이 소멸한다.
- 명중 시 현재 공격력의 100% 범위 피해를 주며 같은 적에게 여러 폭발이 중첩될 수 있다.

## 7.4 고학년 스킬

- 입력 키: `Q`
- 최대 10초 동안 WASD로 조작 가능한 이동 속도 2배의 무적 돌진 상태가 된다.
- 방향 입력이 없으면 마지막 이동 방향으로 계속 진행하며 중도 취소할 수 없다.
- 적과 접촉하면 현재 공격력의 200% 광역 피해와 0.2초 넉백을 적용하고 즉시 종료한다.
- 넉백이 끝난 뒤 일반 적은 0.4초, 보스는 0.15초 동안 이동과 공격이 정지된다.
- 벽 충돌로 종료되지 않으며 방향을 바꾸어 빠져나올 수 있다.
- 돌진과 종료 회복 중 이동, 기본 공격, Space 저학년 스킬, Q 재사용, 방 출입구와 층 출구 전환을 차단한다.
- 쿨타임은 돌진 종료 시점부터 시작한다.
- 적 충돌로 종료하면 플레이어를 충돌 지점에 즉시 멈추고 0.4초 동안 무적 경직을 적용한다.
- 적과 충돌하지 않고 제한 시간이 끝나면 무적 없이 0.25초 동안 현재 돌진 방향으로 감속한 뒤 멈춘다.
- 충돌 경직 또는 감속이 끝난 뒤 이동·공격·스킬·방/층 전환을 함께 허용한다.

## 7.5 피해와 HP 표현

- 현재 공격력은 캐릭터 기본 공격력과 Run 중 공격력 보너스의 합이다.
- 피해와 HP는 내부적으로 `float`를 사용하고 계산 중간에 반올림하지 않는다.
- UI 숫자는 최대 소수점 1자리로 표시하며 HP가 0 이하가 되면 사망한다.
- 스킬 피해 공식은 `현재 공격력 × 스킬 배율 × (1 + 스킬 피해 보너스)`다.

# 8. Room

## 8.1 방의 역할

방은 게임 플레이의 기본적인 전투 단위다.

플레이어가 새로운 방에 진입하면 적이 등장하고, 적을 모두 처치하면 방이 클리어된다.

기본 흐름:

```text
방 입장
   ↓
적 스폰
   ↓
전투
   ↓
모든 적 처치
   ↓
방 클리어
   ↓
보상 / 다음 방
```

---

## 8.2 기본 방 상태

방은 최소한 다음 상태를 가질 수 있다.

```text
RoomState

WAITING
  ↓ 전투방 첫 입장
COMBAT
  ↓ 클리어 조건 달성
CLEARED
```

예:

```text
플레이어 방 진입
      ↓
적 생성
      ↓
문 잠금
      ↓
전투
      ↓
적 전멸
      ↓
문 해제
      ↓
다음 방 이동
```

## 8.3 방 화면과 전환

최종 게임에서는 화면에 현재 방 하나만 표시한다. Phase E-5~F-4에서는 3개 층에 각각 3개 방을 둔
고정 선형 그래프로 한 화면 전환, 층 이동, 재방문 상태 보존과 Run seed 수명주기를 먼저 검증했다.
Phase F-5부터는 이 검증 기반을 상하좌우 격자형 가변 그래프로 확장한다. 방 ID는 seed나 방 종류와
관계없이 `floor-XX-room-YY` 형식의 안정 키를 사용하고, 격자 좌표는 별도 생성 데이터로 관리한다.

```text
현재 방 클리어
  → 출입구 개방
  → 다음 RoomNode 선택
  → 플레이어를 다음 방 입구에 배치
  → 카메라를 다음 방 화면으로 전환
  → 다음 방 활성화
```

방을 떠나도 방문·클리어 여부와 아티팩트 획득 여부를 같은 Run 동안 유지한다. 같은 층의 연결은
양방향으로 이동할 수 있고, 위쪽 문은 목적지 아래쪽 진입점, 오른쪽 문은 목적지 왼쪽 진입점처럼
서로 반대 방향의 진입점을 사용한다. 생성 그래프에 연결되지 않은 방향은 문과 전환 트리거를
비활성화하고 벽으로 봉인한다. 보스 처치 후 다음 층으로 향하는 출구만 단방향으로 유지한다.

- 연결문의 초록 문은 클리어 후에도 포탈형 물리 장벽으로 유지한다. 별도의 전환 트리거는 통로 중앙에 두고, 플레이어가 장벽에 닿기 전에 트리거에 진입하면 다음 방의 안전 진입점으로 이동한다.
- 일반 연결문은 초록 계열, 보스방과 맞닿은 양쪽 연결문은 보라 계열로 표시한다. 잠금 상태는 같은 색상의 어두운 톤, 열린 상태는 밝은 톤으로 구분한다. 다음 층 출구는 잠금 여부와 관계없이 청록 계열을 유지한다.
- 기본 방 레이아웃은 `16 × 9`, 격자 배치 간격은 `20 × 13`, Orthographic 카메라 크기는 `5.25`를 사용한다. 벽, 문, 전환 트리거, 안전 진입점, Encounter 범위, 스폰 위치와 층 출구 위치는 공통 `RoomLayout` 규격에서 파생한다. 문 시각물과 blocker는 벽 중심선에 두고 폭 `0.3`인 전환 트리거 중심은 벽에서 `0.2` 안쪽에 둔다. 안전 진입점은 트리거에서 추가로 `1.7`, 즉 벽에서 기존과 같은 `1.9`만큼 안쪽에 유지한다.
- 돌진·기본 공격 투사체·적 투사체는 잠금 여부와 관계없이 연결문 장벽을 통과하지 못한다.
- 저학년 유도탄은 발사 시 타깃이 배정된 경우 벽과 연결문 장벽을 관통하고, 타깃 없이 발사된 경우 벽과 문에서 폭발 없이 소멸한다.
- 방 전환 직전에 남아 있는 발사 완료 투사체를 정리하여 다음 방 화면에 노출하지 않는다.
- 층 출구도 같은 방 그래프 전환 경로를 사용해 플레이어 HP·인벤토리·아이템 효과를 보존하고,
  카메라와 `RunProgress`를 다음 층 1번 방으로 함께 갱신한다.

# 9. Room 종류

MVP에서는 지나치게 많은 방 종류를 만들지 않는다.

MVP의 격자형 층 생성에서는 시작방·일반 전투방·보물방·보스방 네 종류를 필수로 사용한다.

### 9.1 시작방

층 진입과 플레이어 배치의 기준이 되는 안전한 방이다. 첫 입장 전투를 요구하지 않으며, 생성
그래프의 모든 거리 계산은 시작방을 기준으로 한다.

### 9.2 일반 전투방

가장 기본적인 방.

```text
입장
 ↓
일반 몬스터 등장
 ↓
전투
 ↓
전멸
 ↓
방 클리어
```

### 9.3 보물방

Run의 빌드를 변화시키는 아티팩트를 획득할 수 있는 공간이다. MVP에서는 층마다 최소 1개의
보물방을 보장하며, 엘리프나 열쇠를 요구하지 않고 현재 검증된 보상 획득 흐름을 재사용한다.

### 9.4 보스방

시작방에서 일정 거리 이상 떨어진 끝방에 배치한다.

```text
보스 등장
 ↓
보스 전투
 ↓
보스 처치
 ↓
층 클리어
```

상점은 엘리프를 소비하는 후속 방으로 고려한다. 엘리프, 열쇠, 잠긴 보물방, 이벤트방, 비밀방은
기본 격자 탐색과 아티팩트 보상 흐름이 안정된 뒤 확장하며 이번 MVP 필수 범위에는 포함하지 않는다.

# 10. Floor

## 10.1 층의 역할

여러 개의 방을 하나의 진행 단위로 묶는다.

각 층은 시작방에서 여러 일반방과 선택 가지를 탐색하고, 보물방에서 아티팩트를 획득한 뒤
멀리 떨어진 보스방에 도전할 수 있는 구조를 기본으로 한다. 모든 방을 방문해야 보스방에 입장할
수 있는 것은 아니지만, 보물방과 선택 가지가 추가 탐색의 이득을 제공해야 한다.

```text
          Normal
        ↗        ↘
Start ─ Normal ─ Boss
        ↘
          보물방
          아티팩트
```

---

## 10.2 MVP 층 구성

총 3개 층을 사용한다.

MVP의 첫 검증 설정은 층마다 6~8개의 방을 생성한다. 모든 방은 시작방에서 도달 가능해야 하며,
동일한 격자 좌표를 공유할 수 없다. 보스방은 시작방 바로 옆에 배치하지 않고 시작방에서 일정
거리 이상 떨어진 끝방 후보 중 선택한다. 보물방은 보스방이 아닌 선택 가지나 끝방에 우선 배치한다.

```text
Floor 1
└── Boss

Floor 2
└── Boss

Floor 3
└── Final Boss
```

각 층의 테마와 난이도는 점진적으로 상승한다.

### 기본 난이도 방향

```text
Floor 1
쉬운 적
낮은 체력
기본적인 패턴

      ↓

Floor 2
적 종류 증가
공격 패턴 증가
난이도 상승

      ↓

Floor 3
강한 적
복합적인 패턴
최종 보스
```

# 11. 절차적 / 랜덤 요소

로그라이크의 반복 플레이 재미를 위해 일부 요소는 랜덤하게 구성한다.

### 랜덤화 대상

- 층별 목표 범위 안의 방 수
- 상하좌우 격자 좌표와 방 연결
- 시작방·일반방·보물방·보스방 배정
- 검증된 Room Layout 또는 RoomDefinition 선택
- 검증된 일반 몬스터 구성과 Encounter 선택
- 아이템 등장
- 아이템 획득 순서
- 일부 이벤트

출입구 안전 영역, 장애물과 개별 spawn point의 위치는 임의 좌표로 흩뿌리지 않는다. 사람이 미리
구성하고 검증한 Layout과 spawn point 조합을 seed에 따라 선택한다. 같은 Run seed와 콘텐츠
버전에서는 같은 층 그래프와 방·몬스터 구성을 재현할 수 있어야 한다.

생성 완료 후에는 전체 연결성, 좌표 중복, 문 방향 대응, 필수 Room 종류, 보스 최소 거리와 생성
재시도 상한을 검증한다. 상세 참고 설계는
[아이작식 층·방 생성 구조와 Unity MVP 설계안](./drafts/Isaac_Style_Roguelike_Floor_Room_Design.md)에 둔다.

# 12. Monster

## 12.1 기본 구조

MVP에서는 약 **3~5종의 일반 몬스터**를 구현한다.

각 몬스터는 서로 다른 공격 또는 이동 패턴을 갖도록 구성한다.

예:

```text
Monster A
└── 플레이어 추적

Monster B
└── 원거리 공격

Monster C
└── 돌진 공격

Monster D
└── 특정 방향 공격

Monster E
└── 특수 패턴
```

실제 몬스터 종류와 패턴은 구현 단계에서 확정한다.

Phase E에서 확정한 원거리형은 플레이어를 8 유닛 안에서 감지한다. 6 유닛보다 멀면 접근하고
3 유닛보다 가까우면 후퇴하며, 3~6 유닛 구간에서는 정지해 1.5초마다 플레이어 방향으로
적 투사체를 발사한다. 투사체는 벽과 포탈형 연결문 장벽을 통과하지 않으며 방 전환 시 제거된다.

Phase E에서 확정한 돌진형은 플레이어를 7 유닛 안에서 감지하면 0.65초 동안 정지해 예고하고,
예고 시작 시점의 방향을 고정해 최대 0.8초 동안 빠르게 돌진한다. 돌진 중 플레이어나 벽,
포탈형 연결문 장벽과 충돌하면 즉시 멈추고 회복 상태에 들어간다. 플레이어 피해는 돌진 한 번에
한 번만 적용하며, 넉백·경직·사망·방 비활성화는 진행 중인 패턴을 취소한다.

Phase E-4의 1층 기본 전투 프로필은 다음과 같다. 돌진형의 이동 속도는 상시 추적 속도가 아닌
돌진 중 속도를 뜻한다. 이 값은 역할 구분을 위한 MVP 기준이며 최종 체감 밸런스는 8주차에 조정한다.

| 유형 | HP | 공격 피해 | 이동 속도 | 역할 |
|---|---:|---:|---:|---|
| 추적형 | 5 | 접촉 1 | 2.5 | 균형형 |
| 원거리형 | 3 | 투사체 2 | 1.5 | 저체력 화력형 |
| 돌진형 | 7 | 돌진 3 | 8 | 고체력 단발 위협형 |

Phase E-6의 고정 층별 전투 구성은 다음과 같다. 일반 전투방은 스폰 지점별 프리팹 목록을
사용해 서로 다른 몬스터를 한 방에 함께 배치한다. 각 층 3번 방은 기존 보스 프리팹을 재사용하며,
1~2층 보스는 성장 아이템을 드롭하고 3층 보스만 최종 보스로서 Run 클리어를 발생시킨다.

| 층 | 1번 방 | 2번 방 | 3번 방 |
|---|---|---|---|
| 1층 | 추적형 | 돌진형 + 원거리형 | 보스 |
| 2층 | 원거리형 | 추적형 + 돌진형 | 보스 |
| 3층 | 돌진형 | 추적형 + 원거리형 | 최종 보스 |

Phase E-7의 층 연결은 `1층 3번 방 → 2층 1번 방`, `2층 3번 방 → 3층 1번 방` 두 개다.
층을 되돌아가는 연결은 만들지 않으며, 보스방 클리어 전과 고학년 돌진·회복 중에는 진입할 수 없다.

# 14. Item

## 14.1 기본 방향

아이템은 플레이어의 능력을 변화시키고 Run마다 다른 빌드를 구성하게 하는 핵심 요소다.

MVP에서는 **약 10종의 아이템**을 구현한다.

원작 효과와 시너지 후보를 비교할 때는 [트릭컬 리바이브 아티팩트 원본 참고표](11-artifact-reference.md)를 참고한다.

---

## 14.2 아이템 효과 유형

아이템은 다음과 같은 효과를 가질 수 있다.

### 능력치 증가

```text
공격력 +
HP +
이동 속도 +
공격 속도 +
```

### 공격 변화

```text
투사체 크기 증가
투사체 개수 증가
공격 방식 변경
공격 범위 증가
```

### 특수 효과

```text
적 처치 시 추가 효과
피격 시 효과
특정 조건에서 추가 공격
```

## 14.3 아이템 등급

| 표시 등급 | 데이터 계약 | 기본 드롭 가중치 |
|---|---|---:|
| 일반 | `COMMON` | 60 |
| 고급 | `UNCOMMON` | 25 |
| 희귀 | `RARE` | 12 |
| 전설 | `EPIC` | 3 |

가중치는 고정 확률이 아니다. 최대 스택이 아닌 활성 아이템만 후보로 만든 뒤 후보들의 가중치 합을
기준으로 추첨한다. 높은 등급일수록 낮은 가중치를 사용한다. 구체적인 아이템 이름, 효과 값,
최대 스택은 별도의 아이템 구체화 작업에서 확정한다.

## 14.4 최대 스택 보상

- 최대 스택 아이템은 보상 후보에서 제외한다.
- 남은 획득 가능 후보로 다시 가중치 추첨한다.
- 모든 후보가 최대 스택이면 아이템 대신 회복 보상을 지급한다.
- 아이템 선택 UI가 추가되더라도 같은 획득 가능 판정을 사용한다.

# 15. Item Synergy

아이템 시스템의 핵심 재미 요소 중 하나로 **아이템 간 시너지**를 구현한다.

예:

```text
Item A
공격력 증가

+

Item B
투사체 증가

        ↓

공격력이 증가된 투사체를 여러 발 발사
```

또는:

```text
Item C
공격 속도 증가

+

Item D
투사체 크기 증가

        ↓

빠르고 큰 투사체
```

MVP에서는 모든 아이템에 복잡한 시너지를 부여하기보다 **일부 아이템 조합에서 명확한 시너지 효과가 발생하도록 설계**한다.

# 16. Item 획득 및 Build

플레이어는 Run을 진행하면서 아이템을 획득한다.

```text
Run Start
   ↓
기본 능력치
   ↓
Item A
   ↓
Build 변화
   ↓
Item B
   ↓
Synergy 발생
   ↓
Item C
   ↓
최종 Build
```

따라서 Run 데이터에는 단순히 어떤 아이템을 가지고 있었는지만 기록하는 것이 아니라 **아이템을 획득한 순서와 시점**도 기록할 수 있도록 한다.

# 17. 보상

방 또는 층을 클리어하면 플레이어에게 보상이 제공될 수 있다.

MVP에서는 보상 시스템을 복잡하게 만들지 않고 다음 범위에서 구현한다.

- 아이템
- 회복
- 적 처치 시 확률적으로 생성되는 SP 픽업
- 다음 방으로 이동

향후 필요에 따라 추가 보상을 도입할 수 있다.

# 22. 게임 플레이 목표 시간

포트폴리오 프로젝트의 범위를 고려하여 한 번의 Run이 지나치게 길어지지 않도록 한다.

### 목표

**한 Run당 약 10~15분**

단, 실제 플레이 테스트 결과에 따라 조정한다.

목표는 긴 플레이 타임이 아니라 다음 경험을 짧은 시간 안에 보여주는 것이다.

```text
캐릭터 선택
```

# 23. 게임 외적 데이터 연동

게임은 단순히 플레이 가능한 상태에서 끝나는 것이 아니라 Run 데이터를 Backend로 전달해야 한다.

```text
[Game]

Player
 ↓
Room
 ↓
Combat
 ↓
Item
 ↓
Boss
 ↓
Clear / Death
 ↓
Run Result

        ↓

[Backend API]

        ↓

[Database]

        ↓

[Web Service]

유저 전적
통계
랭킹
```

게임 시스템을 설계할 때부터 **웹에서 활용할 수 있는 데이터가 생성되도록 고려한다.**

## 23.1 캐릭터 메타 성장

- 경험치는 Run 종료 시 Backend가 도달 층, 처치 수, 획득 아이템 등급을 기준으로 계산한다.
- 캐릭터는 Lv.1에서 시작하며 MVP 최대 레벨은 Lv.19다.
- 레벨업마다 스킬 포인트 1을 얻고 저학년 또는 고학년 스킬을 선택해 강화한다.
- 두 스킬은 각각 Lv.1에서 시작해 최대 Lv.10까지 성장한다.
- 초과 경험치는 다음 레벨 구간으로 이월하며 한 Run에서 여러 레벨 연속 상승을 허용한다.
- 최대 레벨은 캐릭터 진행 데이터로 관리하여 추후 확장할 수 있게 한다.
- Run 재전송으로 경험치가 중복 지급되지 않도록 Backend가 멱등성을 보장한다.

# 25. MVP에서 제외하는 기능

개발 기간을 고려하여 다음 기능은 기본 MVP 범위에서 제외한다.

- 다수의 플레이 캐릭터
- 다수 캐릭터의 고유 스킬 구현 (에르핀 1명의 저학년·고학년 스킬은 MVP 포함)
- 방대한 아이템 수
- 대규모 맵
- 온라인 멀티플레이
- PvP
- 복잡한 인벤토리
- 상점 시스템과 엘리프 경제
- 열쇠와 잠긴 보물방
- 이벤트방·비밀방과 폭탄 벽
- 완성형 미니맵
- 방 내부 장애물·spawn point의 완전 절차적 배치
- 런타임 방 언로드·재로딩 최적화
- 장비 강화 시스템
- 계정 / 로그인 시스템
- 장비·패시브를 포함한 복잡한 메타 성장 (캐릭터 레벨과 스킬 포인트는 MVP 포함)
- 게임 내 결제
- 장시간 플레이 콘텐츠

필요한 경우 MVP 완성 후 추가한다.

# 26. 개발 우선순위

게임 시스템은 다음 순서로 구현한다.

```text
완료된 수직 슬라이스
  → PlayerStats·공통 피해·처치 이벤트 기반 정리
  → 한 화면 한 방·카메라 전환·방 상태 보존
  → SP와 저학년 스킬
  → 행동 상태와 고학년 스킬
  → 몬스터 3종·3개 층·전체 Run 통합
  → 방 그래프 랜덤 생성
  → 아이템 10종·등급 가중치·최대 스택 대체 보상
  → Backend 캐릭터 경험치·스킬 포인트·멱등성
  → 치명타·밸런스·UI 폴리싱
```

초기에는 그래픽과 연출보다 **게임 로직과 데이터 흐름을 우선 구현한다.**

# 28. 게임 디자인 핵심 원칙

## 28.1 콘텐츠보다 플레이 루프

게임의 콘텐츠 양을 늘리는 것보다 다음 루프가 완성되는 것을 우선한다.

```text
방 진입
 ↓
전투
 ↓
보상
 ↓
빌드 강화
 ↓
다음 방
 ↓
보스
 ↓
다음 층
```

---

## 28.2 캐릭터는 1종으로 제한

MVP에서는 캐릭터를 1종으로 제한하여 개발 범위를 통제한다.

다만 캐릭터 선택창과 캐릭터 데이터 구조는 향후 추가 캐릭터를 고려하여 설계한다.

---

## 28.3 데이터가 남는 게임

모든 게임 시스템을 구현할 때 **웹 서비스에서 어떤 데이터를 사용할 수 있는가**를 고려한다.

게임 플레이 데이터가 단순히 게임 내부에서 사라지지 않고 Run 기록으로 남도록 한다.

---

## 28.4 짧고 완성도 있는 경험

목표 플레이 시간은 약 10~15분으로 설정한다.

게임의 규모를 크게 만드는 것보다 짧은 시간 안에 다음 경험을 제공하는 것을 우선한다.

> **캐릭터 선택 → 전투 → 아이템 → 빌드 변화 → 층 진행 → 보스 → 클리어/사망 → 전적 기록**

---
