# 31. 방 Layout 작성 기준

방 하나를 텍스트 파일 하나로 적어 전투방을 추가·수정할 때의 기준 문서다. 파일 형식, 글자, 배치 규칙, 작성 순서를
여기에 모은다. 임포터 메뉴·배치 명령·검증기 실행법은 `05-development-setup.md`의 "T7 방 Layout 임포터" 항목을 따른다.

- 형식의 원본 코드: `game/Assets/Editor/RoomLayoutFormat.cs`(형식·글자), `RoomLayoutImporter.cs`(배치 검사·Prefab 생성)
- 이 문서와 코드가 다르면 코드가 기준이다. 차이를 발견하면 이 문서를 고친다.

## 1. 파일

- 위치: `game/RoomLayouts/<방 ID>.room.txt`. 하위 폴더는 읽지 않는다.
- 인코딩: UTF-8. 줄바꿈은 CRLF·LF 모두 된다.
- 파일 하나 = 방 하나. 파일 이름(확장자 제외)과 `id`가 같아야 한다.
- 결과물: `Assets/Rooms/Prefabs/Layouts/room-<ID>.prefab`과 `Assets/Rooms/Templates/Layouts/<ID>.asset`이 만들어지고
  Game Scene 생성기 목록에 등록된다. 이 에셋은 손으로 고치지 않는다(다음 임포트 때 덮어쓴다).

## 2. 형식

위쪽은 `키: 값` 머리말, `grid:` 줄 아래는 격자다.

```text
// 이 줄은 주석이다(머리말에서만)
id: basic-gold-mine
profile: basic
weight: 40
note: 황금돌이 네 모서리에 몰려 있는 금광 방
grid:
GG#.........#GG
G.............G
...1.......5...
.......3.......
...............
...4.......2...
G.............G
GG#.........#GG
```

### 2.1 머리말

| 키 | 필수 | 값 | 기본값 |
| --- | --- | --- | --- |
| `id` | 예 | 소문자·숫자·하이픈. `<프로필>-`로 시작하고 뒤에 이름이 있어야 한다(`basic-gold-mine`) | — |
| `profile` | 예 | `small`·`basic`·`wide`·`tall`·`large` | — |
| `weight` | 아니오 | 등장 가중치 정수 1~1000 | 100(기존 방과 같은 확률) |
| `difficulty` | 아니오 | Layout 난이도 보정 정수 0~5 | 장애물·구덩이·함정이 하나라도 있으면 1, 없으면 0 |
| `floors` | 아니오 | 나오는 층. `2`(한 층) 또는 `1-3`(범위) | 모든 층 |
| `note` | 아니오 | 사람이 읽는 한 줄 설명. 게임에 쓰이지 않는다 | 빈 값 |

- 위 6개 외의 키, 같은 키 두 번은 거부된다.
- 빈 줄과 `//`로 시작하는 줄은 머리말에서 무시된다.
- `note`는 꼭 적는다(규칙은 아니지만 방 목록·리포트에서 방을 구분하는 유일한 설명이다).

### 2.2 격자

- `grid:` 다음 줄부터 위에서 아래로 한 줄 = 격자 한 행, 한 글자 = 1×1 한 칸이다.
- 행 수와 행마다 글자 수는 프로필 크기와 정확히 같아야 한다.
- 줄 끝 공백과 격자 뒤의 빈 줄은 무시된다. **줄 앞 공백, 격자 중간의 빈 줄, 격자 안의 주석은 오류다.**
- 격자는 방 중심에 맞춰지며 **실제로 걸을 수 있는 바닥과 정확히 같다**. 바깥 줄 칸은 벽에 바로 붙는다.

| 프로필 | 가로 × 세로 | SpawnPoint 수 |
| --- | --- | --- |
| `small` | 10 × 5 | 4 (`1`~`4`) |
| `basic` | 13 × 7 | 5 (`1`~`5`) |
| `wide` | 21 × 7 | 5 (`1`~`5`) |
| `tall` | 13 × 11 | 5 (`1`~`5`) |
| `large` | 21 × 11 | 6 (`1`~`6`) |

## 3. 글자

대소문자를 구분한다(`m` 진흙케이크 ≠ `M` 마리의 폭탄상자).

| 글자 | 분류 | 뜻 |
| --- | --- | --- |
| `.` | 바닥 | 빈 바닥 |
| `#` | 장애물 | 짱돌. 방마다 최대 1개가 seed에 따라 40% 확률로 특수 장애물이 된다 |
| `T` | 장애물 | 나무. 비행 적도 막는다 |
| `o` | 구덩이 | 붙어 있는 `o`는 직사각형으로 합쳐진다 |
| `1`~`6` | SpawnPoint | 프로필의 개수만큼 각각 정확히 한 번 |
| `c` `g` `d` | 상자 | 일반·황금·다이아몬드 상자. 방에 처음 들어갈 때부터 놓여 있고 한 번만 나온다 |
| `M` `G` `K` | 종류 고정 장애물 | 마리의 폭탄상자·황금돌·마요의 열쇠꾸러미 |
| `S` `B` `F` | 종류 고정 장애물 | 에르핀의 간식상자·에슈르의 빵상자·리코타의 음식상자 |
| `V` `X` `R` `Q` | 종류 고정 장애물 | 시스트의 금고·폭발 상자·셰이디의 랜덤박스·마요의 수집품 상자 |
| `^` `~` `w` | 바닥 함정 | 바닥 가시·장판·거미줄 |
| `a` `b` | 바닥 함정 | 주기 가시 A 위상(내려간 상태로 시작)·B 위상(올라온 상태로 시작) |
| `m` | 바닥 함정 | 진흙케이크(1회용) |
| `*` `Z` `P` | 장애물 함정 | 불(비행도 막음)·가시 돌·독버섯. 장애물 규칙을 그대로 따른다 |

- 종류 고정 장애물은 "방당 특수 장애물 1개"에 세지 않는다. 같은 방의 `#`는 그대로 추첨된다.
- 바닥 함정은 막지 않는 칸(콜라이더 없음), 장애물 함정은 막는 칸이다.

### 3.1 SpawnPoint 역할

| 번호 | 역할 |
| --- | --- |
| `1` `2` | 근접 압박 + 후방 사격 |
| `3` | 돌진 통로 + 후방 사격 |
| `4` 이후 | 근접·후방 사격 (Small의 `4`는 모든 역할) |

숫자는 서로 다른 SpawnPoint의 안정 ID다. `1` 여섯 개는 여섯 지점으로 인정하지 않으며 번호마다 정확히 한 번 사용한다. 번호가 적 종류나 실제 출현 수를 고정하지는 않는다. Encounter가 허용 역할에 맞는 지점을 선택한다.

모든 SpawnPoint는 후방 사격 지점으로도 쓰인다. `3`은 돌진 적이 직선으로 달릴 수 있는 열린 줄에 두는 것이 좋다.

## 4. 배치 규칙 (어기면 임포터가 거부)

임포터는 어긴 규칙과 칸 위치를 사유로 남기고, 거부된 방은 이전에 통과한 버전을 그대로 둔다.

### 4.1 문과 통로

- 문은 네 변의 가운데에 있다. **문 앞 통로**(문 너비 × 안전 진입점까지 깊이)에는 아무것도 둘 수 없다.
  - 장애물·구덩이는 통로 옆에 붙여도 된다. §4.5 지도의 `X` 칸만 금지다.
  - 상자·SpawnPoint는 통로 옆 한 칸도 비운다. §4.5 지도의 `O`·`X` 칸이 금지다.
- 문이 어떤 조합으로 열려도 **파괴형 장애물을 제거한 상태에서** 모든 문 사이를 걸어서 오갈 수 있어야 한다. 불·돌·독버섯 등을 부숴 길을 여는 방을 허용한다. 구덩이·나무 같은 파괴 불가 지형과 상자는 통로 검사에 남는다. 문 바로 앞 배치 금지는 파괴 가능 여부와 무관하게 유지한다.
- 길 판정은 발 원 기준이다(플레이어 0.3, 걷는 적 0.35 중 큰 값). **장애물 사이 1칸 길은 통로로 인정**한다.
  1칸보다 좁은 틈(반 칸)은 Grid-1 규칙으로 거부된다.
  - 나는 적(쥬비·대왕쥬비)은 몸 원 전체로 부딪힌다. 낮은 장애물·구덩이는 넘지만 나무 사이 1칸 길은 막힐 수 있으니 Play로 확인한다.
  - 장애물·SpawnPoint 겹침과 상자 위치 검사는 계속 몸 원(반지름 0.5) 기준이다.

### 4.2 SpawnPoint와 상자

- SpawnPoint와 상자는 다음 칸에 둘 수 없다(도달 판정이 점을 오른쪽 위 칸으로 보기 때문).
  - 장애물·구덩이의 **바로 왼쪽 칸**과 **바로 아래 칸**
  - 격자의 **맨 윗줄**과 **맨 오른쪽 열**
- SpawnPoint는 파괴형 장애물을 제거한 상태에서 문으로부터 접근 가능하고 전투 구역의 35% 이상이 보여야 한다. 파괴형에 둘러싸인 적은 허용하지만 파괴 불가 지형으로 완전히 격리하면 안 된다. 스폰 접근 검사에는 바닥 함정 회피를 요구하지 않는다.
- 문이 어떤 조합으로 열려도 그 프로필의 모든 Encounter가 배치되어야 한다. SpawnPoint를 문 안전 진입점에서 1.5,
  문에서 2 이상 떨어뜨리면 된다.
- 고정 배치 상자는 파괴형 장애물을 제거한 뒤 걸어서 닿을 수 있어야 하고, 상자끼리 1.5 이상(사이에 한 칸 이상) 떨어져야 한다.
- 상자는 밀 수 있는 몸이므로 문 통로·SpawnPoint 검사는 상자가 놓인 상태로도 한 번 더 한다.

### 4.3 바닥 함정

- 문 안전 진입점에서 1.5 안에 둘 수 없다. 프로필별 정확한 칸은 §4.5 지도의 `X`·`t` 칸이다.
- 모든 문 사이에 **파괴형 제거 후에도 상시 바닥 가시(`^`)를 밟지 않는 길**이 있어야 한다. 발밑 원(반지름 0.3) 기준이며 대각선으로 맞닿은 상시 가시 사이 통과는 인정하지 않는다.
- 주기 가시 `a/b`는 내려간 타이밍에 통과하는 경로를 허용한다. 요청한 정책에 따라 장판 `~`·거미줄 `w`·진흙케이크 `m`도 연결로를 막는 요소로 세지 않는다. 이는 무피해 통과 보장이 아니며 실제 피해·감속·대기 여유는 Play에서 확인한다.
- 모든 바닥 함정의 문 안전거리·스폰 중첩 금지는 그대로 적용한다.
- SpawnPoint와 같은 칸에는 둘 수 없고, 옆 칸은 된다. 적은 중심이 함정 그림 안에 있을 때만 밟는다.

### 4.4 그 밖의 거부 사유

- 파일 이름과 `id` 불일치, `id`가 프로필로 시작하지 않음, 생성기 밖에서 만든 템플릿과 같은 ID
- 알 수 없는 글자, 행·열 수 불일치, SpawnPoint 번호 누락·중복·초과
- `floors` 범위에서 그 프로필을 지원하는 Encounter가 하나도 없음

### 4.5 프로필별 문 주변 금지 칸

네 문은 항상 모두 검사한다(실제로 열리는 문과 관계없다). 지도는 격자와 같은 크기이고 위가 위쪽 문이다.

| 표시 | 장애물·구덩이 | 상자·SpawnPoint | 바닥 함정 |
| --- | --- | --- | --- |
| `X` | 금지 | 금지 | 금지 |
| `O` | 가능 | 금지 | 가능 |
| `t` | 가능 | 가능 | 금지 |
| `.` | 가능 | 가능 | 가능 |

규칙은 따로 지켜야 한다.

  문 크기·벽 두께·바닥 크기 상수가 바뀌면 다시 계산한다.

## 5. 작성 권장 (거부되지는 않음)

- **좌우·상하 대칭 복사본을 따로 만들지 않는다.** 임포트 리포트가 서로 뒤집은 것과 같은 방을 경고한다.
- 방마다 성격을 하나로 잡고 `note`에 적는다(예: "불 사이 통로", "구석 금광"). 한 방에 함정 종류를 다 넣지 않는다.
- **드롭·상자가 많은 방은 `weight`를 낮춘다**(황금돌·상자 방은 40~50 정도). 함정·지형만 있는 방은 기본 100.
- `difficulty`는 기본값(지형 있으면 1)을 쓰고, 함정이 빽빽하거나 통로가 좁아 확실히 어려운 방만 올린다.
- 크기별 방 수와 등장 비중은 `30-beta-release-plan.md` §3.2를 확인하고, 크게 바꾸는 추가는 계획 문서에 먼저 적는다.

## 6. 작성 순서

1. `game/RoomLayouts/`에 새 `<ID>.room.txt`를 만든다. 아래 빈 틀을 복사해 쓴다.
2. Unity 메뉴 `Trickal Fan Game > Tools > Validate Room Layouts`로 검사만 한다(에셋을 쓰지 않음).
   거부 사유는 Console과 `game/Logs/room-layout-import-report.txt`에 나온다.
3. 통과하면 `Import Room Layouts`. 글이 바뀐 방만 다시 만든다.
4. Game Scene Play → `F1` 개발 패널 `— Layout —` → `Show layouts` → `Force <방 ID>`로 그 방을 강제로 띄워 본다.
   장애물·구덩이·함정 위치, 종류 고정 장애물, 상자, 적이 끼이지 않고 클리어되는지 확인한다.
   끝나면 `Clear forced layout and restart`.
5. 자동 검증: `Trickal Fan Game > Tools > Verify Room Layouts`(실행법은 05번 문서).

## 7. 이미 쓰인 방을 고칠 때

- **방 ID는 안정 키**다. 이미 쓴 ID의 의미를 바꾸거나 지운 ID를 다른 방에 재사용하지 않는다. 완전히 다른 방이면 새 ID를 쓴다.
- 장애물·구덩이·상자·함정 ID는 칸 위치로 정해진다(`obstacle-c03-r05`). 한 칸을 고쳐도 다른 칸 ID는 바뀌지 않는다.
- 방을 추가·삭제하거나 배치를 바꾼 묶음을 내보낼 때 `RoomLayoutImporter.RoomContentVersion`을 한 번 올린다
  (seed 재현 기준이 바뀌기 때문).
- 파일을 지우면 다음 임포트에서 그 방의 Prefab·템플릿이 삭제되고 생성기 목록에서 빠진다.
- 강제 재임포트(`Reimport All Room Layouts`, 검증 배치)는 고치지 않은 방 Prefab의 내부 fileID만 바꾼다.
  고치지 않은 방의 Prefab diff는 커밋 전에 되돌린다.

## 8. 새 글자를 추가할 때

1. `RoomLayoutFormat.BuildSymbols`에 한 줄을 넣는다. 기존 글자와 대소문자까지 겹치지 않게 한다.
2. `RoomLayoutImporter.PlaceContent`에 배치 분기를 넣는다. 새 칸 종류면 `RoomLayoutCellKind`와 검사 규칙도 정한다.
3. `RoomLayoutImporterVerification`에 글자 종류 확인을 더한다.
4. 이 문서 §3 표와, 규칙이 생기면 §4를 고친다.
5. 아티팩트·함정처럼 개발 패널로 확인해야 하는 것은 `F1` 패널 경로를 같이 적는다.
