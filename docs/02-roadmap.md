# 개발 로드맵

## 1. 로드맵 개요

본 프로젝트는 약 **3~4개월(12~16주)**을 기준으로 개발한다.

1인 개발을 전제로 하며, 게임 콘텐츠의 규모를 무리하게 확장하기보다 **게임 → Backend → Database → Web으로 이어지는 전체 데이터 파이프라인을 완성하는 것**을 최우선 목표로 한다.

전체 개발은 다음 Phase로 진행한다.

```text
Phase 0
프로젝트 설계 및 개발 환경 구축
        ↓
Phase 1
게임 코어 프로토타입
        ↓
Phase 2
Backend / Database 기반 구축
        ↓
Phase 3
Vertical Slice & 데이터 연동
        ↓
Phase 4
게임 콘텐츠 확장
        ↓
Phase 5
전적 검색 Web Service
        ↓
Phase 6
통계 / 랭킹 / 데이터 시각화
        ↓
Phase 7
통합 테스트 / 폴리싱 / 배포
        ↓
Phase 8
포트폴리오 문서화
```

---

# 2. 개발 우선순위

전체 개발의 우선순위는 다음과 같다.

### Priority 1 — 전체 시스템 연결

```text
Unity
 ↓
REST API
 ↓
Backend
 ↓
Database
 ↓
Web
```

게임 플레이 결과가 실제 DB에 저장되고 웹에서 조회되는 흐름을 가장 먼저 검증한다.

### Priority 2 — 플레이 가능한 게임

```text
캐릭터 선택
 ↓
층 진행
 ↓
방
 ↓
전투
 ↓
아이템
 ↓
보스
 ↓
클리어 / 사망
```

최종 게임 콘텐츠는 MVP 범위 안에서 완성한다.

### Priority 3 — 데이터 활용

게임에서 수집한 데이터를 기반으로 다음 기능을 구현한다.

- 유저 전적
- 플레이 기록
- 캐릭터 통계
- 아이템 통계
- 랭킹
- 데이터 시각화

### Priority 4 — 폴리싱

핵심 기능이 모두 완성된 이후 다음 작업을 진행한다.

- 버그 수정
- 코드 리팩토링
- 성능 개선
- UI/UX 개선
- 배포
- 문서화

# 6. Phase 3 — Vertical Slice & 데이터 연동

### 목표

이 프로젝트에서 가장 중요한 **Game → Backend → DB → Web의 전체 흐름을 조기에 검증**한다.

이 Phase에서는 완성된 게임을 만드는 것이 목적이 아니다.

**아주 작은 게임을 끝까지 플레이하고 그 결과를 웹에서 확인하는 것**이 목적이다.

### Vertical Slice 범위

```text
캐릭터 1종
 ↓
1개 층
 ↓
2~3개 방
 ↓
일반 몬스터
 ↓
아이템 1~2종
 ↓
보스
 ↓
사망 / 클리어
```

### 핵심 테스트

```text
Unity에서 게임 플레이
        ↓
캐릭터 선택
        ↓
방 진행
        ↓
아이템 획득
        ↓
보스
        ↓
사망 / 클리어
        ↓
Run Result 생성
        ↓
POST /api/runs
        ↓
Backend
        ↓

        ↓
GET /api/users/:nickname/runs
        ↓

        ↓

```

### 완료 조건

> Unity에서 실제로 한 번의 Run을 플레이한 뒤 게임을 종료하면 해당 기록이 DB에 저장되고, 웹에서 해당 유저를 검색하여 방금 플레이한 기록을 확인할 수 있어야 한다.

### 중요

**이 Phase가 완료되면 프로젝트의 핵심 기술 검증이 끝난 것으로 본다.**

이후부터는 게임 콘텐츠와 웹 기능을 확장하되, 이미 검증된 데이터 파이프라인을 유지한다.

# 7. Phase 4 — 게임 콘텐츠 확장

### 목표

Vertical Slice에서 검증한 게임 구조를 MVP 범위까지 확장한다.

기능 추가로 기존 전투 코드가 분산되지 않도록 일정의 주차보다 다음 의존성 순서를 우선한다.

```text
전투 기반(PlayerStats·피해·처치 이벤트)
  → 한 화면 한 방 전환
  → 저학년·고학년 스킬
  → 몬스터·3층 통합
  → Run seed 기반 격자형 랜덤 방 그래프
  → 아이템 10종·등급
  → 캐릭터 메타 성장
  → 치명타·폴리싱
```

세부 계약은 [스킬 & 메타 시스템 계획](./12-skill-system-plan.md)을 따른다.

반복되는 Unity 구성·검증, 계층 간 계약 검사, 플레이테스트 측정과 조건부 Unity MCP는
[개발 생산성·검증 인프라 계획](./13-development-tooling-plan.md)에서 별도 병행 트랙으로 관리한다.
이 도구들은 현재 기능의 반복 비용이나 검증 위험을 줄일 때 도입하며 Phase 4 완료를 막는 독립 선행 조건으로 사용하지 않는다.

```text
데이터 파이프라인 미완성
```

항상 **데이터 파이프라인 완성**을 우선한다.

---

## 13.3 Phase 완료 조건을 만족한 후 다음 단계로 이동한다.

단순히 작업을 "시작했다"는 이유로 다음 Phase로 넘어가지 않는다.

각 Phase의 **Definition of Done**을 만족해야 다음 단계로 이동한다.

---

## 13.4 Should / Could 기능은 일정에 영향을 주지 않는다.

Should와 Could 기능은 기본 일정에 포함하지 않는다.

MVP가 완성된 후 남은 시간에 따라 추가한다.

```text
MUST 완료
   ↓
MVP 완성
   ↓
남은 일정 확인
   ↓
SHOULD 추가
   ↓
남은 일정 확인
   ↓
COULD 추가
```

---

## 13.5 개발 도구는 확인된 병목을 기준으로 도입한다.

생성기, 검증기, 계약 검사, 텔레메트리와 MCP 자체를 목표로 삼지 않는다.
현재 기능 구현에서 반복 비용, 계약 불일치 또는 수동 검증 누락을 줄일 수 있을 때 작은 범위로 도입한다.

상세한 착수 조건과 완료 기준은 [개발 생산성·검증 인프라 계획](./13-development-tooling-plan.md)을 따른다.
