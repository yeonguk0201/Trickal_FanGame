# 개발 로드맵

## 1. 로드맵 개요

본 프로젝트는 약 **3~4개월(12~16주)**을 기준으로 개발한다.

1인 개발을 전제로 하며, 게임 콘텐츠의 규모를 무리하게 확장하기보다 **게임 → Backend → Database → Web으로 이어지는 전체 데이터 파이프라인을 완성하는 것**을 최우선 목표로 한다.

전체 개발은 다음 Phase로 진행한다.

```text
Phase 0
프로젝트 설계 및 개발 환경 구축
        ↓
Phase 1
게임 코어 프로토타입
        ↓
Phase 2
Backend / Database 기반 구축
        ↓
Phase 3
Vertical Slice & 데이터 연동
        ↓
Phase 4
게임 콘텐츠 확장
        ↓
Phase 5
전적 검색 Web Service
        ↓
Phase 6
통계 / 랭킹 / 데이터 시각화
        ↓
Phase 7
통합 테스트 / 폴리싱 / 배포
        ↓
Phase 8
포트폴리오 문서화
```

---

# 2. 개발 우선순위

전체 개발의 우선순위는 다음과 같다.

### Priority 1 — 전체 시스템 연결

```text
Unity
 ↓
REST API
 ↓
Backend
 ↓
Database
 ↓
Web
```

게임 플레이 결과가 실제 DB에 저장되고 웹에서 조회되는 흐름을 가장 먼저 검증한다.

### Priority 2 — 플레이 가능한 게임

```text
캐릭터 선택
 ↓
층 진행
 ↓
방
 ↓
전투
 ↓
아이템
 ↓
보스
 ↓
클리어 / 사망
```

최종 게임 콘텐츠는 MVP 범위 안에서 완성한다.

### Priority 3 — 데이터 활용

게임에서 수집한 데이터를 기반으로 다음 기능을 구현한다.

- 유저 전적
- 플레이 기록
- 캐릭터 통계
- 아이템 통계
- 랭킹
- 데이터 시각화

### Priority 4 — 폴리싱

핵심 기능이 모두 완성된 이후 다음 작업을 진행한다.

- 버그 수정
- 코드 리팩토링
- 성능 개선
- UI/UX 개선
- 배포
- 문서화

# 6. Phase 3 — Vertical Slice & 데이터 연동

### 목표

이 프로젝트에서 가장 중요한 **Game → Backend → DB → Web의 전체 흐름을 조기에 검증**한다.

이 Phase에서는 완성된 게임을 만드는 것이 목적이 아니다.

**아주 작은 게임을 끝까지 플레이하고 그 결과를 웹에서 확인하는 것**이 목적이다.

### Vertical Slice 범위

```text
캐릭터 1종
 ↓
1개 층
 ↓
2~3개 방
 ↓
일반 몬스터
 ↓
아이템 1~2종
 ↓
보스
 ↓
사망 / 클리어
```

### Unity → Backend

- [ ] Run Result 데이터 정의
- [ ] Unity HTTP Client 구현
- [ ] API 요청
- [ ] JSON Serialization
- [ ] 서버 응답 처리
- [ ] 네트워크 오류 처리
- [ ] 게임 종료 시 결과 전송

### Backend → Database

- [ ] Run 데이터 검증
- [ ] User 연결
- [ ] Character 연결
- [ ] Item 연결
- [ ] Run 저장
- [ ] RunItem 저장

### Web → Backend

- [ ] 유저 검색 페이지
- [ ] 유저 조회 API 연결
- [ ] 최근 Run 조회
- [ ] Run 상세 조회

### 핵심 테스트

```text
Unity에서 게임 플레이
        ↓
캐릭터 선택
        ↓
방 진행
        ↓
아이템 획득
        ↓
보스
        ↓
사망 / 클리어
        ↓
Run Result 생성
        ↓
POST /api/runs
        ↓
Backend
        ↓
PostgreSQL
        ↓
GET /api/users/:nickname/runs
        ↓
Next.js
        ↓
전적 표시
```

### 완료 조건

> Unity에서 실제로 한 번의 Run을 플레이한 뒤 게임을 종료하면 해당 기록이 DB에 저장되고, 웹에서 해당 유저를 검색하여 방금 플레이한 기록을 확인할 수 있어야 한다.

### 중요

**이 Phase가 완료되면 프로젝트의 핵심 기술 검증이 끝난 것으로 본다.**

이후부터는 게임 콘텐츠와 웹 기능을 확장하되, 이미 검증된 데이터 파이프라인을 유지한다.

# 13. 개발 일정의 핵심 원칙

## 13.1 Phase 3 이전에 반드시 데이터 연동을 검증한다.

게임 콘텐츠를 전부 만든 후 서버를 연결하지 않는다.

가장 작은 게임 루프를 먼저 완성하고:

```text
Unity
→ API
→ Backend
→ DB
→ Web
```

전체 흐름을 조기에 검증한다.

---

## 13.2 콘텐츠보다 시스템 완성을 우선한다.

다음과 같은 상황에서는 콘텐츠 추가를 중단한다.

```text
게임 콘텐츠 부족
        VS
데이터 파이프라인 미완성
```

항상 **데이터 파이프라인 완성**을 우선한다.

---

## 13.3 Phase 완료 조건을 만족한 후 다음 단계로 이동한다.

단순히 작업을 "시작했다"는 이유로 다음 Phase로 넘어가지 않는다.

각 Phase의 **Definition of Done**을 만족해야 다음 단계로 이동한다.

---

## 13.4 Should / Could 기능은 일정에 영향을 주지 않는다.

Should와 Could 기능은 기본 일정에 포함하지 않는다.

MVP가 완성된 후 남은 시간에 따라 추가한다.

```text
MUST 완료
   ↓
MVP 완성
   ↓
남은 일정 확인
   ↓
SHOULD 추가
   ↓
남은 일정 확인
   ↓
COULD 추가
```
