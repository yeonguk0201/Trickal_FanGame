# 프로젝트 개요

## 1. 프로젝트명

**트릭컬 IP 기반 로그라이크 팬게임 & 전적 검색 웹 서비스**

> Unity와 C#으로 제작한 2D 로그라이크 팬게임과 게임 플레이 데이터를 기반으로 한 전적 검색 및 통계 웹 서비스를 결합한 하이브리드 프로젝트

---

## 2. 프로젝트 한 줄 소개

Unity와 C#을 활용하여 **트릭컬 IP를 기반으로 한 아이작 스타일의 2D 탑다운 로그라이크 팬게임**을 개발하고, 게임 플레이 데이터를 서버에 저장하여 웹에서 **유저 전적 및 게임 통계**를 조회할 수 있는 통합 서비스를 구축한다.

---

## 3. 프로젝트 목적

### 3.1 게임 개발 역량 증명

Unity와 C#을 활용하여 실제 플레이 가능한 로그라이크 게임을 제작한다.

단순한 프로토타입 수준의 기능 구현을 넘어 다음과 같은 게임 시스템을 직접 설계하고 구현하는 것을 목표로 한다.

- 플레이어 이동 및 전투
- 몬스터 AI
- 방 단위 게임 진행
- 층 단위 게임 진행
- 아이템 시스템
- 아이템 시너지
- 보스 전투
- 게임 결과 및 Run 데이터 관리

### 3.2 웹 / 백엔드 개발 역량 증명

게임에서 발생하는 플레이 데이터를 서버로 전송하고 DB에 저장한 뒤, 웹 서비스에서 해당 데이터를 조회하고 시각화한다.

이를 통해 단순 게임 개발을 넘어 다음과 같은 웹 개발 역량을 보여주는 것을 목표로 한다.

- REST API 설계 및 구현
- 서버와 클라이언트 간 데이터 통신
- 데이터 검증 및 가공
- 관계형 데이터베이스 설계
- 게임 로그 데이터 저장
- 통계 데이터 집계
- 웹 기반 데이터 조회 및 시각화

### 3.3 통합 시스템 설계 역량 증명

본 프로젝트의 핵심은 게임과 웹 서비스를 별개의 결과물로 만드는 것이 아니라, 하나의 데이터 흐름으로 연결하는 것이다.

```text
Unity / C#
    ↓
게임 플레이
    ↓
Run 결과 생성
    ↓
Backend API
    ↓
Database
    ↓
통계 데이터 집계
    ↓
Web Service
    ↓
유저 전적 / 랭킹 / 게임 통계
```

이를 통해 **게임 클라이언트 → 백엔드 → 데이터베이스 → 웹 프론트엔드**로 이어지는 전체 시스템을 직접 설계하고 구현한다.

## 4. 프로젝트 방향

본 프로젝트는 크게 다음 세 가지 영역으로 구성된다.

### A. Game Client

**Unity + C#**

트릭컬 IP를 기반으로 한 2D 탑다운 로그라이크 팬게임을 제작한다.

게임의 기본적인 플레이 흐름은 다음과 같다.

```text
캐릭터 선택
    ↓
Run 시작
    ↓
층 진입
    ↓
방 진입
    ↓
일반 몬스터 전투
    ↓
아이템 획득
    ↓
다음 방
    ↓
층 보스
    ↓
다음 층
    ↓
반복
    ↓
최종 보스
    ↓
클리어 / 사망
    ↓
Run 종료
```

### B. Backend & Database

**Node.js + TypeScript**

게임 클라이언트에서 전송한 플레이 결과를 수신하고 검증 및 가공한 뒤 DB에 저장한다.

Backend Framework는 프로젝트 설계 단계에서 최종 결정한다.

주요 역할:

- 게임 결과 수신
- 요청 데이터 검증
- 플레이 기록 저장
- 유저 전적 조회
- 게임 기록 조회
- 통계 데이터 제공
- 랭킹 데이터 제공

Database는 **PostgreSQL + Supabase**를 사용한다.

### C. Web Service

**Next.js + TypeScript**

게임에서 축적된 데이터를 기반으로 유저 전적 및 게임 통계를 제공하는 웹 서비스를 구축한다.

주요 기능:

- 유저 닉네임 검색
- 유저 전적 조회
- 최근 플레이 기록 조회
- 개별 Run 상세 조회
- 전체 랭킹
- 캐릭터별 통계
- 아이템별 통계
- 게임 플레이 데이터 시각화

## 5. 게임 MVP 범위

프로젝트 기간과 1인 개발이라는 제약을 고려하여 게임 콘텐츠의 범위를 제한한다.

### 기본 구성

| 항목      | MVP 범위               |
| ------- | -------------------- |
| 장르      | 2D 탑다운 로그라이크         |
| 개발 엔진   | Unity                |
| 개발 언어   | C#                   |
| 캐릭터     | 1종                   |
| 캐릭터 선택창 | 구현                   |
| 층       | 3층                   |
| 방       | 층별 여러 방              |
| 일반 몬스터  | 3\~5종                |
| 보스      | 1\~2종                |
| 아이템     | 약 10종                |
| 플레이 구조  | 층 → 방 → 전투 → 보상 → 보스 |
| 게임 종료   | 클리어 / 사망             |
| 플레이 기록  | 서버 전송 및 DB 저장        |

### 캐릭터 구성

MVP에서는 실제 플레이 가능한 캐릭터를 **1종으로 제한**한다.

다만 캐릭터 선택 화면과 게임 내부 구조는 향후 캐릭터 추가가 가능하도록 설계한다.

```text
Character
├── Character A  ← MVP
├── Character B  ← 향후 확장
└── Character C  ← 향후 확장
```

콘텐츠의 양을 늘리는 것보다 **확장 가능한 구조를 설계하는 것**을 우선한다.

## 6. 게임의 핵심 플레이 루프

본 프로젝트에서 하나의 게임 플레이를 **Run**이라는 단위로 정의한다.

Run은 플레이어가 게임을 시작한 시점부터 사망하거나 최종적으로 클리어하는 시점까지의 한 번의 플레이를 의미한다.

```text
Run 시작
    ↓
캐릭터 선택
    ↓
1층
 ├─ 방
 ├─ 전투
 ├─ 보상
 └─ 보스
    ↓
2층
 ├─ 방
 ├─ 전투
 ├─ 보상
 └─ 보스
    ↓
3층
 ├─ 방
 ├─ 전투
 ├─ 보상
 └─ 최종 보스
    ↓
클리어 / 사망
    ↓
Run 종료
```

Run이 종료되면 해당 플레이에서 발생한 데이터를 정리하여 서버로 전송한다.

## 9. MVP 성공 조건

본 프로젝트에서 가장 중요한 목표는 게임의 콘텐츠 규모가 아니라 **게임 데이터가 실제 서비스 전체를 관통하는 구조를 완성하는 것**이다.

다음의 전체 흐름이 정상적으로 동작하면 MVP를 완성한 것으로 정의한다.

```text
게임 실행
    ↓
캐릭터 선택
    ↓
게임 플레이
    ↓
사망 또는 클리어
    ↓
Run 결과 생성
    ↓
Backend API 전송
    ↓
서버 데이터 검증
    ↓
Database 저장
    ↓
Web에서 유저 검색
    ↓
전적 조회
    ↓
통계 및 시각화
```

### MVP Definition of Done

다음 조건을 모두 만족해야 한다.

- [ ] 실제 플레이 가능한 게임이 존재한다.
- [ ] 최소 1개의 Run을 처음부터 끝까지 플레이할 수 있다.
- [ ] 사망 또는 클리어 시 Run 결과가 생성된다.
- [ ] Unity에서 서버 API로 Run 데이터를 전송할 수 있다.
- [ ] 서버에서 데이터를 검증하고 DB에 저장할 수 있다.
- [ ] 웹에서 특정 유저를 검색할 수 있다.
- [ ] 해당 유저의 플레이 기록을 조회할 수 있다.
- [ ] 저장된 데이터를 기반으로 최소한의 통계 정보를 표시할 수 있다.

## 10. 개발 범위 원칙

### 10.1 선택과 집중

게임의 완성도를 높이는 것보다 **전체 데이터 파이프라인을 완성하는 것**을 우선한다.

따라서 게임 콘텐츠가 부족하더라도 다음 구조가 정상적으로 동작하는 것을 최우선으로 한다.

```text
Game
→ API
→ Backend
→ Database
→ Web
```

### 10.2 확장 가능한 구조

MVP에서는 콘텐츠의 수를 최소화한다.

그러나 다음 요소들은 향후 확장할 수 있도록 설계한다.

- 캐릭터
- 몬스터
- 아이템
- 층
- 방
- 통계
- 랭킹

### 10.3 AI 활용 원칙

AI를 활용하여 개발 속도를 높일 수 있지만 AI가 생성한 코드를 그대로 사용하는 것을 목표로 하지 않는다.

AI가 작성한 코드 역시 다음 내용을 직접 이해하고 설명할 수 있는 상태를 유지한다.

- 코드의 역할
- 데이터 흐름
- 클래스 및 모듈 구조
- API 통신 과정
- DB 데이터 구조
- 예외 처리
- 주요 설계 결정

## 11. 프로젝트 제약 사항

### 개발 기간

**약 3\~4개월**

1인 개발을 기준으로 하며, 게임 콘텐츠의 볼륨은 포트폴리오 목적에 맞게 제한한다.

### 개발 목표

게임의 플레이 시간과 콘텐츠 양을 무리하게 늘리지 않고 **짧은 플레이 경험과 완성된 데이터 연동 구조**를 구현하는 것을 목표로 한다.

### 저작권 및 2차 창작

본 프로젝트는 트릭컬 IP를 활용한 팬게임 형태로 제작한다.

원작의 이미지, 음성, 게임 리소스 등을 무단으로 추출하여 사용하는 것을 지양하며, 가능한 한 자체 제작 또는 적법하게 사용 가능한 리소스를 활용한다.

실제 공개 및 배포 시에는 &#x2A;*에피드게임즈의 최신 2차 창작 관련 정책 및 가이드라인을 반드시 확인한다.**

## 13. 프로젝트 최종 목표

최종적으로 다음의 세 가지 결과물을 하나의 시스템으로 연결하는 것을 목표로 한다.

### 1. Playable Game

Unity + C# 기반의 실제 플레이 가능한 로그라이크 팬게임

### 2. Data Backend

게임 플레이 데이터를 수집하고 저장하며 통계 데이터로 가공하는 Backend + Database

### 3. Web Service

축적된 데이터를 활용하여 유저 전적과 게임 통계를 제공하는 Web Dashboard

```text
┌──────────────────────┐
│      GAME            │
│ Unity + C#           │
│                      │
│ 트릭컬 IP 팬게임      │
└──────────┬───────────┘
           │
           │ Play Data
           ▼
┌──────────────────────┐
│      BACKEND         │
│ Node.js + TypeScript │
│                      │
│ REST API             │
└──────────┬───────────┘
           │
           ▼
┌──────────────────────┐
│      DATABASE        │
│ PostgreSQL           │
│ Supabase             │
└──────────┬───────────┘
           │
           ▼
┌──────────────────────┐
│       WEB            │
│ Next.js + TypeScript │
│                      │
│ 전적 / 통계 / 랭킹    │
└──────────────────────┘
```

**핵심 목표:**

> **“게임을 만들었다”에서 끝나는 것이 아니라, 게임에서 생성된 데이터를 실제 서비스에서 활용할 수 있는 하나의 시스템으로 완성한다.**
