## 1. 이 문서의 역할

첫째 달부터 셋째 달까지 Unity → Backend → Database → Web의 전체 흐름과 3층 Run, 스킬,
아티팩트, 메타 성장, 전적, 통계와 랭킹을 완성했다. 넷째 달에는 새로운 시스템의 수를 늘리기보다
현재 플레이에서 확인된 다음 문제를 해결한다.

1. 플레이에 필요한 HP, SP, 스킬, 아티팩트와 진행 정보가 충분히 보이지 않는다.
2. 게임 실행 직후 전투 화면이 노출되고 홈·설정·성장으로 이어지는 제품 흐름이 없다.
3. 방의 절대 크기와 전투 공간이 작고 모든 방의 체감이 비슷하다.
4. 현재 적 3종은 감지 거리 밖에서 쉽게 무력화되며 행동과 조합이 단순하다.
5. 층별 보스의 고유 패턴과 공략 과정이 아직 확정되지 않았다.
6. 아티팩트가 존재하지만 플레이어가 보상을 비교하고 선택하는 과정이 부족하다.

이번 달은 **화면 흐름과 전투 가독성 → 공간과 Encounter → 적 행동과 보스 → 선택 보상과
종합 플레이테스트** 순서로 진행한다. 정식 아트를 먼저 완성하지 않고 임시 UI와 기능성 에셋으로
규격과 재미를 검증한 뒤 교체한다.

## 2. 시작 시점의 확정 기반

### 완료된 게임 흐름

- 에르핀 1종으로 시작하는 3층 전체 Run
- 층당 6~8개의 seed 기반 격자형 방
- 시작방·일반 전투방·보물방·보스방
- 추적형·원거리형·돌진형 일반 적 3종
- 층별 보스와 최종 보스 진행
- 기본 공격, SP, 저학년 스킬과 고학년 스킬
- 활성 아티팩트 10종, 등급, 최대 스택과 시너지
- Run 종료 경험치와 스킬 포인트 기반 영구 성장
- Run 저장, Web 전적·통계·랭킹 연동

### 이번 달의 제품 방향

- 캐릭터 수는 에르핀 1종으로 유지한다.
- 16:9 화면 비율과 한 화면에 한 방이 보이는 원칙을 유지한다.
- 기준 UI 해상도는 `1920 × 1080`으로 한다.
- 게임용 계정이나 로그인 대신 한 PC의 **로컬 플레이어 프로필**을 사용한다.
- 타이틀·홈을 전투 Scene과 분리하고 게임 시작 전에는 전투 맵을 노출하지 않는다.
- 기존 `16 × 9` 방을 삭제하지 않고 더 큰 Room Profile과 Encounter를 추가해 비교한다.
- 새 일반 적을 추가하기 전에 기존 3종의 역할과 대응 방법을 완성한다.
- 정식 장식 에셋보다 플레이 정보와 공격을 읽게 해주는 기능성 에셋을 우선한다.

## 3. 넷째 달 최종 완료 조건

2026-12-07까지 다음 흐름을 한 게임 안에서 반복할 수 있어야 한다.

```text
EXE 실행
  → 타이틀 화면
  → 최초 사용자라면 닉네임 등록
  → 홈 화면
  → 캐릭터 선택
  → 서로 다른 크기와 Encounter의 방 진행
  → HUD를 보며 스킬과 아티팩트 상태 판단
  → 행동이 명확한 일반 적 3종과 전투
  → 층별 보스 전투
  → 아티팩트 후보 3개 중 1개 선택
  → 최종 클리어 또는 사망
  → 결과 확인
  → 홈 또는 캐릭터 선택
```

### 플레이 경험 완료 조건

- 사용자는 게임 실행부터 Run 시작까지 전투 Scene을 보지 않고 이동할 수 있다.
- 최초 사용자는 중복되지 않는 닉네임으로 로컬 플레이어 프로필을 만들 수 있다.
- 사용자는 전투 중 HP, SP, 스킬, 아티팩트, 방·층과 보스 상태를 확인할 수 있다.
- 기존 크기와 1.5배 크기 이상의 방이 같은 Run에서 서로 다른 전투 공간으로 느껴진다.
- 적은 방 전투가 시작되거나 피격된 뒤 감지 거리 밖에서 무력화되지 않는다.
- 추적형은 거리 관리, 원거리형은 파고들기, 돌진형은 회피라는 서로 다른 대응을 요구한다.
- 보물방과 보스 보상에서 후보를 비교하고 하나를 선택할 수 있다.
- 보스의 공격은 예고, 대응 방법과 공격 후 빈틈을 제공한다.
- 전체 Run을 여러 seed로 완료하며 심각한 진행 차단이나 중복 보상이 없다.

## 4. 이번 달에서 제외하는 범위

- 새 플레이 캐릭터
- 계정, 비밀번호, 로그인과 사용자 전환
- 닉네임 변경
- 상점과 엘리프 경제
- 열쇠와 잠긴 보물방
- 이벤트방·비밀방
- 새로운 일반 적 종류
- 3층을 넘는 추가 층
- 한 화면 원칙을 벗어나는 대규모 맵
- 방 내부 장애물과 spawn point의 완전 절차적 생성
- 캐릭터·몬스터·배경 전체의 정식 아트 교체
- 고품질 연출과 전체 사운드 완성

위 항목은 다섯째 달 이후의 게임 콘텐츠 확장 후보로 둔다. 다만 넷째 달의 UI와 전투 가독성을
검증하기 위한 임시 배경, 아이콘, 공격 예고, 피격 효과와 샘플 사운드는 사용한다.

# 6. 13주차 — Frontend와 전투 UI

## 목표

게임 실행 직후 전투 화면이 노출되는 현재 구조를 타이틀·홈 중심의 제품 흐름으로 교체하고,
플레이어가 전투 판단에 필요한 정보를 확인할 수 있는 최소 HUD를 완성한다.

## 권장 진행 순서

```text
UI 규격 확정
  → Frontend Scene 분리
  → 타이틀과 Frontend 화면 상태 관리
  → 닉네임 등록 UI와 프로필 등록 계약
  → 홈 화면 골격
  → 로컬 프로필 재실행·오류 통합 검증
  → 스킬 강화와 설정
  → 캐릭터 선택
  → Game Scene 진입과 로컬 Run 초기화
  → 전투 HUD(HUD-1~7B)
  → Run 결과와 Frontend 복귀
  → 일시정지에서 홈 나가기(HUD-7C)
  → 전체 흐름 통합 검증
  → 임시 에셋 교체 규격 확정
```

## 작업 조각과 진행 기준

13주차 작업은 아래 조각 단위로 구현하고 검증한다. 표의 순서는 시스템 의존성 순서이며,
앞 조각의 완료 조건을 만족한 뒤 다음 조각으로 이동한다. 서로 독립적인 화면 배치 작업은 먼저
진행할 수 있지만, 프로필·Run·설정 데이터를 임시 값으로 우회한 상태를 해당 조각의 완료로
처리하지 않는다.

### 5. 통합 검증과 작업 단위 운영

- 각 조각은 구현 코드, 가장 가까운 자동 검증, 필요한 수동 확인과 검증 기록 갱신까지 하나의
  작업 단위로 취급한다.
- 자동 검증 또는 사용자가 제공한 수동 확인 근거가 있는 항목만 아래 필수 작업 체크리스트와
  조각 상태에서 완료로 바꾼다.
- `Flow-0~1 → Profile-1~2 → Flow-2 → Profile-3~4 → Skill·Setting-1A~1B →
  Flow-3 → Flow-4 → HUD-1~7B → Flow-5 → HUD-7C·Setting-1C`의 전체 흐름을 마지막에
  EXE로 확인한다.
- 전체 흐름 검증은 신규 프로필, 기존 프로필 재실행, 등록 네트워크 실패 후 재시도, Run 클리어,
  Run 사망, 결과 저장 실패 후 재시도와 홈 복귀를 각각 포함한다.
- Frontend는 프로필·설정·선택 상태를 표시하고 요청하지만 전투 상태를 소유하지 않는다. Game
  Scene의 `RunSession`은 한 Run의 상태를 소유하며, Backend Run 레코드는 종료 결과 저장 시 만든다.

### HUD-1 HP·SP 전투 상태 자동·Build 검증 — 2026-09-09

Game Scene의 플레이어 `Health`, `PlayerSP`, `PlayerSkill`을 좌상단 생존 HUD에 직접 연결했다. HP는
현재·최대 수치와 가로 게이지로 표시하고 피해·회복 방향에 따라 짧은 오버레이 피드백을 제공한다.
SP는 하나의 40×40 임시 도형을 최대치만큼 반복하며 획득·소비와 최대 SP 증가 때 슬롯 수와 활성

# 7. 14주차 — Room Profile과 Encounter

| 프로필 | 내부 세로 기준 | 카메라 Ortho Size 후보 | 우선 용도 |
|---|---:|---:|---|

# 8. 15주차 — 일반 적 3종과 보스 전투

## 목표

감지 거리 밖에서 적을 일방적으로 공격하는 문제를 제거하고 추적형·원거리형·돌진형이 서로
다른 이동과 공격 대응을 요구하게 한다. 층별 보스는 원작 보스 선정 후 상세 패턴을 확정한다.

## 공통 적 인식 계약

```text
대기
  → 방 전투 시작 또는 피격
경계
  → 플레이어가 멀어져도 추적·공격 유지
  → 방 클리어, 플레이어 사망 또는 방 비활성화 시 종료
```

- 감지 범위는 전투 전 활성화나 행동 시작 조건으로 사용할 수 있다.
- 한 번 경계한 적은 같은 전투 중 단순히 감지 범위를 벗어났다는 이유로 대기 상태로 돌아가지 않는다.
- 방 전투가 시작되면 해당 Encounter의 모든 적을 경계 상태로 만드는 것을 기본값으로 한다.
- 피격된 적은 공격 출처를 기준으로 즉시 플레이어를 인식한다.

## 적 3종의 대응 축

| 적 | 위협 방식 | 플레이어의 대응 |
|---|---|---|
| 추적형 | 붙어서 압박하고 근접 공격 | 거리 관리 |
| 원거리형의 저격형 변형 | 멀리서 멈춰 저격 | 파고들기 |
| 돌진형 | 방향을 고정한 직선 돌진 | 옆으로 회피 |

세 적이 모두 거리를 벌리는 대응만 요구하면 조합을 섞어도 플레이가 비슷해진다. 저격형 변형이
접근을 요구하는 축을 맡아 추적형·돌진형과 반대 방향의 압박을 만든다.

저격형은 기존 원거리형을 보존한 채 변형으로 추가한다. 이번 달 원거리 대응 축은 저격형으로
검증하며, 기존 원거리형을 대체할지는 플레이테스트 후 결정한다.

## 피해 모델 계약

- 원거리형과 돌진형은 접촉만으로 피해를 주지 않고 공격 동작 구간에서만 피해를 준다.
- 추적형은 접촉 피해와 예고 있는 근접 공격을 함께 가지며, 둘 다 해당 적의 공격력에 맞는 피해를 준다.
- 추적형의 접촉 피해는 근접 공격의 예고·회복 중에도 유지한다. 회복은 공격 동작과 추격의 빈틈이며 몸에 닿아도 안전한 시간은 아니다.
- 접촉 피해와 공격 피해는 플레이어의 같은 무적 시간을 공유하며 한 번에 두 번 적용되지 않는다.
- 새 공격을 추가할 때 접촉 피해를 함께 두려면 무적 시간 공유 여부를 먼저 확인한다.

## 필수 작업

### 공통 행동과 가독성

- [ ] 경계 상태 계약을 세 컨트롤러에 각각 구현하지 않고 공유 컴포넌트 하나로 제공한다.
- [ ] 방 전투 시작, 피격, 플레이어 사망과 방 비활성화에 맞춰 경계 상태를 전환한다.
- [ ] 먼 거리에서 공격하는 플레이어를 감지하지 못해 멈춰 있는 악용 경로를 제거한다.
- [ ] 넉백·사망·공격 예고 중의 이동 금지를 하나의 판정으로 통합하고 각 컨트롤러가 이를 참조한다.
- [ ] 세 컨트롤러에 중복된 대상 탐색과 행동 억제 로직을 공유 계약으로 정리한다.
- [ ] 플레이어의 공통 피격 무적 시간을 구현해 접촉·근접 공격·투사체·돌진의 중복 피해를 차단하고, 고학년 스킬 무적과 서로 해제하지 않게 한다.
- [ ] 공격 예고, 실제 위험 구간과 공격 후 빈틈을 색상 외의 형태·동작으로도 구분한다.
- [ ] 경직·넉백·사망·방 전환 중 진행 중인 공격이 올바르게 취소되는지 확인한다.
- [ ] 적이 방 경계 밖으로 이탈하지 않는지 회귀 확인한다. 벽 콜라이더로 이미 차단되어 있으므로
  신규 구현이 아니라 확인 항목으로 다룬다.

### 추적형

- [ ] 자체 공격 범위를 두고 플레이어가 그 안에 들어오면 근접 공격을 시작한다.
- [ ] 근접 공격 전에 짧고 읽을 수 있는 예고를 제공하고 예고 중에는 이동을 멈춘다.
- [ ] 근접 공격 판정은 공격 동작 구간에서만 활성화한다. 접촉 피해 판정은 별도로 유지한다.
- [ ] 공격 후 플레이어가 반격하거나 거리를 벌릴 수 있는 빈틈을 제공한다.
- [ ] 접촉 피해와 근접 공격 피해를 해당 적의 공격력 기준으로 적용하고, 예고·회복 중에도 접촉 피해를 유지한다.
- [ ] 근접 공격을 추격 로직에 직접 넣지 않고 별도 컴포넌트로 분리해 프리팹 단위로 적용한다.
- [ ] 추격과 공격이 같은 이동 제어를 다투지 않도록 이동 금지 판정을 공유한다.
- [ ] 플레이어를 지속적으로 추적하되 공통 피격 무적 시간으로 접촉 피해의 연속 중첩을 방지한다.

추적형끼리의 위치 겹침은 허용하며, 개체 간 분리 이동은 이번 달 필수 작업에 포함하지 않는다.

### 원거리형 변형 — 롱레인지 저격형

- [ ] 전투 정체성을 "멀리서 멈춰 쏘고 파고들면 약한 적"으로 확정한다.
- [ ] 기존 원거리형을 보존하고 저격형을 원거리형의 변형으로 추가한다.
- [ ] 재배치 → 정지 조준 → 발사 → 회복 사이클을 반복한다.
- [ ] 재배치 중 앞뒤 거리 조절과 필요에 따른 좌우 이동으로 다음 사격 위치를 선택한다.
- [ ] 플레이어가 정지해 있어도 사이클에 따라 재배치하되, 좌우 이동을 항상 강제하지 않는다.
- [ ] 이동 중에는 발사하지 않고 발사할 때는 정지한다.
- [ ] 가까운 거리라는 이유만으로 사격 시작을 금지하지 않는다.
- [ ] 사격 전 조준 방향과 발사 시점을 읽을 수 있는 예고를 제공한다.
- [ ] 발사 후 짧은 경직을 두어 플레이어가 거리를 좁힐 기회를 만든다.
- [ ] 후퇴 속도를 플레이어 이동 속도보다 느리게 두어 무한 도주를 막는다.
- [ ] 일정 시간마다 이동 방향을 재평가하고 벽이나 다른 적에게 막히면 좌우 방향을 뒤집는다.
- [ ] 구석에 몰린 상황을 별도 상태로 만들지 않고 좌우 성분과 방향 재선택으로 해소한다.
- [ ] 사거리는 대형 방에서 검증하고 기존 방에는 배치하지 않거나 사거리를 줄인 변형을 사용한다.

> 저격형의 빈틈은 매번 한 번에 처치할 수 있게 보장하는 것이 아니라 조준·발사·회복 사이에
> 거리를 좁히고 공격할 기회다. 후퇴 속도와 플레이어 이동 속도의 차이, 재배치 시간과 정지 시간을
> 함께 조율해 현재 4방향 사격으로 접근과 명중 기회가 생기는지 확인한다.

### 돌진형

- [ ] 기존 예고 → 돌진 → 회복 상태를 보존하고 경계 상태와 연결한다.
- [ ] 예고 중 돌진 경로와 고정된 방향을 명확하게 표시한다.
- [ ] 벽 충돌 또는 돌진 종료 후 플레이어가 공격할 수 있는 빈틈을 강화한다.
- [ ] 돌진 거리와 방 크기의 비율을 대형 방 도입 후 다시 확인한다.

> 여러 돌진형의 동시 돌진은 방향이 예고 시작 시점에 고정되어 대체로 회피 가능하므로 사전
> 차단 대상으로 두지 않고 16주차 플레이테스트 관찰 항목으로 옮긴다.

### 층별 보스

- [ ] 1·2·3층에 사용할 트릭컬 보스 몬스터를 각각 선정한다.
- [ ] 원작의 특징과 현재 조작 체계에 맞는 보스별 전투 정체성을 한 문장으로 정의한다.
- [ ] 각 보스에 최소 3개의 행동 또는 공격, 예고, 대응 방법과 공격 후 빈틈을 정의한다.
- [ ] 1층은 기본 패턴 학습, 2층은 공간과 패턴 조합, 3층은 페이즈 전환과 복합 대응을 목표로 한다.
- [ ] 최종 보스는 최소 한 번의 페이즈 또는 패턴 조합 변화를 갖는다.
- [ ] 보스 캐릭터 선정 전에는 구체적인 패턴 구현을 확정 완료로 처리하지 않는다.

> **미정:** 보스 3종의 이름과 상세 패턴은 사용자가 트릭컬 보스 몬스터를 선정하고 구상을
> 공유한 뒤 확정한다. 문서 확정 전까지 임의의 캐릭터나 패턴을 영구 계약으로 추가하지 않는다.

## 완료 조건

> 일반 적 3종이 방 전투 시작 이후 플레이어를 놓치지 않고 각자 다른 이동·공격·빈틈을 보인다.
> 추적형은 거리 관리를, 원거리형은 파고들기를, 돌진형은 회피를 요구하며 서로 섞인
> Encounter에서도 공격을 읽고 대응할 수 있다. 보스 3종은 선정된 원작 정체성에 맞는
> 패턴 계약과 검증 가능한 완료 조건을 갖는다.

# 9. 16주차 — 선택 보상과 종합 플레이테스트

## 목표

아티팩트를 무작위로 하나 받는 흐름을 후보 비교와 선택으로 바꾸고, 여러 Room·Encounter·적·보스가
포함된 전체 Run을 반복해 전투와 빌드 선택의 재미를 검증한다.

## 필수 작업

### 아티팩트 선택 보상

- [ ] 보물방과 1·2층 보스 처치 후 아티팩트 후보 3개를 표시한다.
- [ ] 각 후보에 이름, 등급, 효과, 현재 스택과 최대 스택을 표시한다.
- [ ] 현재 활성 상태이고 최대 스택이 아닌 아티팩트만 후보에 포함한다.
- [ ] 후보 하나를 선택하면 나머지 후보를 제거하고 선택한 아티팩트만 적용한다.
- [ ] 획득 가능한 후보가 부족한 경우 후보 수 축소 또는 회복 대체 규칙을 확정한다.
- [ ] 회복 대체 보상은 현재 HP와 최대 HP를 표시하고 선택 결과를 즉시 반영한다.
- [ ] 선택 중 전투 입력, 방 이동과 다음 층 이동을 차단한다.
- [ ] 재방문하거나 선택 입력을 반복해도 보상이 중복 지급되지 않는다.
- [ ] 같은 seed에서 후보까지 재현할지, 보상 진입 시 별도 결정값을 사용할지 계약을 확정한다.
- [ ] 선택한 아티팩트만 기존 획득 순서와 Run 결과에 기록한다.

### 보상 UI와 입력

- [ ] 마우스와 키보드로 세 후보를 이동하고 하나를 확정할 수 있다.
- [ ] 선택된 카드와 선택 불가능한 상태를 색상 외 표현으로 구분한다.
- [ ] 긴 효과 설명과 최대 스택 표기가 `1920 × 1080`에서 잘리지 않는다.
- [ ] 선택 후 HUD의 아티팩트와 스탯 변화가 즉시 갱신된다.

### 전체 Run 플레이테스트

- [ ] 서로 다른 seed로 전체 3층 Run을 반복한다.
- [ ] 기존 방과 대형 방의 이동 시간, 피격량과 전투 밀도를 비교한다.
- [ ] Encounter별 클리어 시간과 주된 피격 원인을 기록한다.
- [ ] 감지 거리 밖 공격, 문 주변 공격과 spawn 안전지대 악용 여부를 확인한다.
- [ ] 적 조합에 회피 불가능하거나 지나치게 수동적인 상황이 없는지 확인한다.
- [ ] 여러 돌진형의 동시 돌진이 실제로 회피 불가능한지 관찰하고 필요할 때만 조정한다.
- [ ] 저격형의 멈춤·발사·경직 사이클에서 플레이어가 실제로 거리를 좁힐 수 있는지 확인한다.
- [ ] 추적형의 접촉 피해와 근접 공격 중 어느 쪽이 주된 피격 원인인지 구분해 기록한다.
- [ ] 보스 패턴별 피격 원인과 공격 기회가 명확한지 확인한다.
- [ ] 후보 선택이 현재 빌드와 이후 플레이 방식을 실제로 바꾸는지 확인한다.
- [ ] 거의 선택되지 않거나 항상 선택되는 아티팩트를 기록하고 원인을 구분한다.
- [ ] 한 Run의 10~15분 목표와 층별 소요 시간을 측정한다.
- [ ] 클리어와 사망 Run이 한 번만 저장되고 결과·Web 통계에 반영되는지 확인한다.

### 회귀 검증

- [ ] Backend의 사용자 등록·진행·Run 관련 Jest 테스트와 `pnpm build`를 통과한다.
- [ ] Web 계약을 변경했다면 `pnpm lint`와 `pnpm build`를 통과한다.
- [ ] Unity의 Room 생성 결정성, 재방문 상태, 스킬, 아티팩트와 Run 저장 검증을 통과한다.
- [ ] 자동 검증이 어려운 UI와 체감 항목은 정확한 메뉴 경로, 입력과 기대 결과를 기록한다.
- [ ] 실제 플레이 증거가 없는 밸런스·체감 항목은 완료 처리하지 않는다.

## 완료 조건

> 신규 또는 기존 로컬 플레이어가 홈에서 Run을 시작하고, 정보를 확인하며 다양한 크기의 방과
> 적 조합을 공략하고, 보상을 비교해 빌드를 선택하고, 최종 결과를 저장할 수 있다. 여러 seed의
> 전체 Run에서 심각한 진행 차단, 회피 불가능한 조합과 중복 보상이 발견되지 않는다.

## 10. 에셋 제작과 적용 원칙

에셋은 사용자가 직접 준비하되 구현 전에 용도와 크기를 합의한다. 에셋 제작 때문에 기능 검증을
막지 않으며, 임시 에셋으로 화면과 전투를 먼저 확인한 뒤 교체한다.

### 우선 제작할 기능성 에셋

- 홈 화면 임시 배경과 게임 로고
- HP·SP·저학년·고학년 스킬 아이콘
- 아티팩트 아이콘과 선택 카드에 필요한 등급 표현
- 적 공격 범위, 조준 방향과 돌진 경로 예고
- 피격·회복·SP 획득·무적 상태 표현
- 보스 HP와 페이즈 구분 요소
- 장애물과 방 크기를 구분하는 간단한 타일
- 버튼·패널·팝업의 기본 UI 구성 요소
- 최소한의 피격·회복·선택·보스 공격 효과음

### 에셋 명세에 포함할 정보

- 사용 화면과 용도
- 권장 픽셀 크기와 비율
- 투명 배경 여부
- 기본·호버·선택·비활성 상태
- 9-slice 적용 여부와 테두리 영역
- 파일명과 Unity 저장 위치
- Pixels Per Unit과 필터 설정
- 애니메이션이 필요할 경우 프레임 크기와 수

### 후순위 에셋

- 캐릭터·몬스터·보스 정식 스프라이트 전체 교체
- 정식 방 배경과 대규모 타일 세트
- 고품질 VFX와 화면 전환 연출
- 전체 BGM과 상황별 사운드 완성

## 11. 플레이테스트 기록 기준

넷째 달의 완료 판단은 구현 수가 아니라 실제 플레이 변화에 둔다. 최소한 다음 내용을 기록한다.

| 항목 | 확인 목적 |
|---|---|
| Room Profile별 이동·클리어 시간 | 방이 넓기만 하고 비어 있지 않은지 확인 |
| Encounter별 피격량과 사망 원인 | 적 조합의 공정성과 위협도 확인 |
| 적 유형별 공격 성공·회피 체감 | 역할과 대응 방법 구분 |
| 보스 패턴별 피격 원인 | 예고와 안전지대 검증 |
| 아티팩트 후보와 실제 선택 | 선택 편향과 사장된 효과 확인 |
| 층별·전체 Run 시간 | 10~15분 목표 확인 |
| 네트워크 성공·실패와 재시도 | 결과 저장 안정성 확인 |

플레이테스트 텔레메트리 자동화는 [13-development-tooling-plan.md](./13-development-tooling-plan.md)의
T4 범위와 연결한다. 자동 수집이 이번 달 기능을 지연시키면 먼저 수동 기록으로 근거를 남긴다.

## 12. 일정이 밀릴 때의 축소 순서

다음 순서로 범위를 줄인다.

1. 홈과 전투 UI의 장식·전환 애니메이션을 제외한다.
2. 실패한 Run의 재실행 후 로컬 재전송을 제외한다.
3. 기둥·장애물 Room Profile을 제외한다.
4. 2배 보스방을 제외하고 기존 방과 1.5배 방만 유지한다.
5. Encounter 수를 줄이되 혼합 조합과 웨이브를 각각 하나 이상 유지한다.
6. 아티팩트 카드의 연출을 제외하고 텍스트와 아이콘으로 비교한다.

다음 항목은 축소하지 않는다.

- 타이틀 → 로컬 프로필 → 홈 → 캐릭터 선택 → Run의 기본 흐름
- Game Scene과 Frontend의 분리
- HP·SP·스킬·아티팩트·진행 상태 HUD
- 기존 Room 보존과 대형 Room Profile 1종 검증
- 방 전투 시작 또는 피격 후 적의 지속 경계 상태
- 일반 적 3종의 구분되는 이동·공격·빈틈
- 아티팩트 후보 비교와 1개 선택
- 보상 중복 방지와 전체 Run 회귀 검증

보스 3종의 세부 패턴은 선정이 늦어질 경우 임의로 대체하지 않는다. 선정된 보스부터 계약과 구현을
완료하고, 남은 보스의 미정 상태와 다음 실행 순서를 명확하게 기록한다.

## 13. 다음 계획 후보

넷째 달의 전투 가독성, Room Profile, Encounter와 선택 보상이 검증된 뒤 다음 후보를 검토한다.

- 수작업 Room Layout 기반 장애물·함정과 제한적 배치 랜덤화
- 상점과 엘리프 경제
- 열쇠와 잠긴 보물방
- 폭탄과 파괴 가능한 벽, 이벤트방·비밀방
- 새로운 일반 적과 Encounter 확장
- 보스 추가 또는 기존 보스 고도화
- 아티팩트와 시너지 확장
- 정식 캐릭터·몬스터·보스·방 에셋 적용
- BGM, 효과음과 전투 연출
- 게임 빌드와 배포 준비

다섯째 달 범위는 넷째 달 플레이테스트에서 확인된 가장 큰 반복성 문제를 기준으로 정하며,
기능 목록을 미리 모두 필수 범위로 확정하지 않는다.

### 우선 예정 작업 — Room Layout과 장애물·함정

넷째 달에 검증한 방 크기와 적 행동을 바탕으로, 다섯째 달에는 지형에 따라 이동 경로와 공격
방법을 선택하는 전투를 실험한다. 기본 방향은 다음과 같다.

| 구성 | 제작·선택 방식 |
|---|---|
| Room Layout | 벽·출입구·통로를 수작업으로 배치 |
| 장애물·함정 | 기본 위치와 회피 공간을 수작업으로 설계 |
| 일부 장식·파괴물 | 미리 지정한 안전한 후보 위치에서 랜덤 활성화 |
| 적 종류·조합 | 해당 Layout에 맞는 Encounter 후보 중 랜덤 선택 |
| 일부 SpawnPoint | 선택한 Encounter에 적합한 지점 또는 spawn group을 랜덤 활성화 |

- [ ] Room Profile의 방 크기·카메라 계약과 연결되는 수작업 Room Layout을 구성한다.
- [ ] 같은 방 크기와 적 조합으로 빈 방, 기둥이 있는 방, 고정 함정이 있는 방을 비교한다.
- [ ] 장애물로 사선을 끊거나 함정의 안전 시간에 접근하는 등 전투 판단이 달라지는지 검증한다.
- [ ] SpawnPoint에 후방 사격·근접 압박·돌진 경로 확보 등의 배치 역할을 지정한다.
- [ ] 적 종류와 SpawnPoint를 독립적으로 추첨하지 않고, Layout·Encounter·배치 역할의 적합성을 확인해 선택한다.
- [ ] 랜덤 파괴물이 출입구·필수 통로·함정 회피 공간을 막지 않도록 후보 위치를 제한한다.
- [ ] 같은 seed와 콘텐츠 버전에서 Layout·장식·파괴물·Encounter·활성 SpawnPoint 선택을 재현한다.
- [ ] 재방문 시 파괴물 상태와 Encounter 진행을 보존하고, 배치 재추첨·적 재생성·보상 중복을 방지한다.

### 구현 전에 정할 규칙

아래 항목은 미정이며 다섯째 달의 상세 계획에서 확정한다.

- [ ] 장애물별로 플레이어·적·투사체·돌진 중 무엇을 막는지 정한다.
- [ ] 파괴물별로 누가 어떤 공격으로 파괴할 수 있는지, 파괴 후 통로 개방과 드롭 여부를 정한다.
- [ ] 함정의 작동 조건·예고·위험 구간·안전 시간과 플레이어·적 피해 여부를 정한다.
- [ ] 함정이 전투 종료 후에도 작동하는지, 재방문 시 작동 상태를 어떻게 처리할지 정한다.
- [ ] 장식과 전투 지형을 구분하고, 랜덤 활성화 수·확률·동시 배치 제한을 정한다.
- [ ] 적 이동과 저격 사선, 돌진이 장애물에 막혔을 때의 행동을 정한다.
- [ ] 첫 구현의 장애물·파괴물·함정 종류와 Layout 수는 넷째 달 플레이테스트 결과에 맞춰 정한다.

### 탐색·소모 자원 확장 후보와 결정 사항

상점·열쇠·폭탄·비밀방은 서로 연결되는 확장 후보이며, 전부를 다섯째 달 필수 작업으로
확정한 것은 아니다. 아래 규칙을 정한 뒤 구현 범위와 순서를 확정한다.

- [ ] 상점: 엘리프 획득·소비·Run 종료 시 유지 여부, 상품 후보·가격·재고와 구매 상태 보존을 정한다.
- [ ] 열쇠: 획득 경로·보유 한도·소비 대상과 잠긴 방을 열지 못했을 때의 진행 규칙을 정한다.
- [ ] 폭탄: 획득 경로·보유 한도·설치 입력·폭발 예고·범위·피해 대상과 파괴 가능한 지형을 정한다.
- [ ] 비밀방: 생성·인접 조건, 발견 단서, 진입 수단과 보상을 정한다. 폭탄 벽을 사용할지도 함께 확정한다.
- [ ] 소모 자원이 없어도 필수 진행 경로를 완료할 수 있는지 확인하고, 선택 보상 접근 조건과 구분한다.
- [ ] 잠금 해제·구매·폭탄 소비·벽 파괴·보상 수령 상태를 재방문 시 보존하고 중복 소비·지급을 방지한다.
