# 전투 이펙트 제작 가이드

작성일: 2026-10-07. 신규 이펙트 제작과 기존 이펙트 개선에 공통 적용한다.
이 문서는 제작 기준이며, 개별 이펙트의 구현 완료나 미술 검수 통과를 의미하지 않는다.

## 1. 목표와 우선순위

이펙트는 어떤 행동이 어디에서 일어났는지 전달하면서 캐릭터와 게임의 그림체에 어울려야 한다.
공격 방향·타격 순간·착지 위치·회복 종류를 먼저 읽을 수 있게 하고, 그 위에 강도와 재미를 더한다.

- 작은 SD 캐릭터와 밝은 배경에 맞는 명확한 실루엣과 정돈된 색을 사용한다.
- 가장 밝은 핵심 부분과 덜 밝은 잔광을 구분한다. 화면 전체를 같은 밝기의 빛으로 채우지 않는다.
- 일반 공격·회복은 캐릭터 가독성을 우선한다. 필살기는 더 크게 연출하되 위험 정보와 플레이어 위치를 확인할 수 있어야 한다.
- 시각 효과를 키우거나 재생 시간을 바꿀 때 피해 범위·피해 시점·무적 시간도 자동으로 바꾸지 않는다.
- 경고 영역은 실제 위험을 전달하고, 착지 그림자는 착지 위치를 전달한다. 장식용 잔광까지 피해 영역으로 오해하게 하지 않는다.

## 2. 제작 전에 정할 내용

각 이펙트는 아래 항목을 작업 기록에 적고 시작한다. 모르는 값은 임의로 확정하지 말고 가정으로 표시한다.

| 항목 | 정할 내용 |
|---|---|
| 사용처 | 캐릭터·적·스킬, 어떤 이벤트에서 발생하는지 |
| 전달 정보 | 피해 경로, 타격, 실제 회복, 착지 위치 등 |
| 참고 자료 | 게임 화면·사용자 스케치·원화, 참고할 형태와 타이밍 |
| 기준점 | 발, 몸 중심, 무기 끝, 충돌점, 고정된 공격 경로 |
| 방향 | 원본이 향하는 방향, 좌우 반전 여부, 바닥의 위쪽 방향 |
| 크기 | 캐릭터 대비 높이·두께, 경로 길이와 함께 바뀔 부분 |
| 단계 | 준비 → 발생 → 최대 강도 유지 → 소멸, 각 단계 시간 |
| 레이어 | 각 요소의 제작 방식, 앞뒤 순서, 독립 조절 항목 |
| 경계 | 방 중앙·벽·모서리·짧은 경로에서 어떻게 보일지 |
| 검수 | 원화, 움직임, 실제 Play 화면에서 확인할 항목 |

참고 이미지는 원하는 형태를 설명하는 자료로 다룬다. 참고 게임이 같은 도구나 내부 구현을 사용한다고 추정하지 않는다.

## 3. 요소마다 제작 방식을 선택한다

| 방식 | 적합한 요소 | 제작 시 주의 |
|---|---|---|
| 직접 그린 프레임 애니메이션 | 검격, 형태가 변하는 검광, 폭발 | 프레임 사이의 변화와 기준점이 일관되어야 한다. |
| 단일 이미지 + 파티클 | SP 입자, 불꽃, 먼지, 작은 파편 | 이동·수명·크기·회전·투명도를 엔진에서 조절한다. |
| 셰이더·코드 | 피격 점멸, 윤곽, 단순 경고 화살표, 잔광 감쇠 | 단순 도형을 그리는 것만으로 미술 품질이 완성됐다고 판단하지 않는다. |
| 별도 메시·텍스처 이동 | 길이가 달라지는 빛줄기·경로 효과 | 형태가 중요한 시작·끝부분과 길이를 조절할 몸통을 구분한다. |
| 합성 연출 | 큰 스킬·보스 필살기 | 위 요소에 캐릭터 동작·소리·필요한 화면 연출을 타격 시점에 맞춘다. |

모든 효과에 스프라이트 시트가 필요한 것은 아니다. 반대로 프레임 애니메이션이 필요한 효과를 단일 이미지의 확대·축소만으로 대체하지 않는다.
AI 이미지 생성은 원화와 형태 후보를 만드는 데 사용할 수 있지만, 생성 결과를 바로 최종 애니메이션으로 취급하지 않는다.
프레임별 형태·방향·여백·알파·기준점·연속성을 확인하고 필요한 수정을 거친다. 생성·편집 이력과 최종 사용 파일을 기록한다.

## 4. 독립 레이어로 구성한다

크기·방향·타이밍·투명도 중 하나라도 다르게 조절할 요소는 분리한다.
레이어 수를 늘리는 것 자체가 목표는 아니며, 분리할 이유가 있는 요소만 나눈다.

용사용 내려찍기의 구성 예시는 다음과 같다. 이는 향후 제작안이며 모든 레이어가 현재 적용된 것은 아니다.

| 레이어 | 역할 | 독립 조절 |
|---|---|---|
| 무기 근처 섬광 | 공격 시작 위치와 힘 전달 | 무기 기준점, 짧은 수명, 밝기 |
| 큰 검광 | 위에서 내려오는 필살기의 실루엣 | 높이·두께, 최대 강도 유지 시간 |
| 경로를 따라 뻗는 빛 | 공격 진행 방향 표현 | 경로 길이, 시작·몸통·끝 모양 |
| 지면 충격 | 바닥에 닿은 순간 표현 | 지면 기준점, 낮은 높이, 짧은 수명 |
| 돌·먼지 | 보조 타격감 | 작은 크기, 이동, 생성 수, 소멸 |

검광을 키우려고 돌 파편까지 확대하지 않는다. 지면 충격이 검광과 어울리지 않으면 빼고 검광부터 완성한다.
용사용 내려찍기는 v21부터 검수한 뾰족한 지면 충격파와 흙·돌 파편을 독립 레이어로 런타임에 연결했다.
이전 지면 충격 시트는 사용하지 않는다. 실제 Play 미술 검수는 자동 검증과 별도로 진행한다.

## 5. 제작과 검수 순서

### A. 가장 강한 순간의 원화

1. 최대 강도의 대표 프레임을 먼저 만든다. 이 단계에서 전체 시트부터 만들지 않는다.
2. 실제 배경과 캐릭터를 함께 놓고 사용할 크기로 합성한다.
3. 방향·실루엣·밝기·기준점·캐릭터와의 거리·화면 가림을 확인한다.
4. 사용자 미술 검수를 받는다. 형태가 바뀌면 대표 프레임부터 다시 확인한다.

큰 원본 확대 화면만으로 판단하지 않는다. 실제 게임 크기에서 선명하고 용도가 읽혀야 한다.
프로토타입을 Unity에서 보여줄 수는 있지만, 미술 승인과 정식 연결 완료는 별도로 기록한다.

### B. 움직임

1. 준비·발생·최대 강도 유지·소멸의 타이밍을 정한다.
2. 대표 형태를 기준으로 전후 프레임을 만든다. 프레임 수와 시트 배치는 효과에 맞춰 정한다.
3. 연속 재생과 프레임별 정지 화면을 둘 다 확인한다.
4. 최대 강도 유지 중에는 필요한 작은 잔광 변화만 추가한다. 같은 정지 프레임 유지도 의도에 맞으면 사용할 수 있다.
5. 마지막 프레임과 투명도 감쇠를 연결해 갑자기 잘리거나 잔상이 남지 않게 한다.

동일한 시간 간격으로 프레임을 넘기는 것을 기본 답으로 삼지 않는다.
준비와 발생은 짧게, 최대 형태는 길게 유지하는 등 기술의 성격에 맞게 배분한다.
유지 시간이 길어져도 실제 피해 판정이 추가로 발생하거나 경고처럼 보이지 않는지 확인한다.

### C. 보조 효과와 Unity 연결

1. 핵심 검광·폭발이 통과한 뒤 입자·지면 충격 등 필요한 보조 효과를 추가한다.
2. 보조 효과를 끈 상태와 켠 상태를 비교한다. 핵심 형태를 흐리거나 캐릭터를 가리면 줄이거나 제거한다.
3. 실제 게임 이벤트와 연결하고 방향·위치·수명·정렬 순서를 검증한다.
4. 실제 Play에서 중앙·벽 근처·짧은 경로·여러 방향·동시 발생을 검수한다.
5. 자동 검증 결과와 사용자 미술 검수 결과를 각각 기록한다.

웹 검수 화면은 원화와 타이밍 비교용이다. Unity와 같은 에셋 및 타이밍을 사용하되,
셰이더·정렬·좌표·실제 이벤트 연결까지 동일하다고 가정하지 않는다.
검수 페이지에는 가능하면 실제 크기 합성, 연속 재생, 프레임 정지, 레이어별 표시, 좌우 방향 비교를 제공한다.
페이지가 열리지 않으면 로컬 이미지나 영상으로 검수 자료를 제공하고 실행 방법을 기록한다.

## 6. 에셋 규격과 임포트

- 실제 알파가 있는 투명 PNG를 사용한다. 흰 배경이나 체크무늬를 투명 배경 대신 넣지 않는다.
- 프레임 시트는 균일 셀을 기본으로 하며 프레임 순서·열·행·셀 크기를 기록한다.
- 효과가 셀 밖으로 넘치거나 옆 프레임이 섞이지 않도록 여백을 둔다.
- 모든 프레임의 발·지면·발생 기준점을 맞춘다. 이미 다른 기준점이면 프레임별 보정값을 명시한다.
- 투명 여백을 포함한 캔버스 중심과 실제 빛의 시작점을 구분한다. 캔버스 크기만으로 캐릭터와의 간격을 계산하지 않는다.
- 실제 표시 크기로 필요한 해상도를 정한다. 전체 시트 해상도와 프레임 한 장의 해상도를 구분한다.
- PPU·피벗·필터·압축·Max Size를 기록하고 축소 임포트와 알파 경계 번짐을 확인한다.
- 현재 Resources 이펙트의 임포트·분할 방식과 맞추거나, 변경 시 로더와 검증기를 함께 갱신한다.
- 새 `.meta`는 에셋과 함께 보존하고, 교체 시 기존 GUID를 유지한다.
- 현재 4×2·8프레임은 기존 효과의 규격이다. 앞으로의 모든 이펙트에 강제하지 않는다.

캐릭터 시트의 왼쪽 원본 방향 규칙을 이펙트에 자동 적용하지 않는다.
각 이펙트의 원본 진행 방향과 바닥 기준선을 명시한다.

## 7. 위치·방향·길이·방 경계

### 좌표와 방향

- 실제 공격의 고정된 시작점·끝점·방향을 표시에도 사용한다. 경고 뒤에 플레이어가 이동했다고 검광만 새 위치를 추적하지 않는다.
- 발·몸 중심·무기 끝·공격 경로 중 어떤 기준을 쓰는지 정하고, 필요한 시각 보정은 별도 값으로 기록한다.
- 세계 Y 보정과 효과의 로컬 방향 보정을 구분한다. 회전 후 의도하지 않은 방향으로 이동하지 않게 한다.
- 좌우 반전과 회전을 따로 검증한다. 바닥 효과가 왼쪽 공격에서 180도 회전해 상하가 뒤집히면 안 된다.
- 정지한 차징 중에도 공격 방향과 캐릭터가 바라보는 방향이 맞아야 한다.

### 크기와 경계

- 경로 길이, 검광 높이·두께, 지면 파편 크기를 독립적으로 정한다.
- 원본 비율 보존이 필요한 그림은 유지한다. 비율을 바꿔야 하는 요소는 분리하거나 그 목적에 맞는 메시·텍스처를 만든다.
- 가변 길이 효과는 시작·몸통·끝을 나누는 방식을 먼저 검토한다. 반복 몸통을 쓰면 반복 무늬와 연결부가 보이지 않는지 확인한다.
- 전체 그림을 방 안에 넣으려고 일괄 축소하는 방식은 필살기의 규모를 잃을 수 있다.
- 전체 검광을 넓은 범위에서 투명하게 만드는 방식은 핵심 부분까지 흐리게 할 수 있다.
- 벽에서 끝나는 효과는 자연스러운 끝 모양·짧은 감쇠 구간·별도 종결 효과 중 적합한 방법을 선택한다.
- 짧은 경로에서는 몸통을 줄이거나 생략하고 시작·끝을 조정하는 등 별도 구성을 검토한다. 늘림이나 반전으로 해결하지 않는다.
- 방 밖으로 나오는 장식의 허용 여부는 효과별로 정한다. 피해 경고와 장식 검광에 같은 경계 처리를 무조건 적용하지 않는다.

## 8. 검증과 완료 기준

자동 검증은 가까운 기존 검증기를 확장한다. 프레임 로드·셰이더 오류·이벤트 발생 조건·방향·기준점·수명·취소 시 제거를 확인한다.
작은 미술 조정마다 수치만 복제하는 테스트를 추가하지 않는다. 공격 경로가 달라지거나 상하가 뒤집히는 핵심 오류를 검출한다.

현재 진입점:

- Unity 메뉴: `Trickal Fan Game/Effects/Verify Reviewed Combat Effects`.
- 배치: `TrickalFanGame.Editor.ReviewedCombatEffectsVerification.VerifyWithRegressionsBatch`.
- 실행 제한·검증기 선택은 저장소의 `unity-verification-runner` 스킬과 개발 환경 문서를 따른다.

미술 검수는 다음을 실제 Play 화면에서 확인한다.

- 캐릭터·발 위치·공격 방향과 자연스럽게 연결되는가.
- 경고와 실제 공격 표시의 경로가 일치하는가.
- 왼쪽·오른쪽·수직·대각선에서 원치 않는 상하 반전이 없는가.
- 큰 방·작은 방·벽·모서리·짧은 경로에서도 핵심 형태와 선명도가 유지되는가.
- 최대 강도 유지와 소멸이 의도대로 보이는가.
- 플레이어와 적을 과하게 가리지 않고, 동시 발생에서도 필요한 정보가 읽히는가.
- 회복은 실제 회복 이벤트에서만 나오며, 공격 취소·사망·방 이동 뒤 효과가 남지 않는가.

자동 검증 통과를 미술 승인으로 대체하지 않는다. 완료는 이벤트 연결과 필요한 검증이 통과하고,
사용자가 실제 표시를 수용했을 때 기록한다. 잠정 수용은 알려진 한계와 후속 개선을 함께 남긴다.

## 9. 작업 기록 템플릿

효과별 기록은 `docs/art-prompts/`에 작성한다. 기존 효과 개선은 기존 기록에 최종 상태를 추가한다.
과거 수치와 현재 수치를 혼동하지 않도록 최종 적용 버전을 명시한다.

```markdown
# <이펙트 이름>

## 목적과 사용처
- 발생 이벤트 / 전달 정보:
- 기준점 / 실제 공격·회복 로직과의 관계:
- 참고 자료와 참고할 특징:

## 제작 구성
| 레이어 | 에셋·제작 방식 | 기준점·방향 | 크기 규칙 | 타이밍 | 정렬·투명도 |
|---|---|---|---|---|---|
| 핵심 효과 | | | | | |

- 프레임 수·셀 크기·배치·PPU·피벗·임포트 설정:
- 가변 길이 / 짧은 경로 / 벽 근처 처리:
- 생성·편집 이력 / 최종 사용 파일·버전:

## 검수와 검증
- 대표 원화 검수 결과·근거:
- 움직임 검수 결과·근거:
- Unity 실행한 검증·결과·로그:
- 실제 Play 확인 방법·결과·사용자 근거:
- 미확인 항목 / 알려진 한계 / 후속 개선:

## 최종 적용 상태
- 적용 버전·파일·연결 위치:
- 승인 / 잠정 수용 / 검수 대기:
```

## 10. 현재 효과에 적용할 때

| 효과 | 유지할 제작 방향 |
|---|---|
| 적 피격 | 이미지 없이 코드·셰이더의 빨간 윤곽과 반투명 점멸 |
| 플레이어 피격 | 기존 무적 점멸 유지 |
| HP 회복 | 발 기준의 초록빛·작은 하트, 몸을 과하게 가리지 않음 |
| SP 획득 | 파란 입자의 회전 흡수, 몸에 가까워질수록 불투명도 감소 |
| 착지 예고 | 납작한 바닥 그림자, 피해 범위 전체 표시와 구분 |
| 직선 경로 예고 | 반투명 주황 배경과 빨간 화살표 세 개 묶음 이동, 용사용 대시에는 표시하지 않음 |
| 검격 | 캐릭터 대비 크기와 타격 순간 검수, 명확한 검광 실루엣 |
| 용사용 내려찍기 | v21 분리 검광·뾰족한 지면 충격파·흙과 돌 입자, 높이·파편 크기 독립, 벽·대각선·극히 짧은 경로의 실제 Play 검수 필요 |

새 지침을 작성했다고 기존 효과 전체를 재제작하지 않는다. 새 효과와 다음 개선 작업부터 적용하고,
기존 효과는 실제 문제가 확인되거나 사용자가 개선을 요청했을 때 수정한다.
