## 1. 목적과 적용 원칙

이 문서는 정식 UI 아트를 만들기 전에 화면 구조와 제작 크기를 고정하는 기준이다. UI는 전투와
분리된 표시·입력 계층이며, 실제 게임 상태·프로필·진행 데이터를 직접 소유하거나 변경하지 않는다.

- 기준 캔버스는 `1920 × 1080`, 기준 화면 비율은 16:9다.
- 지원하는 해상도 선택지는 16:9만 제공한다. 최초 구현의 최소 확인 해상도는 `1280 × 720`이며,
  확인 대상은 `1280 × 720`, `1920 × 1080`, `2560 × 1440`이다.
- Unity Canvas는 **Screen Space - Overlay**와 `Canvas Scaler / Scale With Screen Size`를 사용한다.
  Reference Resolution은 `1920 × 1080`, Screen Match Mode는 `Match Width Or Height`, Match 값은
  `0.5`로 둔다. 따라서 기준 좌표·크기와 여백은 같은 비율로 확대·축소한다.
- 창 모드에서 16:9가 아닌 크기가 들어오면 UI를 넓은 쪽 끝까지 늘리지 않는다. 16:9 기준
  콘텐츠 영역을 중앙에 유지하고 남는 좌우 또는 상하 영역은 배경으로 처리한다. 이 동작은
  해상도 설정 화면 구현 때 실제로 확인한다.
- `1280 × 720`보다 작은 창은 지원 대상이 아니다. 해당 크기 아래로는 창 크기를 제한하거나
  가장 가까운 지원 해상도로 되돌린다.
- 설정 화면은 `1280 × 720`, `1920 × 1080`, `2560 × 1440`만 제공한다. 전체 화면은 테두리 없는
  전체 화면으로, 토글을 끄면 선택한 해상도의 고정 크기 창으로 적용하며 두 값은 로컬에 즉시 저장한다.
- Frontend와 Game 카메라는 실제 화면이 16:9보다 넓으면 좌우, 좁으면 상하에 남는 영역을 두고
  중앙 16:9 뷰포트를 유지한다. 각 Scene의 UI도 별도 `1920 × 1080` 기준 프레임을 같은 중심에 맞춘다.

## 2. 안전 영역과 레이아웃

기준 캔버스에서 일반 화면 콘텐츠의 안전 영역은 `x: 64~1856`, `y: 54~1026`이다. 즉 좌우
64px, 상하 54px 안쪽에 중요한 버튼·문구·HUD를 둔다. 배경과 장식은 이 영역 밖까지 확장할 수
있다. 팝업은 안전 영역 안에서 중앙 정렬한다.

| 영역 | 기준 좌표·크기 | 용도 |
|---|---|---|
| 좌상단 생존 HUD | 좌 64, 상 54, 폭 500, 높이 128 | 캐릭터 초상·레벨, HP·SP |
| 선택형 스탯 HUD | 좌 64, 상 198, 폭 240, 최대 높이 320 | 설정에서 켰을 때만 핵심 전투 스탯 |
| 우상단 미니맵 | 우 64, 상 54, 폭 220, 높이 180 | 현재 층의 방 연결·방문·클리어 상태 |
| 향후 Run 자원 | 우 64, 상 250, 최대 폭 220 | 코인·폭탄·열쇠 구현 후에만 표시 |
| 좌하단 아티팩트 | 좌 64, 하 54, 폭 288, 높이 112 | 최대 10개 아이콘을 5개 × 2줄로 표시 |
| 우하단 스킬 HUD | 우 64, 하 48, 폭 300, 높이 128 | 저학년·고학년 스킬 상태와 쿨타임 |
| 하단 보스 HUD | 중앙, 하 54, 폭 720, 높이 64 | 보스 이름·HP·페이즈 |
| 중앙 팝업 | 폭 720~1120, 높이 360~760 | 등록, 설정, 일시정지, 결과, 선택 보상 |
| Frontend 주 조작부 | 중앙 폭 560, 버튼 간격 16 | 타이틀·홈·캐릭터 선택의 주요 행동 |

HUD는 중앙 전투 영역(`x: 304~1616`, `y: 198~880`)을 일반적으로 가리지 않아야 한다. 보스 HUD는
보스 전투 중에만 하단 중앙에 나타난다. 화면 중앙 안내·카운트다운·보상 선택은 표시 중에만 전투
입력을 막고, 그 외 HUD는 클릭을 가로채지 않는다.

### 2.1 미니맵과 층 정보

상시 층·방 진행 점 표시는 사용하지 않고 방의 공간 관계를 보여주는 미니맵으로 대체한다.

- 현재 방은 밝은 외곽선 또는 플레이어 표식으로 강조한다.
- 방문한 방과 클리어한 방을 구분하고, 클리어는 체크 또는 내부 채움처럼 색 외의 표식을 함께 쓴다.
- 현재 방과 연결됐지만 방문하지 않은 방은 윤곽만 표시한다.
- 시작방·보물방·보스방의 정체는 해당 방의 특수 문이 탐색 범위에 들어오면 전용 아이콘으로 표시한다.
  전투 없는 보물방이 시스템상 미리 열린 상태여도 실제 진입 전에는 클리어 표식을 표시하지 않는다.
- 층 이름은 미니맵의 작은 머리글에서 `요정의 숲 · 1층` 형식으로 확인할 수 있게 한다. 새 층에
  들어갈 때는 같은 층 이름을 화면 중앙보다 조금 위에 약 1.5초 표시한 뒤 사라지게 한다. 일반 방 이름이나
  방 번호는 표시하지 않으며, 추후 층별 개성이 필요할 때만 숫자 층 이름을 고유 이름으로 교체한다.
- 코인·폭탄·열쇠처럼 아직 없는 Run 자원은 빈 자리나 비활성 아이콘도 만들지 않는다. 시스템이
  실제로 구현된 뒤 미니맵 아래의 향후 Run 자원 영역에 필요한 항목만 데이터로 구성한다.

### 2.2 아티팩트와 스탯

- 보유 아티팩트는 획득 순서대로 좌하단에 항상 표시한다. 각 아이콘은 48 × 48px이며 스택 수는
  우하단 배지로 겹쳐 표시한다.
- 현재 활성 아티팩트 10종은 5개 × 2줄 안에 모두 들어간다. 종류가 10개를 넘는 확장에서는 먼저
  10개를 유지하고 목록 옆에 `+N` 표시를 추가한다. 전체 목록·스택·설명은 일시정지 화면에서 본다.
- 아티팩트를 획득하면 화면 중앙에 이름과 짧은 한 줄 설명을 약 1.5초 표시한다. 이 알림은
  게임을 멈추거나 전투 입력을 가로채지 않는다.
- 상세 스탯 HUD는 설정에서 켜고 끌 수 있으며 기본값은 끔이다. 설정은 로컬에 저장한다.
- 상세 스탯을 켜면 공격력·공격속도·이동속도·치명타율처럼 직접 비교하는 핵심 수치만 좌측에
  표시한다. 방어막·조건부 피해의 세부 규칙은 일시정지의 아티팩트 상세에서 확인한다.
- 첫 구현은 선택형 스탯 HUD 영역의 위쪽 `240 × 216px`만 사용한다. 배경은 8%, 수치 텍스트는
  68%, 아이콘은 55% 불투명도로 두고 입력 Raycast를 받지 않는다. 정식 아이콘이 생기기 전에는
  공격력·공격속도·이동속도·치명타율을 구분하는 `A`·`AS`·`M`·`C` 색상 표식을 임시로 사용한다.
  실제 전투 화면에서 가독성이 부족하거나 지나치게 눈에 띄면 이 알파 값과 행 간격만 먼저 조정한다.

### 2.3 캐릭터 선택과 스킬 강화

- 게임 시작과 스킬 강화는 같은 데이터 기반 캐릭터 선택 화면을 사용하되, 확정 버튼 문구와 확정 뒤
  목적지를 구분한다. 캐릭터 카드를 누른 것만으로 Run 생성이나 강화 조회를 시작하지 않는다.
- 현재 캐릭터가 한 명이어도 카드는 `320 × 520px` 세로형으로 표시한다. 이후 캐릭터가 추가되면 같은
  카드 규격을 가로로 배치하고 슬라이드/페이지 입력을 추가하되, 이번 구현에는 슬라이드를 넣지 않는다.
- 카드에는 `128 × 128px` 임시 초상 영역, 이름, 여러 줄 설명과 색상 외 선택 테두리·`선택됨` 표식을 둔다.
- 스킬 강화 화면은 상단 진행 요약과 저학년·고학년 스킬 카드 두 장으로 구성한다. 요약에는 캐릭터
  레벨, 현재/필요 경험치와 남은 스킬 포인트를 표시하고 각 스킬 카드에는 현재/최대 레벨, 현재 효과와
  `1 포인트로 강화` 행동을 표시한다.
- 진행 조회 중에는 모든 강화 행동을 막는다. 진행 없음과 조회 실패는 다른 문구로 표시하고 두 경우
  모두 `다시 불러오기`를 제공한다.
- 강화 요청 중에는 두 강화 버튼을 함께 잠근다. 성공하면 서버가 반환한 전체 진행 스냅샷으로 화면을
  즉시 갱신하며, 포인트 부족·최대 레벨·진행 충돌·네트워크/서버 오류를 서로 다른 문구로 표시한다.

## 3. 글자·컨트롤·아이콘

모든 수치는 기준 캔버스의 픽셀 값이다. 텍스트는 한글과 영문·숫자를 모두 지원하는 TMP 폰트를
사용한다. 본문·버튼·입력값은 최소 20px을 지키며, 보조 정보만 16px까지 허용한다.

| 항목 | 기준 크기 | 비고 |
|---|---:|---|
| 게임 로고 | 72px | 타이틀에서 사용 |
| 화면 제목 | 40px | 홈·설정·선택·결과 제목 |
| 섹션 제목 | 28px | 패널 내부 구분 |
| 기본 버튼·입력 텍스트 | 24px | 한글 2~12자 닉네임도 이 기준 |
| 본문·HUD 수치 | 20px | HP·SP·설명·상태 |
| 보조 정보 | 16px | 단축키, 오류 코드가 아닌 짧은 안내 |
| 주 버튼 | 280 × 64px | `GAME START`, 확인, Run 시작 |
| 일반 버튼 | 220 × 52px | 홈 메뉴, 취소, 뒤로 |
| 아이콘 버튼 | 48 × 48px | 닫기 등; 접근성 이름 필수 |
| 닉네임 입력 | 440 × 56px | 입력 안내와 오류 문구는 아래에 배치 |
| HP 바 | 320 × 32px | 내부 게이지 308 × 20px, 현재/최대 수치 우측 정렬 |
| SP 슬롯 | 아이콘 40 × 40px, 간격 8px | 최대 SP 수만큼 가로 반복하고 현재 SP만 활성 표현 |
| 보스 HP 바 | 720 × 32px | 하단 중앙, 이름·페이즈 영역 포함 전체 높이 64px |
| HUD 스킬 아이콘 | 72 × 72px | 단축키와 쿨타임 표기를 겹쳐 표시 |
| HUD 아티팩트 아이콘 | 48 × 48px | 스택은 우하단 배지로 표시 |
| 보상 카드 아이콘 | 96 × 96px | 카드 전체는 최소 300 × 420px |
| 캐릭터 카드 초상 | 128 × 128px | 카드 전체는 세로형 320 × 520px |

텍스트가 한 줄을 넘길 수 있는 카드 설명·오류 안내에는 고정 높이 자르기를 쓰지 않는다. 중앙
팝업의 내용이 길면 내부 세로 스크롤을 사용하며, 제목·닫기·확인 버튼은 항상 보인다.

## 4. 상호작용 상태와 키보드 포커스

모든 실행 가능한 버튼·카드에는 아래 상태를 같은 의미로 적용한다. 색만으로 상태를 구분하지
않는다.

| 상태 | 시각 규칙 | 입력 규칙 |
|---|---|---|
| 기본 | 기본 배경·테두리·텍스트 | 클릭 또는 Enter/Space로 실행 |
| 호버 | 밝기 증가와 2px 테두리 강조 | 포인터가 머무를 때만 표시 |
| 선택 | 3px 강조 테두리와 선택 표식 | 캐릭터·보상 카드의 현재 선택 |
| 비활성 | 45% 불투명도, 대비를 낮춘 아이콘, 잠금/사유 문구 | 포커스·클릭·제출 불가 |
| 키보드 포커스 | 3px 외곽선과 2px 바깥 여백; 호버와 독립 | Tab/방향키 이동, Enter/Space 실행 |

첫 포커스는 각 화면의 주요 행동에 둔다. 팝업이 열리면 포커스를 팝업 안으로 제한하고, 닫히면
열기 전 컨트롤로 돌린다. Escape는 취소·뒤로가 가능한 팝업에서만 사용하며, 진행을 잃을 수 있는
행동에는 확인 팝업을 먼저 표시한다.

### 4.1 일시정지

- Game Scene에서 취소 불가능한 팝업이 열려 있지 않을 때 `Esc`로 일시정지 화면을 열고, 다시
  `Esc`를 누르면 게임으로 돌아간다.
- 일시정지 중에는 플레이어·적·투사체·Encounter·전투 시간과 스킬 쿨타임을 함께 멈춘다.
- 일시정지 화면에서 보유 아티팩트 전체 목록·스택·설명과 현재 상세 스탯을 확인할 수 있다.
- 보상 선택과 Run 결과처럼 취소할 수 없는 화면에서는 `Esc`로 일시정지 화면을 중첩하지 않는다.
- 일시정지의 `홈으로 나가기`는 즉시 실행하지 않고 확인 팝업을 연다. 팝업은 현재 진행과 획득
  아티팩트가 저장되지 않고 결과 보상이 지급되지 않음을 알리며, 첫 포커스는 안전한 `계속 플레이`에
  둔다. 취소 또는 `Esc`는 확인 팝업만 닫고 일시정지를 유지한다.
- `Run 끝내기`를 확정하면 사망·클리어 결과 화면과 저장 요청을 만들지 않고 Game Scene의 Run 상태를
  정리한 뒤 Frontend 홈으로 이동한다. 홈에서는 `Time.timeScale`과 입력 포커스를 정상 상태로 복원한다.
- 일시정지의 `처음부터 다시하기`도 즉시 실행하지 않고 같은 확인 팝업을 사용한다. 팝업은 현재 Run의
  진행과 획득 아티팩트가 저장되지 않으며 같은 캐릭터로 새 Run을 시작함을 알린다. 첫 포커스와
  취소·`Esc` 규칙은 홈 나가기 확인과 같다.
- `다시 시작`을 확정하면 기존 Run의 결과 저장과 보상을 만들지 않고 같은 캐릭터로 Game Scene을
  다시 시작한다. 새 Run은 새 `clientRunId`와 seed를 사용하며 방·처치·인벤토리 상태를 초기화한다.

### 4.2 HP·SP와 월드 숫자

- HP 바와 SP 슬롯은 Screen Space Canvas가 현재·최대값과 즉시 사용할 수 있는 상태를 고정 표시한다.
  HP 감소·회복 때는 게이지 변화, SP 소비·획득 때는 해당 슬롯의 점등 변화와 짧은 점멸을 제공한다.
- SP는 최대 SP 수만큼 같은 단일 아이콘을 가로로 반복하고 현재 SP 수만 활성 색으로 표시한다.
  빈 슬롯은 같은 에셋을 낮은 밝기와 불투명도로 표시하며, 최대 SP가 바뀌면 슬롯 수만 늘리거나
  줄이므로 활성·비활성 상태별 별도 에셋을 만들지 않는다.
- 적이 받은 피해 숫자는 대상 위에 생성되는 월드 오브젝트로 표시한다. 발생 위치에서 조금 위로
  이동하며 0.6~1초 안에 사라지고 오브젝트 풀로 재사용한다. 여러 숫자가 동시에 생기면 좌우 시작
  위치를 조금 분산한다. 플레이어의 피해·회복은 고정 HP 바의 변화 피드백만 사용하고 월드 숫자를
  중복 표시하지 않는다.
- 일반 적의 월드 체력바는 첫 피격 뒤 나타나 대상을 따라가고, 풀 체력으로 회복하거나 사망하면
  숨긴다. 보스는 하단의 전용 보스 HUD를 사용하므로 머리 위 체력바를 중복 표시하지 않는다.
- 보스 HP 바는 보스 전투 중에만 표시하며 현재·최대 HP, 보스 이름과 페이즈를 제공한다.

### 4.3 Run 결과 화면과 순차 연출

- 사망 시에는 이 결과 화면으로 즉시 전환하지 않는다. 플레이어 입력과 전투 진행을 막은 뒤
  Game Scene에서 캐릭터 쓰러짐 모션을 끝까지 보여주고, 그 위에 `GAME OVER`와 `결과 보기` 또는
  `다음` 조작을 표시한다. 사용자가 확인한 뒤에만 Frontend의 사망 결과 화면으로 이동한다.
- 사망 결과 저장은 쓰러짐·게임 오버 연출과 병행할 수 있지만 같은 `clientRunId`로 한 번만
  시작한다. 화면 확인 입력은 저장 요청을 중복 호출하지 않으며, 저장이 끝나지 않았다면 결과
  화면에서 진행·재시도 상태를 이어받는다.
- Run 결과는 Game Scene의 일시정지 팝업과 분리한다. Frontend Scene의 전체 화면 상태로 표시하며
  불투명한 전용 배경을 사용해 이전 전투·HUD·팝업이 보이지 않게 한다.
- 기준 배치는 왼쪽 캐릭터 반응 영역과 오른쪽 단일 연출 영역으로 나눈다. 캐릭터는 결과 화면 동안
  유지하고 클리어·사망에 맞는 표정, 동작과 짧은 말풍선을 표시한다. 오른쪽에는 여러 정보 패널을
  동시에 펼치지 않고 Run 기록, 경험치, 레벨 변화, 스킬 포인트, 아티팩트를 순서대로 교체한다.
- 경험치 바는 이전 진행에서 시작해 Backend가 확정한 최종 진행까지 움직인다. 레벨 경계를 넘을
  때마다 짧은 빛·크기 변화·효과음 피드백을 반복하되, 첫 충전 뒤에는 속도를 높여 여러 레벨 상승도
  루즈해지지 않게 한다. 마지막 경험치 위치에서는 잠깐 감속해 최종 상태를 읽을 수 있게 한다.
- 여러 레벨이 오르면 레벨별 `LEVEL UP` 화면을 반복하지 않는다. 연속 충전을 모두 보여준 뒤
  `LEVEL UP!`과 `Lv. 1 → Lv. 10` 형식의 시작·최종 레벨을 한 번만 크게 표시한다. 레벨 상승이
  없으면 큰 레벨업 표시는 생략한다.
- 연출 완료 후에는 레벨·경험치·스킬 포인트, 도달 층·처치 수·플레이 시간, 획득 아티팩트와 저장
  상태를 작은 최종 요약으로 다시 모은다. 주요 행동은 `다시 도전`과 `홈으로`이며, 다시 도전은
  캐릭터 선택 화면으로 이동한다.
- 확인 입력은 진행 중인 숫자·게이지를 즉시 최종값으로 보내고, 다시 입력하면 남은 순서를 건너뛰어
  최종 요약으로 이동한다. 건너뛰기는 화면 전환 흐름만 단축하고 최종 데이터는 바꾸거나 누락하지 않는다.
- 결과 저장이 진행 중이면 상태를 명확히 표시하고 성장 연출을 확정하지 않는다. 실패하면 같은
  `clientRunId`로 재시도하는 버튼과 오류 안내를 우선 표시한다. 저장 성공 후에만 경험치·레벨·스킬
  포인트 연출을 시작한다.
- 결과 화면이 활성화된 동안 전투 입력과 `Esc` 일시정지를 막고 포커스를 현재 연출 또는 결과 화면
  버튼 안에 제한한다. 홈이나 다시 도전으로 이동한 뒤에는 `Time.timeScale`, EventSystem 선택과
  입력 상태를 정상값으로 복원한다.

## 6. 구현과 화면 검증 순서

1. `FrontendCanvas`와 `GameCanvas`에 이 문서의 Canvas Scaler와 안전 영역 가이드를 적용한다.
2. 타이틀, 닉네임 등록, 홈, 캐릭터 선택, 스킬 강화, 설정, HUD, 결과 화면을 도형·TMP 텍스트와
   임시 아이콘으로 배치한다. HP·보스 게이지는 단색 Image와 테두리로, SP는 반복하는 단일 임시
   아이콘으로 먼저 구현한다.
3. 실제 HP·SP·보스 상태와 미니맵·아티팩트·스탯 데이터를 연결한 뒤 지정한 세 해상도에서 잘림,
   겹침, 포커스 순서와 HUD의 중앙 전투 영역 침범을 확인한다.
4. 실제 화면 검증 결과로 필요한 카드·문구의 길이와 패널 최소 크기를 조정한 뒤에만 정식 에셋을
   이 명세의 파일명·9-slice 규격으로 제작·적용한다.

이 문서의 수치 변경은 화면 검증 근거와 함께 기록한다. 검증 전에는 에셋의 화풍·색상·애니메이션을
확정 범위로 취급하지 않는다.

## 7. 후속 UI 방향 — 2026-09-14 사용자 피드백

아래 내용은 현재 구현을 즉시 변경한 상태가 아니라 다음 기능 조각의 확정 방향이다.

### 7.1 인게임 설정

- `Esc` 일시정지 메뉴에 `설정`을 추가하고 Frontend 설정과 같은 로컬 값을 사용한다.
- 설정을 열고 닫는 동안 게임은 계속 멈춰 있으며, 닫으면 일시정지 메뉴의 `설정` 버튼으로
  포커스를 돌린다. 다시 `Esc`를 누르면 설정만 닫고 일시정지는 유지한다.
- 음량과 상세 스탯 HUD는 변경 즉시 반영한다. 화면 모드·해상도 변경 시에도 중앙 16:9 프레임과
  팝업 포커스를 다시 계산한다.

### 7.2 획득 전 아티팩트 설명

- 플레이어가 미획득 아티팩트의 설명 감지 범위에 들어오면 화면 한쪽에 아이콘, 이름, 희귀도와
  핵심 효과를 표시한다. 설명은 전투를 멈추거나 이동 입력을 가로채지 않는다.
- 이름 색은 희귀도를 반영할 수 있지만 색각에 의존하지 않도록 `일반`, `희귀`, `영웅`, `전설`처럼
  실제 데이터 계약에 맞는 희귀도 텍스트 또는 표식을 함께 표시한다.
- 설명 감지 범위는 획득 범위보다 넓게 둔다. 여러 아티팩트가 겹치면 가장 가까운 하나를 표시하고,
  대상 변경 시 짧게 교체한다. 자동 획득과 별도 상호작용 입력 중 어떤 방식을 쓸지는 구현 전에
  실제 이동 속도와 읽는 시간을 비교해 결정한다.

### 7.3 현재 방 중심 미니맵과 HUD 재배치

- 미니맵은 전체 층을 매번 축소해 모두 보여주지 않는다. 현재 방을 밝게 강조하고 현재 방을 따라
  지도 뷰포트가 부드럽게 이동한다.
- 뷰포트에는 마스크를 적용해 바깥 방과 긴 Room Template 일부가 자연스럽게 잘릴 수 있게 한다.
  방의 실제 월드 크기를 그대로 축소하기보다 탐색 관계를 읽을 수 있는 최소 두께와 간격을 보장한다.
- 현재의 사각형 방도 같은 계약으로 표시하고, 이후 좁은방·넓은방·일자방·ㄱ/ㄴ자방·초대형 방은
  Room Template이 제공하는 미니맵 실루엣을 사용한다.
- 보유 아티팩트 목록은 후속 HUD 재배치에서 좌하단 대신 우상단 미니맵 아래에 둔다. 현재 최대
  10종·스택·`+N` 규칙은 유지하며, 미래 Run 자원은 그 아래나 별도 압축 행으로 배치한다.

### 7.4 한 화면 밖 Room Template과 카메라

- `한 화면에 한 방`은 **현재 방 하나만 활성·노출한다**는 뜻으로 사용한다. 현재 방 전체가 항상
  한 화면 안에 들어와야 한다는 제한은 두지 않는다.
- 기존 16:9 기본 방과 그보다 작은 방은 두 축 모두 방 중앙에 카메라를 고정한다. 가로로만 긴
  방은 가로만, 세로로만 긴 방은 세로만, 양쪽으로 큰 방은 두 축 모두 플레이어를 추적한다.
- 추적 위치는 플레이어 위치를 방별 카메라 경계로 제한해 벽 바깥과 비활성 방이 보이지 않게 한다.
  출입구 전환 중에는 다음 방의 유효 카메라 위치로 급격히 튀지 않게 보간한다.
- Small·Basic·Wide 같은 직사각형 템플릿과 축별 카메라 계약은 14주차 Room Profile에서 먼저
  검증한다. ㄱ자·ㄴ자처럼 하나의 사각 경계가 빈 공간을 비추는 형태는 여러 카메라 구역과 구역 간
  보간이 필요하므로 후속 Room Template 확장으로 둔다.
- 현재 방 중심 미니맵도 같은 `templateId`와 실루엣 정보를 사용하되 실제 월드 좌표와 UI 축척은
  분리한다.
