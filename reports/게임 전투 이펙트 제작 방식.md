# 샤샤와 용사용의 움직임을 실시간 VFX로 개선한다

**Line Renderer + UV 스크롤보다 표현력이 높은 방법은 있다. 다만 기술을 통째로 교체하기보다 형태·흐름·입자를 각각 제어하는 제작 방식이 이번 프로젝트에 더 적합하다.** 샤샤에는 길이를 제어하는 본체에 셰이더 변형과 독립적인 물방울을 합성하고, 용사용에는 공격 모양에 맞춘 메시와 검광 셰이더를 사용하는 방향을 권한다. Flowmap, 리본, VAT, 실시간 유체까지 다른 선택지가 있지만, 모두가 직선 물줄기나 짧은 내려찍기에 더 좋은 결과를 주는 것은 아니다. 특히 Line Renderer도 선을 폭이 있는 표면으로 만드는 방식이라 사용자 메시로 바꿨다는 사실만으로 품질이 올라가지는 않는다. 홍보 화면의 매력은 기술 이름보다 고유한 실루엣, 움직임의 리듬, 색과 명암, 캐릭터와의 조화로 평가해야 한다. 아래 권장은 공개 제작 사례와 공식 문서에 근거한 프로젝트 적용 판단이며, 실제 게임 화면에서 개선 효과를 검증한 결과는 아니다.

## 샤샤는 표면뿐 아니라 외곽과 물방울도 움직여야 한다

단순 UV 스크롤은 표면 무늬를 밀어낸다. 이를 확장해 노이즈로 무늬를 왜곡하고 알파 경계와 폭을 변화시키면 실시간으로 흐르고 일렁이는 물을 만들 수 있다. Shader Graph는 정점 위치를 변경할 수 있어 무늬뿐 아니라 메시 형태도 제어할 수 있다. 단, 정점이 충분해야 원하는 변형이 나온다. ([Unity 정점 변형](https://learn.unity.com/tutorial/shadergraph-vertex-position))

**추천 구성은 제어 가능한 물줄기 본체 + 내부 흐름·외곽 변화 셰이더 + 월드 공간 물방울 + 접촉부 물보라다.** 본체를 Line Renderer로 만들지 사용자 메시로 만들지는 필요한 폭·곡률·UV 제어 범위로 결정한다. 짧은 직선 줄기는 기존 Line Renderer에서도 개선 여지가 크고, 끝으로 갈수록 벌어지거나 비대칭으로 갈라지는 실루엣을 정밀하게 만들려면 사용자 메시가 유리하다. 일반 Particle System도 늘어난 빌보드와 메시 입자를 지원하므로 물방울·분출·파편에 사용할 수 있다. ([Unity Particle Renderer](https://docs.unity3d.com/6000.0/Documentation/Manual/PartSysRendererModule.html))

Flowmap은 위치별 흐름 방향을 데이터로 저장해 UV를 서로 다른 방향으로 움직인다. 단순히 모두 같은 방향으로 스크롤하는 방식보다 흐름이 돌아가거나 모이는 표면에 적합하다. 그러나 곧은 짧은 물줄기에서는 다층 노이즈 왜곡만으로 원하는 결과가 나올 수 있다. Flowmap은 필수 단계가 아니라 그 한계가 보일 때 추가할 선택지다. ([SideFX Flowmap Shader](https://www.sidefx.com/docs/houdini/nodes/shop/labs--flowmap_shader.html))

플레이어 이동 중 어색함은 별도로 확인해야 한다. 발사점 추적, 벽 끝점 갱신, 월드·로컬 공간 선택이 잘못되면 고급 셰이더도 문제를 해결하지 못한다. 이미 방출된 물방울은 월드에 남겨 관성을 표현하되, 직선 공격 판정인 본체를 크게 휘게 만들면 화면과 판정이 달라질 수 있다. 현재 화면을 프레임 단위로 검수하지 않았으므로 원인을 특정하지 않는다.

## 대안마다 잘하는 형태가 다르다

다음 표의 적합성은 조사 자료를 이 프로젝트에 적용한 판단이다. 난이도와 성능의 보편적인 순위를 뜻하지 않는다.

| 방식 | 단순 스크롤보다 추가되는 표현 | 샤샤·용사용에 대한 판단 |
|---|---|---|
| 메시 + 셰이더 | 폭·곡률·외곽 변형, 드러남·침식·소멸 | 샤샤 본체와 용사용 검광의 우선 후보. 사용자 메시 자체가 고품질을 보장하지 않음 |
| Flowmap | 위치마다 다른 흐름 방향과 UV 왜곡 | 굽거나 모이는 물에 유용. 짧은 직선 줄기는 노이즈로 먼저 비교 |
| Trail·리본 | 이동 궤적을 따라 연결된 표면 생성 | 실제 칼 궤적이나 잔류 물 궤적에 적합. 즉시 직선 판정과의 일치 필요 |
| 파티클 중심 | 방울마다 다른 속도·관성·수명 | 분무·물보라·먼지에 적합. 굵은 연속 줄기는 본체와 합성 권장 |
| VAT | 미리 계산한 복잡한 메시 변형 재생 | 큰 물덩어리·고정 물보라 후보. 자유롭게 늘어나는 본체에는 제약 |
| 실시간 유체 | 장애물과의 상호작용, 액체 이동·축적 | 물이 쌓이고 흐르는 게임플레이에 가치. 현재 짧은 공격에는 도입 비용이 큼 |
| 손그림 마스크 + 실시간 합성 | 고유한 외곽과 충격 모양을 셰이더로 변형 | SD 그림체에 맞추기 좋은 후보. 완성 프레임을 전부 교체할 필요 없음 |

Trail Renderer는 시간에 따라 궤적을 생성하고 폭 곡선·색·텍스처 반복을 제어한다. VFX Graph의 strip도 입자를 연결해 연속 표면을 만드는 별도 저작 경로다. 리본이라는 표현 방식과 VFX Graph라는 제작 도구는 구분해야 한다. ([Unity Trail Renderer](https://docs.unity3d.com/6000.0/Documentation/Manual/class-TrailRenderer.html), [VFX Graph strip 개념: 17.6 문서](https://docs.unity.cn/Packages/com.unity.visualeffectgraph@17.6/manual/Context-OutputStrip-LandingPage.html))

VAT는 정점 애니메이션을 텍스처로 저장하고 셰이더에서 재생한다. SideFX는 액체의 변화하는 메시까지 다루는 VAT와 Unity URP 패키지 경로를 제공하지만, 텍스처 메모리와 제한적인 실시간 상호작용도 명시한다. 프로젝트 URP 17.3에서 패키지가 그대로 동작하는지는 별도 확인이 필요하다. 실제 유체 계산과 VAT 베이크 재생은 서로 다른 방식이다. ([SideFX VAT 3.1](https://www.sidefx.com/docs/houdini/nodes/out/labs--vertex_animation_textures-3.1.html))

실시간 액체 도구도 존재한다. Zibra는 충돌·거품·표면장력 등을 제공한다고 설명하지만, 이는 제품사의 기능 설명이며 이 프로젝트에서의 성능이나 미술 품질 검증이 아니다. 현재 목적을 위해 구매를 먼저 권할 근거는 없다. ([Zibra 기술 설명](https://www.zibra.ai/blog-posts/setting-new-standards-how-zibra-effects-advanced-real-time-simulations-bring-liquid-smoke-and-fire-to-life-in-gaming))

## 용사용은 메시 검광과 지면 충격의 시간을 분리한다

**용사용에는 공격의 방향과 실루엣에 맞춘 쐐기·초승달 메시를 만들고, 셰이더로 검광이 드러나고 지나가고 지워지는 과정을 제어하는 방식을 우선 권한다.** 실제 무기의 움직임이 존재하면 트레일이 유용하지만, 독립적인 아이템 연출이라면 모양과 타이밍을 지정한 메시가 더 예측 가능하다. 검광·접지 충격·파편·먼지의 크기와 수명을 별도로 설계하면 검광을 키울 때 돌까지 함께 커지는 문제도 피할 수 있다.

실제 제작 사례인 Geri의 Venom Slash는 고리 모양 메시, 알파 마스크, 스크롤 노이즈, 색 램프, 도형 아틀라스 기반 보조 입자를 합성한다. 완성된 검광 프레임을 연속 재생하지 않고도 복잡한 검광을 만드는 구체적인 사례다. 다만 해당 사례의 스타일이 곧 우리 게임의 정답은 아니다. ([제작자 분해 설명](https://realtimevfx.com/t/venom-slash-breakdown-of-the-effect-included/18903))

준비 → 빠른 검광 → 접지 순간의 강한 모양 → 늦게 남는 먼지·파편이라는 시간 구조를 먼저 잡을 것을 권한다. 손그림 마스크는 이때 날카로운 외곽과 고유한 충격 형태를 만드는 재료다. 원화를 쓰는 것과 정적인 완성 그림을 늘리는 것은 다르며, 모든 이미지 재료를 없앨 이유도 없다.

## 현재 URP 2D에서 시작하고 실제 게임 크기로 비교한다

로컬 조사에서 프로젝트는 Unity 6000.3.22f1, URP 17.3.0, Renderer2D, Linear 색 공간을 사용하며 Particle System 모듈이 있고 VFX Graph 직접 의존성은 없음을 확인했다. 따라서 **현재 환경을 유지한 Particle System + URP용 셰이더 + 메시가 첫 구현 경로**다. Unity는 Particle System의 URP 호환성을 명시한다. Sprite Unlit Shader Graph도 정점 위치·색·알파와 혼합 방식을 제공한다. ([Unity 입자 시스템 비교](https://docs.unity3d.com/6000.0/Documentation/Manual/ChoosingYourParticleSystem.html), [Sprite Unlit Shader Graph](https://docs.unity.com/en-us/engine/6000.0/manual/materials-and-shaders/built-in/shaders-in-universalrp/prebuilt-shader-graphs-urp/sprite-unlit))

VFX Graph가 2D Renderer에서 불가능한 것은 아니다. Unity는 VFXSpriteLit·VFXSpriteUnlit Shader Graph로 연결하는 절차를 제공한다. 다만 확인한 2D 절차는 URP 17.0 문서이며, 17.3 시스템 요구 사항에는 Compute Shader·SSBO 요구와 OpenGL ES 미지원 등이 있다. **VFX Graph 도입은 작업 방식 선택이지 자동적인 품질 업그레이드가 아니다.** 정확한 프로젝트 빌드와 타깃 기기 호환성은 도입 시 검사해야 한다. ([Unity 2D Renderer 연동: 17.0](https://docs.unity.cn/Packages/com.unity.render-pipelines.universal@17.0/manual/2d-visual-effect-graph-compatibility.html), [VFX Graph 17.3 요구 사항](https://docs.unity3d.com/Packages/com.unity.visualeffectgraph@17.3/manual/System-Requirements.html))

외부 도구도 역할이 다르다. Houdini는 메시·시뮬레이션·베이크 제작에, JangaFX의 LiquiGen은 액체 제작에, IlluGen은 노이즈·flowmap·마스크 같은 재료 제작에 해당한다. EmberGen은 불·연기·폭발 중심이므로 샤샤 물줄기의 대표 해결책으로 고를 이유가 없다. 고급 flipbook에는 motion vector를 이용한 프레임 보간도 있지만, 이는 사용자가 묻는 실시간 형상 생성과 구분된다. ([JangaFX 공식 문서](https://docs.jangafx.com/), [SideFX Flipbook Textures](https://www.sidefx.com/docs/houdini/nodes/out/labs--flipbook_textures-1.0.html))

눈으로 비교할 제작자 공개 예시는 [Venom Slash 분해](https://realtimevfx.com/t/venom-slash-breakdown-of-the-effect-included/18903), [Gabriel Aguiar Sword Slash](https://gabrielaguiarproductions.artstation.com/projects/G82XxB), [Gabriel Aguiar Tsunami](https://gabrielaguiarproductions.artstation.com/projects/Ze8Y31), [Omid Saadat Open Flowmap](https://www.omid-saadat.com/writing/open-flowmap/), [SideFX Unity VAT 세션](https://www.sidefx.com/tutorials/building-levels-procedurally-vertex-animation-textures-in-unity/)이다. Gabriel의 작품은 제작자 예제이며 실제 Riot 게임의 내부 구현 공개 자료는 아니다.

홍보 관점에서는 샤샤 한 개를 대표 효과로 정해, 현재 방식과 셰이더 합성 방식을 같은 카메라·배경·캐릭터·크기로 비교하는 실험을 권한다. 정지 확대샷뿐 아니라 이동 중 발사, 벽 접촉, 여러 효과 동시 재생을 봐야 한다. VFX의 예술적 원칙을 다루는 GDC 강연도 기술의 복잡도와 별도로 형태·타이밍·게임플레이 표현을 논의한다. 특정 기법이 홍보 전환율이나 매출을 높인다는 인과 근거는 이번 조사에서 확보하지 않았다. ([GDC Artistic Principles of VFX](https://gdcvault.com/play/1023943/Visual-Effects-Bootcamp-Artistic-Principles))
