# Ship

`AGENTS.md`와 `.github/pull_request_template.md`를 기준으로 이번 대화의 변경을 올린다. 스킬 호출 자체를 모든 외부 작업의 승인으로 취급하지 않는다.

## 요청 범위와 변경 확인

1. `git status --short`, `git branch --show-current`, 최근 커밋과 staged/unstaged diff를 확인한다.
2. “커밋”은 커밋까지, “커밋하고 푸시”는 푸시까지, “PR 올려줘” 또는 전체 ship 요청은 검증·커밋·푸시·PR까지 진행한다. 명시한 제외 조건을 우선한다. “올려줘”가 무엇을 뜻하는지 대화로도 판단할 수 없으면 필요한 범위만 질문한다.
3. 작업은 `dev/<주차 또는 주제>` 브랜치에서 한다. main에서 시작했거나 작업 브랜치가 없으면 기존 변경을 보존한 채 적절한 dev 브랜치를 만들고 계속한다. 같은 브랜치에 관련 없는 커밋이 있으면 PR 전체 범위를 확인하고 이번 작업만 분리할 수 있는 방법을 선택한다.
4. 이번 작업과 사용자·다른 작업의 변경을 구분한다. 기존 staged 변경도 검토하고 이번 범위와 다르면 임의로 포함하거나 unstage하지 않는다. 출처가 불분명해 분리할 수 없는 부분만 질문한다.

## 사전 점검과 검증

- [pre-commit-check](../pre-commit-check/SKILL.md)를 읽고 이번 커밋 범위의 점검과 필요한 검증을 수행한다. 계약 또는 Unity 검증은 그 스킬이 연결하는 절차를 따른다.
- 같은 최종 변경에 대해 이미 통과한 검증은 근거를 재사용한다. 이후 영향을 주는 수정이 있으면 해당 검증을 다시 실행한다.
- 이번 변경의 검증 실패는 수정하고 다시 확인한다. 기존 실패나 실행 제한은 근거와 함께 구분해 보고하고, 실패를 숨기거나 훅을 우회하지 않는다.
- Unity 다중 인스턴스 잠금은 코드 실패가 아니다. 실행하지 못한 항목과 수동 메뉴·기대 결과를 기록한다. 통과로 표시하지 않는다.

## 커밋과 푸시

- 파일 또는 필요한 hunk를 명시해 stage한다. `git add -A`나 `git add .`로 다른 변경을 섞지 않는다. staged diff를 최종 확인한다.
- 커밋 직전에 현재 브랜치를 확인한다. main 직접 커밋을 하지 않는다. 제목은 `type(scope): 영어 요약 (조각 ID)`이며 scope와 조각 ID는 해당할 때만 쓴다.
- 훅을 건너뛰거나 기존 커밋을 임의로 amend하지 않는다. 커밋 뒤 남은 변경을 확인한다.
- 푸시가 승인된 범위에 있을 때 원격 URL과 실제 목적 브랜치를 확인하고 `git push -u origin <현재 dev 브랜치>`를 실행한다. main을 대상으로 하는 refspec을 사용하지 않는다.
- 강제 푸시는 명시적으로 요청한 경우에만 한다. 원격이 앞서 푸시가 거부되면 원인을 보고하고 임의의 rebase·merge·강제 푸시로 해결하지 않는다.
- `.claude/hooks/protect-main.js`의 Claude PreToolUse 설정은 Codex에서 자동 실행된다고 가정하지 않는다.

## PR

- PR 작업까지 승인되었다면 `gh pr list --head <브랜치> --state open`으로 기존 PR을 확인한다. 기존 PR이 있으면 최종 변경에 맞게 본문을 갱신하고, 없으면 생성한다. 이미 승인된 단계의 재확인을 반복하지 않는다.
- base는 main이며 PR 전체 diff와 커밋을 확인한다. 저장소의 실제 remote main ref를 기준으로 비교하고, 최근 커밋 하나만 설명하지 않는다.
- 본문은 `.github/pull_request_template.md`를 채운다. 검증 체크박스는 실제 통과 근거가 있는 것만 체크하고 수동 미확인 항목은 대기로 남긴다.
- 본문을 UTF-8 파일에 저장하고 `gh pr create` 또는 `gh pr edit`의 `--body-file`에 전달한다. PR을 생성하거나 작업 대상의 기존 PR을 확인하면 `mcp__codex_app__attach_artifact`로 해당 URL을 현재 채팅에 연결한다.
- gh 또는 인증을 사용할 수 없으면 원격 기준의 compare 링크와 준비된 본문 파일을 제공한다. 승인 없이 PR을 병합하지 않는다.

## 결과

커밋 해시·제목, 푸시 브랜치, PR 링크, 실제 검증 결과와 미실행 이유, 제외한 변경과 필요한 수동 확인을 짧게 보고한다.
